# 로그인

`cloudiactl` 은 비밀번호를 직접 받지 않습니다. 터미널에서 로그인을 요청하면 웹 콘솔에서 그 요청을 승인하는 방식으로 로그인합니다. 원격 서버의 셸처럼 브라우저가 없는 곳에서도, 다른 기기의 브라우저로 승인하면 됩니다.

## 로그인하기

1. 터미널에서 웹 콘솔 주소를 넣어 로그인을 시작합니다.

    ```bash
    cloudiactl login --endpoint https://cloudia.example.com
    ```

    터미널에 승인 주소와 코드가 나오고, 브라우저를 열 수 있으면 승인 주소를 엽니다. 브라우저를 열지 않으려면 `--no-browser` 를 붙입니다.

    ```text
    Open this URL in a browser, check that the code is NH79-3FP7, and approve it within 10 minutes:
      https://cloudia.example.com/cli-login?code=NH79-3FP7
    ```

2. 브라우저에서 승인 주소를 엽니다. 웹 콘솔에 로그인돼 있지 않으면 로그인 화면이 먼저 나옵니다.
3. **CLI 로그인 승인** 화면에서 화면 위의 코드가 터미널에 나온 코드와 같은지 확인합니다.
4. **요청 IP**가 지금 내 위치와 맞는지 확인합니다.
5. 비밀번호를 입력합니다. 일회용 코드(OTP)를 쓰는 계정이면 일회용 코드도 입력합니다.
6. **이 코드는 내가 지금 실행한 cloudiactl 터미널에 표시된 코드와 같습니다**를 선택하고 **허용**을 누릅니다.
7. 터미널에 로그인한 계정 이름이 나오면 끝입니다.

> ⚠️ **주의:** 직접 실행한 `cloudiactl login` 이 아니거나 코드·요청 IP 가 다르면 **거부**를 누르세요. 승인하면 그 터미널이 내 계정으로 Cloud:iA 를 조작할 수 있습니다. 누군가 보낸 승인 주소를 그대로 열어 승인하지 마세요.

처음 로그인할 때 넣은 주소는 저장되므로, 다음부터는 `cloudiactl login` 만 실행하면 됩니다.

## 로그인 유지 기간

| 조건 | 다시 로그인해야 하는 때 |
|---|---|
| 계속 쓰는 경우 | 승인한 때부터 최대 수명(기본 90일)이 지나면 |
| 쓰지 않는 경우 | 마지막으로 쓴 때부터 유휴 기간(기본 30일)이 지나면 |

두 기간은 Cloud:iA 설치 설정에 따라 다를 수 있습니다. 승인 화면의 경고 상자에 그 환경의 최대 수명이 나옵니다.

로그인 상태는 아래처럼 확인합니다. `auth status` 는 서버에 묻지 않고 프로필·접속 주소·계정·지금 쓰는 프로젝트(`project`)를 보여 줍니다. `--check` 를 붙이면 서버에 물어 지금도 유효한지 보고, 그 프로젝트에서 계정이 가진 역할(`role`)과 관리자 여부(`isAdmin`)도 함께 보여 줍니다. 계정이 그 프로젝트에 역할이 없으면 `warning` 이 붙습니다.

```bash
cloudiactl auth status --check
```

## 승인 알림

로그인을 승인하면 그 계정에 알림이 갑니다.

- **웹 콘솔 알림**: 오른쪽 위 알림(종)에 "CLI 로그인 승인" 이 표시됩니다.
- **메일**: 관리자가 메일 발송(SMTP)을 설정한 환경이면 승인 시각·요청 IP·기기 이름이 담긴 메일이 옵니다.

내가 승인한 적 없는 알림을 받았다면 바로 **내 정보 → 비밀번호 변경**으로 비밀번호를 바꾸세요. 비밀번호를 바꾸면 다른 기기의 웹 로그인과 CLI 로그인이 모두 끊깁니다. 그 뒤 관리자에게 알리세요.

## 로그아웃

```bash
cloudiactl logout
```

서버 쪽 로그인을 끝내고 이 기기에 저장된 로그인 정보를 지웁니다.

## 로그인 정보 저장 위치

로그인을 이어 가는 토큰(refresh token)은 운영체제의 키 저장소(macOS 키체인, Windows 자격 증명 관리자, Linux Secret Service)에 저장됩니다. 계정 이름·주소 같은 나머지 정보는 사용자 설정 폴더의 `cloudiactl/credentials/<프로필>.json` 에 저장됩니다. 키 저장소를 쓸 수 없는 환경에서는 토큰도 이 파일에 저장하고, 그렇게 했다는 경고를 보여 줍니다. 이 파일은 Linux·macOS 에서 소유자만 읽을 수 있습니다.

## 여러 환경 쓰기 (프로필)

Cloud:iA 환경이 여러 개면 프로필로 나눕니다. 프로필마다 주소와 로그인이 따로 저장됩니다.

```bash
cloudiactl config use staging                      # staging 프로필로 바꾸기(없으면 만듦)
cloudiactl login --endpoint https://staging.example.com
cloudiactl --profile production instance list      # 한 번만 다른 프로필로 실행
cloudiactl config view
```

## 무인 실행(CI)

CI 처럼 사람이 승인할 수 없는 실행은 아직 정식으로 지원하지 않습니다.

- 실행 서버에서 사람이 한 번 `cloudiactl login` 을 하고 저장된 로그인을 쓰면 동작은 합니다. 다만 최대 수명(기본 90일)이 지나면 사람이 다시 로그인해야 합니다.
- `CLOUDIA_AUTH_*` 환경 변수로 로그인하는 방식은 관리자가 따로 만든 자동화 전용 클라이언트가 있어야 쓸 수 있습니다. 그 클라이언트를 만드는 절차는 아직 제공하지 않습니다.
- 웹 콘솔 로그인용 클라이언트를 환경 변수에 넣는 방식은 막혀 있습니다. 그 비밀값은 서버 밖으로 나가면 안 됩니다.
- 무인 실행용 인증은 이후 버전에서 정식으로 제공할 예정입니다.

# 콘솔로 부팅 문제 진단하기

이 문서는 인스턴스가 부팅되지 않거나 네트워크로 접속되지 않을 때 `콘솔 로그`와 `시리얼 콘솔`로 원인을 찾고 조치하는 실습입니다.

부팅이 실패한 인스턴스는 SSH가 열리지 않습니다. 네트워크 스택이 올라오기 전에 멈췄기 때문입니다. 이때 쓸 수 있는 통로는 두 가지입니다.

| | 콘솔 로그 | 시리얼 콘솔 |
|---|---|---|
| 성격 | 읽기 전용 기록 | 실시간 · **입력 가능** |
| 인스턴스 상태 | 종료된 인스턴스도 조회 가능 | 종료된 인스턴스는 불가 (일시 중지는 접속됨) |
| 쓰는 때 | "어디서 멈췄는지" 확인 | "한 글자 넣어야 풀리는" 상황 |

먼저 콘솔 로그로 어디서 멈췄는지 보고, 조작이 필요하면 시리얼 콘솔로 들어가는 순서가 일반적입니다.

## 사전 준비
- Cloud:iA 웹콘솔 접근 가능
- 프로젝트 계정(`project-owner`)으로 로그인 가능
- 대상 인스턴스가 존재
- 브라우저에서 **팝업이 허용**되어 있을 것 (시리얼 콘솔은 새 창으로 열립니다)

<a id="step-1"></a>
## 1단계: 콘솔 로그로 멈춘 지점 확인
**수행 계정/화면:** `프로젝트 계정` / `가상머신 > 인스턴스 > 상세 > 인스턴스 구성 > 콘솔 로그`

### 절차
1. 대상 인스턴스의 상세 페이지로 이동합니다.
2. `인스턴스 구성` 그룹에서 `콘솔 로그` 탭을 선택합니다.
3. 부팅 메시지의 **마지막 줄**을 확인합니다. 대부분 그 지점이 멈춘 곳입니다.
4. 필요하면 `다운로드`로 전체 로그를 내려받아 검색합니다.

### 확인
- 게스트 OS의 커널 부팅 메시지가 표시됩니다.
- 인스턴스를 **종료했다가 다시 실행해도 이전 부팅의 로그는 지워지지 않고** 아래에 이어서 쌓입니다.

> 💡 **왜 이 로그가 필요한가:** 부팅 초기 단계에서 멈추면 게스트 내부 로그(`journalctl`)는 아직 메모리에만 있어 디스크에 남지 않습니다. 그 부팅의 흔적은 이 콘솔 로그가 유일합니다. 그래서 "고쳐보려고 재시작했더니 정작 필요한 로그가 사라지는" 일이 없도록 이어쓰기로 보존됩니다.

<a id="step-2"></a>
## 2단계: 시리얼 콘솔 접속
**수행 계정/화면:** `프로젝트 계정` / `가상머신 > 인스턴스 > 상세`

### 절차
1. 인스턴스가 `종료됨`이 아닌지 확인합니다. 부팅 중이거나 `일시 중지` 상태여도 접속됩니다 — 부팅 과정을 보는 것이 이 콘솔의 주 용도입니다.
2. 상세 페이지 상단의 `시리얼 콘솔`을 클릭합니다.
3. 새 창이 열리고 상태 바가 `연결 중` → `연결됨`으로 바뀝니다.
4. 화면이 비어 있으면 `Enter`를 한 번 입력해 프롬프트를 깨웁니다.

### 확인
- 상태 바에 `연결됨`이 표시되고 터미널에 로그인 프롬프트 또는 셸이 나타납니다.

> ⚠️ **주의:** 이 콘솔에 입력한 명령은 **콘솔 로그에 그대로 기록되며 프로젝트 구성원이 조회할 수 있습니다.** 비밀번호는 프롬프트가 가려주는 경우에만 안전하며, 명령줄에 직접 적은 자격 증명은 로그에 남습니다.

<a id="step-3"></a>
## 3단계: 콘솔에서 조치하기

시리얼 콘솔은 일반 터미널처럼 동작합니다. 자주 쓰는 상황은 다음과 같습니다.

| 상황 | 조치 |
|---|---|
| 파일 시스템 검사가 응답을 기다리며 멈춤 | 프롬프트에 맞춰 `y` 입력 |
| `/etc/fstab` 오류로 비상 모드 진입 | root로 로그인해 문제 줄을 주석 처리 후 재부팅 |
| 네트워크 설정 실수로 접속 불가 | 콘솔로 로그인해 설정을 되돌림 |
| 부팅 옵션 변경 필요 | 재부팅 후 부트로더 화면에서 편집 |

### 붙여넣기
`Ctrl` + `Shift` + `V` 를 사용합니다 (macOS는 `⌘` + `V`). `Ctrl` + `V` 는 게스트에 제어 문자로 전달됩니다.

### 알아둘 점
- **터미널 크기는 게스트에 전달되지 않습니다.** 브라우저 창을 넓혀도 게스트가 인식하는 화면 크기는 그대로여서, `vi` 같은 전체 화면 프로그램의 표시가 어긋날 수 있습니다. 필요하면 게스트에서 크기를 직접 지정하세요.
- **자동 재연결은 없습니다.** 연결이 끊기면 창을 닫고 `시리얼 콘솔`을 다시 클릭합니다.
- **오랫동안 입력이 없으면 연결이 종료됩니다.** 상태 바에 사유가 표시되며, 다시 접속하면 됩니다.
- 작업을 마치면 **창을 닫아 주세요.** 인스턴스당 한 세션만 열 수 있으므로, 열어두면 다른 구성원이 접속할 수 없습니다.

<a id="step-4"></a>
## 4단계: 콘솔이 이미 사용 중일 때

시리얼 콘솔은 **인스턴스당 한 세션**만 허용됩니다. 이미 누군가 접속해 있으면 `콘솔이 이미 사용 중입니다` 안내가 표시됩니다.

### 절차
1. 다른 구성원이 작업 중일 수 있으므로 먼저 확인합니다.
2. 그래도 접속해야 하면 `인계`를 클릭합니다.
3. 기존 세션은 **즉시 종료되며**, 그쪽 화면에는 `다른 사용자가 콘솔을 가져갔습니다`가 표시됩니다.

> ⚠️ **주의:** 인계는 남의 작업을 끊는 동작입니다. 상대가 콘솔에서 편집 중이었다면 그 작업이 중단됩니다. `취소`를 누르면 기존 세션은 그대로 유지됩니다.

> 💡 접속이 끊긴 채 방치된 세션은 일정 시간이 지나면 자동으로 회수되므로, 급하지 않다면 잠시 후 다시 시도해도 됩니다.

<a id="step-5"></a>
## 5단계: 화면이 비어 있을 때

`연결됨`인데 아무것도 표시되지 않는다면 대부분 게스트 쪽 설정 문제입니다.

| 원인 | 확인 · 조치 |
|---|---|
| 게스트 커널이 시리얼로 출력하지 않음 | 부팅 옵션에 `console=ttyS0`이 포함되어야 합니다. 기본 제공 Linux 이미지는 이미 설정되어 있습니다. 직접 만든 이미지는 추가가 필요합니다. |
| 시리얼 포트에 로그인 서비스가 없음 | 게스트에서 `serial-getty@ttyS0` 서비스를 활성화합니다. |
| 부팅이 끝나 조용한 상태 | 정상입니다. `Enter`를 입력하면 프롬프트가 나타납니다. |
| 인스턴스가 `일시 중지` 상태 | 게스트가 멈춰 있어 출력이 없습니다. 상태 바에 그 사실이 표시됩니다. |
| Windows 인스턴스 | Windows는 시리얼 콘솔(EMS)을 기본으로 사용하지 않습니다. 게스트에서 별도로 활성화해야 하며, 그래픽 화면이 필요하면 `콘솔`(그래픽)을 사용하세요. |

접속 자체가 되지 않고 상태 바가 `종료됨`으로 끝나는 경우, 표시된 사유를 먼저 확인하세요.

| 사유 | 뜻 |
|---|---|
| 콘솔 접속 정보가 유효하지 않습니다 | 접속 정보의 유효 시간이 지났습니다. 창을 닫고 다시 시도하세요. |
| 인스턴스가 종료되어 연결이 끊겼습니다 | 사용 중 인스턴스가 종료·재배치되었습니다. |
| 출력이 너무 많아 연결을 종료했습니다 | 게스트가 화면이 감당할 수 없는 속도로 출력했습니다. 출력을 멈춘 뒤 다시 접속하세요. |
| 오랫동안 입력이 없어 연결을 종료했습니다 | 유휴 상태로 방치되어 자동 회수되었습니다. |

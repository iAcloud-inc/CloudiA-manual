# 콘솔로 부팅 문제 진단하기

이 문서는 인스턴스가 부팅되지 않거나 네트워크로 접속되지 않을 때 `콘솔 로그`와 `직렬 콘솔`로 원인을 찾고 조치하는 실습입니다.

부팅이 실패한 인스턴스는 SSH가 열리지 않습니다. 네트워크 스택이 올라오기 전에 멈췄기 때문입니다. 이때 쓸 수 있는 통로는 두 가지입니다.

| | 콘솔 로그 | 직렬 콘솔 |
|---|---|---|
| 성격 | 읽기 전용 기록(파일로 다운로드) | 실시간 · **입력 가능** |
| 인스턴스 상태 | 상태와 무관하게 항상 다운로드 가능(`종료됨`도 포함) | `실행 중`, `부팅 중`, `재부팅 중`, `종료 중`, `일시 중지`에서만 접속 가능 |
| 쓰는 때 | "어디서 멈췄는지" 확인 | "한 글자 넣어야 풀리는" 상황 |

먼저 콘솔 로그를 내려받아 어디서 멈췄는지 보고, 조작이 필요하면 직렬 콘솔로 들어가는 순서가 일반적입니다.

## 사전 준비
- Cloud:iA 웹콘솔 접근 가능
- 프로젝트 계정(`project-owner`)으로 로그인 가능
- 대상 인스턴스가 존재
- 브라우저에서 **팝업이 허용**되어 있을 것 (직렬 콘솔은 새 창으로 열립니다)

<a id="step-1"></a>
## 1단계: 콘솔 로그 다운로드로 멈춘 지점 확인
**수행 계정/화면:** `프로젝트 계정` / `가상머신 > 인스턴스 > 상세 > 콘솔 > 콘솔 로그 다운로드`

### 절차
1. 대상 인스턴스의 상세 페이지로 이동합니다.
2. 상세 페이지 상단의 `콘솔`을 클릭해 메뉴를 엽니다. 메뉴 하단에는 "직렬 콘솔 세션 입출력도 함께 담깁니다."라는 각주가 항상 표시됩니다.
3. `콘솔 로그 다운로드`를 선택합니다. 별도 확인 창 없이 즉시 파일이 저장됩니다.
4. 저장된 파일을 텍스트 편집기로 열어 **마지막 줄**을 확인합니다. 대부분 그 지점이 멈춘 곳입니다. 필요하면 편집기의 찾기 기능으로 오류 문자열을 검색합니다.

### 파일명 읽는 법
파일명은 `<인스턴스 이름>-console-<시각>Z.log` 형식입니다 (예: `myvm-console-20260101T000000Z.log`). 이 시각은 **내려받은 시점이 아니라 콘솔 로그가 마지막으로 갱신된 시각(UTC)**입니다. 같은 인스턴스를 다시 내려받아도 그 사이 새 출력이 없었다면 파일명의 시각은 바뀌지 않습니다.

### 확인
- 게스트 OS의 커널 부팅 메시지부터 이후 직렬 콘솔로 입출력한 내용까지 시간 순으로 담깁니다.
- `종료됨` 상태의 인스턴스에서도 내려받을 수 있습니다 — 콘솔 로그 다운로드는 인스턴스 상태와 무관하게 항상 가능합니다(권한만 있으면 됩니다).
- 인스턴스를 종료했다가 같은 호스트에서 다시 실행하면 로그는 초기화되지 않고 아래에 이어서 쌓입니다.
  단 내려받는 파일에는 최근 기록만 담깁니다 — 기록이 일정 크기를 넘으면 오래된 부분이 빠지고,
  다른 호스트에서 다시 실행된 경우 이전 호스트의 기록은 함께 내려받아지지 않습니다.
  진단에 쓸 로그는 그때그때 내려받아 보관합니다.

> 💡 **왜 이 로그가 필요한가:** 부팅 초기 단계에서 멈추면 게스트 내부 로그(`journalctl`)는 아직 메모리에만 있어 디스크에 남지 않습니다. 그 부팅의 흔적은 이 콘솔 로그가 유일합니다. 그래서 "고쳐보려고 재시작했더니 정작 필요한 로그가 사라지는" 일이 없도록 이어쓰기로 보존됩니다.

### 로그가 비어 있거나 아예 없을 때
- **"콘솔 로그가 없습니다."** 인스턴스를 한 번도 기동하지 않았거나 로그가 정리된 경우입니다. 인스턴스를 한 번 부팅해 본 뒤 다시 시도하세요.
- **"콘솔 로그가 비어 있습니다."** 게스트가 직렬 콘솔로 출력하도록 설정되어 있지 않을 수 있습니다. Linux는 부팅 옵션에 커널 파라미터 `console=ttyS0`가 필요하고, Windows는 EMS(Emergency Management Services) 활성화가 필요합니다. → [5단계: 화면이 비어 있을 때](#step-5)에서 게스트 쪽 설정을 확인하세요.
- 그 외에 파일이 상한을 넘어 뒷부분만 담겼거나, 호스트 접속 실패·에이전트 미지원 등으로 저장 자체에 실패하는 경우도 있습니다. 화면에 뜨는 안내 문구를 그대로 원인 파악에 활용하세요.

> ⚠️ **주의:** 이 로그에는 직렬 콘솔 세션에서 게스트가 출력한 내용이 담기며, 게스트가 화면에 되돌려 보낸 입력도 함께 남습니다. 명령줄에 직접 적은 비밀번호나 자격 증명이 있다면 이 로그에도 남고, 콘솔 로그 조회 권한(`instanceconsole-view`) 이상을 가진 사용자가 내려받아 볼 수 있습니다. **그래픽 콘솔(VNC) 세션은 이 로그에 담기지 않습니다** — 비밀번호 등 비밀을 다뤄야 한다면 직렬 콘솔 대신 그래픽 콘솔이나 SSH를 사용하세요.

<a id="step-2"></a>
## 2단계: 직렬 콘솔 접속
**수행 계정/화면:** `프로젝트 계정` / `가상머신 > 인스턴스 > 상세`

### 절차
1. 인스턴스 상태가 `실행 중`, `부팅 중`, `재부팅 중`, `종료 중`, `일시 중지` 중 하나인지 확인합니다.
   부팅 중이거나 `일시 중지` 상태여도 접속됩니다 — 부팅 과정을 보는 것이 이 콘솔의 주 용도입니다.
   그 외 상태(`마이그레이션 중`, `업데이트 중`, `스냅샷 처리 중`, `종료됨`, `정지됨`, `에러`)에서는
   `직렬 콘솔`이 비활성입니다. 이때는 콘솔 로그 다운로드만 사용합니다.
2. 상세 페이지 상단의 `콘솔`을 클릭하고 메뉴에서 `직렬 콘솔`을 선택합니다.
3. 새 창이 열리고 상태 바가 `연결 중` → `연결됨`으로 바뀝니다.
4. 화면이 비어 있으면 `Enter`를 한 번 입력해 프롬프트를 깨웁니다.

### 확인
- 상태 바에 `연결됨`이 표시되고 터미널에 로그인 프롬프트 또는 셸이 나타납니다.

### 접속했는데 화면에 아무것도 안 보일 때
연결은 됐는데(`연결됨`) 화면이 비어 있다면 화면에 다음 안내가 표시됩니다. 두 안내는 조건이 맞으면 **함께** 표시될 수 있습니다.
- 출력이 약 5초간 없으면 "출력이 없습니다. 게스트에 직렬 콘솔이 설정되지 않았을 수 있습니다 — Enter 를 입력해 보세요."가 표시됩니다. 안내대로 `Enter`를 입력해도 반응이 없으면 [5단계: 화면이 비어 있을 때](#step-5)에서 게스트 쪽 설정을 확인하세요.
- 콘솔을 열 때 인스턴스가 `일시 중지` 상태였다면 "일시 중지된 인스턴스라 출력이 없습니다."가 함께 표시됩니다. 게스트가 멈춰 있어 정상이며, 재개하면 출력이 다시 보입니다. 단 이 안내는 콘솔을 여는 시점의 상태로 판단하므로, 접속한 뒤에 일시 중지된 경우에는 표시되지 않습니다.

> ⚠️ **주의:** 이 콘솔에 입력한 명령은 콘솔 로그에 기록되며 콘솔 로그 조회 권한(`instanceconsole-view`) 이상을 가진 사용자가 내려받아 볼 수 있습니다. 비밀번호는 프롬프트가 입력을 화면에 되돌려 보내지 않는 경우에만 안전하며, 명령줄에 직접 적은 자격 증명은 로그에 남습니다. **그래픽 콘솔 세션은 기록되지 않으므로**, 비밀을 다뤄야 하는 작업은 직렬 콘솔 대신 그래픽 콘솔이나 SSH를 사용하세요.

<a id="step-3"></a>
## 3단계: 콘솔에서 조치하기

직렬 콘솔은 일반 터미널처럼 동작합니다. 자주 쓰는 상황은 다음과 같습니다.

| 상황 | 조치 |
|---|---|
| 파일 시스템 검사가 응답을 기다리며 멈춤 | 프롬프트에 맞춰 `y` 입력 |
| `/etc/fstab` 오류로 비상 모드 진입 | root로 로그인해 문제 줄을 주석 처리 후 재부팅 |
| 네트워크 설정 실수로 접속 불가 | 콘솔로 로그인해 설정을 되돌림 |
| 부팅 옵션 변경 필요 | 재부팅 후 부트로더 화면에서 편집 |

### 붙여넣기 및 화면 크기
콘솔 화면에 "붙여넣기: Ctrl+Shift+V (macOS: ⌘V)"라는 안내가 항상 표시됩니다. `Ctrl` + `V` 는 게스트에 제어 문자로 그대로 전달되므로 붙여넣기에는 쓰지 마세요.
같은 화면에 "게스트가 인식하는 창 크기와 다를 수 있습니다."라는 안내도 함께 표시됩니다 — 브라우저 창을 넓혀도 게스트의 화면 크기 인식은 바뀌지 않으므로, `vi` 같은 전체 화면 프로그램의 표시가 어긋날 수 있습니다.

### 알아둘 점
- **자동 재연결은 없습니다.** 연결이 끊기면 창을 닫고 `콘솔` 메뉴에서 `직렬 콘솔`을 다시 클릭합니다.
- **오랫동안 입력이 없으면 연결이 종료됩니다.** 상태 바에 사유가 표시되며, 다시 접속하면 됩니다.
- 작업을 마치면 **창을 닫아 주세요.** 인스턴스당 한 세션만 열 수 있으므로, 열어두면 다른 구성원이 접속할 수 없습니다.

<a id="step-4"></a>
## 4단계: 콘솔이 이미 사용 중일 때

직렬 콘솔은 **인스턴스당 한 세션**만 허용됩니다. 이미 다른 세션이 연결되어 있으면 접속을 시도할 때 `콘솔이 이미 사용 중입니다` 모달이 표시됩니다. 본문에는 "이 인스턴스의 직렬 콘솔에 다른 세션이 연결되어 있습니다. 인계하면 기존 세션은 즉시 종료됩니다."라는 안내가 함께 나타납니다.

### 절차
1. 다른 구성원이 작업 중일 수 있으므로 먼저 확인합니다.
2. 그대로 두려면 `취소`를 클릭합니다 — 기존 세션은 유지됩니다.
3. 그래도 접속해야 하면 `인계`를 클릭합니다. 기존 세션은 **즉시 종료되며**, 그쪽 화면에는 "다른 사용자가 콘솔을 가져갔습니다."가 표시됩니다.

> ⚠️ **주의:** 인계는 남의 작업을 끊는 동작입니다. 상대가 콘솔에서 편집 중이었다면 그 작업이 중단됩니다.

<a id="step-5"></a>
## 5단계: 화면이 비어 있을 때

`연결됨`인데 아무것도 표시되지 않는다면 대부분 게스트 쪽 설정 문제입니다.

| 원인 | 확인 · 조치 |
|---|---|
| 게스트 커널이 직렬로 출력하지 않음 | 부팅 옵션에 `console=ttyS0`이 포함되어야 합니다. 기본 제공 Linux 이미지는 이미 설정되어 있습니다. 직접 만든 이미지는 추가가 필요합니다. |
| 직렬 포트에 로그인 서비스가 없음 | 게스트에서 `serial-getty@ttyS0` 서비스를 활성화합니다. |
| 부팅이 끝나 조용한 상태 | 정상입니다. `Enter`를 입력하면 프롬프트가 나타납니다. |
| 인스턴스가 `일시 중지` 상태 | 게스트가 멈춰 있어 출력이 없습니다. 콘솔을 열 때 이미 일시 중지 상태였다면 화면에 그 사실이 안내됩니다. |
| Windows 인스턴스 | Windows는 직렬 콘솔(EMS)을 기본으로 사용하지 않습니다. 게스트에서 별도로 활성화해야 하며, 그래픽 화면이 필요하면 그래픽 콘솔을 사용하세요. |

접속 자체가 되지 않고 상태 바가 `종료됨`으로 끝나는 경우, 표시된 사유를 먼저 확인하세요.

| 사유 | 뜻 |
|---|---|
| 콘솔 접속 정보가 유효하지 않습니다 | 접속 정보의 유효 시간이 지났습니다. 창을 닫고 다시 시도하세요. |
| 인스턴스가 종료되어 콘솔 연결이 끊겼습니다 | 사용 중 인스턴스가 종료·재배치되었습니다. |
| 호스트와의 연결이 끊겼습니다 | 인스턴스가 올라간 호스트에 닿지 못했습니다. |
| 출력이 너무 많아 연결을 종료했습니다 | 게스트가 화면이 감당할 수 없는 속도로 출력했습니다. 출력을 멈춘 뒤 다시 접속하세요. |
| 오랫동안 입력이 없어 연결을 종료했습니다 | 유휴 상태로 방치되어 연결이 종료되었습니다. 다시 접속하면 됩니다. |

창이 아예 뜨지 않고 **인스턴스 상세 화면에 안내가 뜨는 경우**도 있습니다. 콘솔 개설 자체가 실패한 경우로, 이때는 열리려던 창이 닫히므로 상태 바를 볼 수 없습니다.

| 안내 | 뜻 |
|---|---|
| 열려 있는 직렬 콘솔이 너무 많습니다 | 동시에 열어 둔 직렬 콘솔 수가 상한을 넘었습니다. 사용하지 않는 콘솔 창을 닫은 뒤 다시 시도하세요. |
| 이 호스트의 에이전트 업그레이드가 진행 중입니다 | 호스트 에이전트가 업그레이드 중입니다. 잠시 후 다시 시도하세요. |
| 현재 상태에서는 직렬 콘솔에 접속할 수 없습니다 | 인스턴스 상태가 직렬 콘솔을 허용하지 않습니다. 콘솔 로그는 내려받을 수 있습니다. |
| 인스턴스가 올라가 있는 호스트에 연결할 수 없습니다 | 호스트에 닿지 못했습니다. |

## 참고
- 그래픽 화면이 필요한 작업(설치 마법사, GUI)은 직렬 콘솔이 아니라 그래픽 콘솔을 사용합니다. 그래픽 콘솔도 새 창으로 열리지만, 직렬 콘솔과 달리 팝업이 차단되어 창이 뜨지 않을 때 이를 알려주는 안내 문구는 없습니다 — 창이 뜨지 않으면 브라우저의 팝업 차단 여부를 먼저 확인하세요. → [윈도우 가상머신 ISO 생성 및 콘솔 확인](04-create-windows-instance-from-iso-and-open-console.md)
- 정상 접속이 가능한 인스턴스는 콘솔보다 SSH가 편합니다. → [SSH 키를 사용한 인스턴스 접속하기](07-access-instance-with-ssh-key.md)

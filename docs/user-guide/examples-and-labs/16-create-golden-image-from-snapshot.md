# 스냅샷 이미지 생성으로 골든 이미지 만들기 및 인스턴스 실행

이 문서는 인스턴스 스냅샷에서 이미지를 생성해 골든 이미지로 활용하고, 새 인스턴스를 실행하는 실습입니다.

## 사전 준비
- Cloud:iA 웹콘솔 접근 가능
- 프로젝트 계정(`project-owner`)으로 로그인 가능
- [인스턴스 스냅샷 롤백하기](./15-rollback-instance-to-snapshot.md)에서 생성한 스냅샷 또는 부팅 가능한 스냅샷 존재
- Linux 게스트에서 `cloud-init`를 사용하는 경우, 골든 이미지 생성 전에 `cloud-init clean` 수행 가능
- ISO로 설치한 인스턴스는 먼저 골든 이미지 준비 문서를 진행해야 함
  - Linux: [ISO로 설치한 Rocky 인스턴스를 골든 이미지로 준비하기](./24-prepare-rocky-instance-for-golden-image.md)
  - Windows: [ISO로 설치한 Windows 인스턴스를 골든 이미지로 준비하기](./19-prepare-windows-instance-for-golden-image.md)

<a id="step-1"></a>
## 1단계: 골든 이미지 생성 전 준비
**수행 계정/화면:** `인스턴스 OS 접속`

Golden Image에 `cloud-init` 상태가 그대로 포함되지 않도록, 이미지 생성 전에는 게스트 OS에서 `cloud-init clean`을 수행하는 것을 표준 절차로 권장합니다.

특히 `PER_ONCE` 단계의 사용자 스크립트가 이미 실행된 상태에서 이미지를 만들면, 해당 실행 이력이 이미지에 포함되어 새 인스턴스에서 `PER_ONCE` 스크립트가 기대대로 다시 실행되지 않을 수 있습니다.

또한 게스트 OS에 남아 있는 사용자 계정은 이미지에 그대로 포함되어, 이 이미지로 만든 새 인스턴스에도 유지됩니다. CloudiA는 인스턴스 생성 시 지정한 계정 하나만 관리하므로, 이미지에 불필요한 계정이 남아 있지 않도록 골든 이미지 생성 전에 직접 정리합니다.

### 절차
1. 대상 Linux 인스턴스에 접속합니다.
2. 필요한 애플리케이션/설정을 모두 마무리합니다.
3. 직렬 콘솔이 동작하는지 확인합니다. `cat /proc/cmdline` 출력에 `console=ttyS0`이 없으면 [게스트에서 직렬 콘솔 켜기](23-troubleshoot-boot-with-console.md#guest-serial-setup)를 따라 설정합니다. ISO로 설치한 OS는 대부분 빠져 있습니다.
4. 이미지에 남길 필요가 없는 OS 사용자 계정이 있으면 정리합니다(예: `sudo userdel -r <계정>`).
5. `sudo cloud-init clean`을 실행합니다.
6. Cloud:iA 웹에서 인스턴스를 `종료`합니다. 게스트 안에서 `poweroff` 등으로 끄지 않습니다.
7. `종료됨` 상태에서 스냅샷을 생성합니다. 이미지는 2단계에서 이 스냅샷으로 만듭니다. 인스턴스에서 바로 이미지를 만드는 기능은 없습니다.

### 확인
- `cloud-init` 실행 이력과 캐시가 정리된 상태로 이미지를 생성할 수 있습니다.
- 새 인스턴스에서 `cloud-init` 초기 부팅 절차가 다시 시작됩니다.
- 직렬 콘솔 설정은 이미지에 담겨, 이 이미지로 만든 인스턴스에서도 `직렬 콘솔`과 `콘솔 로그 다운로드`를 바로 쓸 수 있습니다.

> ⚠️ **주의:** 정리한 Linux 인스턴스는 게스트 안에서 `poweroff`나 `shutdown`으로 끄지 말고 Cloud:iA 웹의 `종료`로 끕니다. 게스트 안에서 끄면 Cloud:iA가 비정상 종료로 보고 30~60초 안에 인스턴스를 다시 켭니다. 다시 켜진 첫 부팅에서 machine-id, SSH 호스트 키, cloud-init 실행 이력이 새로 만들어져 정리한 내용이 무효가 됩니다. 실수로 다시 켜졌다면 정리를 처음부터 다시 합니다.

<a id="step-2"></a>
## 2단계: 스냅샷에서 이미지 생성
**수행 계정/화면:** `프로젝트 계정` / `프로젝트 페이지`

### 절차
1. 대상 인스턴스 상세 화면에서 `인스턴스 구성 요소 > 스냅샷`으로 이동합니다.
2. 부팅 가능한 스냅샷을 선택하고 `이미지 생성`을 클릭합니다.
3. 스토리지 도메인과 이미지 이름을 입력하고 생성합니다. (생성된 이미지는 `스토리지 > 이미지`에서 확인합니다.)

### 입력 예시
| 항목 | 값 |
|---|---|
| 스냅샷 | `example-snapshot-001` |
| 스토리지 도메인 | `NFS-SD` |
| 이미지 이름 | `example-golden-image-001` |

### 확인
- 이미지 생성 요청 토스트가 표시됩니다.

<a id="step-3"></a>
## 3단계: 이미지 목록 확인
**수행 계정/화면:** `프로젝트 계정` / `프로젝트 페이지`

### 절차
1. `스토리지 > 이미지`로 이동합니다.
2. 생성한 이미지 이름으로 검색합니다.
3. 이미지를 열어 상세 정보를 확인합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 검색어 | `example-golden-image-001` |

### 확인
- 목록에 `example-golden-image-001`이 표시됩니다.
- 분류가 `프로젝트 이미지`로 표시됩니다.
- Linux 이미지는 이미지 상세에서 `cloud-init`과 `qemu-guest-agent`가 `설치됨`으로 표시됩니다. `cloud-init`이 `미설치`이면 아래 4단계의 주의를 확인합니다. Windows 이미지는 두 항목이 `미확인`으로 표시되며 정상입니다.
- ISO로 설치한 인스턴스의 스냅샷으로 만든 이미지는 생성이 끝난 뒤에도 `OS 타입`이 `알 수 없음`으로 표시되고 그대로 남습니다. 운영체제를 판별하지 못한 것일 뿐 실패가 아니며, Linux 이미지는 인스턴스를 만들고 쓰는 데 지장이 없습니다.

<a id="step-4"></a>
## 4단계: 골든 이미지로 인스턴스 생성
**수행 계정/화면:** `프로젝트 계정` / `프로젝트 페이지`

### 절차
1. `가상머신 > 인스턴스`에서 `생성`을 클릭합니다.
2. OS 이미지로 `example-golden-image-001`을 선택합니다.
3. 네트워크/인증 정보를 입력하고 인스턴스를 생성합니다.
4. 인스턴스를 실행합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 인스턴스 이름 | `example-instance-from-golden-001` |
| 인스턴스 타입 | `t2.medium`                               |
| OS 이미지 | `example-golden-image-001` |
| 디스크 크기 설정 | `30 GB`                                   |
| VPC | `example-vpc`                             |
| 서브넷 | `example-subnet`                          |
| IP 주소 | `자동 할당`                                   |
| 보안그룹 | `example-vpc-default-sg`                  |
| 사용자 이름 | `cloudia`                                 |
| 비밀번호 | `cloudia`                               |

### 확인
- 인스턴스가 정상 생성되고 `실행 중`으로 전환됩니다.
- 골든 이미지 기준으로 동일 초기 구성이 반영됩니다.

> ⚠️ **주의:** `cloud-init`이 없는 이미지로 인스턴스를 만들면 입력한 사용자 이름·비밀번호와 새로 배정한 IP가 적용되지 않습니다. 입력한 계정으로 로그인할 수 없고, 이미지를 만들 때의 계정이 그대로 남으며, **원본 인스턴스의 IP, 호스트 이름, machine-id**로 뜹니다. 원본이 켜져 있으면 IP가 충돌합니다. 이미지 상세에서 `cloud-init`이 `설치됨`인지 먼저 확인합니다.

> 💡 **참고:** Windows 이미지는 인스턴스를 만들 때 입력한 계정 정보(`사용자 이름`, `비밀번호`)가 Windows에 적용되지 않습니다. 첫 부팅의 Windows 설정 화면에서 관리자 비밀번호를 정하고, IP는 직접 입력합니다. 자세한 내용은 [ISO로 설치한 Windows 인스턴스를 골든 이미지로 준비하기 — 4단계](./19-prepare-windows-instance-for-golden-image.md#step-4)를 참고합니다.

> 💡 **참고:** 이미지보다 큰 `디스크 크기 설정`으로 만들면 첫 부팅에서 루트 파일 시스템이 늘어납니다. 이미지에 `cloud-init`과 `cloud-utils-growpart`가 있어야 합니다. 루트가 LVM이면(Rocky 설치 기본 분할) 자동으로 늘어나지 않으므로 [인스턴스 부팅 디스크 증설하기 — 4단계](./22-grow-boot-disk.md#step-4)의 LVM 순서로 직접 늘립니다.

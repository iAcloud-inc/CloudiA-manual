# 인스턴스 마이그레이션하기 (호스트 마이그레이션)

이 문서는 어드민 페이지의 컴퓨트 노드 화면에서 인스턴스를 **다른 호스트(컴퓨트 노드)** 로 마이그레이션하는 실습입니다.
라이브/콜드 방식의 차이와 제약을 함께 확인합니다. 마이그레이션은 2단계 마법사(`목적지 지정` → `계획 확인`)로 진행하며, 이 실습에서는 인스턴스를 한 개씩 옮깁니다.

> **두 종류의 마이그레이션 구분**
>
> CloudiA에는 이름이 비슷한 두 가지 마이그레이션이 있습니다. 목적이 다르니 혼동하지 마십시오.
> - **호스트 마이그레이션**(이 문서): 인스턴스가 **실행되는 컴퓨트 노드**를 옮깁니다. 어드민 페이지에서 수행합니다.
> - **스토리지 마이그레이션**: 디스크(부팅 디스크·블록)를 **다른 스토리지 도메인**으로 옮깁니다. 프로젝트 페이지에서 수행합니다.
>   - 부팅 디스크: [가상머신 > 인스턴스 - 스토리지 마이그레이션](../../project/vm/instance/instance.md#스토리지-마이그레이션)
>   - 블록: [스토리지 > 블록 - 블록 스토리지 마이그레이션](../../project/storage/block/block.md#블록-스토리지-마이그레이션)

## 시작하기 전 
### 라이브 마이그레이션과 콜드 마이그레이션 비교
| 구분 | 라이브 마이그레이션 | 콜드 마이그레이션 |
|---|---|---|
| 동작 방식 | 실행 중인 인스턴스를 중단 최소화 상태로 이동 | 마이그레이션 시 인스턴스 재기동(중단 발생 가능) 기반으로 이동 |
| 대상 인스턴스 상태 | 현재 `실행 중` 인스턴스 대상 | 인스턴스 `실행/종료` 여부와 무관하게 대상 지정 가능 |
| 서비스 영향 | 상대적으로 짧은 끊김 또는 무중단에 가까움 | 라이브 마이그레이션보다 중단 시간이 길 수 있음 |
| 대상 노드 선택 | 제약 조건을 만족하는 노드만 선택 가능 | 라이브 마이그레이션 대비 선택 가능한 노드 범위가 넓음 |
| 주요 제약 | 보안 타입, CPU 피닝, NPU 패스스루, vTPM, Windows OS 등 조건에 따라 제한될 수 있음 | 라이브 마이그레이션 대비 제약이 적음 |
| 권장 상황 | 운영 중 서비스 영향 최소화가 필요한 경우 | 유지보수/점검처럼 짧은 중단 허용이 가능한 경우 |

> vTPM이 활성화된 인스턴스는 라이브 마이그레이션이 지원되지 않습니다. 해당 인스턴스는 콜드 마이그레이션을 사용해 이동하세요.

## 사전 준비
- Cloud:iA 웹콘솔 접근 가능
- `admin` 계정으로 로그인 가능
- 실행 중 인스턴스 1개 이상 존재 (마이그레이션 중이거나 대기 중인 인스턴스는 제외)
- 컴퓨트 노드 2대 이상 존재

## 개요
1. [라이브 마이그레이션 수행](#step-1)
2. [콜드 마이그레이션 수행](#step-2)


<a id="step-1"></a>
## 1단계: 라이브 마이그레이션 수행
**수행 계정/화면:** `admin 계정` / `어드민 페이지 > 물리 머신 > 컴퓨트 노드`

### 절차
1. 컴퓨트 노드 목록에서 인스턴스가 있는 노드의 이름을 클릭하고 **인스턴스** 탭을 엽니다.
2. 옮길 인스턴스를 한 개 선택하고 **`마이그레이션`** 버튼을 클릭합니다. 마이그레이션 창(마법사)이 열립니다.
3. 마법사의 `목적지 지정` 단계에서 `목적지`를 대상 노드로 고르고 `방식`이 `라이브`인지 확인합니다. 처음에는 자동 배치가 목적지와 방식을 골라 둡니다. 고른 노드가 `라이브`를 지원하지 않으면 방식이 `콜드`로 자동 변경됩니다. **`다음`** 을 클릭합니다.
4. `계획 확인` 단계에서 요약의 `라이브 1건`과 노드별 자원 변화를 확인하고 **`마이그레이션 1건`** 버튼을 클릭합니다.
5. 완료 후 소스 노드/대상 노드 인스턴스 목록을 확인합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 목적지 | `compute-node-002` |
| 방식 | `라이브` |

### 확인
- 마이그레이션 요청/완료 알림이 표시됩니다.
- 진행 중에는 인스턴스 목록의 `상태` 칸에 `마이그레이션 중 n%`가 표시됩니다. 노드가 동시에 처리할 수 있는 건수를 넘으면 `마이그레이션 대기 · n번째`로 표시되고, 순서가 되면 시작합니다. 자세한 내용은 [대기와 취소](../../administrator/host-machine/compute-node/compute-node.md#대기와-취소)를 참고하세요.
- 인스턴스가 대상 노드로 이동합니다.
- 완료 후 상태가 `실행 중`입니다.

<a id="step-2"></a>
## 2단계: 콜드 마이그레이션 수행
**수행 계정/화면:** `admin 계정` / `어드민 페이지 > 물리 머신 > 컴퓨트 노드`

### 절차
1. 인스턴스를 한 개 선택하고 **`마이그레이션`** 버튼을 클릭해 마법사를 다시 엽니다. 1단계에서 옮긴 인스턴스는 대상 노드로 이동했으므로, 같은 인스턴스를 쓰려면 대상 노드의 **인스턴스** 탭에서 고르고 다른 인스턴스를 쓰려면 그 인스턴스가 있는 노드의 **인스턴스** 탭에서 고릅니다.
2. `목적지 지정` 단계에서 `목적지`를 대상 노드로 고르고 `방식`을 `콜드`로 선택합니다. 콜드는 `예상 시간` 칸이 비어 있습니다. **`다음`** 을 클릭합니다.
3. `계획 확인` 단계에서 요약의 `콜드 1건`을 확인하고 **`마이그레이션 1건`** 버튼을 클릭합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 목적지 | 인스턴스가 지금 있는 노드가 아닌 노드 (1단계에서 옮긴 인스턴스를 쓰면 원래 노드) |
| 방식 | `콜드` |

### 확인
- 콜드 모드에서도 마이그레이션이 정상 완료됩니다.
- 대상 노드에서 인스턴스가 확인됩니다.

> ⚠️ **주의:** 콜드 마이그레이션은 인스턴스를 종료했다가 대상 노드에서 다시 시작하므로 그동안 서비스가 중단됩니다. `마이그레이션 1건` 버튼을 누르는 것이 곧 동의이므로, 누르기 전에 `콜드 1건`인지 확인합니다.

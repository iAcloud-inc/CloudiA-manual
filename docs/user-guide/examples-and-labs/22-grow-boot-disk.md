# 인스턴스 부팅 디스크 증설하기

이 문서는 전원을 끈 인스턴스의 `부팅 디스크 크기`를 늘려(증설) 게스트 OS가 늘어난 용량을 사용하도록 만드는 실습입니다. 증설은 플랫폼이 블록 디바이스를 확대한 뒤 게스트 OS가 파티션과 파일 시스템을 확장하는 순서로 진행됩니다. cloud-init(Linux)·Cloudbase-init(Windows) 같은 확장 도구가 포함된 이미지는 게스트 확장이 자동으로 이루어지고, 확장 도구가 없는 이미지는 수동 확장이 필요합니다.

## 사전 준비
- Cloud:iA 웹콘솔 접근 가능
- 프로젝트 계정(`project-owner`)으로 로그인 가능
- 증설할 인스턴스가 `종료됨` 상태 (부팅 디스크 증설은 전원을 끈 상태에서만 가능)
- 증설 전 인스턴스 스냅샷 또는 백업 확보 권장

## 개요
1. [부팅 디스크 크기 증설](#step-1)
2. [자동 확장 확인](#step-2)
3. [사용자(BYO) 이미지에 필요한 패키지](#step-3)
4. [Linux 수동 확장](#step-4)
5. [Windows 수동 확장](#step-5)

<a id="step-1"></a>
## 1단계: 부팅 디스크 크기 증설
**수행 계정/화면:** `프로젝트 계정` / `가상머신 > 인스턴스`

### 절차
1. 대상 인스턴스를 선택하고 `종료`합니다. 상태가 `종료됨`으로 전환될 때까지 기다립니다.
2. 인스턴스를 선택한 뒤 `편집`을 클릭합니다.
3. `디스크 크기 설정`을 펼친 뒤 `부팅 디스크 크기`를 현재 값보다 크게 입력합니다.
4. `저장`을 클릭한 뒤 인스턴스를 `실행`합니다. 플랫폼이 다음 실행 시점에 블록 디바이스 크기를 늘립니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 변경 전 부팅 디스크 크기 | `20 GB` |
| 변경 후 부팅 디스크 크기 | `40 GB` |

### 확인
- 인스턴스 상세 `디스크` 탭에서 부팅 디스크 `크기`가 늘어난 값으로 표시됩니다.

> ⚠️ **주의:** 부팅 디스크 크기는 증설(확대)만 가능하며 축소는 지원하지 않습니다. 증설 전 스냅샷 또는 백업을 확보하세요.

## 2단계: 자동 확장 확인
**수행 계정/화면:** `프로젝트 계정` / `인스턴스 콘솔 또는 SSH`

확장 도구가 포함된 이미지로 만든 인스턴스는 재기동 시 게스트 OS의 파티션과 파일 시스템이 자동으로 확장됩니다(Linux는 cloud-init, Windows는 Cloudbase-init). 자동 확장 여부는 이미지 분류가 아니라 게스트에 이 도구가 포함됐는지로 결정되므로, 도구가 없는 이미지는 3단계 이후의 수동 확장이 필요합니다.

루트 볼륨이 LVM으로 구성된 인스턴스도 자동 확장 대상입니다. RHEL·Rocky 계열 설치 프로그램은 LVM을 기본값으로 쓰므로, ISO로 직접 설치했거나 사내 표준 이미지를 반입한 인스턴스는 대부분 여기에 해당합니다. 증설한 뒤 처음 기동할 때 파티션 → 물리 볼륨 → 루트 논리 볼륨 → 파일 시스템 순서로 확장됩니다. 확장은 부팅 디스크가 실제로 커졌을 때만 일어나므로, 증설하지 않은 평소 재기동은 볼륨 그룹 구성을 바꾸지 않습니다.

다만 아래 구성은 기존 스토리지 구성을 보호하려고 자동 확장을 건너뜁니다. 이때는 4단계에서 직접 확장합니다.

| 자동 확장을 건너뛰는 구성 | 조치 방법 |
|---|---|
| 루트 볼륨 그룹이 여러 디스크에 걸쳐 있음 | 4단계에서 늘릴 디스크를 직접 지정해 확장합니다. |
| 씬 프로비저닝 논리 볼륨 | 씬 풀을 먼저 확장한 뒤 루트 논리 볼륨을 확장합니다. |
| 소프트웨어 RAID 또는 디스크 암호화 위에 올린 물리 볼륨 | 해당 계층을 먼저 확장한 뒤 4단계를 진행합니다. |
| 물리 볼륨이 파티션이 아니라 디스크 전체 | 4단계에서 `pvresize` 부터 직접 진행합니다. |
| 루트 파일 시스템이 `xfs`·`ext4` 계열이 아님(예: `btrfs`) | 4단계에서 해당 파일 시스템의 확장 명령으로 직접 진행합니다. |
| 늘릴 파티션 뒤에 다른 파티션이 있음 | 뒤쪽 파티션을 옮기거나 지운 뒤 확장합니다. |
| `cloud-utils-growpart` 또는 `lvm2` 가 설치돼 있지 않음 | 3단계의 패키지를 설치하고 재기동하거나, 4단계로 직접 확장합니다. |
| 루트 볼륨 그룹에 루트 말고 다른 논리 볼륨이 있음(예: `/var`, `/home`) | 파티션과 물리 볼륨까지는 자동으로 넓어집니다. 늘어난 공간을 어느 논리 볼륨에 붙일지는 정해 드리지 않으므로, 4단계의 `lvextend` 부터 직접 진행합니다. (swap 은 다른 논리 볼륨으로 세지 않습니다) |

> **자동 확장이 가져가는 크기:** 이번에 **늘린 만큼만** 루트 논리 볼륨에 할당합니다. 증설 전부터 **볼륨 그룹**에 비워 둔 공간은 그대로 남습니다. 늘어난 공간을 다른 논리 볼륨에 붙이려면 자동 확장 뒤 `lvextend` 로 직접 옮기지 말고, 증설 전에 계획해 두는 편이 안전합니다 — `xfs` 는 축소할 수 없습니다.

> **파티션을 만들지 않고 남겨 둔 디스크 영역은 다릅니다.** 볼륨 그룹의 여유 공간과 달리, 루트 파티션 **뒤쪽에 파티션 없이 비워 둔 영역**은 재기동할 때 루트 파티션에 포함됩니다. LVM 이 아닌 일반 파티션 인스턴스도 동일하게 동작합니다. 나중에 별도 파티션으로 쓰려고 비워 둔 영역이 있다면 부팅 디스크에 남겨 두지 마시고, **볼륨을 추가해** 사용하시기 바랍니다.

### 확인
- Linux: `df -h /` 에서 루트 파일 시스템 크기가 늘어났는지 확인합니다.
- Windows: `디스크 관리(diskmgmt.msc)` 에서 OS 볼륨 크기가 늘어났는지 확인합니다.
- 자동 확장은 기동 직후 백그라운드에서 수행될 수 있으니, 즉시 반영되지 않으면 잠시 뒤 다시 확인합니다.

<a id="step-3"></a>
## 3단계: 사용자(BYO) 이미지에 필요한 패키지
**수행 계정/화면:** `인스턴스 콘솔 또는 SSH` / `터미널`

직접 업로드한 이미지에 아래 도구를 미리 설치해 두면 기본 제공 이미지처럼 자동 확장을 사용할 수 있습니다. 없으면 4단계·5단계로 수동 확장합니다.

### Linux
| 용도 | 패키지 |
|---|---|
| 부팅 시 자동 확장 | `cloud-init` |
| 파티션 확장(growpart) | RHEL/Rocky 계열 `cloud-utils-growpart` / Debian·Ubuntu `cloud-guest-utils` |
| GPT 파티션 확장 | `gdisk` 또는 최신 `util-linux`(sfdisk) |
| 파일 시스템 확장 | ext4 `e2fsprogs`(resize2fs) / xfs `xfsprogs`(xfs_growfs) |
| LVM 루트 볼륨 확장 | `lvm2` |

### Windows
| 용도 | 구성 요소 |
|---|---|
| 부팅 시 자동 확장 | `cloudbase-init` + `ExtendVolumes` 플러그인 |

<a id="step-4"></a>
## 4단계: Linux 수동 확장
**수행 계정/화면:** `인스턴스 콘솔 또는 SSH` / `터미널`

자동 확장이 동작하지 않은 경우 게스트에서 파티션과 파일 시스템을 직접 확장합니다. 아래는 부팅 디스크가 `/dev/sda`, 루트 파티션이 `/dev/sda4`인 예시이며, 실제 값은 `lsblk` 결과에 맞게 바꿔 입력합니다.

```bash
lsblk                          # 늘어난 크기 인식 확인
sudo growpart /dev/sda 4       # 파티션을 디스크 끝까지 확장
sudo resize2fs /dev/sda4       # 파일 시스템 확장 (ext4)
# xfs 는 sudo xfs_growfs / 를 사용
df -h /                        # 확인
```

루트가 LVM인 인스턴스는 2단계의 자동 확장이 처리하므로 보통 이 절차가 필요 없습니다. 2단계 표의 건너뛰는 구성에 해당하거나 필요한 패키지가 없어 자동 확장이 동작하지 않은 경우에만 아래 순서로 직접 확장합니다(`lsblk` 의 `TYPE` 이 `lvm` 이면 LVM입니다).

```bash
lsblk                                  # 루트가 어느 디스크·파티션 위에 있는지 확인
sudo growpart /dev/sda 3               # 물리 볼륨이 올라간 파티션을 확장
sudo pvresize /dev/sda3                # 물리 볼륨에 늘어난 공간 반영
sudo lvextend -L +10G /dev/mapper/rl-root        # 이번에 늘린 크기만큼만 루트 논리 볼륨 확장
sudo xfs_growfs /                      # 파일 시스템 확장 (ext4 는 sudo resize2fs /dev/mapper/rl-root)
df -h /                                # 확인
```

`lvextend` 에 `+100%FREE` 를 쓰면 볼륨 그룹에 **남겨 둔 여유 공간까지 모두** 루트로 들어갑니다. 다른 논리 볼륨에 쓰려고 남겨 둔 공간이 있으면 위처럼 이번에 늘린 크기만 지정합니다. XFS 루트는 줄일 수 없어 한 번 가져간 공간은 되돌릴 수 없습니다.

<a id="step-5"></a>
## 5단계: Windows 수동 확장
**수행 계정/화면:** `인스턴스 콘솔 또는 RDP` / `디스크 관리`

`diskmgmt.msc` 를 열어 OS 파티션(보통 `C:`)을 우클릭하고 `볼륨 확장`으로 최대 크기까지 확장합니다. `diskpart` 를 쓰면 `list volume` → `select volume N`(OS 볼륨) → `extend` 순서입니다.

`C:` 바로 뒤에 복구(Recovery) 파티션이 있으면 여유 공간이 `C:` 에 인접하지 않아 확장이 되지 않습니다. 이때는 복구 파티션을 재배치한 뒤 확장하며, 조작 전 스냅샷/백업을 확보합니다.

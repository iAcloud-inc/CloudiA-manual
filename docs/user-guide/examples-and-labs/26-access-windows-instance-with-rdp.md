# 원격 데스크톱(RDP)으로 Windows 인스턴스 접속하기

이 문서는 Windows 인스턴스에 원격 데스크톱(RDP)을 켜고, 보안그룹과 플로팅 IP를 설정해 내 PC에서 접속하는 실습입니다.

웹 콘솔의 그래픽 콘솔은 설치와 장애 복구에 쓰는 화면입니다. 창을 옮기거나 스크롤하는 일상 작업에서는 화면이 끊겨 보일 수 있습니다. Windows를 매일 쓴다면 원격 데스크톱으로 접속하는 편이 훨씬 부드럽습니다.

## 사전 준비
- Cloud:iA 웹콘솔 접근 가능
- 프로젝트 계정(`project-owner`)으로 로그인 가능
- 접속할 Windows 인스턴스가 `실행 중`이고 그래픽 콘솔로 로그인할 수 있음
- 로그인할 Windows 계정에 비밀번호가 설정되어 있음
- 프로젝트에 플로팅 IP로 쓸 외부 IP 여유가 있음
- 내 PC에 원격 데스크톱 클라이언트 준비(Windows는 기본 포함, macOS는 Microsoft `Windows App`)

> Windows Home 버전은 원격 데스크톱 접속을 받을 수 없습니다. Pro, Enterprise, Education, Server 버전에서 진행합니다.

<a id="step-1"></a>
## 1단계: Windows에서 원격 데스크톱 켜기
**수행 계정/화면:** `프로젝트 계정` / `그래픽 콘솔`

### 절차
1. `가상머신 > 인스턴스 상세`에서 `콘솔` > `그래픽 콘솔`을 열고 Windows에 로그인합니다.
2. `Win + R`을 눌러 실행 창을 열고 `SystemPropertiesRemote`를 입력한 뒤 `OK`를 클릭합니다.
3. `System Properties`의 `Remote` 탭에서 `Allow remote connections to this computer`를 선택합니다.
4. 방화벽 예외를 켠다는 안내 창이 나오면 `OK`를 클릭합니다.
5. `Allow connections only from computers running Remote Desktop with Network Level Authentication (recommended)`가 체크된 상태로 두고 `OK`를 클릭합니다.

Windows 11과 Windows Server 2025는 `설정 > 시스템 > 원격 데스크톱`에서 `원격 데스크톱`을 `켬`으로 바꿔도 같습니다.

> 관리자가 아닌 계정으로 접속하려면 같은 `Remote` 탭의 `Select Users...`(설정 앱은 `원격 데스크톱 사용자`)에서 그 계정을 추가합니다. 관리자 계정은 추가하지 않아도 접속할 수 있습니다.

### 확인
- `Remote` 탭에서 `Allow remote connections to this computer`가 선택되어 있습니다.
- Windows 방화벽의 원격 데스크톱 허용 규칙은 이 설정을 켤 때 함께 켜집니다. 따로 열 필요가 없습니다.
- 설정이 실제로 반영되기까지 몇 분 걸릴 수 있습니다. 바로 접속이 안 되면 잠시 뒤 다시 시도합니다.

### 인증서 지문 적어 두기
원격 데스크톱은 Windows가 스스로 만든 인증서로 통신을 암호화합니다. 이 인증서는 내 PC가 미리 알 수 없어서 처음 접속할 때 경고가 나옵니다. 경고 창의 인증서가 이 인스턴스의 것인지 5단계에서 비교할 수 있도록, 그래픽 콘솔에서 지문을 미리 확인해 적어 둡니다.

1. 그래픽 콘솔에서 PowerShell을 엽니다.
2. 아래 명령을 실행하고 `Thumbprint` 값을 적어 둡니다.

   ```powershell
   Get-ChildItem 'Cert:\LocalMachine\Remote Desktop' | Format-Table Thumbprint, Subject, NotAfter
   ```

- `Subject`는 `CN=<컴퓨터 이름>` 형식입니다.
- 이 인증서는 만료되면 Windows가 새로 만듭니다. 그때 지문도 바뀌므로 다시 확인합니다.

<a id="step-2"></a>
## 2단계: 원격 데스크톱 전용 보안그룹 만들기
**수행 계정/화면:** `프로젝트 계정` / `프로젝트 페이지`

원격 데스크톱 포트(TCP `3389`)는 인터넷 전체에 열면 무작위 로그인 시도를 바로 받습니다. 접속할 PC나 사무실 대역에만 여는 전용 보안그룹을 만들어 씁니다.

### 절차
1. `네트워크 보안 > 보안그룹`에서 `생성`을 클릭합니다.
2. 이름, VPC, 설명을 입력하고 `생성`을 클릭합니다.
3. 목록에서 새 보안그룹 이름을 클릭해 상세 화면으로 이동합니다.
4. `인바운드 규칙` 탭에서 `편집`을 클릭합니다.
5. `규칙 추가`를 클릭하고 아래처럼 입력한 뒤 `저장`을 클릭합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 이름 | `example-rdp-sg` |
| VPC | `example-vpc` |
| 같은 보안그룹 VM 통신 | `허용 안 함` |
| 설명 | `Windows 원격 데스크톱 접속 허용` |
| 인바운드 규칙 | `TCP / 203.0.113.25/32 / 3389 / rdp-from-admin-pc` |

`IP / CIDR`에는 인스턴스 쪽에서 보이는 접속 PC의 출발지 주소를 넣습니다. PC 한 대면 `/32`, 사무실 대역이면 그 대역(예: `203.0.113.0/24`)을 넣습니다.

- 내 PC가 공유기나 사내 NAT 뒤에 있으면 PC에 표시되는 사설 IP(예: `192.168.0.10`)가 아니라, 바깥으로 나갈 때 쓰는 공인 IP나 NAT 대역을 넣습니다. 모르면 네트워크 관리자에게 확인합니다.
- 내 PC와 Cloud:iA가 같은 사내망에 있어 주소 변환 없이 연결되면 PC의 IP를 그대로 넣습니다.

### 확인
- 보안그룹 상세의 `인바운드 규칙`에 `TCP`, `3389` 규칙이 표시됩니다.

> ⚠️ 주의: 인스턴스에 붙은 보안그룹은 모든 규칙을 합쳐서 적용합니다. 함께 붙어 있는 다른 보안그룹(예: VPC 기본 보안그룹)이 인바운드 `모든 트래픽 / 0.0.0.0/0`을 허용하고 있으면, 여기서 출발지를 좁혀도 3389가 모두에게 열립니다. 3단계에서 함께 붙어 있는 보안그룹의 인바운드 규칙도 확인합니다.

<a id="step-3"></a>
## 3단계: 인스턴스에 보안그룹 연결
**수행 계정/화면:** `프로젝트 계정` / `프로젝트 페이지`

기본 네트워크 인터페이스의 보안그룹은 인스턴스가 실행 중일 때도 바꿀 수 있습니다.

### 절차
1. `가상머신 > 인스턴스`에서 대상 인스턴스를 선택하고 `편집`을 클릭합니다.
2. `네트워크 인터페이스 구성`의 `인터페이스` 목록에서 `기본 인터페이스`가 `예`인 행을 선택하고 `편집`을 클릭합니다.
3. `인터페이스 편집` 창의 `보안그룹`에 2단계에서 만든 보안그룹을 추가하고 `확인`을 클릭합니다.
4. 화면 하단의 `편집`을 클릭해 저장합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 대상 인스턴스 | `example-windows-001` |
| 인터페이스 | 기본 인터페이스(`10.0.1.15`) |
| 보안그룹 | `example-vpc-default-sg`, `example-rdp-sg` |

### 확인
- `네트워크 보안 > 보안그룹` 상세의 `연결된 리소스 > 인스턴스`에 대상 인스턴스가 표시됩니다.

<a id="step-4"></a>
## 4단계: 플로팅 IP 생성 및 연결
**수행 계정/화면:** `프로젝트 계정` / `프로젝트 페이지`

### 절차
1. `네트워크 > 플로팅 IP`에서 `생성`을 클릭합니다.
2. 이름과 VPC를 입력하고 `외부 IP 주소`는 `자동 할당`으로 둡니다.
3. `리소스 연결`을 `적용`으로 바꾸고 `타겟 유형`을 `인스턴스`로 둡니다.
4. `인스턴스`에서 대상 인스턴스를, `내부 IP 주소`에서 3단계의 기본 인터페이스 IP를 고릅니다.
5. `생성`을 클릭합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 이름 | `example-windows-rdp-fip` |
| VPC | `example-vpc` |
| 외부 IP 주소 | `자동 할당` |
| 리소스 연결 | `적용` |
| 타겟 유형 | `인스턴스` |
| 인스턴스 | `example-windows-001` |
| 내부 IP 주소 | `10.0.1.15` |

이미 플로팅 IP가 연결된 인스턴스라면 이 단계는 건너뜁니다. 플로팅 IP는 [플로팅 IP로 인스턴스 접속하기](../quickstarts/04-access-instance-via-floating-ip.md)도 참고합니다.

### 확인
- 플로팅 IP 목록의 `연결된 리소스`에 대상 인스턴스가 표시됩니다.
- `외부 IP 주소` 열의 주소가 접속할 주소입니다.

<a id="step-5"></a>
## 5단계: 원격 데스크톱으로 접속
**수행 계정/화면:** `내 PC` / `원격 데스크톱 클라이언트`

### 절차
1. 원격 데스크톱 클라이언트를 엽니다.
   - Windows: `Win + R`에 `mstsc`를 입력해 `원격 데스크톱 연결`을 엽니다.
   - macOS: `Windows App`에서 PC를 추가합니다.
2. 컴퓨터(PC 이름) 칸에 4단계의 플로팅 IP를 입력하고 연결합니다.
3. 사용자 이름과 비밀번호를 입력합니다.
4. 인증서 확인 창이 나오면 인증서 정보를 열어 지문(SHA1)을 1단계에서 적어 둔 `Thumbprint`와 비교합니다. 같을 때만 연결을 계속합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 컴퓨터 | `198.51.100.10` |
| 사용자 이름 | `Administrator` (로컬 계정은 `.\계정이름`으로도 입력할 수 있습니다) |
| 비밀번호 | Windows 계정 비밀번호 |

> ⚠️ 주의: 지문이 다르면 연결하지 않습니다. 다른 서버가 이 주소를 가장하고 있을 수 있고, 계속하면 Windows 사용자 이름과 비밀번호가 그 서버로 넘어갑니다. 그래픽 콘솔에서 지문을 다시 확인하고, 그래도 다르면 관리자에게 알립니다.

### 확인
- 원격 데스크톱 창에 Windows 바탕 화면이 열립니다.
- 그래픽 콘솔로 로그인해 있던 계정과 같은 계정으로 접속하면, 그래픽 콘솔은 잠금 화면으로 바뀌고 열려 있던 창은 원격 데스크톱 쪽에 그대로 보입니다. 정상 동작입니다.

## 접속이 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 연결 시간이 초과됩니다. | 2단계 규칙의 `IP / CIDR`가 인스턴스 쪽에서 보이는 내 PC의 출발지 주소(NAT 뒤라면 공인 IP)를 포함하는지 확인합니다. 3단계의 보안그룹이 `기본 인터페이스`에 붙어 있는지, 4단계 플로팅 IP의 `내부 IP 주소`가 그 인터페이스의 IP인지 확인합니다. 1단계 설정 직후라면 몇 분 뒤 다시 시도합니다. |
| 연결 시간이 초과됩니다(ISO로 설치한 인스턴스). | 게스트에 IP를 직접 넣었다면 기본 게이트웨이에 서브넷의 `게이트웨이`가 들어 있어야 합니다. 그래픽 콘솔에서 `ipconfig`를 실행해 `Default Gateway`를 확인합니다. |
| 사용자 이름 또는 비밀번호가 틀리다고 나옵니다. | 비밀번호가 없는 계정은 원격 데스크톱으로 로그인할 수 없습니다. 관리자가 아닌 계정은 1단계의 `Select Users...`에 추가되어 있어야 합니다. |
| 인증서 지문이 1단계 값과 다릅니다. | 인증서가 만료돼 새로 만들어졌는지 그래픽 콘솔에서 지문을 다시 확인합니다. 다시 확인한 값과도 다르면 연결하지 않습니다. |
| 허용하지 않은 곳에서도 접속됩니다. | 함께 붙어 있는 보안그룹 중 인바운드 `모든 트래픽 / 0.0.0.0/0`을 허용하는 것이 있는지 확인합니다. |

원격 데스크톱 접속이 끊겨 네트워크로 들어갈 수 없을 때는 웹 콘솔의 그래픽 콘솔로 접속해 설정을 확인합니다.

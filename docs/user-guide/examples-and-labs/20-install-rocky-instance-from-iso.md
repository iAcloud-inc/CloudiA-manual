# Rocky Linux ISO 업로드 후 VM 설치

이 문서는 `Rocky Linux ISO`를 업로드해 인스턴스를 생성하고, 설치 완료 후 재부팅해 설치한 디스크로 부팅되는 것과 정상 로그인까지 확인하는 실습입니다.

## 사전 준비
- Cloud:iA 웹콘솔 접근 가능
- 프로젝트 계정(`project-owner`)으로 로그인 가능
- Rocky Linux ISO 파일 준비
- 인스턴스에서 사용할 VPC/서브넷/보안그룹 준비

## 개요
1. [Rocky ISO 업로드](#step-1)
2. [ISO 기반 VM 생성 및 실행](#step-2)
3. [콘솔 접속 후 Rocky OS 설치(네트워크 수동 설정 포함)](#step-3)
4. [설치 완료 후 재부팅](#step-4)
5. [설치된 OS로 로그인 확인](#step-5)
6. [설치 뒤 네트워크 확인 및 수정](#step-6)
7. [직렬 콘솔 사용 설정 (권장)](#step-7)

<a id="step-1"></a>
## 1단계: Rocky ISO 업로드
**수행 계정/화면:** `관리자 또는 권한 보유 계정` / `ISO 관리 화면`

### 절차
1. Cloud:iA 웹에서 `스토리지 > ISO`로 이동한 뒤 `업로드`를 클릭합니다.
2. `스토리지 도메인`을 선택합니다.
3. `ISO` 항목에서 Rocky Linux `.iso` 파일을 선택합니다.
4. `OS 타입`이 자동으로 채워지는지 확인합니다. `Rocky-9.5-x86_64-dvd.iso`를 선택하면 `Rocky Linux 9`가 채워집니다. 비어 있으면 목록에서 직접 선택합니다.
5. 필수 항목이 모두 입력되어 `업로드` 버튼이 활성화되면 `업로드`를 클릭합니다.
6. ISO 목록에서 업로드된 항목의 상태와 정보를 확인합니다.

### 입력 예시
| 항목 | 값 |
|---|---|
| 스토리지 도메인 | `LOCAL-SD` |
| ISO 파일 | `Rocky-9.5-x86_64-dvd.iso` |
| OS 타입 | `Rocky Linux 9` (자동으로 채워짐) |

### 확인
- ISO 목록에 Rocky ISO가 추가됩니다.
- `이름`, `스토리지 도메인`, `크기`가 입력값과 일치합니다.
- `OS 타입`이 `Rocky Linux 9`로 표시됩니다.

> 주의
>
> ISO 업로드 시 `CEPH`(RBD) 타입 스토리지 도메인은 지원하지 않습니다. Ceph 클러스터에 올리려면 `CEPHFS` 타입을 선택합니다.

<a id="step-2"></a>
## 2단계: ISO 기반 VM 생성 및 실행
**수행 계정/화면:** `프로젝트 계정` / `가상머신 > 인스턴스`

### 절차
1. `생성`을 클릭합니다.
2. `기본 정보`에서 인스턴스 이름과 스펙을 입력합니다.
3. `설치 유형`에서 `ISO 파일`을 선택하고, 1단계에서 업로드한 Rocky ISO를 선택합니다. ISO 선택 목록의 `OS 타입`은 `Rocky Linux 9`로 표시됩니다.
4. `부팅 디스크 크기`를 입력합니다.
5. `네트워크 인터페이스`를 `1개`만 설정합니다.
6. `NIC 1`에 대해 `서브넷`, `IP 주소(자동 또는 수동)`, `보안그룹`을 지정합니다.
7. `생성`을 클릭합니다.
8. 인스턴스 상태가 `종료됨`으로 전환되면 인스턴스를 선택해 `실행`합니다.

### 입력 예시
| 항목 | 값                           |
|---|-----------------------------|
| 인스턴스 이름 | `example-rocky-iso-001`     |
| 인스턴스 타입 | `t2.medium`                 |
| 설치 유형 | `ISO 파일`                    |
| ISO 파일 | `Rocky-9.5-x86_64-dvd.iso`  |
| 부팅 디스크 크기 | `15 GB`                      |
| VPC | `example-vpc`               |
| 네트워크 인터페이스 수 | `1`                         |
| NIC 1 서브넷 | `example-public-subnet-001` |
| NIC 1 IP 주소 | `자동 할당`                     |
| NIC 1 보안그룹 | `example-vpc-default-sg`    |

### 확인
- 생성 직후 인스턴스 상태가 `생성 중`으로 표시됩니다.
- 생성 완료 후 상태가 `종료됨`으로 전환됩니다.
- 인스턴스 상태가 `실행 중`으로 전환됩니다.
- 콘솔에서 Rocky 설치 화면으로 진입할 수 있습니다.

> 참고
>
> `ISO 파일` 설치 유형에서는 `고급 설정`의 `보안 유형`과 `오브젝트 스토리지`를 사용할 수 없습니다. `부팅 펌웨어`, `무중단 증설`, 추가 `블록`은 사용할 수 있습니다.
>
> `사용자 계정`과 `사용자 스크립트`는 입력할 수 있지만 필수가 아닙니다. ISO는 사용자가 직접 준비한 매체라 게스트에 cloud-init이 설치되어 있다는 보장이 없어, 입력해도 적용되지 않을 수 있습니다. 이 실습에서는 비워 두고 OS 설치 과정에서 계정을 직접 만듭니다.

<a id="step-3"></a>
## 3단계: 콘솔 접속 후 Rocky OS 설치
**수행 계정/화면:** `프로젝트 계정` / `인스턴스 콘솔`

### 절차
1. 대상 VM 상세 화면에서 `콘솔`을 클릭하고 메뉴에서 `그래픽 콘솔`을 선택합니다. OS 설치 화면은 그래픽 콘솔에서 봅니다.
2. Rocky 설치 메뉴에서 `Install Rocky Linux`를 선택합니다.
3. 언어, 시간, 디스크 파티션, 사용자 정보를 설정합니다.
4. 네트워크를 수동으로 설정합니다. 먼저 Cloud:iA 웹에서 인스턴스 상세의 배정 IP와, 서브넷 상세의 `게이트웨이`, `DNS`를 확인해 둡니다.
   1. 설치 화면에서 `Network & Host Name`을 선택합니다.
   2. 인터페이스(예: `enp1s0`)를 선택하고 설정 화면(`Configure...`)을 엽니다.
   3. `IPv4 Settings`의 `Method`를 `Manual`로 바꿉니다.
   4. `Add`를 클릭해 `Address`에 배정 IP, `Netmask`에 서브넷 CIDR에 맞는 값([6단계의 Netmask 예시](#step-6) 참고), `Gateway`에 서브넷의 게이트웨이를 입력합니다.
   5. `DNS servers`에 서브넷의 DNS를 입력하고 `Save`를 클릭합니다.
   6. 인터페이스 스위치를 `ON`으로 바꾸고, `Network & Host Name` 화면에 입력한 IP가 표시되는지 확인합니다.
5. `root` 비밀번호 또는 설치 중 생성한 사용자 비밀번호를 설정합니다.
6. 설치를 완료하고 `Reboot System` 화면까지 진행합니다.

### 확인
- `Network & Host Name`에서 인터페이스가 켜져 있고 수동으로 입력한 IP가 표시됩니다.
- 설치 완료 화면에서 `Reboot System` 버튼이 표시됩니다.

> 주의
>
> VPC는 DHCP로 IP를 주지 않습니다. 설치 화면 기본값(자동)대로 두면 설치된 OS에 IP가 없어 접속할 수 없습니다. 반드시 IPv4를 `Manual`로 설정하고 인스턴스 상세의 배정 IP를 입력합니다.

<a id="step-4"></a>
## 4단계: 설치 완료 후 재부팅
**수행 계정/화면:** `프로젝트 계정` / `인스턴스 콘솔`

ISO 인스턴스는 생성할 때부터 부팅 디스크가 부팅 순서 1, 설치 CD(CD-ROM)가 2로 잡혀 있습니다. 설치 전에는 디스크가 비어 있어 자동으로 설치 CD로 부팅하고, 설치가 끝난 뒤 재부팅하면 설치한 디스크로 부팅합니다. 부팅 순서를 바꿀 필요가 없습니다.

### 절차
1. 설치 완료 화면에서 `Reboot System`을 클릭합니다.
2. 재부팅이 끝날 때까지 기다립니다.

### 확인
- 설치 화면이 아니라 설치된 Rocky OS의 로그인 프롬프트가 표시됩니다.
- `인스턴스 구성 요소 > 디스크 및 CD/DVD`의 `부팅 순서`에서 부팅 디스크가 `1`, 설치 CD(`CD-ROM`)가 `2`로 표시됩니다.

> 참고
>
> 설치 CD는 설치 뒤에도 인스턴스에 붙어 있습니다. 골든 이미지를 준비할 때 이 CD를 패키지 저장소로 쓸 수 있습니다.

<a id="step-5"></a>
## 5단계: 설치된 OS로 로그인 확인
**수행 계정/화면:** `프로젝트 계정` / `가상머신 > 인스턴스`

### 절차
1. 콘솔 또는 접속 경로(SSH/포트포워딩/플로팅IP)로 접속합니다.
2. 설치 시 설정한 계정으로 로그인합니다.

### 로그인 예시
| 계정 | 비밀번호 |
|---|---|
| `root` | `{설치 시 설정한 password}` |

### 확인
- ISO 설치 화면이 아닌, 설치된 Rocky OS 로그인 프롬프트가 표시됩니다.
- 설정한 비밀번호로 로그인이 정상 동작합니다.

<a id="step-6"></a>
## 6단계: 설치 뒤 네트워크 확인 및 수정
**수행 계정/화면:** `인스턴스 콘솔` / `설치된 Rocky OS`

3단계에서 수동으로 설정한 IP가 설치된 OS에 제대로 반영됐는지 확인하고, 다르면 인스턴스 상세와 서브넷 상세의 값을 기준으로 고칩니다.

### 절차
1. Cloud:iA `인스턴스 상세`에서 NIC의 `IP`를, 서브넷 상세에서 `서브넷(CIDR)`, `게이트웨이`, `DNS`를 확인합니다.
2. 콘솔에서 `ip a`와 `nmcli con show`로 인터페이스(예: `enp1s0`)에 위 `IP`가 설정되어 있는지 확인합니다. NIC 이름은 보통 `enp1s0`이며 환경에 따라 다를 수 있습니다.
3. 값이 다르거나 IP가 없으면 해당 연결에 IP를 수동 설정합니다. 연결 프로필 이름은 `nmcli con show`의 `NAME` 열에서 확인합니다.
4. `Netmask`는 NIC IP가 속한 서브넷 CIDR을 기준으로 입력합니다.

### Netmask 예시
| 서브넷 | Netmask |
|---|---|
| `10.0.1.0/24` | `255.255.255.0` |
| `10.0.0.0/16` | `255.255.0.0` |
| `192.168.10.0/25` | `255.255.255.128` |

### `nmcli` 설정 예시
```bash
nmcli con show
nmcli con mod "<프로필 이름>" ipv4.method manual \
  ipv4.addresses 10.0.1.10/24 \
  ipv4.gateway 10.0.1.1 \
  ipv4.dns "<서브넷의 DNS>"
nmcli con up "<프로필 이름>"
```

### 확인
- `ip a` 또는 `nmcli device show`에서 수동 설정한 IP가 적용됩니다.
- 게이트웨이 및 DNS가 정상 반영되어 외부/내부 통신이 가능합니다.

<a id="step-7"></a>
## 7단계: 직렬 콘솔 사용 설정 (권장)
**수행 계정/화면:** `프로젝트 계정` / `그래픽 콘솔 또는 SSH`

ISO로 설치한 Rocky는 직렬 콘솔 설정이 기본으로 빠져 있습니다. 이대로 두면 `직렬 콘솔`에 접속해도 빈 화면만 보이고, `콘솔 로그 다운로드`에도 부팅 기록이 남지 않습니다. 나중에 네트워크 설정 실수나 부팅 실패로 SSH가 막혔을 때 쓸 수 있도록 설치 직후 켜 두는 것을 권장합니다.

### 절차
1. 설치된 OS에 root 또는 sudo 권한이 있는 계정으로 로그인합니다.
2. 직렬 포트 로그인 서비스를 켭니다.

   ```bash
   sudo systemctl enable --now serial-getty@ttyS0.service
   ```

3. 커널 부팅 옵션에 직렬 콘솔을 추가합니다.

   ```bash
   sudo grubby --update-kernel=ALL --args="console=tty0 console=ttyS0,115200"
   ```

4. 부팅 메시지를 빠짐없이 남기려면 기본으로 들어 있는 `rhgb quiet` 옵션을 뺍니다. 이 옵션이 있으면 커널은 오류 이상만 출력하고, 서비스 시작 메시지도 실패한 것만 나타나 콘솔 로그에 담기는 내용이 적습니다.

   ```bash
   sudo grubby --update-kernel=ALL --remove-args="rhgb quiet"
   ```

5. 인스턴스를 재부팅합니다.

### 확인
- `cat /proc/cmdline` 출력에 `console=ttyS0,115200`이 포함되고, 4번을 진행했다면 `rhgb quiet`이 없습니다. 나중에 커널을 업데이트했다면 재부팅 후 다시 확인합니다.
- 인스턴스 상세의 `콘솔` 메뉴에서 `직렬 콘솔`을 열면 로그인 프롬프트가 나타납니다. 비어 있으면 `Enter`를 입력합니다.
- `콘솔 로그 다운로드`로 받은 파일에 이번 부팅의 기록이 담깁니다. 4번을 진행했다면 커널 부팅 메시지가 처음부터 담깁니다.

> 💡 위 설정을 하면 직렬 콘솔이 주 콘솔이 되어, 비상 모드 안내 문구처럼 일부 메시지는 직렬 콘솔에만 나타납니다. 부팅이 멈추면 직렬 콘솔이나 콘솔 로그로 원인을 확인하세요. 자세한 내용과 Ubuntu·Windows 설정 방법은 [콘솔로 부팅 문제 진단하기 — 게스트에서 직렬 콘솔 켜기](23-troubleshoot-boot-with-console.md#guest-serial-setup)를 참고하세요.

> 💡 이 인스턴스로 골든 이미지를 만들면 직렬 콘솔 설정도 함께 담겨, 그 이미지로 만든 인스턴스에서도 바로 쓸 수 있습니다.

> 💡 이 인스턴스로 골든 이미지를 만들려면 [ISO로 설치한 Rocky 인스턴스를 골든 이미지로 준비하기](./24-prepare-rocky-instance-for-golden-image.md)로 이어서 진행합니다. 패키지 설치와 정리 없이 이미지를 만들면, 그 이미지로 만든 인스턴스가 입력한 계정·IP 대신 원본 인스턴스의 설정으로 뜹니다.

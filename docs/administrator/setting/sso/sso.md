# SSO 연동 — Microsoft Entra

조직의 Microsoft 계정으로 Cloud:iA에 로그인하도록 설정합니다. Cloud:iA 관리자와 고객사 Microsoft Entra 담당자가 함께 진행합니다.

## 시작 전

- 설치 담당자에게 이 사이트의 SSO 기능이 활성화됐는지 확인합니다. 꺼져 있으면 설정 화면에 설치 설정 안내가 표시됩니다.
- Entra 담당자는 앱을 등록하고 자격 증명을 관리할 권한이 필요합니다. 조직의 테넌트 정책을 따릅니다.
- Cloud:iA에서는 **사용자 연동 조회** 권한으로 화면을 보고, **사용자 연동 편집** 권한으로 저장합니다. LDAP과 권한을 공유합니다.
- 기존 Cloud:iA 계정을 연결할 사용자는 해당 계정의 비밀번호를 준비합니다. 처음 오는 사용자는 첫 로그인 시 계정이 자동 생성됩니다(JIT). SSO 연결·계정 생성만으로 관리자·프로젝트 권한이 추가되지는 않습니다.

## 1. 돌아올 주소 확인

Cloud:iA 관리자 콘솔의 **환경설정 > SSO 연동**에서 **리디렉션 URI**를 복사해 Entra 담당자에게 전달합니다. Cloud:iA가 표시한 사이트별 주소를 그대로 사용합니다.

예시 형태: `https://cloud.example.com/realms/iacloud/broker/microsoft/endpoint`

로그인 화면 주소나 `/cloudia-secure/.../callback`을 대신 입력하지 않습니다. 해당 주소는 별도 내부 왕복 경로입니다.

## 2. Entra 앱 등록

1. [Microsoft Entra 관리 센터](https://entra.microsoft.com/)에서 고객사의 테넌트를 선택합니다.
2. **Entra ID > 앱 등록(App registrations) > 새 등록(New registration)**을 엽니다.
3. 앱 이름을 입력하고, 이 조직용 구성이라면 지원 계정 유형을 **이 조직 디렉터리의 계정만(Single tenant)**으로 지정합니다.
4. 등록 후 개요에서 **디렉터리(테넌트) ID**와 **애플리케이션(클라이언트) ID**를 기록합니다.
5. **인증(Authentication)**의 리디렉션 URI 설정에서 플랫폼 **웹(Web)**을 선택하고 1단계에서 복사한 URI를 등록합니다. 코드를 교환하는 쪽은 서버이므로 SPA 플랫폼을 선택하지 않습니다.

Entra의 **엔터프라이즈 애플리케이션 > 해당 앱 > 속성**에서 사용자 할당 필요 여부를 설정하고, **사용자 및 그룹**에서 이 앱을 사용할 대상을 지정합니다. JIT는 앱 접근이 허용된 사용자에게 적용됩니다. 고객사 정책에 따라 게스트 사용자 허용 범위도 확인합니다. 할당된 사용자만 허용하려면 **사용자 할당 필요(Assignment required) = 예**로 설정해야 합니다. [Microsoft 앱 접근 제한 안내](https://learn.microsoft.com/en-us/entra/identity-platform/howto-restrict-your-app-to-a-set-of-users)

포털 표시는 언어·테넌트에 따라 달라질 수 있습니다. [Microsoft 앱 등록 안내](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app)와 [리디렉션 URI 안내](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-redirect-uri)를 함께 확인하세요.

## 3. 클라이언트 시크릿 준비

앱의 **인증서 및 비밀(Certificates & secrets) > 클라이언트 비밀(Client secrets)**에서 조직 정책에 맞는 만료일로 시크릿을 만듭니다. 필요한 것은 **값(Value)**이며 **시크릿 ID(Secret ID)**가 아닙니다. 생성 직후 안전하게 보관하고, 만료 전에 교체할 담당자·일정을 정합니다. 화면을 벗어나면 값을 다시 볼 수 없습니다.

현재 Cloud:iA 화면은 시크릿 방식만 지원합니다. Microsoft는 운영 환경에 인증서 또는 페더레이션 자격 증명을 권장하므로, 조직 정책이 시크릿 사용을 허용하지 않으면 도입 전에 설치 담당자와 지원 방식을 협의하세요. [Microsoft 자격 증명 관리 안내](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-credentials)

## 4. Cloud:iA에 저장

1. **환경설정 > SSO 연동**을 엽니다.
2. 테넌트 ID·클라이언트 ID·클라이언트 시크릿 값을 입력합니다.
3. 활성화 여부를 **사용함**으로 지정하고 **편집**을 눌러 저장합니다.
4. 로그인 화면에서 **Microsoft 계정으로 로그인** 버튼을 확인합니다.

시크릿은 조회 응답에 포함되지 않습니다. 저장한 값은 입력칸에 다시 표시되지 않습니다. 동일한 ID로 설정만 바꾸거나 사용 여부만 변경할 때는 시크릿을 비워 기존 값을 유지합니다. 테넌트 ID나 클라이언트 ID를 바꾸면 시크릿을 다시 입력해야 합니다.

## 5. 첫 로그인과 MFA

Microsoft 버튼을 누르고 조직의 인증 절차를 따릅니다.

- **같은 이메일의 기존 계정이 있으면:** 해당 Cloud:iA 계정의 비밀번호로 본인 확인 후 연결합니다. Microsoft 사용자명이 같은지는 연결 기준으로 사용하지 않습니다.
  - 연결 화면(**Microsoft 계정 연결**)에 그 계정의 ID가 보입니다. 비밀번호를 입력하고 **연결하기**를 누릅니다.
  - 그 계정에 OTP를 등록해 두었다면 이어서 `본인 확인을 위해 인증 앱의 일회용 코드를 입력하세요.` 안내가 나옵니다. 인증 앱의 **일회용 코드**를 입력하고 **연결하기**를 누르면 연결됩니다. OTP를 등록하지 않은 계정은 이 단계가 없습니다.
  - 비밀번호를 틀리면 `로그인에 실패했습니다. 로그인 시도가 반복되면 일시적으로 로그인이 제한될 수 있습니다.`가, 코드를 틀리면 `정확한 코드를 입력하세요.`가 나옵니다. 이 확인은 처음 연결할 때 한 번만 합니다.
  - OTP 정책이 켜져 있는데 아직 OTP를 등록하지 않은 계정은 연결한 뒤 **OTP 등록** 화면이 한 번 나올 수 있습니다. [정책 설정](../policy-setting/policy-setting.md#otp)을 참고하세요.
- **같은 이메일의 기존 계정이 없으면:** 계정을 자동 생성합니다(JIT). 내부 로그인 ID는 `sso-`로 시작하는 별도 값이며, Microsoft 사용자명을 기존 계정의 ID로 해석하지 않습니다. 신규 계정에는 기본 역할·그룹을 부여하지 않습니다. 필요한 권한은 Cloud:iA 관리자가 배정합니다.
- **이메일이 없거나 이메일 중복을 허용하는 설치라면:** 최초 연결·자동 생성을 진행하지 않습니다. 설치 담당자에게 문의합니다.

연결 후에는 저장된 Microsoft 외부 사용자 식별자와 Cloud:iA 계정의 연결로 로그인합니다. 이메일 변경·외부 계정 삭제 후 재생성은 기존 연결을 임의로 새 계정에 넘기는 사유가 아닙니다.

같은 이메일의 기존 계정은 없지만 그 이메일이 다른 계정의 로그인 ID로 이미 사용 중이면, 기존 로그인을 보호하기 위해 JIT 생성을 중단합니다. 그 계정으로 자동 연결하지 않습니다. 관리자가 ID·이메일 충돌을 확인해야 합니다.

SSO의 다단계 인증은 **Entra의 MFA 정책**으로 관리합니다. Cloud:iA 비밀번호 로그인용 OTP와 구분합니다. 기존 계정의 비밀번호 로그인 정책은 [정책 설정](../policy-setting/policy-setting.md#otp)을 확인하세요. Entra 담당자는 이 애플리케이션에 필요한 MFA 정책이 실제 적용되는지 시험 계정으로 확인해야 합니다.

Entra에서 Cloud:iA 역할·그룹을 자동 부여하는 Keycloak 매퍼는 이 구성에서 사용하지 않습니다. 권한은 Cloud:iA에서 관리합니다.

로그인 후 필요한 프로젝트·역할이 없으면 Cloud:iA 관리자에게 요청합니다. Entra 앱 접근 허용과 Cloud:iA 작업 권한은 별개입니다.

## 로그아웃과 Microsoft 로그인 상태

Cloud:iA에서 로그아웃하면 Cloud:iA 세션만 끝납니다. 브라우저의 Microsoft 로그인 상태는 그대로 남습니다. SSO로 로그인했던 사용자에게는 로그아웃 화면에 `Microsoft 계정은 로그인된 채로 남아 있습니다.` 안내가 함께 표시됩니다. 장시간 활동이 없어 자동으로 로그아웃되거나 세션이 만료된 경우에도 같습니다.

- 같은 브라우저에서 다시 **Microsoft 계정으로 로그인**을 누르면 Microsoft가 다시 묻지 않고 바로 Cloud:iA에 들어올 수 있습니다. Cloud:iA 로그아웃이 실패한 것이 아닙니다.
- 여러 사람이 쓰는 PC에서는 Microsoft 계정에서도 따로 로그아웃하세요.

## 시크릿 교체·사용 중지

시크릿 만료 전에 Entra에서 새 값을 만들고 Cloud:iA의 시크릿 입력에 넣어 저장한 뒤 로그인 성공을 확인합니다. 기존 시크릿 폐기는 확인 이후 조직 정책에 따라 진행합니다. Cloud:iA는 시크릿 만료일을 조회·알림하지 않습니다.

연동을 중지할 때는 **사용 안 함**으로 저장합니다. 로그인 버튼은 숨겨지고 기존 외부 계정 연결은 남습니다. 여러 보안 서버로 운영하면 다른 서버의 버튼 표시에는 캐시 갱신까지 최대 60초가 걸릴 수 있습니다. 기존 로그인 세션을 강제로 종료하는 기능으로 간주하지 않습니다. IdP 삭제 버튼은 제공하지 않습니다.

## 문제가 있을 때

| 증상 | 확인할 내용 |
|---|---|
| SSO 메뉴 없음·진입 제한 | 관리자 유형과 사용자 연동 조회 권한 |
| 입력·편집 버튼 비활성 | 편집 권한, 변경사항, 필수 입력. ID를 바꿨다면 시크릿 재입력 |
| 로그인 버튼 없음 | 설치 SSO 활성화와 연동 사용 여부. 설치 담당자에게 문의 |
| 리디렉션 URI 오류 | Entra 웹 플랫폼에 화면에서 복사한 주소를 정확히 등록했는지 |
| 시크릿 변경 후 인증 실패 | 테넌트·클라이언트 ID, 시크릿 값(Value), 만료 여부 |
| 로그인 뒤 권한 없음 | Cloud:iA 프로젝트·역할 배정 |
| 로그인 왕복 만료 | 로그인 화면부터 다시 시작. 브라우저 쿠키 차단 정책도 확인 |
| 로그아웃 후 Microsoft 버튼을 누르면 바로 로그인됨 | 정상 동작입니다. Cloud:iA 로그아웃은 Microsoft 로그인 상태를 끝내지 않습니다. 위 **로그아웃과 Microsoft 로그인 상태**를 참고하세요 |

문의 시 발생 시각·오류 코드·제품 버전을 전달하세요. 비밀번호·시크릿·토큰·쿠키가 들어간 로그나 전체 인증 URL은 보내지 않습니다.

## 폐쇄망 설치

Microsoft Entra 인증에는 외부 접속이 필요합니다. 외부 통신이 차단된 설치에서는 외부 SSO를 켜는 것만으로 사용할 수 없습니다. 기존 Cloud:iA 로그인·사용자 연동 방식을 사용하고, 사내 IdP가 필요하면 별도 지원 범위를 설치 담당자와 협의합니다. 이 화면이 임의의 SAML/OIDC 제공자 등록을 지원하는 것은 아닙니다.

Microsoft 공식 문서 확인일: 2026-11-03. 앱 등록 문서 수정일 2026-06-05, URI 문서 수정일 2026-05-14, 자격 증명 문서 수정일 2025-04-08 기준입니다.

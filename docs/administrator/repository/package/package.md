# 패키지 저장소

`패키지 저장소`는 관리자 `저장소` 메뉴에서 **패키지 미러**를 관리하는 화면입니다. 패키지 미러는 관리형 VPC 안의 **VM**으로 동작하며, 폐쇄망에서도 인스턴스가 시작될 때 qemu-guest-agent 와 NFS 클라이언트(Rocky Linux 는 nfs-utils, Ubuntu 는 nfs-common)를 설치할 수 있게 합니다.

환경당 **1대만** 존재하므로 목록 없이 단일 상세 화면으로 제공됩니다. 미러 이미지는 설치·업데이트가 등록한 이미지 하나만 다루며, 새 이미지로의 교체는 플랫폼 업데이트 단계에서 이루어집니다.

## 화면 개요
- `상세 정보`: 미러의 존재 여부와 상태, 상태 검사 결과, VM 정보를 확인하고 생성·삭제·실행·종료 작업을 수행합니다.
- `패키지` 탭: 미러 이미지에 든 패키지를 OS 별로 확인합니다.

## 주요 작업
- `생성`: 패키지 미러를 생성합니다. 미러가 없을 때만 활성화됩니다.
- `삭제`: 패키지 미러를 삭제합니다. 미러 VM 은 반납됩니다.
- `실행`: 정지된(`DOWN`) 또는 에러(`ERROR`) 상태의 미러를 실행합니다.
- `종료`: 실행 중(`RUNNING`) 또는 에러(`ERROR`) 상태의 미러를 정지합니다.

> 💡 **참고:** 네 개 버튼은 항상 표시되며, 현재 상태에 따라 활성 여부만 바뀝니다. 비활성 버튼에는 사유가 함께 표시됩니다. 생성·업데이트·종료·부팅·삭제가 진행 중이면 모든 버튼이 비활성화됩니다.

## 상세 정보
| 항목 | 설명 |
| --- | --- |
| **상태** | 미러 상태입니다. 진행 중이면 시작 시각과 함께 "최대 60분 걸릴 수 있습니다" 안내가 표시됩니다. |
| **상태 검사 결과** | 미러 헬스 점검 결과입니다. `정상`, `저하`, `이상`, `알 수 없음` 중 하나입니다. 실행 중·업데이트 중이 아니면 `알 수 없음`으로 표시됩니다. |
| **점검 일시** | 마지막 헬스 점검 일시입니다. 실행 중·업데이트 중이 아니면 `-`로 표시됩니다. |
| **이미지 버전** | 미러가 서빙 중인 이미지 버전입니다. |
| **IP** | 미러 VM 의 IP 주소입니다. |
| **스토리지 도메인** | 미러 VM 이 만들어진 스토리지 도메인입니다. |
| **미러 VM** | 미러 VM 이름과 ID 입니다. |
| **퇴역 중인 VM** | 업데이트로 미러가 교체된 뒤 아직 남아 있는 옛 VM 의 ID 입니다. 있을 때만 표시됩니다. |
| **삭제 예정 일시** | 옛 VM 이 지워지는 시각입니다. 진행 중인 부트스트랩이 끝날 시간을 두고 지웁니다. 있을 때만 표시됩니다. |
| **메시지** | 마지막 실패나 점검 문제의 사유입니다. 있을 때만 표시됩니다. |
| **상태 변경 일시** | 상태가 마지막으로 바뀐 일시입니다. |

> 💡 **참고:** 미러가 아직 없으면 상세 정보 대신 "생성된 패키지 저장소가 없습니다. 먼저 생성하세요." 안내가 표시되고 `생성` 버튼만 활성화됩니다.

> ⚠️ **주의:** 상태 검사 결과가 `저하`(서빙 중인 저장소 해시가 이미지와 다름)나 `이상`(미러가 응답하지 않음)이면 화면에 경고가 표시됩니다. 이때는 미러를 쓸 수 없어 새로 시작하는 인스턴스가 패키지 설치를 건너뜁니다.

## 상태 값
| 상태 | 설명 |
| --- | --- |
| `CREATING` | `생성 중`입니다. |
| `UPDATING` | `업데이트 중`입니다. 플랫폼 업데이트가 미러를 새 이미지로 교체하는 중입니다. |
| `RUNNING` | `실행 중`입니다. `종료`·`삭제`가 가능합니다. |
| `STOPPING` | `종료 중`입니다. |
| `DOWN` | `정지됨` 상태입니다. `실행`·`삭제`가 가능합니다. |
| `POWERING_UP` | `부팅 중`입니다. |
| `DELETING` | `삭제 중`입니다. |
| `ERROR` | `에러` 상태입니다. `실행`·`종료`·`삭제`가 가능합니다. 원인은 **메시지**에서 확인합니다. |

## 패키지 저장소 생성
1. `생성`을 클릭합니다.
2. 확인 창에서 생성에 쓸 **이미지 버전**을 확인하고 `생성`을 클릭합니다.
3. 상태가 `생성 중`으로 바뀌고, 화면이 자동으로 갱신됩니다.
4. 상태가 `실행 중`, **상태 검사 결과**가 `정상`이 되면 완료입니다.

> 💡 **참고:** 생성에는 VM 프로비저닝 시간이 필요해 수 분이 걸립니다. 진행 중인 작업은 최대 60분까지 기다린 뒤 실패로 처리됩니다.

> ⚠️ **주의:** "생성에 쓸 미러 이미지가 없습니다" 안내가 표시되면 미러 이미지가 스토리지 도메인에 등록되지 않은 것입니다. 플랫폼 설치·업데이트 단계에서 이미지를 등록한 뒤 다시 시도합니다.

## 패키지 저장소 실행 / 종료
1. `실행` 또는 `종료`를 클릭합니다.
2. 확인 창에서 이미지 버전, 미러 VM, IP 를 확인합니다.
3. 확인하면 상태가 `부팅 중` 또는 `종료 중`으로 바뀌고, 완료되면 `실행 중`·`정지됨`으로 전환됩니다.

> ⚠️ **주의:** 미러를 정지하면 다시 실행할 때까지 새로 시작하는 인스턴스가 패키지 설치를 건너뜁니다.

## 패키지 저장소 삭제
1. `삭제`를 클릭합니다.
2. 경고 내용을 확인합니다.
3. 확인 입력란에 **`package-repository`** 를 정확히 입력합니다.
4. `삭제`를 클릭합니다.

> ⚠️ **주의:** 삭제는 인스턴스에 남아 있는 임시 NIC 을 먼저 회수한 뒤 미러 VM 을 반납합니다. 미러가 없는 동안 새로 시작하는 인스턴스는 패키지 설치를 건너뜁니다.

> 💡 **참고:** 회수에 실패하면 미러가 `에러` 상태로 멈춥니다. 다시 삭제하면 남은 것부터 지웁니다.

> 💡 **참고:** 미러에는 이름이 없어 레지스트리와 달리 고정 문자열 `package-repository` 로 삭제를 확인합니다.

## 패키지 탭
미러 이미지에 든 패키지를 OS 별로 보여 줍니다. 미러가 있으면 서빙 중인 이미지 버전을, 없으면 생성에 쓸 이미지 버전을 보여 줍니다.

1. OS 드롭다운에서 OS 를 고릅니다. OS 이름 옆에 패키지 수가 표시됩니다. 예: `Rocky Linux 9 (147)`, `Ubuntu 22.04 (104)`
2. 검색란에 패키지 이름을 입력해 목록을 좁힙니다.
3. `필수만 보기`를 선택하면 부트스트랩이 설치하는 패키지만 표시됩니다.

| 열 | 설명 |
| --- | --- |
| **이름** | 패키지 이름입니다. |
| **버전** | 패키지 버전입니다. 에포크가 있으면 `1:2.5.4-42.el9`처럼 앞에 붙습니다. |
| **아키텍처** | `x86_64`, `amd64`, `noarch`, `all` 등입니다. |
| **필수** | `예`면 부트스트랩이 설치하는 패키지(qemu-guest-agent, nfs-utils·nfs-common)이고, `아니오`면 그 의존성입니다. |

> 💡 **참고:** 의존성은 인스턴스에 이미 설치되어 있을 법한 패키지까지 모두 담습니다. 의존 패키지가 없거나 오래된 인스턴스도 외부 저장소 없이 미러만으로 설치를 마칠 수 있게 하기 위해서입니다. 실제 설치 때는 인스턴스에 없거나 버전이 낮은 패키지만 받습니다.

> 💡 **참고:** 패키지 목록 기능 이전에 만든 이미지는 "이 이미지는 패키지 목록을 담고 있지 않습니다" 안내가 표시됩니다.

## 참고 사항
- 패키지 설치 대상은 cloud-init 으로 만든 Rocky Linux 9·10, Ubuntu 22.04·24.04 인스턴스입니다. 인스턴스를 CloudiA 에서 시작할 때 임시 NIC 을 붙여 미러에서 패키지를 받고, 끝나면 떼어 냅니다.
- 미러가 없거나 정상이 아니어도 인스턴스 시작은 막지 않습니다. 패키지 설치만 건너뜁니다.
- 새 미러 이미지로의 교체는 플랫폼 업데이트가 수행합니다. 교체 중에는 상태가 `업데이트 중`으로 표시되며, 새 VM 이 준비될 때까지 옛 VM 이 계속 서빙합니다.

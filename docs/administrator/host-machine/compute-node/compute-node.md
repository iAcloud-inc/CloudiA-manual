# 컴퓨트 노드

**컴퓨트 노드** 메뉴에서는 Cloud:iA에 등록된 컴퓨트 노드의 상태와 리소스 정보를 확인하고, 오버커밋 비율을 관리할 수 있습니다.
컴퓨트 노드 상세 화면에서는 리소스, 시스템 정보, 인스턴스, 스토리지 도메인 정보를 탭으로 구분하여 제공합니다.

---

## 컴퓨트 노드 목록

컴퓨트 노드 목록 화면에서는 등록된 컴퓨트 노드의 상태와 기본 운영 정보를 확인할 수 있습니다.

### 주요 작업

- **`편집`**: 노드를 한 개 선택했을 때 활성화됩니다. 클릭 시 **컴퓨트 노드 편집** 화면으로 이동합니다.
- **이름 클릭**: 선택한 컴퓨트 노드의 **상세 화면**으로 이동합니다.

> 💡 **참고:** 컴퓨트 노드 메뉴에서는 생성/삭제 기능을 제공하지 않으며, 편집 기능만 제공합니다.

### 테이블 컬럼

| 컬럼 | 설명 |
| --- | --- |
| **이름**          | 컴퓨트 노드 이름입니다. 클릭 시 상세 화면으로 이동합니다. |
| **상태**          | 현재 컴퓨트 노드 상태입니다. |
| **인스턴스 수**      | 해당 노드에 배치된 인스턴스의 수입니다. |
| **CPU 오버커밋 비율** | CPU 오버커밋 비율입니다. |
| **메모리 오버커밋 비율** | 메모리 오버커밋 비율입니다. |
| **생성 일시**       | 컴퓨트 노드가 등록된 일시입니다. |

### 상태 이해하기

목록과 상세 화면에 표시되는 컴퓨트 노드 상태는 다음과 같습니다.

| 상태 | 의미 |
| --- | --- |
| **`실행 중`** | 노드가 정상 동작 중이며 인스턴스를 배치할 수 있습니다. |
| **`생성 중`** | 노드가 등록·준비 중입니다. |
| **`삭제 중`** | 노드 삭제가 진행 중입니다. |
| **`페일오버 진행 중`** | 노드 장애가 감지되어 해당 노드의 인스턴스를 다른 노드로 옮기는 작업이 진행 중입니다. |
| **`유지관리 모드 설정 중`** | 노드를 유지관리 모드로 전환하는 중입니다. 전환이 끝나면 `유지관리 모드`가 됩니다. |
| **`유지관리 모드`** | 점검을 위해 노드를 인스턴스 배치 대상에서 제외한 상태입니다. 자세한 내용은 [유지관리 모드](../machine/machine.md#유지관리-모드)를 참고하세요. |
| **`정지됨`** | 노드가 중지되었거나 연결이 끊긴 상태입니다. |
| **`에러`** | 내부 복구 실패 등 오류가 발생한 상태입니다. |

## 컴퓨트 노드 편집

컴퓨트 노드 편집 화면에서는 노드 이름은 조회만 가능하며, CPU/메모리 오버커밋 비율만 수정할 수 있습니다.

### 입력 항목

| 항목 | 설명 |
| --- | --- |
| **이름** | 읽기 전용 항목입니다. |
| **CPU 오버커밋 비율** | 슬라이더로 비율을 조정합니다. |
| **메모리 오버커밋 비율** | 슬라이더로 비율을 조정합니다. |

### 오버커밋 비율 규칙

- 설정 범위: **1.00 ~ 2.00**
- 권장 기준: **1.5 이하**
- 기존 값과 동일하면 **저장 버튼이 비활성화**됩니다.
- 오버커밋은 **여러 인스턴스를 한 노드에 겹쳐 얹기 위한 총량 설정**입니다. 인스턴스 하나의 `vCPU`·메모리는 비율과 무관하게 그 노드의 **물리** 자원을 넘을 수 없습니다. 예를 들어 물리 16코어 노드에 비율 2.00을 설정하면 합계 32 vCPU까지 배치할 수 있지만, 24 vCPU짜리 인스턴스 하나는 배치되지 않습니다.

### 저장/취소

- **`저장`**: 변경한 오버커밋 비율을 반영하고 목록 화면으로 이동합니다.
- **`취소`**: 변경 사항을 저장하지 않고 목록 화면으로 이동합니다.

## 컴퓨트 노드 상세

컴퓨트 노드 상세 화면은 상단 **정보 영역**과 하단 **탭 정보**로 구성됩니다.
상단 정보 영역은 기본 정보, 상태 정보 두 묶음으로 나뉩니다.

### 기본 정보

| 항목 | 설명 |
| --- | --- |
| **이름** | 컴퓨트 노드 이름입니다. |
| **CPU 오버커밋 비율** | CPU 오버커밋 비율입니다. |
| **메모리 오버커밋 비율** | 메모리 오버커밋 비율입니다. |
| **인스턴스 수** | 노드에 배치된 인스턴스의 수입니다. |
| **생성 일시** | 컴퓨트 노드 생성 일시입니다. |

### 상태 정보

| 항목 | 설명 |
| --- | --- |
| **상태** | 컴퓨트 노드 운영 상태입니다. |
| **Agent 연결 상태** | Host Agent 연결 상태를 표시합니다. |
| **네트워크 상태** | 네트워크 점검 결과를 표시합니다. |
| **가상화 연결 상태** | 노드의 가상화 계층 연결 상태를 표시합니다. |

#### 연결 상태 값

`Agent 연결 상태`, `네트워크 상태`, `가상화 연결 상태`는 다음 값으로 표시됩니다.

| 구분 | 값 | 의미 |
| --- | --- | --- |
| **가상화 연결 상태** | `연결` | 노드의 가상화 계층과 정상적으로 연결되어 있습니다. |
| | `해제` | 노드에는 연결되지만 가상화 계층이 응답하지 않습니다. |
| | `도달 불가` | 노드에 확인을 요청했으나 응답이 오지 않았습니다. |
| | `알 수 없음` | 연결 상태를 확인할 수 없습니다. |
| **Agent 연결 상태** | `연결` | Host Agent와 정상적으로 연결되어 있습니다. |
| | `해제` | Host Agent 연결이 끊겼습니다. |
| **네트워크 상태** | `정상` | 내부망과 외부망 점검이 모두 정상입니다. |
| | `내부만 정상` | 내부망 점검은 정상이고 외부망 점검은 정상이 아닙니다. |
| | `외부만 정상` | 외부망 점검은 정상이고 내부망 점검은 정상이 아닙니다. |
| | `에러` | 네트워크 점검이 정상이 아닙니다. |
| | `알 수 없음` | 네트워크 상태를 확인할 수 없습니다. |

### 인스턴스 마이그레이션

인스턴스 탭에서 인스턴스를 한 개 선택하면 **`마이그레이션`** 버튼이 활성화됩니다. 버튼을 클릭하면 **마이그레이션** 창이 열립니다.

마이그레이션 방식은 두 가지입니다.

- **`라이브`**: 인스턴스를 켜 둔 채로 다른 컴퓨트 노드로 옮깁니다.
- **`콜드`**: 인스턴스를 종료한 뒤 대상 노드에서 다시 시작합니다.

#### 대상 노드 목록

`컴퓨트 노드 선택` 목록에는 **인스턴스가 속한 노드 그룹의 컴퓨트 노드가 현재 노드만 빼고 모두** 표시됩니다. 옮길 수 없는 노드도 목록에서 사라지지 않고, 대신 왜 옮길 수 없는지를 함께 보여줍니다.

| 컬럼 | 설명 |
| --- | --- |
| **이름** | 대상 컴퓨트 노드 이름입니다. |
| **vCPU** | `이관 후 논리 CPU 수 / 전체 논리 CPU 수`입니다. |
| **메모리(GB)** | `이관 후 메모리 / 전체 메모리`이며 단위는 GB입니다. |
| **`라이브`** | 라이브 마이그레이션 가능 여부입니다. `가능` 또는 `불가 · <범주>`로 표시됩니다. |
| **`콜드`** | 콜드 마이그레이션 가능 여부입니다. 표기 방식은 `라이브`와 같습니다. |

- 이관 후 값이 전체 용량을 넘으면 그 숫자가 붉게 표시됩니다.
- **라이브와 콜드가 둘 다 `불가`인 노드만 선택할 수 없습니다.** 라이브만 `불가`인 노드는 콜드로 옮길 수 있으므로 선택할 수 있습니다.
- `불가 · <범주>`를 클릭하면 그 노드를 선택하지 않고도 아래 적합성 영역에서 차단 사유를 확인할 수 있습니다.
- 범주는 `호스트 상태`, `스토리지`, `하드웨어`, `용량`, `인스턴스 제약`, `배치 규칙` 중 하나이며, 가장 우선하는 사유의 범주가 표시됩니다.

> 💡 **참고:** `유지관리 모드`인 노드도 목록에 그대로 남으며, 차단 사유로 `호스트가 UP 상태가 아님`이 표시됩니다.

#### 적합성 확인

목록 아래 영역에는 선택했거나 사유를 조회 중인 노드의 이름과 함께 다음 정보가 표시됩니다.

| 항목 | 설명 |
| --- | --- |
| **`방식`** | 선택한 노드로 수행할 방식을 `라이브`/`콜드` 중에서 고릅니다. 그 노드가 지원하지 않는 방식은 선택할 수 없습니다. |
| **용량 변화** | `논리 CPU 수`와 `메모리`를 `현재 사용량 / 전체 → 이관 후` 형식과 막대로 보여줍니다. |
| **차단 사유** | 옮길 수 없는 이유를 한 줄씩 보여주고, 각 줄 앞에 그 사유가 막는 경로(`라이브·콜드` 또는 `라이브`)를 표시합니다. |

- 차단 사유가 하나도 없으면 `이 호스트로는 라이브·콜드 모두 마이그레이션할 수 있습니다.`가 표시됩니다.
- 선택한 노드가 현재 고른 방식을 지원하지 않으면 **가능한 방식으로 자동 변경**됩니다. 예를 들어 `라이브`를 고른 상태에서 라이브가 `불가`인 노드를 선택하면 방식이 `콜드`로 바뀝니다.
- `콜드`를 고르면 `콜드 마이그레이션은 인스턴스를 종료한 뒤 대상 호스트에서 다시 시작합니다.` 경고가 표시됩니다.
- 노드를 선택하지 않고 `불가` 문구만 클릭한 경우에는 `방식` 대신 라이브·콜드 각각의 가능 여부가 표시되며, 실행 대상 노드를 이미 선택해 두었다면 어느 노드가 실행 대상인지 안내 문구가 함께 표시됩니다.

#### 실행

- 실행 버튼 라벨은 고른 방식에 따라 **`라이브 마이그레이션`** 또는 **`콜드 마이그레이션`** 으로 바뀝니다. 버튼에 적힌 이름이 실제로 수행되는 작업입니다.
- 대상 노드를 선택하지 않았거나, 고른 방식이 그 노드에서 `불가`이면 실행 버튼이 비활성화됩니다.
- **`취소`**: 마이그레이션을 수행하지 않고 창을 닫습니다.

> ⚠️ **주의:** 콜드 마이그레이션은 인스턴스를 종료했다가 다시 시작하므로 그동안 서비스가 중단됩니다. 방식이 자동으로 바뀔 수 있으니 실행 전에 버튼 라벨을 확인합니다.

#### 자주 나타나는 차단 사유

| 화면에 표시되는 사유 | 막는 경로 | 확인·조치 |
| --- | --- | --- |
| `호스트가 UP 상태가 아님` | `라이브·콜드` | 대상 노드 상태가 `실행 중`이 아닙니다. 다른 노드를 고르거나, 노드가 `실행 중`이 된 뒤 다시 시도합니다. |

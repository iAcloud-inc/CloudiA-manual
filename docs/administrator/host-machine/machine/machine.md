# 노드

**노드(Node)** 메뉴에서는 Cloud:iA에 등록된 **물리 머신**을 관리합니다.  
물리 머신은 초기 설치 단계에서만 추가할 수 있으며, 설치 완료 후에는 노드를 직접 추가하거나 삭제하는 기능을 제공하지 않습니다.
노드 추가가 필요한 경우에는 아이에이클라우드 영업팀에 문의하시기 바랍니다. 별도의 라이선스 구매 및 기술팀의 설치 지원 절차가 필요합니다.

노드 상세 화면에서는 해당 물리 서버의 **하드웨어 사양**, **모니터링 지표**, **BMC(Baseboard Management Controller)** 관리 기능 등을 확인할 수 있습니다.

---

## 노드 목록

**노드 목록** 페이지에서는 현재 등록된 모든 물리 머신의 리스트와 주요 정보를 한눈에 볼 수 있습니다.  

### 주요 작업

노드 목록 상단의 도구 모음에서는 사용자가 선택한 노드에 대해 다음과 같은 작업을 수행할 수 있습니다.

- **`편집`**: 노드를 **한 개만 선택**하고, 그 노드의 `Agent 연결 상태`가 `연결`인 경우 활성화됩니다. 클릭 시 선택된 노드의 정보 편집 화면으로 이동합니다.  
- **`전원 켜기`**: 선택한 노드에 BMC 정보가 등록된 경우 활성화됩니다. BMC를 통해 **원격 부팅** 명령을 전송합니다.  
- **`전원 끄기`**: 선택한 노드에 BMC 정보가 등록된 경우 활성화됩니다. BMC를 통해 **원격 종료** 명령을 전송합니다.  
  이 작업을 수행하면 해당 노드의 모든 VM과 서비스가 중단되므로 주의가 필요합니다.  
- **`더보기`**: 선택한 노드에 대한 추가 작업을 모아 둔 드롭다운입니다. 다음 항목을 제공합니다.  
  - `강제 종료`: 정상 종료 절차를 건너뛰고 노드의 전원을 즉시 차단합니다. 자세한 내용은 [전원 관리](#전원-관리)를 참고합니다.  
  - `유지관리 진입`, `유지관리 복귀`(또는 `대피 중지`): 노드를 점검 상태로 넣거나 되돌립니다. 자세한 내용은 [유지관리 모드](#유지관리-모드)를 참고합니다.  

### 테이블 컬럼

| 컬럼 | 설명 |
|------|------|
| **이름** | 노드를 식별하는 이름입니다. 클릭 시 해당 노드의 상세 화면으로 이동합니다. |
| **Agent 연결 상태** | Host Agent 연결 상태를 표시합니다. “연결” 또는 “해제”로 표시됩니다. |
| **유지관리 상태** | 노드가 점검 중일 때 현재 단계를 표시합니다. `대피 중`, `유지관리 중`, `유지관리 준비 실패`, `복귀 중`, `취소 중` 중 하나이며, 점검 중이 아니면 `-`로 표시됩니다. 값의 의미는 [유지관리 상태 값](#유지관리-상태-값)을 참고합니다. |
| **BMC** | 노드의 BMC 정보 등록 여부를 표시합니다. |
| **전원** | 현재 물리 머신의 전원 상태입니다. “켜짐” 또는 “꺼짐”으로 표시됩니다. |
| **설명** | 관리자가 입력한 노드에 대한 설명이나 메모입니다. |
| **생성 일시** | 노드가 등록된 날짜와 시간입니다. |

> 💡 **참고:** `유지관리 상태`, `BMC`, `전원` 컬럼은 정렬을 제공하지 않습니다.

## 전원 관리

물리 머신의 전원 상태를 원격으로 제어합니다. 전원 제어는 **BMC 정보가 등록된 노드**에서만 사용할 수 있습니다.

| 작업 | 설명 | 위치 | 활성화 조건 |
|-----|-----|-----|-------------|
| **`전원 켜기`** | 선택한 노드의 전원을 원격으로 켭니다. | 도구 모음 | BMC 등록, 현재 전원 상태가 `꺼짐` |
| **`전원 끄기`** | 선택한 노드의 전원을 원격으로 끕니다. | 도구 모음 | BMC 등록, 현재 전원 상태가 `켜짐` |
| **`강제 종료`** | 정상 종료 절차를 건너뛰고 선택한 노드의 전원을 즉시 차단합니다. | `더보기` 메뉴 | BMC 등록, 현재 전원 상태가 `켜짐` |
>💡 **참고:** BMC가 등록되지 않은 물리 머신은 전원 상태가 '-'로 표시됩니다.


### 사용 절차
1. 대상 노드를 선택합니다.
2. 전원 상태를 확인합니다. (`켜짐` / `꺼짐`)  
3. `전원 켜기` 또는 `전원 끄기` 버튼을 클릭합니다. 강제 종료가 필요하면 `더보기` 메뉴에서 `강제 종료`를 선택합니다.  
4. 확인 대화상자에서 안내 문구를 확인하고 동작을 승인합니다.  
5. 전원 상태가 반영될 때까지 잠시 대기한 후, 전원 상태가 업데이트 됩니다.

> ⚠️ **주의: 전원관리**
>  - 전원 관리 기능은 **BMC 정보가 등록된 노드**에서만 사용할 수 있으며, BMC 정보가 없거나 인증 정보가 올바르지 않으면 전원 제어 버튼이 비활성화되거나 실패할 수 있습니다.
>  - `전원 끄기`를 수행하면 해당 호스트의 **모든 VM과 서비스가 즉시 중단**됩니다. 작업 전 반드시 안전한 종료 절차를 확인합니다.  

> ⚠️ **주의: 강제 종료**
>  - 강제 종료는 **정상 종료 절차를 건너뛰고 물리 머신의 전원을 즉시 차단**합니다. 실행 중인 모든 VM과 서비스가 비정상 종료되어 **데이터 손실이 발생할 수 있습니다.**
>  - `전원 끄기`로 노드가 내려가지 않을 때 마지막 수단으로만 사용합니다.
>  - 노드를 점검하려고 잠시 빼는 것이 목적이라면 강제 종료 대신 [유지관리 모드](#유지관리-모드)를 사용합니다. 유지관리 모드는 워크로드를 다른 노드로 옮긴 뒤 노드를 떼어 놓습니다.

## 유지관리 모드

**유지관리 모드**는 노드를 끄는 기능이 아니라, 노드를 클러스터에서 논리적으로 떼어 두는 상태입니다.
노드가 유지관리 모드에 들어가면 새 인스턴스가 그 노드에 배치되지 않고, 자동 복구의 목적지로도 쓰이지 않으며, 노드가 응답하지 않아도 장애로 판정하지 않아 페일오버가 발동하지 않습니다.
동시에 그 노드가 맡고 있던 워크로드를 다른 노드로 옮깁니다. 이 과정을 **대피**라고 합니다.
하드웨어 점검, 펌웨어 교체처럼 노드를 잠시 빼 두어야 할 때 사용합니다.

### 실행 위치

노드 목록에서 노드를 한 개 선택한 뒤, 도구 모음의 `더보기` 메뉴에서 실행합니다.

| 항목 | 설명 | 활성화 조건 |
| --- | --- | --- |
| **`유지관리 진입`** | 진입 마법사를 엽니다. | 노드가 점검 중이 아닐 때. 유지관리 상태가 `유지관리 준비 실패`이면 재시도할 수 있도록 함께 활성화됩니다. |
| **`유지관리 복귀`** | 복귀 화면을 엽니다. | 노드가 점검 중일 때 |
| **`대피 중지`** | 진행 중인 대피를 멈춥니다. 유지관리 상태가 `대피 중`이면 `유지관리 복귀` 항목의 이름이 이렇게 바뀝니다. | 유지관리 상태가 `대피 중`일 때 |

> 💡 **참고:** 유지관리 진입과 복귀는 노드의 **전원 상태와 무관하게** 실행할 수 있습니다. 노드를 끄고 켜는 동작이 아니기 때문입니다.

### 유지관리 상태 값

노드 목록의 `유지관리 상태` 컬럼과 노드 상세의 `유지관리` 섹션에 표시되는 값입니다.

| 상태 | 의미 |
| --- | --- |
| **`대피 중`** | 이 노드의 워크로드를 다른 노드로 옮기고 있습니다. |
| **`유지관리 중`** | 대피가 끝나 노드가 클러스터에서 떨어져 있습니다. 점검을 진행할 수 있습니다. |
| **`유지관리 준비 실패`** | 대피를 끝내지 못했습니다. 사유를 확인한 뒤 다시 진입하거나 복귀합니다. |
| **`복귀 중`** | 노드를 클러스터로 되돌리고 있습니다. |
| **`취소 중`** | 대피 중지 요청을 처리하고 있습니다. |
| **`-`** | 점검 중이 아닙니다. |

### 유지관리 진입

`유지관리 진입`을 선택하면 2단계 마법사가 열립니다.

#### 1단계 `대피 대상`

무엇을 어디로 옮길지 정하는 단계입니다.

- **`인스턴스`**: 이 노드에 배치된 인스턴스 목록입니다. 이름, 상태, `vCPU`, 메모리를 확인할 수 있습니다.
- **`대피 목적지`**: 워크로드를 받을 수 있는 다른 노드의 목록입니다. 노드 이름, 상태, 여유 자원(`vCPU` / 메모리)을 확인하고 체크박스로 선택합니다.
  - 처음에는 **선택할 수 있는 노드가 모두 선택된 상태**로 시작합니다. 이미 점검 중인 노드는 처음부터 해제되어 있습니다. 체크를 해제한 노드는 대피 목적지에서 제외됩니다.
  - 이미 점검 중인 노드는 이름 옆에 `점검 중` 뱃지가 붙고 선택할 수 없습니다.
  - 관리 연결이 끊긴 노드는 `관리 연결 끊김` 뱃지가 붙습니다.

> ⚠️ **주의:** `대피 목적지`를 하나도 선택하지 않으면 이 노드의 인스턴스가 **모두 종료됩니다.** 처음에는 전부 선택된 상태이므로, 체크를 해제할 때 옮길 곳이 남는지 확인합니다.

#### 2단계 `대피 계획`

선택한 내용으로 계획을 계산해 결과를 보여 줍니다. 노드에 인스턴스가 많으면 계산에 1분 가까이 걸릴 수 있으며, 진행 중에는 경과 시간이 함께 표시됩니다.

- **`목적지별 배정`**: 목적지 노드마다 몇 건을 받는지 표시합니다.
- **`대피 계획`**: 워크로드를 등급으로 나눠 건수를 표시합니다.

| 등급 | 의미 |
| --- | --- |
| **`무중단`** | 서비스를 멈추지 않고 다른 노드로 옮깁니다. |
| **`다운타임`** | 껐다가 다른 노드에서 다시 켭니다. |
| **`마이그레이션 불가`** | 옮길 수 없어 이 노드에서 종료합니다. |
| **`전체`** | 위 세 등급의 합계입니다. |

- **`진입 영향`**: `다운타임 N건 · 정지 잔류 M건` 형식으로 이번 진입의 결과를 요약합니다.
- **`주의 대상`**: `다운타임`과 `마이그레이션 불가` 워크로드의 이름·등급·사유를 표로 보여 줍니다. 무중단으로 옮겨지는 워크로드는 이 표에 나오지 않습니다.

`주의 대상` 표의 `사유` 열에 자주 나오는 내용과 대응은 다음과 같습니다.

| 사유 | 대응 |
| --- | --- |
| 제외한 노드를 빼고 나면 남는 목적지가 없습니다 | 1단계로 돌아가 `대피 목적지`에서 해제한 노드를 다시 선택합니다. |
| 목적지 자원이 부족합니다 | 목적지 노드의 여유 자원을 확보한 뒤 다시 계산합니다. |
| 강제 선호도 그룹에 묶여 있습니다 | 그룹에 속한 인스턴스를 함께 옮기거나, 선호도 그룹을 해제합니다. |
| 재이관 후보가 없어 이 VPC 통신이 점검 동안 단절됩니다 | 해당 VPC의 통신이 끊기고, 진입 즉시 그 VPC의 로드 밸런서·플로팅 IP·DNS 구성 변경도 막힙니다. 다른 네트워크 노드를 먼저 복귀시키거나, 단절을 감수하고 진행합니다. |
| 조건을 만족하는 마이그레이션 목적지가 없습니다 · 디스크를 옮길 공유 스토리지가 없습니다 · 디스크를 대상 스토리지로 옮길 수 없습니다 | 이 인스턴스는 이번 점검에서 옮길 수 없습니다. 종료를 감수하고 진행하거나 점검을 미룹니다. |

> ⚠️ **주의: 진입 버튼이 곧 동의입니다**
>  - 이 마법사에는 **별도의 동의 체크박스가 없습니다.** `진입` 버튼을 누르는 것 자체가 화면에 표시된 계획에 동의하는 것입니다.
>  - 버튼을 누르기 전에 `진입 영향`의 건수와 `주의 대상` 목록을 반드시 확인합니다.

### 진입이 막히거나 경고가 표시될 때

2단계 화면에는 두 종류의 안내가 나올 수 있습니다.

- **`진입할 수 없습니다`**: 사유가 해소되기 전에는 진입할 수 없습니다. `진입` 버튼이 비활성화됩니다.
- **`경고`**: 진입은 할 수 있지만, 진행하기 전에 영향 범위를 확인해야 하는 내용입니다.

#### `진입할 수 없습니다`

| 사유 | 대응 |
| --- | --- |
| 다른 노드의 대피가 진행 중입니다 | 대피는 클러스터 전체에서 한 번에 한 노드만 할 수 있습니다. 문구에 표시된 노드의 대피가 끝난 뒤 다시 시도합니다. |
| 전환 중입니다 · 상태를 확인할 수 없는 워크로드입니다 | 해당 인스턴스가 시작·종료 같은 전환을 마칠 때까지 기다렸다가 다시 시도합니다. |
| 이 VM 의 이관 경로를 판정하지 못했습니다 | 잠시 뒤 마법사를 다시 열어 계획을 새로 계산합니다. |
| 역할을 판정할 수단이 없습니다 · 이 노드가 무엇을 지고 있는지 판정하지 못했습니다 | 노드의 `Agent 연결 상태`와 상세 화면의 상태를 먼저 확인합니다. 상태가 정상으로 돌아온 뒤에도 같은 안내가 반복되면 기술 지원에 문의합니다. |

#### `경고`

| 사유 | 대응 |
| --- | --- |
| Ceph OSD·모니터를 지금 멈추면 안 됩니다 · 모니터 정족수가 위태로워집니다 | 스토리지 복구가 끝난 뒤 점검을 시작합니다. 그대로 진행하면 스토리지 가용성이 떨어질 수 있습니다. |
| 이 노드가 NFS 익스포트를 제공합니다 | 이 스토리지를 쓰는 **다른 노드의 인스턴스도 함께 끊깁니다.** 영향 범위를 확인한 뒤 진행합니다. |
| VIP 를 넘겨받을 다른 마스터 노드가 없습니다 | 다른 마스터 노드가 정상으로 돌아온 뒤 진행하는 것이 안전합니다. |
| 주인 없는 vRouter 네임스페이스가 남아 있습니다 | 점검 동안에는 정리되지 않습니다. 복귀한 뒤 정리합니다. |

> 💡 **참고:** 그 밖의 사유는 화면에 직접 안내됩니다.

### 진행 상황 확인

점검 중인 노드의 **상세 화면**에는 `유지관리` 섹션이 나타납니다. 점검 중이 아닌 노드에는 이 섹션이 표시되지 않습니다.

| 항목 | 설명 |
| --- | --- |
| **유지관리 상태** | 현재 유지관리 상태입니다. |
| **요청자** | 유지관리 진입을 요청한 사용자입니다. |
| **진입 일시** | 유지관리에 진입한 시각입니다. |
| **진행** | `완료 건수/전체 건수`를 표시하고, 그 아래에 지금 처리 중인 인스턴스 이름과 단계, 경과 시간을 표시합니다. 다음 항목을 고르는 동안에는 준비 중이라는 안내가 표시됩니다. |
| **직전 실패 사유** | 대피나 복귀가 실패했다면 그 사유를 표시합니다. |
| **실패한 워크로드** | 옮기지 못한 워크로드의 이름과 사유 목록입니다. 실패한 항목이 있을 때만 표시됩니다. |

### 유지관리 복귀

점검이 끝나면 `더보기` 메뉴에서 `유지관리 복귀`를 선택해 노드를 클러스터로 되돌립니다.

#### `복귀 검증`

복귀 화면은 먼저 노드가 다시 일할 수 있는 상태인지 5개 항목으로 확인합니다.

| 검증 항목 | 무엇을 보는가 | `조치 필요`로 나오면 |
| --- | --- | --- |
| **`호스트 에이전트`** | Cloud:iA가 이 노드와 통신할 수 있는지 | 노드가 켜져 있는지, 목록의 `Agent 연결 상태`가 `연결`인지 확인합니다. |
| **`VDSM 연결`** | 노드의 가상화 관리 데몬이 응답하는지 | 노드를 재부팅한 직후에는 잠시 준비 중일 수 있습니다. 몇 분 뒤 복귀 화면을 다시 엽니다. |
| **`내부 네트워크`** | 노드가 내부망으로 다른 노드와 통신되는지 | 점검 중 분리한 케이블·스위치 포트가 원래대로 돌아왔는지 확인합니다. |
| **`스토리지 도달성`** | 노드가 스토리지에 접근할 수 있는지 | 스토리지망 연결과 스토리지 도메인 상태를 확인합니다. |
| **`Ceph OSD 상태`** | 이 노드가 가진 Ceph OSD가 정상인지 | 스토리지 복구가 진행 중일 수 있습니다. 복구가 끝난 뒤 다시 확인합니다. |

각 항목은 `정상`, `조치 완료`, `조치 필요`, `확인 불가`, `해당 없음` 중 하나로 표시됩니다.

> ⚠️ **주의: 검증을 통과해야만 복귀할 수 있습니다**
>  - 검증을 통과하지 못하면 `복귀` 버튼이 비활성화되며, **검증을 건너뛰고 강제로 복귀시키는 수단은 없습니다.**
>  - `조치 필요` 항목은 노드에서 직접 해결해야 합니다. 조치를 마친 뒤 복귀 화면을 다시 열면 검증이 새로 수행됩니다.

#### `복귀할 때 이 노드에서 다시 시작`

이번 점검 때문에 정지된 인스턴스가 있으면 `정지된 인스턴스` 목록과 함께 이 체크박스가 표시됩니다. **기본값은 켜짐**입니다.

- 체크를 켜 두면 이번 점검이 정지시킨 인스턴스를 복귀와 함께 다시 시작합니다.
- 점검 전부터 꺼져 있던 인스턴스는 대상이 아닙니다. 복귀해도 켜지지 않습니다.
- 체크를 해제하면 인스턴스를 정지된 상태로 두고 노드만 복귀시킵니다.

### 대피 중지

유지관리 상태가 `대피 중`일 때 `더보기` 메뉴의 항목 이름이 `대피 중지`로 바뀝니다. 선택하면 진행 중인 대피를 멈춥니다.

- 이미 시작된 이관 한 건은 **끝까지 진행**되고, 그 다음부터 멈춥니다.
- **이미 옮겨진 워크로드는 원래 노드로 되돌리지 않습니다.**

### 점검 중 제약

노드가 유지관리 모드에 있는 동안에는 다음 동작이 제한됩니다.

- 대피는 **클러스터 전체에서 한 번에 한 노드만** 가능합니다. 다른 노드가 대피 중이면 진입할 수 없습니다.
- 점검 중인 노드의 인스턴스는 **사양 변경**, **`vCPU`·메모리·NIC·디스크 증설**, **일시중지 상태의 재개**가 거부됩니다.
- 다른 인스턴스를 **이 노드로 마이그레이션할 수 없습니다.** 대상 노드 목록에는 그대로 남지만 선택할 수 없으며, 사유로 `호스트가 UP 상태가 아님`이 표시됩니다.

위 동작은 노드가 복귀하면 다시 사용할 수 있습니다.

> ⚠️ **주의: 유지관리 모드를 사용하기 전에 확인합니다**
>  - **대피한 인스턴스는 복귀해도 원래 노드로 돌아오지 않습니다.** 다른 노드로 옮겨진 상태 그대로 유지되며, 원래 노드로 되돌리려면 인스턴스를 직접 마이그레이션해야 합니다.
>  - **이관하지 못한 인스턴스는 이 노드에서 종료되고, 복귀할 때 다시 시작됩니다.** 그만큼 서비스 중단 시간이 발생합니다. 진입 전에 `대피 계획`의 `주의 대상` 목록으로 어떤 인스턴스가 여기에 해당하는지 반드시 확인합니다. (복귀 화면에서 `복귀할 때 이 노드에서 다시 시작` 체크를 해제하면 정지된 상태로 둘 수도 있습니다.)

## 노드 편집

**노드 편집** 화면에서는 노드 이름은 조회만 가능하며, 설명을 수정할 수 있습니다.  
`Agent 연결 상태`가 `연결`인 노드를 하나 선택한 후 `편집` 버튼을 클릭하면 진입할 수 있습니다.

- **이름**: 필수 입력 항목이며, 읽기 전용 항목입니다.
- **설명**: 선택 입력 항목으로 최대 200자까지 작성 가능합니다.  
- **저장/취소 버튼**: 
  - `저장`: 변경 내용을 저장 후 목록으로 복귀합니다.
  - `취소`: 변경 내용을 저장하지 않고 목록으로 복귀합니다.

### 입력 필드 유효성 검증

| 필드 | 허용 값 및 길이 | 검증 규칙 | 비고 |
|------|------------------|------------|------|
| **이름** | 읽기 전용 항목입니다. | 필수 입력 |
| **설명** | 모든 문자 / 최대 200자 | 형식 제한 없음 | 선택 입력 |

## 노드 상세

**노드 상세** 페이지에서는 선택한 물리 머신의 상세 정보를 확인할 수 있습니다.  
상단에는 기본 정보 및 BMC 설정 상태가 요약되어 표시되며, 하단에는 여러 **탭** 형태로 세부 정보가 구성되어 있습니다.  
Host Agent 연결이 정상인 노드의 경우 CPU·메모리 사용률 등 실시간 모니터링 데이터가 표시됩니다.

### 기본 정보 및 BMC 설정

- **이름 및 ID**: 노드의 표시 이름과 시스템 고유 ID가 표시됩니다.  
- **Agent 연결 상태**: Host Agent 연결 상태를 표시합니다.  
- **BMC**: 등록된 BMC의 IP, 계정(사용자), 마스킹된 패스워드를 표시합니다.  
- **BMC 등록/삭제**: 등록되지 않은 경우 `등록`, 등록된 경우 `삭제` 버튼이 표시됩니다.  
- **전원**: 물리 머신의 전원 상태를 표시합니다. (켜짐/꺼짐)  
- **설명 및 생성 일시**: 노드 등록 시 입력한 설명과 등록 시각을 표시합니다.  

> 💡 **참고:** BMC 등록 시 전원 제어, 섀시 정보, 시스템 이벤트 로그, 센서 모니터링 기능이 활성화됩니다.

### BMC 등록

#### 등록 위치
- **노드 상세 화면 상단**의 BMC `등록` 버튼을 클릭합니다.  
  (이미 등록된 경우 버튼이 `삭제`로 표시됩니다.)

#### 입력 항목

| 필드 | 설명 | 입력 형식 | 비고 |
|------|------|-----------|------|

| **관리자 비밀번호** | BMC 로그인 비밀번호 | 최대 20자 | 필수 입력 |



- BMC 등록 시, BMC 접근용 IP 주소를 통한 등록 가능 여부 확인 절차가 필요합니다.
> 💡 **참고:**  BMC 등록 시, ID/비밀번호 정책은 BMC 벤더사에서 제공하는 정책을 따름

- 등록이 완료되면 상단 요약 정보에 BMC IP와 계정명이 표시됩니다.

#### BMC 삭제
- 이미 등록된 BMC 정보는 `삭제` 버튼으로 제거할 수 있습니다.  
- 삭제 시 BMC 기반 기능(전원 관리, 섀시, 센서, 시스템 이벤트 로그)은 비활성화됩니다.

> 💡 **참고:** 디스크와 네트워크 그래프는 `bytes/sec` 단위로 표시됩니다.

### 로그

로그 탭에서는 노드에서 발생한 시스템 로그를 실시간으로 확인할 수 있습니다.
이 로그에는 운영 체제와 서비스에서 기록하는 시스템 이벤트, 오류, 경고 메시지 등이 포함되어 있어, 노드의 상태를 점검하거나 문제를 진단할 때 활용할 수 있습니다.
최근 1시간 로그가 실시간으로 표시되며, 기간 지정 후 CSV 다운로드가 가능합니다.

| 컬럼 | 설명 |
|------|------|
| **로그 소스** | 로그 발생 소스 |
| **유닛명** | 로그 유닛명 |
| **프로세스 ID** | PID |
| **로그 수준** | 로그 수준 |
| **메시지** | 로그 메시지 |
| **생성 일시** | 로그 발생 시각 |

> 💡 **참고:** 1시간 이전 로그는 CSV 다운로드를 통해 확인할 수 있습니다.

### 센서 모니터링

# CPU 세대 호환

**CPU 세대 호환**은 CPU 세대가 다른 컴퓨트 노드가 섞여 있어도 인스턴스가 노드 사이를 라이브 마이그레이션할 수 있게 하는 기능입니다.
CPU 세대 호환을 켠 인스턴스는 노드 CPU를 그대로 쓰지 않고, 제조사마다 정한 **공통 CPU**의 기능만 씁니다. 공통 CPU는 관리자가 고른 세대의 CPU 기능이며, 그 세대 이상의 같은 제조사 노드라면 어디서든 실행할 수 있습니다.

**물리 머신 › 컴퓨트 노드** 화면의 **CPU 세대 호환** 탭에서 새 인스턴스 기본값과 제조사별 공통 CPU를 정하고, 노드마다 공통 CPU를 실행할 수 있는지 봅니다.
인스턴스 쪽 설정은 [인스턴스의 CPU 세대 호환](../../../project/vm/instance/instance.md#cpu-세대-호환)을 참고하세요.

---

## 화면 구성

**물리 머신 › 컴퓨트 노드** 화면 위쪽 탭에서 **CPU 세대 호환**을 누르면 열립니다. 위에서 아래로 두 섹션으로 나뉩니다.

| 섹션 | 버튼 | 내용 |
| --- | --- | --- |
| **설정** | `편집` | 새 인스턴스 기본값, 제조사별 공통 CPU |
| **현황** | - | 지금 공통 CPU로 실행하지 않는 인스턴스 수, 노드별 공통 CPU 실행 여부 |

## 설정

| 항목 | 값 | 설명 |
| --- | --- | --- |
| **새 인스턴스 기본값** | `사용함` / `사용 안 함` | 인스턴스를 만들 때 `CPU 세대 호환` 토글의 처음 값입니다. 기본값은 `사용함`입니다. 사용자는 인스턴스마다 바꿀 수 있습니다. 시스템이 만드는 인스턴스(쿠버네티스 노드, 레지스트리, NFS 서버, 패키지 미러)도 이 값을 따릅니다. |
| **Intel 공통 CPU** | 세대 이름(예: `Cascade Lake`) | Intel 노드에서 CPU 세대 호환 인스턴스가 쓰는 CPU 기능의 세대입니다. |
| **AMD 공통 CPU** | 세대 이름(예: `Rome`) | AMD 노드에서 쓰는 세대입니다. |

Intel·AMD 칸은 늘 보입니다. 그 밖의 제조사 노드가 있으면 그 제조사 칸이 뒤에 붙습니다. 컴퓨트 노드가 없는 제조사는 `노드 없음`, 노드는 있는데 공통 CPU를 아직 정하지 못한 제조사는 `정하지 못함`으로 보입니다. **설정 편집**에서 `노드 없음`인 제조사는 고칠 수 없습니다.

**`편집`**을 누르면 **설정 편집** 화면으로 이동합니다. 값을 바꾼 뒤 아래쪽 **`편집`**을 누르면 저장되고 CPU 세대 호환 탭으로 돌아옵니다. 바꾼 값이 없으면 아래쪽 **`편집`**은 비활성입니다.

### 공통 CPU 고르기

공통 CPU 드롭다운에는 지금 붙어 있는 노드의 세대만 나옵니다. 옵션마다 그 세대로 정했을 때 공통 CPU를 실행할 수 있는 노드 수가 붙습니다(예: `Broadwell · 실행 노드 11대`).
세대를 고르면 드롭다운 아래에 저장했을 때의 결과가 한 줄로 보입니다.

| 고른 세대 | 아래에 보이는 결과 | 뜻 |
| --- | --- | --- |
| 지금보다 낮은 세대 | `실행 노드 9대 → 11대 / 인스턴스 42개는 다음 시작부터 적용` | 실행할 수 있는 노드가 늘어납니다. 실행 중인 인스턴스는 그대로이고, 완전히 종료한 뒤 시작할 때부터 새 공통 CPU를 씁니다. |
| 지금보다 높은 세대 | `실행 노드 9대 → 1대 / 실행 안 함이 되는 노드에서 실행 중 38개` | 실행할 수 있는 노드가 줄어듭니다. 실행 중인 인스턴스는 그대로 돌지만, 다시 시작할 때는 실행 노드에만 놓입니다. |
| 지금과 같은 세대 | `다시 계산 · 실행 노드 9대 → 10대` | 같은 세대로 공통 CPU를 다시 계산합니다. 신형 노드를 붙인 뒤 그 노드도 실행 노드에 넣고 싶을 때 씁니다. |
| 운영체제가 요구하는 CPU 수준보다 낮아지는 경우 | `더 높은 CPU 세대가 필요한 인스턴스 2개는 사용 안 함으로 바뀝니다` | 해당 인스턴스는 다음 시작부터 노드 CPU를 그대로 씁니다. |
| 그 세대의 노드가 모두 꺼져 있음 | `대상 노드가 모두 꺼져 있어 저장할 수 없습니다` | 노드를 켠 뒤 다시 시도합니다. |

> 💡 **참고:** 공통 CPU를 낮추면 더 많은 노드 사이를 옮길 수 있는 대신, 인스턴스가 신형 CPU 기능(예: AVX-512, 새 암호화 명령)을 쓰지 못합니다. 암호화나 계산이 많은 인스턴스는 성능이 크게 떨어질 수 있습니다. 그런 인스턴스는 인스턴스 쪽에서 CPU 세대 호환을 끄는 것이 낫습니다.

### 처음 값

공통 CPU를 한 번도 저장하지 않았으면 시스템이 처음 값을 정합니다. 그 제조사 노드가 가장 많이 실행할 수 있는 세대를 고르고, 노드가 등록되거나 꺼졌던 노드가 다시 켜질 때마다 다시 정합니다.
그 공통 CPU로 인스턴스가 처음 시작하거나 관리자가 저장하면 처음 값이 굳고, `공통 CPU 처음 값 확정` 이벤트가 남습니다. 굳은 뒤로는 관리자가 저장할 때만 바뀝니다.

> ⚠️ **주의:** 오래된 노드 한 대(예: 구형 GPU 노드) 때문에 처음 값이 낮게 정해질 수 있습니다. 설치나 업그레이드 뒤에는 공통 CPU를 확인하세요. 아래 [업그레이드한 뒤 확인할 것](#업그레이드한-뒤-확인할-것)을 참고하세요.

### 신형 노드를 붙였을 때

신형 노드를 붙여도 공통 CPU는 저절로 오르지 않습니다. 이미 실행 중인 인스턴스가 옮겨 갈 곳을 잃지 않게 하려는 것입니다.
공통 CPU를 올리려면 **설정 편집**에서 더 높은 세대를 고르고, 아래에 보이는 실행 노드 수와 영향받는 인스턴스 수를 확인한 뒤 저장합니다. 높은 세대를 고르면 그보다 낮은 세대의 노드는 `실행 안 함`이 되어 CPU 세대 호환 인스턴스를 새로 받지 않습니다.

## 현황

### 지금 공통 CPU로 실행하지 않는 인스턴스

노드 표 위에 CPU 세대 호환을 켰는데 지금 공통 CPU로 실행하지 않는 인스턴스 수가 원인별로 한 줄씩 보입니다. 0개인 줄은 보이지 않습니다.

| 줄 | 뜻 |
| --- | --- |
| `이전 공통 CPU로 실행 중 N개` | 공통 CPU를 바꾸기 전에 시작해 이전 공통 CPU로 돌고 있는 인스턴스입니다. 이전 공통 CPU를 실행할 수 있는 노드끼리는 계속 옮길 수 있습니다. |
| `노드 CPU로 실행 중 N개` | 장애 복구 때 공통 CPU를 실행할 노드가 없어 노드 CPU로 대신 시작한 인스턴스입니다. 세대가 다른 노드로는 옮기지 못할 수 있습니다. |

`N개`를 누르면 인스턴스 목록(`이름`, `프로젝트`, `노드`)이 열립니다. 인스턴스를 완전히 종료한 뒤 시작하면 지금 공통 CPU로 바뀝니다. 인스턴스 안에서 재부팅해서는 바뀌지 않습니다.

### 노드 표

| 열 | 내용 |
| --- | --- |
| **노드** | 컴퓨트 노드 이름입니다. |
| **제조사** | CPU 제조사(예: `Intel`, `AMD`)입니다. |
| **세대** | 노드 CPU의 세대입니다(예: `Cascade Lake`). |
| **세대 호환 인스턴스** | 이 노드가 지금 공통 CPU를 실행할 수 있는지입니다. 아래 표를 참고하세요. |

| 값 | 뜻 | 조치 |
| --- | --- | --- |
| `실행` | CPU 세대 호환 인스턴스를 받을 수 있습니다. | - |
| `실행 안 함 · 공통 CPU보다 낮음` | 노드 세대가 공통 CPU보다 낮습니다. | 이 노드에도 놓으려면 공통 CPU를 이 노드의 세대로 낮춥니다. |
| `실행 안 함 · CPU 기능 부족` | 세대는 같거나 높지만 공통 CPU의 기능 중 노드에 없는 것이 있습니다. BIOS 설정이나 마이크로코드 차이로 생길 수 있습니다. | 노드의 BIOS·마이크로코드를 다른 노드와 맞춘 뒤 노드를 다시 시작합니다. |
| `실행 안 함 · 판정 실패` | 노드의 CPU를 판정하지 못했습니다. | 노드 상태가 `정상`인지 확인합니다. 계속되면 기술 지원에 문의합니다. |

`실행 안 함` 노드에는 CPU 세대 호환 인스턴스가 새로 놓이지 않습니다. CPU 세대 호환을 끈 인스턴스는 그대로 놓입니다. 노드가 `실행`에서 `실행 안 함`으로 바뀌면 `노드 공통 CPU 실행 불가` 이벤트가 남습니다.

같은 판정은 [컴퓨트 노드 상세](../compute-node/compute-node.md#기본-정보)의 기본 정보 `CPU 세대 호환` 줄에도 지금 공통 CPU와 함께 보입니다(예: `실행 · 공통 CPU(Cascade Lake)`).

## 인스턴스를 시작할 수 없을 때

CPU 세대 호환 인스턴스를 시작할 때 실패 이유가 `CPU가 맞는 노드 없음` 또는 `CPU가 맞는 노드 자원 부족`이면 다음을 확인합니다.

| 실패 이유 | 뜻 | 조치 |
| --- | --- | --- |
| `CPU가 맞는 노드 없음` | 공통 CPU를 실행할 수 있는 노드가 모두 꺼졌거나 없습니다. | 현황 노드 표에서 `실행` 노드가 정상인지 확인합니다. 급하면 인스턴스를 종료한 상태에서 CPU 세대 호환을 끄고 시작하거나, 공통 CPU를 낮춥니다. 새 인스턴스를 만들 때마다 막히면 **새 인스턴스 기본값**을 `사용 안 함`으로 바꿉니다. |
| `CPU가 맞는 노드 자원 부족` | 실행 노드는 있지만 vCPU·메모리 여유가 없습니다. | 실행 노드의 인스턴스를 정리하거나, 공통 CPU를 낮춰 실행 노드를 늘립니다. |

> 💡 **참고:** 노드 장애로 시스템이 인스턴스를 다시 시작할 때는 실행 노드가 없어도 노드 CPU로 시작하고 `인스턴스 노드 CPU 재시작` 경고 이벤트를 남깁니다. 가용성을 먼저 지키려는 것입니다. 이 인스턴스는 다음에 완전히 종료한 뒤 시작할 때 공통 CPU로 돌아옵니다.

## 업그레이드한 뒤 확인할 것

이전 버전에서 업그레이드하면 다음과 같이 동작합니다.

- 기존 인스턴스는 CPU 세대 호환이 `사용 안 함`으로 들어옵니다. 지금처럼 노드 CPU를 그대로 쓰고 배치도 바뀌지 않습니다. 세대가 다른 노드 사이를 옮기려면 인스턴스를 종료한 뒤 편집에서 켭니다.
- 새로 만드는 인스턴스는 **새 인스턴스 기본값**(`사용함`)을 따릅니다.

업그레이드를 마치면 다음 순서로 확인합니다.

1. 모든 컴퓨트 노드가 `정상`인지 확인합니다. 꺼져 있던 노드는 켜진 뒤에 판정됩니다.
2. **물리 머신 › 컴퓨트 노드**의 **CPU 세대 호환** 탭에서 제조사별 공통 CPU가 의도한 세대인지 확인합니다. 오래된 노드 때문에 낮게 잡혔으면 **설정 편집**에서 고칩니다.
3. 인스턴스 생성이 `CPU가 맞는 노드 없음`으로 막히면 **새 인스턴스 기본값**을 `사용 안 함`으로 바꾸고 노드 표를 점검합니다.

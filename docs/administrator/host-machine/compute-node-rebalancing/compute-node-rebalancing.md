# 리밸런싱과 이동 이력

**리밸런싱**은 부하가 몰린 컴퓨트 노드에서 여유 있는 노드로 인스턴스를 옮겨 노드 사이 부하를 맞추는 기능입니다.
**모니터링** 메뉴의 **리밸런싱**에서 쓰며, 화면 위쪽 탭은 `이동 이력 | 설정`입니다. 처음에는 `이동 이력` 탭이 열립니다. `이동 이력` 탭에서는 리밸런싱을 포함한 모든 인스턴스 이동 기록을 보고, `설정` 탭에서는 리밸런싱 설정과 노드 현황을 보고 제외 인스턴스를 관리합니다.

리밸런싱은 다음 원칙으로 동작합니다.

- 실행 중이고 라이브 마이그레이션할 수 있는 인스턴스만 옮깁니다. 인스턴스를 끄고 옮기지 않습니다.
- 인스턴스는 자기가 속한 노드 그룹 안에서만 옮겨집니다.
- 시스템 인스턴스와 [제외 인스턴스](#제외-인스턴스)는 옮기지 않습니다. GPU 같은 장치를 직접 연결한 인스턴스처럼 라이브 마이그레이션할 수 없는 인스턴스도 옮기지 않습니다.
- 우선순위가 낮은 인스턴스부터 옮깁니다. 우선순위는 [인스턴스 우선순위](../compute-node/compute-node.md#인스턴스-우선순위)를 참고하세요.
- [선호도 그룹](../../../project/vm/affinity-group/affinity-group.md) 규칙을 지킵니다. 리밸런싱에서만 빼려면 [제외 인스턴스](#제외-인스턴스)를, 늘 특정 노드에 두려면 선호도 그룹의 물리 머신 선호도 규칙을 `강제`로 설정하세요.
- 기본 설정은 `사용 안 함`이라, 리밸런싱을 `사용함`으로 바꾸기 전에는 노드 상태만 판정하고 인스턴스를 옮기지 않습니다. `사용함`이면 승인 없이 옮깁니다.

## 설정 탭 구성

`설정` 탭은 위에서 아래로 세 섹션으로 나뉩니다. 섹션마다 제목 아래에 버튼이 있습니다.

| 섹션 | 버튼 | 내용 |
| --- | --- | --- |
| **설정** | `편집` | 리밸런싱, 균등 유지, 과부하 기준, 이동 시간대 |
| **현황** | `균등 분배` | 노드별 상태와 CPU·메모리 사용률 막대 |
| **제외 인스턴스** | `추가` `삭제` | 리밸런싱으로 옮기지 않을 인스턴스 목록 |

> 💡 **참고:** 지금 누를 수 없는 버튼은 숨기지 않고 비활성으로 표시합니다. 버튼에 마우스를 올리면 누를 수 없는 이유가 보입니다.

## 설정

설정 섹션에서 현재 설정을 보고, **`편집`**을 눌러 **설정 편집** 화면으로 이동합니다. 화면 위쪽 경로는 `모니터링 > 리밸런싱 > 설정 편집`이고, 경로의 `모니터링`을 누르면 리밸런싱 화면으로 돌아옵니다.
모든 값은 정해진 목록에서 고릅니다. 값을 바꾼 뒤 편집 화면 아래쪽의 **`편집`**을 누르면 저장되고 `설정` 탭으로 돌아옵니다. 바꾼 값이 없으면 아래쪽 **`편집`**은 비활성입니다.

| 항목 | 선택 | 설명 |
| --- | --- | --- |
| **리밸런싱** | `사용함` / `사용 안 함` | `사용함`이면 과부하 기준을 넘은 노드에서 승인 없이 인스턴스를 옮깁니다. `사용 안 함`이면 노드 상태만 판정하고 옮기지 않습니다. 기본값은 `사용 안 함`입니다. |
| **균등 유지** | `사용함` / `사용 안 함` | 과부하가 아니어도 노드 사이 사용률 차이가 크면 고르게 옮깁니다. 기본값은 `사용 안 함`입니다. 리밸런싱이 `사용 안 함`이면 비활성이고 `리밸런싱을 사용할 때만 적용됩니다.`라고 안내합니다. 아래 [균등 유지](#균등-유지)를 참고하세요. |
| **과부하 기준** | `기본` / `직접 설정` | 노드를 과부하로 볼 기준입니다. 아래 [과부하 기준](#과부하-기준)을 참고하세요. |
| **이동 시간대** | `항상` / `시간 지정` | 리밸런싱이 인스턴스를 옮겨도 되는 시간대입니다. `시간 지정`은 시작·끝 정시를 고르며, 자정을 넘기는 시간대도 고를 수 있습니다. 시각은 한국 표준시(KST) 기준이고 드롭다운 옆에 시간대가 표시됩니다. 리밸런싱이 `사용 안 함`이면 비활성이고 `리밸런싱을 사용할 때만 적용됩니다.`라고 안내합니다. |

리밸런싱이 `사용 안 함`이면 설정 섹션에서 **균등 유지**와 **이동 시간대** 값은 `-`로 표시됩니다.

> 💡 **참고:** `사용함`으로 바꾸기 전에 메모리가 가장 큰 인스턴스 하나를 평소 업무 시간에 직접 라이브 마이그레이션해 끝까지 옮겨지는지 확인하세요. 이동 시간은 네트워크와 저장소, 인스턴스가 메모리를 얼마나 자주 바꾸는지에 따라 크게 다릅니다. 메모리를 아주 자주 바꾸는 인스턴스는 옮겨지지 않고 실패할 수 있습니다. 실패하면 그 인스턴스를 [제외 인스턴스](#제외-인스턴스)로 넣거나 리밸런싱을 `사용 안 함`으로 두세요.

### 과부하 기준

`기본`을 고르면 아래 기준을 씁니다.

- CPU 대기율 5% 이상 또는 메모리 사용률 90% 이상이 **10분 넘게** 이어지면 과부하입니다.
- CPU 사용률은 기본 기준에서 쓰지 않습니다.

`직접 설정`을 고르면 지표 행이 열립니다. 지표마다 사용 여부와 값을 고르고, 지속 시간을 고릅니다. 사용하는 지표 가운데 하나라도 지속 시간 넘게 기준을 넘으면 과부하입니다.

| 지표 | 고를 수 있는 값 |
| --- | --- |
| **CPU 사용률** | 75 · 80 · 85 · 90 · 95 `% 이상` |
| **CPU 대기율** | 5 · 7 · 10 · 15 `% 이상` |
| **메모리 사용률** | 80 · 85 · 90 · 95 `% 이상` |
| **지속 시간** | 5 · 10 · 15 · 30 `분 넘게` |

- 지표는 하나 이상 사용해야 합니다. 켜진 지표가 하나뿐이면 그 토글을 끌 수 없습니다.
- `직접 설정`에서 고른 값은 `기본`으로 바꿔도 지워지지 않습니다. 다시 `직접 설정`을 고르면 그 값이 보입니다.

> 💡 **참고:** CPU 대기율은 인스턴스가 CPU를 쓰려고 기다린 시간의 비율입니다. 노드의 CPU를 여러 인스턴스가 서로 차지하려 할 때 올라갑니다. CPU 사용률이 높아도 대기율이 낮으면 인스턴스는 느려지지 않습니다. 그래서 기본 기준은 사용률 대신 대기율을 봅니다.

## 현황

현황 섹션은 노드마다 현재 상태와 부하를 보입니다. 제목 오른쪽에 `마지막 판정 <시각> · 1분마다`가 표시됩니다. 노드 상태는 1분마다 다시 판정합니다. 리밸런싱이 `사용 안 함`이어도 현황은 판정합니다.

| 컬럼 | 설명 |
| --- | --- |
| **노드** | 컴퓨트 노드 이름입니다. |
| **상태** | `정상` 또는 `과부하`입니다. 사용하는 지표 가운데 하나라도 과부하 기준을 지속 시간 넘게 넘으면 `과부하`입니다. |
| **인스턴스 수** | 노드에 배치된 인스턴스 수입니다. |
| **CPU 사용률** · **CPU 대기율** · **메모리 사용률** | 막대와 숫자로 표시합니다. 진행 중인 이동이 있으면 `현재 → 진행 중인 이동 반영 후`로 표시합니다. |

막대 아래 범례의 뜻은 다음과 같습니다.

| 범례 | 뜻 |
| --- | --- |
| **현재** | 지금 사용률입니다. |
| **기준 넘음** | 현재값 가운데 과부하 기준을 넘은 부분입니다(노란색). |
| **늘어남** · **줄어듦** | 진행 중인 이동을 반영하면 늘거나 줄어드는 양입니다. |
| **과부하 기준** | 막대 위 세로선입니다. 사용하지 않는 지표에는 표시하지 않습니다. |

> 💡 **참고:** CPU 대기율은 옮긴 뒤 값을 미리 계산하지 않으므로 현재값만 표시합니다. 옮긴 뒤의 효과는 다음 판정에서 확인합니다.

### 리밸런싱이 멈췄을 때

노드에 아래 일이 진행 중이면 리밸런싱을 멈추고 현황 섹션에 노란 안내를 띄웁니다(예: `cl1-nc1-4 노드의 유지관리 대피가 진행 중이라 리밸런싱을 멈췄습니다.`). 이때 시작하지 않은 이동은 취소됩니다.

| 멈춘 이유 | 조치 |
| --- | --- |
| 유지관리 대피·페일오버 진행 중 | 해당 작업이 끝나면 자동으로 다시 시작합니다. |
| 서비스 기동 직후 복구 중 | 복구가 끝나면 자동으로 다시 시작합니다. |
| 노드가 유지관리 중이거나 정상 상태가 아님 | 그 노드를 출발·목적지로 쓰는 이동만 막힙니다. 노드가 정상으로 돌아오면 풀립니다. |
| 노드의 지표가 없음 | 노드의 호스트 에이전트와 지표 수집 상태를 확인합니다. |

## 리밸런싱 이동

리밸런싱이 `사용함`이고 과부하인 노드가 있으면 5분마다 옮길 인스턴스와 목적지 노드를 골라 승인 없이 옮깁니다. 옮긴 이동은 `이동 이력` 탭에 `리밸런싱`으로 남습니다. `사용 안 함`이면 이동을 만들지 않습니다.

- 한 번에 과부하 노드 하나당 인스턴스 1대만 옮깁니다. 옮긴 뒤에도 과부하면 다음 판정에서 다시 옮깁니다.
- 메모리 과부하 노드를 CPU 과부하 노드보다 먼저 처리합니다.
- 목적지는 같은 노드 그룹에서 인스턴스를 받을 수 있고, 받은 뒤에도 여유가 남는 노드 가운데 가장 한가한 노드입니다. 받을 수 있는 노드가 없으면 옮기지 않습니다.
- 인스턴스를 옮기고 받은 노드는 이동을 마친 뒤 5분 동안 다음 이동의 출발·목적지로 쓰지 않습니다. 옮긴 뒤 사용률이 반영될 시간을 주려는 것입니다.
- 한 번 옮긴 인스턴스도 조건이 맞으면 다시 옮깁니다. 인스턴스가 두 노드를 오가지 않도록, 받은 뒤에도 목적지에 여유가 남는 경우에만 옮깁니다.
- 한 노드에서는 리밸런싱 이동이 한 번에 하나만 진행됩니다. 노드가 겹치지 않는 이동은 동시에 진행됩니다.
- 시작 직전에 다시 확인해, 그사이 인스턴스가 꺼졌거나 제외 인스턴스가 되었거나 목적지 여유가 줄었으면 그 이동만 취소합니다. 취소된 이동은 이동 이력에 `취소됨`으로 남습니다.
- 이동 시간대 안에서만 옮깁니다. 시간대 밖에서는 현황만 판정합니다. 시간대가 끝나면 아직 시작하지 않은 이동은 취소합니다.
- 한 시간에 시작하는 리밸런싱 이동 수에 상한을 둡니다. 시간대가 열리는 순간 이동이 한꺼번에 몰리지 않게 하려는 것입니다.
- 옮기다 실패한 인스턴스는 실패가 이어질수록 다시 옮기기까지 더 오래 기다립니다(최대 24시간). 같은 목적지 노드로 가는 이동이 잇달아 실패하면 그 노드를 잠시 목적지에서 뺍니다.
- 같은 회차에 여러 목적지 노드로 가는 이동이 잇달아 실패하면 30분 동안 리밸런싱을 멈추고, 현황에 `목적지 노드로 가는 이동이 잇달아 실패해 <시각> 까지 리밸런싱을 멈췄습니다.`라고 안내합니다. 이때는 노드 사이 네트워크와 저장소 상태를 확인합니다.
- 리밸런싱을 `사용 안 함`으로 바꾸면 새 이동을 만들지 않습니다. 이미 만들어져 시작을 기다리던 이동은 시작 직전 확인을 통과하면 그대로 진행합니다.

## 균등 분배

**균등 분배**는 과부하가 아니어도 노드 그룹 안 노드들의 CPU·메모리 사용률이 비슷해지도록 인스턴스를 옮기는 기능입니다.
예를 들어 점검을 마치고 돌아와 비어 있는 노드로 인스턴스를 나눌 때 씁니다.

- 각 노드의 사용률이 노드 그룹 평균에 가까워지도록 옮길 인스턴스를 고릅니다.
- 한 번에 최대 10대를 옮깁니다. 한 노드에서 여러 대를 차례로 옮길 수 있습니다.
- 리밸런싱이 `사용 안 함`이어도 쓸 수 있습니다.
- 관리자가 직접 실행하는 방법과, [균등 유지](#균등-유지)를 켜서 자동으로 실행하는 방법이 있습니다.

### 직접 실행

1. `설정` 탭의 현황 섹션에서 **`균등 분배`**를 누릅니다.
2. **균등 분배** 창이 열리고 `계획 계산 중 · N초 경과`가 표시됩니다. 노드 수와 인스턴스 수에 따라 수십 초가 걸릴 수 있습니다.
3. 계산이 끝나면 `노드를 고르게 맞추려면 인스턴스 N대를 옮겨야 합니다. 옮기시겠습니까?`와 함께 아래 내용을 보입니다.
   - **옮길 인스턴스**: 옮길 이동 목록과 대수입니다.
   - **노드 사용률 변화**: 모든 이동을 반영했을 때 노드별 사용률 변화입니다(예: `93% → 78%`).
   - 노란 안내: 같은 노드를 쓰는 이동이 있으면 `같은 노드를 쓰는 이동은 앞 이동이 끝나면 시작합니다.`라고 안내합니다. 또 `30분 안에 시작하지 못하거나 유지관리 대피·페일오버가 시작되면 취소됩니다.`라고 안내합니다.
4. **`승인`**을 누르면 이동이 차례로 시작됩니다. **`취소`**를 누르면 계획을 지우고 이동 이력에도 남기지 않습니다.

- 직접 실행한 균등 분배는 이동 시간대와 한 시간 시작 상한을 받지 않습니다.
- 한 노드에서는 리밸런싱 이동이 한 번에 하나만 진행됩니다. 노드가 겹치지 않는 이동은 동시에 진행됩니다.
- 시작 직전에 다시 확인해, 그사이 인스턴스가 꺼졌거나 제외 인스턴스가 되었거나 목적지 여유가 줄었으면 그 이동만 취소합니다. 취소된 이동은 이동 이력에 `취소됨`으로 남습니다.
- 출발·목적지 노드가 유지관리 중이거나 정상 상태가 아니면 승인할 수 없습니다. 여러 건 가운데 일부만 막혔으면 나머지는 승인되고, 막힌 건은 `<인스턴스>: <사유> 승인하지 못했습니다.`로 안내합니다.

옮길 인스턴스가 없으면 창에 아래 가운데 하나로 안내합니다.

| 안내 | 뜻 |
| --- | --- |
| `옮길 인스턴스가 없습니다. 노드가 이미 고르게 나뉘어 있습니다.` | 더 옮길 필요가 없습니다. |
| `진행 중인 이동을 반영하면 더 옮길 인스턴스가 없습니다.` | 진행 중인 이동이 끝나기를 기다린 뒤 다시 실행합니다. |

> 💡 **참고:** 계산 중에 창을 닫거나 다른 화면으로 가면 계획을 지웁니다. 승인하지 않고 둔 계획은 10분 뒤 지워집니다.

### 균등 유지

설정에서 **균등 유지**를 `사용함`으로 바꾸면, 과부하가 아니어도 노드 그룹 안 노드 사이 사용률 차이가 클 때 균등 분배 계획을 만들어 승인 없이 옮깁니다. 리밸런싱이 `사용함`일 때만 동작합니다. 기본값은 `사용 안 함`입니다.

- 5분마다 노드 그룹 안 노드의 사용률을 보고, 평균과 10%p 이상 차이 나는 노드가 있으면 계획을 만듭니다. 계획은 [직접 실행](#직접-실행)과 같은 규칙으로 만들고 한 번에 최대 10대를 옮깁니다.
- 앞서 만든 균등 분배 계획이 아직 끝나지 않았으면(승인 대기·승인됨·대기 중·진행 중) 새 계획을 만들지 않습니다.
- 재부팅·페일오버·유지관리를 마치고 돌아온 노드는 **30분 동안 끊김 없이** 정상일 때까지 옮겨 받는 노드로 쓰지 않습니다. 그 사이 한 번이라도 정상이 아니면 30분을 처음부터 다시 셉니다. 30분이 지나면 평소처럼 인스턴스를 받을 수 있어, 비어서 돌아온 노드로 인스턴스가 나뉩니다.
- 이동 시간대 안에서만 계획을 만듭니다. 옮긴 이동은 이동 이력의 **원인**에 `균등 유지`로 남습니다.

## 제외 인스턴스

리밸런싱으로 옮기면 안 되는 인스턴스를 등록합니다. 제외 인스턴스는 리밸런싱 이동과 균등 분배에서 빠집니다. 유지관리 대피와 페일오버로는 그대로 옮겨집니다.

### 추가

1. **`추가`**를 누르면 인스턴스를 고르는 창이 열립니다.
2. 이름으로 검색하고 인스턴스를 하나 이상 선택합니다. 후보는 최근 만든 인스턴스부터 보입니다. 시스템 인스턴스와 이미 제외한 인스턴스는 후보에 나오지 않습니다.
3. **`추가`**를 누릅니다.

정지된 인스턴스도 제외할 수 있습니다.

### 목록

| 컬럼 | 설명 |
| --- | --- |
| **이름** · **ID** | 제외한 인스턴스입니다. |
| **상태** · **프로젝트** | 인스턴스의 상태와 프로젝트입니다. |
| **노드** | 인스턴스가 실행 중인 노드입니다. 실행 중이 아니면 `-`로 표시합니다. |
| **제외한 사용자** · **제외 시각** | 제외를 등록한 관리자와 시각입니다. 최근 등록한 순서로 보입니다. |

### 삭제

목록에서 인스턴스를 선택하고 **`삭제`**를 누르면 확인 창이 열립니다. 삭제한 인스턴스는 다음 판정부터 다시 리밸런싱 대상이 됩니다.

## 이동 이력

`이동 이력` 탭에서는 인스턴스 이동 기록을 방식과 상관없이 모아 봅니다. 기본 기간은 최근 7일입니다.

- 위쪽에서 기간을 고르고, 방식·결과 필터와 검색 필드(인스턴스·프로젝트·노드)·검색어를 넣은 뒤 **`검색`**을 누릅니다. 기간은 **생성 일시**를 기준으로 찾습니다.
- 기간은 최대 180일까지 고를 수 있습니다. 이동 이력은 180일 동안 보관하고, 그보다 오래된 기록은 지웁니다.
- 열 머리글을 눌러 정렬합니다. **이름**·**ID**·**프로젝트**·**방식**·**출발지**·**목적지**·**결과**·**생성 일시**로 정렬할 수 있고, **원인**과 **소요 시간**은 정렬하지 않습니다. 처음에는 **생성 일시** 최신순입니다.
- **CSV 다운로드**로 조건에 맞는 이력을 파일로 받습니다. 한 번에 10만 건까지 받을 수 있고, 조건에 맞는 기록이 10만 건을 넘으면 내려받을 수 없으니 기간이나 필터를 좁힙니다. 파일에는 화면의 열과 함께 요청자, 시작 시각, 끝 시각이 들어 있고, 시각은 사용 중인 브라우저의 시간대로 적습니다. 파일은 화면 정렬과 상관없이 생성 일시 최신순으로 담깁니다.

| 컬럼 | 설명 |
| --- | --- |
| **이름** · **ID** · **프로젝트** | 옮긴 인스턴스입니다. |
| **방식** | `수동 마이그레이션`, `유지관리 대피`, `페일오버`, `리밸런싱`, `균등 분배` 가운데 하나입니다. |
| **출발지** · **목적지** | 출발 노드와 목적지 노드입니다. |
| **결과** | `완료`, `실패`, `거절됨`, `취소됨`, `만료됨` 가운데 하나입니다. |
| **원인** | 실패·취소된 이유입니다(예: `메모리 여유 부족`, `대기열에서 취소 · 리밸런싱 일시 중지 · 페일오버 진행 중`). 리밸런싱과 균등 유지로 옮긴 이동은 옮긴 이유가 남습니다(예: `CPU 대기율 18%`, `균등 유지`). 없으면 `-`입니다. |
| **소요 시간** | 이동에 걸린 시간입니다. 시작하지 못한 이동은 `-`입니다. |
| **생성 일시** | 이력이 남은 시각입니다. 이력은 이동이 끝날 때 남으므로 이동이 끝난 시각과 같습니다. |

결과의 뜻은 다음과 같습니다.

| 결과 | 뜻 |
| --- | --- |
| **`완료`** | 인스턴스를 목적지로 옮겼습니다. |
| **`실패`** | 옮기다 실패했습니다. 인스턴스는 출발 노드에서 계속 실행됩니다. |
| **`거절됨`** | 관리자가 이동을 거절했습니다. |
| **`취소됨`** | 시작 전 다시 확인했을 때 조건이 맞지 않아 취소했습니다. 이유는 **원인**에 표시됩니다. |
| **`만료됨`** | 승인했지만 30분 안에 시작하지 못했습니다. |

# 프로젝트 관리

## 화면 개요

프로젝트 관리 화면에서는 전체 프로젝트 목록과 자원 사용량을 조회하고 프로젝트 생성, 편집, 삭제를 수행합니다.

### 주요 작업

- `생성`: 새로운 프로젝트를 등록합니다. (항상 활성화)
- `편집`: 선택한 프로젝트를 편집합니다. **1개** 선택 시 활성화됩니다.
- `삭제`: 선택한 프로젝트들을 삭제합니다. **1개 이상** 선택 시 활성화됩니다.

> 💡 **공통 조건:** 목록에서 좌측 **체크박스**를 통해 프로젝트를 선택합니다. 다중 선택이 가능합니다.
> 헤더 체크박스를 통해 전체 선택/해제를 할 수 있습니다.

### 검색

- **검색 조건**: 드롭다운에서 `이름`을 선택합니다.
- **검색어 입력**: 검색어를 입력합니다. (플레이스홀더: `검색어를 입력해주세요.`)
- **검색 버튼**: 검색 버튼을 클릭하여 검색을 실행합니다.

### 테이블 컬럼

프로젝트 관리는 다음과 같은 컬럼으로 구성된 표 형태로 표시됩니다:

| 컬럼          | 설명                                                      |
| ------------- | --------------------------------------------------------- |
| **(선택)**    | 체크박스를 통해 프로젝트를 선택합니다. 개별/전체 선택이 가능합니다. |
| **이름**      | 프로젝트의 표시명입니다. **클릭 시 상세 화면으로 이동합니다.** |
| **ID**        | 프로젝트의 고유 식별자(ID)입니다.                         |
| **vCPU**      | 사용 중인 vCPU 코어 수와 할당된 vCPU 총량을 표시합니다. (형식: `사용량 / 할당량`) |
| **메모리**    | 사용 중인 메모리 용량과 할당된 메모리 총량을 표시합니다. (형식: `사용량 / 할당량`, 단위 포함) |
| **디스크**    | 사용 중인 스토리지 용량과 할당된 스토리지 총량을 표시합니다. (형식: `사용량 / 할당량`, 단위 포함) |
| **외부 IP**   | 사용 중인 외부 IP 개수와 할당된 외부 IP 총 개수를 표시합니다. (형식: `사용량 / 할당량개`) |
| **설명**      | 프로젝트에 대한 설명 글입니다.                            |
| **생성 일시** | 프로젝트가 생성된 날짜와 시간을 표시합니다.               |

## 프로젝트 상세

### 상단 요약

- **이름**: 프로젝트의 표시명입니다. 
- **ID**: 프로젝트의 고유 식별자(ID)입니다.
- **설명**: 프로젝트에 대한 설명 글입니다.
- **vCPU**: 사용 중인 vCPU 코어 수와 할당된 vCPU 총량을 표시합니다.
- **메모리**: 사용 중인 메모리 용량과 할당된 메모리 총량을 표시합니다.
- **디스크**: 사용 중인 스토리지 용량과 할당된 스토리지 총량을 표시합니다.
- **외부 IP**: 사용 중인 외부 IP 개수와 할당된 외부 IP 총 개수를 표시합니다.
- **생성 일시**: 프로젝트가 생성된 날짜와 시간을 표시합니다. 
- **수정 일시**: 프로젝트가 마지막으로 수정된 시점을 표시합니다.

### 하단 영역

프로젝트 상세 화면 하단에는 **멤버**와 **인스턴스** 영역이 위아래로 함께 표시됩니다.

- **멤버**: 멤버 이름, 멤버 ID, 역할 정보를 표로 제공합니다. 
  - **`편집`** 버튼을 클릭하여 멤버 편집 화면에서 해당 프로젝트의 멤버 역할 등록 및 삭제가 가능합니다.
- **인스턴스**: 해당 프로젝트에 속한 인스턴스 목록을 조회하고, 선택한 인스턴스의 전원을 제어(`실행`, `종료`, `재부팅`)합니다. 자세한 내용은 [인스턴스 관리](#인스턴스-관리)를 참고합니다.

## 프로젝트 생성

프로젝트의 이름과 설명, 프로젝트가 사용할 수 있는 리소스의 최대치(할당량)를 지정합니다. **메모리**와 **디스크**는 입력란 오른쪽의 드롭다운에서 단위를 `MB`, `GB`, `TB` 중 선택할 수 있습니다.

### 기본 정보

- **이름**: 프로젝트 이름을 입력합니다.
  - 입력 힌트: `영문 대/소문자, 숫자, -, _ 만 허용하며 최대 20자까지 입력 가능합니다.`
- **설명**: 프로젝트에 대한 부가 설명을 입력합니다. (선택)
  - 글자 수 카운트: `0/200`

### 프로젝트 리소스 할당량

- **vCPU**: 프로젝트에서 사용 가능한 가상 CPU 코어의 총 개수를 설정합니다.
  - 입력 힌트: `0 이상의 정수를 입력하세요.`
- **메모리**: 프로젝트에서 사용 가능한 메모리 용량을 설정합니다.
  - 입력 힌트: `0 이상의 정수 또는 소수를 입력하세요.`
  - 단위 드롭다운: `MB / GB / TB`
- **디스크**: 프로젝트에서 사용 가능한 스토리지 용량을 설정합니다.
  - 입력 힌트: `0 이상의 정수 또는 소수를 입력하세요.`
  - 단위 드롭다운: `MB / GB / TB`
- **외부 IP**: 프로젝트에서 사용할 수 있는 외부 IP 주소의 개수를 설정합니다.
  - 입력 힌트: `1 이상의 정수를 입력하세요.`

#### 입력 필드 유효성

| 필드           | 허용 값                  | 검증 규칙                                    | 비고 |
| -------------- | ------------------------ |------------------------------------------| ---- |
| **프로젝트 이름** | 최대 20자  | 영문 대/소문자, 숫자, 하이픈(-), 밑줄(_)만 사용 가능; 동일 이름 중복 불가 | 필수 |
| **설명**      | 최대 200자 | 입력 제한 없음 (모든 문자 허용)                      | 선택 |
| **vCPU**    | 정수 (0 이상)            | -                                        | 필수 |
| **메모리** | 숫자 (0 이상), 단위 선택 | -                                        | 필수 |
| **디스크** | 숫자 (0 이상), 단위 선택 | -                                        | 필수 |
| **외부 IP** | 정수 (1 이상)            | -                                        | 필수 |

## 프로젝트 편집

> ⚠️ **주의:** 편집 시에는 기존 사용량 이상으로만 수정할 수 있습니다.

프로젝트의 이름과 설명, 프로젝트가 사용할 수 있는 리소스의 최대치(할당량)를 지정합니다. **메모리**와 **디스크**는 입력란 오른쪽의 드롭다운에서 단위를 `MB`, `GB`, `TB` 중 선택할 수 있습니다.

> 💡 **참고:** **편집**에서는 기존 값이 미리 채워져 표시됩니다.

- **이름**: 프로젝트 이름을 입력합니다.
- **설명**: 프로젝트에 대한 부가 설명을 입력합니다. (선택)
- **vCPU**: 프로젝트에서 사용 가능한 가상 CPU 코어의 총 개수를 설정합니다.
- **메모리**: 프로젝트에서 사용 가능한 메모리 용량을 설정합니다. (예: GB 단위)
- **디스크**: 프로젝트에서 사용 가능한 스토리지 용량을 설정합니다. (예: GB 단위)
- **외부 IP**: 프로젝트에서 사용할 수 있는 외부 IP 주소의 개수를 설정합니다.

#### 입력 필드 유효성

| 필드           | 허용 값                  | 검증 규칙                                          | 비고 |
| -------------- | ------------------------ |------------------------------------------------| ---- |
| **프로젝트 이름** | 최대 20자  | 영문 대/소문자, 숫자, 하이픈(-), 밑줄(_)만 사용 가능; 동일 이름 중복 불가       | 필수 |
| **설명**      | 최대 200자 | 입력 제한 없음 (모든 문자 허용)                            | 선택 |
| **vCPU**    | 정수 (0 이상)            | *(편집 시)* 현재 사용량 이상으로 입력 가능                     | 필수 |
| **메모리** | 숫자 (0 이상), 단위 선택 | *(편집 시)* 현재 사용량 이상으로 입력 가능                     | 필수 |
| **디스크** | 숫자 (0 이상), 단위 선택 | *(편집 시)* 현재 사용량 이상으로 입력 가능                     | 필수 |
| **외부 IP** | 정수 (1 이상)            | *(편집 시)* 현재 사용량 이상으로 입력 가능                     | 필수 |

> ⚠️ **주의:** **유효성 검사 실패 시**
> - 현재 사용량보다 작은 값을 입력하면 입력 필드가 오류 스타일(빨간색)로 표시됩니다.
> - 필드 하단에 에러 메시지가 노출됩니다.
> - `편집` 버튼이 비활성화됩니다.

> 💡 **참고:** **에러 메시지 예시**
> - vCPU: `4 이상의 정수를 입력하세요.` (현재 사용량이 4인 경우)
> - 메모리: `8 이상의 정수 또는 소수를 입력하세요.` (현재 사용량이 8GB인 경우)
> - 디스크: `111 이상의 정수 또는 소수를 입력하세요.` (현재 사용량이 111GB인 경우)
> - 외부 IP: `1 이상의 정수를 입력하세요.` (현재 사용량이 1개인 경우)

> 💡 **참고(공통 조건):** 편집 모드에서는 각 할당량 값을 **현재 사용 중인 자원보다 적게** 입력할 수 없습니다. 예: 현재 vCPU 사용량이 4개인 경우, vCPU는 최소 4 이상으로만 수정 가능합니다.

## 프로젝트 삭제

프로젝트 삭제는 관리자 **프로젝트 관리** 화면에서 수행합니다. 프로젝트에 특정 자원이 남아 있으면 삭제 확인 모달에서 **삭제 불가능한 프로젝트**로 분류되어 삭제되지 않습니다.

### 삭제 조건

프로젝트에 아래 **차단 자원 9종**이 하나도 남아 있지 않아야 삭제 확인 모달에서 **삭제 가능한 프로젝트**로 분류됩니다.

- **인스턴스**
- **VPC**
- **외부 IP**
- **블록(디스크)**
- **이미지**
- **파일 시스템**
- **오브젝트 스토리지**
- **오토스케일링 그룹**
- **K8s 클러스터**

위 9종 자원 중 하나라도 프로젝트에 남아 있으면 해당 프로젝트는 **삭제 불가능한 프로젝트**로 분류되어 삭제되지 않습니다.

> 💡 **참고:** **시작 템플릿**, **SSH 키** 등 위 9종에 속하지 않는 부속 자원은 삭제 가능 여부에 영향을 주지 않습니다. 프로젝트를 삭제하면 함께 자동으로 정리되므로 미리 삭제할 필요가 없습니다.

### 삭제 전 리소스 정리

프로젝트를 비우려면 위 차단 자원 9종을 먼저 삭제하거나 반납해야 합니다. 리소스 간 의존성을 고려하여 아래 순서로 정리하는 것을 권장합니다. 각 리소스의 정리 방법은 해당 문서를 참고하세요.

| 순서 | 정리 대상 | 정리 방법 |
| ---- | --------- | --------- |
| 1 | **K8s 클러스터** | [클러스터 삭제](../../../project/kubernetes/cluster/cluster.md#클러스터-삭제)를 참고하세요. |
| 2 | **오토스케일링 그룹** | [오토 스케일링 그룹 삭제](../../../project/vm/auto-scaling/auto-scaling.md#오토-스케일링-그룹-삭제)를 참고하세요. |
| 3 | **인스턴스** | 인스턴스에 연결된 스냅샷이 있으면 [스냅샷 삭제](../../../project/vm/instance/instance.md#스냅샷-삭제)로 먼저 삭제한 뒤, [작업 버튼 사용 기준](../../../project/vm/instance/instance.md#작업-버튼-사용-기준)에 따라 인스턴스를 삭제합니다. |
| 4 | **블록(디스크)** | [블록 삭제](../../../project/storage/block/block.md#블록-삭제)를 참고하세요. |
| 5 | **이미지** | [이미지 삭제](../../../project/storage/image/image.md#이미지-삭제)를 참고하세요. |
| 6 | **파일 시스템** | [파일 시스템 삭제](../../../project/storage/file-system/file-system.md#파일-시스템-삭제)를 참고하세요. |
| 7 | **오브젝트 스토리지** | 버킷이 남아 있으면 삭제할 수 없습니다. 버킷을 먼저 비운 뒤 [오브젝트 스토리지 삭제](../../../project/storage/object-storage/object-storage.md#오브젝트-스토리지-삭제)를 참고하세요. |
| 8 | **외부 IP** | 점유 리소스를 해제하면 자동으로 반납됩니다. [외부 IP 반납](../../../project/network/external-ip/external-ip.md#외부-ip-반납)을 참고하세요. |
| 9 | **VPC** | 서브넷·보안 그룹 등 하위 리소스를 먼저 정리한 뒤 [VPC 삭제](../../../project/network/vpc/vpc.md#vpc-삭제)를 진행합니다. |

> 💡 **참고:** **외부 IP**는 목록에 직접적인 삭제 버튼이 없습니다. 외부 IP를 점유한 리소스(플로팅 IP, 로드 밸런서, 포트 포워딩, VPC 등)를 정리하면 자동으로 반납되며, 자세한 정리 방법은 [외부 IP 반납](../../../project/network/external-ip/external-ip.md#외부-ip-반납)을 참고하세요.

> 💡 **참고:** **시작 템플릿**, **SSH 키** 등 차단 자원 9종에 속하지 않는 부속 자원은 이 표에 포함되지 않습니다. 프로젝트 삭제 시 함께 자동으로 정리되므로 별도 사전 삭제가 필요하지 않습니다.

> 💡 **참고:** 정리 대상별 체크리스트는 [FAQ: 프로젝트 삭제가 안 돼요](../../../user-guide/faq/faq.md#faq-project-cleanup)에서도 확인할 수 있습니다.

### 삭제 절차

1. **프로젝트 선택:** 목록 화면에서 삭제하려는 프로젝트들을 체크박스로 선택한 뒤, 상단 도구 모음의 **`삭제`** 버튼을 클릭합니다.
2. **삭제 확인:** 프로젝트 삭제 확인 모달이 나타납니다. 모달은 선택한 프로젝트의 삭제 가능 여부에 따라 다르게 표시됩니다.

   **2-1. 선택한 프로젝트 중 삭제 가능한 항목이 있는 경우:**
   - **모달 제목**: `프로젝트 삭제`
   - **섹션 구분** (해당하는 섹션만 표시되며, 각 제목 옆에 개수가 함께 표시됩니다):
     - `삭제 불가능한 프로젝트`: 차단 자원이 남아 있는 프로젝트가 있을 때만 표시됩니다. 표의 **남은 자원** 열에 프로젝트별로 남아 있는 차단 자원의 **종류와 개수**가 요약되어 표시됩니다. (예: `인스턴스 1 · 이미지 2`) 표 아래에는 `남은 자원을 먼저 삭제해야 프로젝트를 삭제할 수 있습니다.` 안내가 함께 표시됩니다.
     - `삭제 가능한 프로젝트`: 차단 자원이 하나도 없어 바로 삭제할 수 있는 프로젝트 목록입니다.
   - **하단 확인 문구**: `삭제 가능한 N개 프로젝트를 삭제하시겠습니까?` (N은 삭제 가능한 프로젝트 수)
   - **하단 버튼**: `취소`, `삭제`

   **2-2. 선택한 프로젝트가 모두 삭제 불가능한 경우:**
   - **모달 제목**: `프로젝트 삭제`
   - **모달 내용**: `삭제 불가능한 프로젝트` 표(남은 자원의 종류·개수 요약 포함)와 `남은 자원을 먼저 삭제해야 프로젝트를 삭제할 수 있습니다.` 안내만 표시됩니다. `삭제 가능한 프로젝트` 섹션과 확인 문구는 표시되지 않습니다.
   - **하단 버튼**: `취소`, `삭제`(삭제 가능한 프로젝트가 없으므로 `삭제` 버튼 비활성)

3. **삭제 실행:** 확인 모달에서 삭제 대상을 다시 확인한 뒤 **`삭제`** 버튼을 눌러 진행합니다. **삭제 가능한 프로젝트**만 실제로 삭제되며, 완료 시 상단에 알림이 표시되고 목록에서 제거됩니다.

> ⚠️ **주의:** 프로젝트에 **인스턴스, VPC, 외부 IP, 블록(디스크), 이미지, 파일 시스템, 오브젝트 스토리지, 오토스케일링 그룹, K8s 클러스터** 중 하나라도 남아 있으면 해당 프로젝트는 **삭제할 수 없습니다**. 이 경우 해당 프로젝트는 확인 모달의 **삭제 불가능한 프로젝트** 섹션에 남은 자원의 종류·개수와 함께 표시되며 삭제되지 않습니다.

> 💡 **참고:** 한 번에 **여러 프로젝트를 선택하여 일괄 삭제**할 수 있습니다. 단, 앞서 설명한 삭제 조건을 만족하는 **삭제 가능한 프로젝트**들만 실제로 삭제 처리됩니다. 선택한 프로젝트가 모두 삭제 불가능한 경우 `남은 자원을 먼저 삭제해야 프로젝트를 삭제할 수 있습니다.` 메시지가 표시되고 `삭제` 버튼이 비활성화됩니다.


## 멤버 편집

프로젝트에 할당된 멤버와 각 멤버의 역할을 편집하는 기능입니다. 

1. **멤버 편집:** 프로젝트 상세 화면의 **멤버** 탭에서 **`편집`** 버튼을 클릭하여 멤버 편집 화면으로 이동합니다.
2. **멤버 편집 방법:**
     - **멤버**: 드롭다운 (검색 가능)
       - 멤버 목록에서 선택
       - 드롭다운 내부 검색 입력 제공
     - **역할**: 드롭다운 (검색 가능)
       - 역할 목록에서 선택
       - 드롭다운 내부 검색 입력 제공
     - **삭제** 버튼: 해당 행 삭제
   - **멤버 추가 버튼**: 우측 하단에 위치하며, 클릭 시 새로운 행 추가
   - **하단 버튼**: `취소`, `저장` (유효성 통과 전 비활성화 가능)
3. **멤버 역할 추가:** **`멤버 추가`** 버튼을 클릭하여 새로운 행을 추가하고, 멤버와 역할을 선택합니다.
4. **멤버 역할 삭제:** 삭제하려는 행의 **`삭제`** 버튼을 클릭하여 해당 멤버 역할을 제거합니다.
5. **변경사항 저장:** 모든 변경이 완료되면 **`저장`** 버튼을 클릭하여 변경사항을 적용합니다.

> 💡 **참고:** 멤버 추가 버튼은 최대 멤버 수까지만 활성화됩니다. 

## 인스턴스 관리

프로젝트 상세 화면 하단의 **인스턴스** 영역에서는 해당 프로젝트에 속한 인스턴스 목록을 조회하고, 선택한 인스턴스의 전원을 제어합니다. 관리자는 프로젝트 운영 중 특정 인스턴스를 프로젝트 화면으로 이동하지 않고도 상세 화면에서 바로 `실행`, `종료`, `재부팅`할 수 있습니다.

### 테이블 컬럼

| 컬럼          | 설명                                                      |
| ------------- | --------------------------------------------------------- |
| **번호**      | 프로젝트 내 인스턴스 생성 순서를 나타내는 고정 순번입니다(1부터 시작). |
| **이름**      | 인스턴스의 표시 이름입니다.                               |
| **생성 방식** | 인스턴스가 생성된 방식입니다. (`수동 생성`, `오토 스케일링 그룹`, `쿠버네티스`, `파일 시스템`, `Gen:iA` 등) |
| **IP 주소**   | NIC에 할당된 IP 주소입니다. NIC가 여러 개면 함께 표시됩니다. |
| **상태**      | 현재 전원 상태를 배지로 표시합니다. (상태 종류는 아래 표 참고) |
| **vCPU**      | 인스턴스에 할당된 vCPU 코어 수입니다.                     |
| **메모리**    | 인스턴스에 할당된 메모리 용량입니다.                      |
| **생성 일시** | 인스턴스가 생성된 날짜와 시간을 표시합니다.               |

### 검색과 선택

- **검색 조건**: `이름`으로 검색합니다.
- 기본 정렬은 `생성 일시` 기준이며, 페이지당 10개를 표시합니다.
- 목록에서는 **인스턴스 1개만 선택**할 수 있습니다. 선택한 인스턴스를 대상으로 전원 제어 버튼이 활성화됩니다.

### 인스턴스 상태

| 상태          | 의미                                            |
| ------------- | ----------------------------------------------- |
| `실행 중`     | 게스트 OS가 동작 중입니다.                      |
| `정지됨`      | 전원이 꺼진 상태입니다. `실행`할 수 있습니다.   |
| `종료됨`      | 전원이 꺼진 상태입니다. `실행`할 수 있습니다.   |
| `일시 중지`   | 실행 상태가 일시 중지되었습니다.                |
| `부팅 중`     | 전원이 인가되고 게스트 OS가 올라오는 중입니다.  |
| `재부팅 중`   | 재부팅 작업이 진행 중입니다.                    |
| `종료 중`     | 종료 작업이 진행 중입니다.                      |
| `생성 중`     | 인스턴스 생성 작업이 진행 중입니다.             |
| `업데이트 중` | 라이브 업데이트 작업이 진행 중입니다.           |
| `삭제 중`     | 삭제 작업이 진행 중입니다.                      |
| `마이그레이션 중` | 호스트 간 이동 작업이 진행 중입니다.        |
| `에러`        | 오류가 발생한 상태입니다. 상태 배지에 마우스를 올리면 원인 안내가 표시됩니다. |

> 💡 **참고:** `종료됨`과 `정지됨`은 모두 전원이 꺼진 상태이지만 내부 상태 정의가 다릅니다. 사용자 관점에서는 두 상태 모두 `실행`할 수 있습니다.

### 전원 제어 버튼

인스턴스 영역 상단에는 `실행`, `종료`, `재부팅` 버튼이 있습니다. 버튼 활성화 조건은 다음과 같습니다.

| 버튼       | 활성화 조건                                                                 |
| ---------- | -------------------------------------------------------------------------- |
| **`실행`**   | 인스턴스 1개를 선택하고, 상태가 `종료됨` 또는 `정지됨`이어야 합니다.          |
| **`종료`**   | 인스턴스 1개를 선택하고, `수동 생성`이며 상태가 `실행 중`, `일시 중지`, `정지됨`, `에러` 중 하나여야 합니다. `종료됨`에서는 비활성화됩니다. `에러` 상태에서 `실행`이 막히므로, 종료는 사용자가 재시도를 시작할 수 있는 경로로 열어 둡니다. |
| **`재부팅`** | 인스턴스 1개를 선택하고, `수동 생성`이며 상태가 `실행 중`이어야 합니다. 단, 보안 유형이 `SEV_ES` 또는 `SEV_SNP`인 인스턴스는 재부팅 불가 제약이 있어 비활성화됩니다. |

> ⚠️ **주의:** `오토 스케일링 그룹`, `쿠버네티스`, `파일 시스템`, `Gen:iA` 등 상위 서비스로 생성된 인스턴스는 `실행`은 가능하지만 `종료`와 `재부팅`은 비활성화됩니다. 이러한 인스턴스는 원래 생성한 서비스 화면에서 관리합니다.

### 전원 제어 실행

1. 인스턴스 목록에서 대상 인스턴스 **1개를 선택**합니다.
2. 활성화된 **`실행`**, **`종료`**, **`재부팅`** 버튼 중 하나를 클릭합니다.
3. 확인 모달에서 대상 인스턴스의 정보(이름, ID, IP 주소, vCPU, 메모리, 생성 일시)를 확인한 뒤, 하단 버튼을 눌러 작업을 실행합니다.

확인 모달은 작업별로 다음과 같이 표시됩니다.

| 작업       | 모달 제목       | 확인 문구                    | 실행 버튼   |
| ---------- | --------------- | --------------------------- | ----------- |
| **실행**   | `인스턴스 실행`   | `인스턴스 실행하시겠습니까?`   | `실행`      |
| **종료**   | `인스턴스 종료`   | `인스턴스 종료하시겠습니까?`   | `종료`      |
| **재부팅** | `인스턴스 재부팅` | `인스턴스 재부팅하시겠습니까?` | `재부팅`    |

> 💡 **참고:** 전원 제어 작업은 요청 직후 목록의 상태가 진행 중 상태(`부팅 중`, `종료 중`, `재부팅 중` 등)로 바뀌며, 작업이 완료되면 최종 상태로 갱신됩니다.

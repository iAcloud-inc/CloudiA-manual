# 백업 서버

`백업 서버`는 CloudiA가 백업·복구 작업을 맡길 Veeam Backup & Replication(이하 VBR) 서버를 등록하고 관리하는 화면입니다. 백업 자체를 만드는 것은 VBR이고, CloudiA는 접속 정보와 대상 지정을 담당합니다.

백업 서버는 **전 프로젝트가 공유하는 자원**입니다. 프로젝트를 바꿔도 같은 목록이 보입니다.

## 화면 개요
- `목록 화면`: 등록된 백업 서버를 조회하고 등록, 연결 테스트, 등록 해제를 시작합니다.
- `등록 화면`: 주소와 계정을 입력해 새 백업 서버를 등록합니다.
- `상세 화면`: 기본 정보를 확인하고 백업 디스크를 이미지로 반입합니다. ([백업 디스크 이미지 반입](#백업-디스크-이미지-반입))

## 사전 준비
백업 서버를 등록하려면 다음 조건이 갖춰져 있어야 합니다.

- VBR의 **REST API가 켜져 있고** CloudiA 관리 노드에서 그 포트(기본 `9419`)로 도달할 수 있어야 합니다.
- 입력할 주소가 **그 VBR 인증서가 대표하는 이름 중 하나여야** 합니다. CloudiA는 등록 시점에 인증서를 확인하므로, 목록에 없는 주소는 서버에 도달하더라도 등록되지 않습니다. 확인 방법은 [등록할 주소 확인하기](#등록할-주소-확인하기)를 참고합니다.
- VBR에 **백업 repository가 정확히 1개** 있어야 합니다. 여럿이면 어느 것을 쓸지 정할 수 없어 등록이 거절됩니다.
- 등록에 쓸 VBR 계정은 REST API를 쓸 수 있는 역할(Backup Administrator 등)을 가져야 합니다.

> ⚠️ 주의: 계정 이름은 영문, 숫자, `-`, `_` 만 입력할 수 있습니다. `DOMAIN\user` 형태의 도메인 계정은 이 화면으로 등록할 수 없습니다.

### 등록할 주소 확인하기
TLS 인증서에는 그 인증서가 대표하는 이름 목록이 `SAN`(Subject Alternative Name) 항목에 들어 있습니다. 접속에 쓴 주소가 그 목록에 없으면 인증서 검증이 실패합니다. 브라우저가 "이 사이트의 보안 인증서에 문제가 있습니다"를 표시하는 것과 같은 원리입니다.

등록하기 전에 아래 명령으로 목록을 확인합니다. **WSL 또는 macOS 터미널에서 실행합니다.** Windows PowerShell에서는 `/dev/null`을 파일 경로로 해석해 실패합니다.

```
echo | openssl s_client -connect <VBR주소>:9419 2>/dev/null | openssl x509 -noout -subject -ext subjectAltName
```

출력 예시입니다.

```
subject=CN=DESKTOP-KLR0C3G
X509v3 Subject Alternative Name:
    IP Address:192.168.210.123, DNS:DESKTOP-KLR0C3G
```

이 서버는 `192.168.210.123` 또는 `DESKTOP-KLR0C3G` 중 하나로만 등록할 수 있습니다. 다른 주소로 접속이 되더라도 등록은 거부됩니다.

| 상황 | 조치 |
| --- | --- |
| 쓰려는 주소가 목록에 있음 | 그대로 입력합니다. |
| 목록의 **이름**(DNS)을 쓰고 싶음 | CloudiA 백엔드가 그 이름을 해석할 수 있어야 합니다. 노드의 `/etc/hosts` 또는 DNS에 등록합니다. |
| 쓰려는 주소가 목록에 없음 | 그 주소를 포함하도록 VBR 인증서를 재발급합니다. |

## 백업 서버 목록
### 주요 작업
- **`등록`**: 새 백업 서버를 등록합니다.
- **`연결 테스트`**: 선택한 1개 백업 서버에 실제로 접속해 봅니다. 도달 여부와 계정 유효성을 함께 확인합니다.
- **`등록 해제`**: 선택한 1개 백업 서버를 목록에서 내립니다.
  > 💡 참고: 그 서버로 백업이 켜진 가상머신이 있으면 해제할 수 없습니다.

### 테이블 컬럼
| 컬럼 | 설명 |
| --- | --- |
| **이름** | 백업 서버 이름입니다. 클릭하면 상세 화면으로 이동합니다. |
| **주소** | `호스트:포트` 형태입니다. IPv6 주소는 `[주소]:포트`로 표시됩니다. |
| **연결 상태** | `확인 안 함`, `확인 중`, `연결됨`, `연결 끊김` 중 하나입니다. |
| **인증서 지문** | 등록 시점에 취득한 인증서 지문(SHA-256)입니다. 목록에서는 앞뒤 일부만 보이고, 전체 값은 상세 화면에 있습니다. |
| **생성 일시** | 백업 서버를 등록한 시각입니다. |

### 연결 상태 읽는 법
연결 상태는 목록을 열 때 자동으로 확인하지 않습니다. `연결 테스트`를 눌러야 확인하며, **그 결과는 화면을 떠나면 사라집니다.** 새로고침하면 다시 `확인 안 함`으로 돌아옵니다. 다른 관리자에게도 보이지 않습니다.

| 상태 | 의미 |
| --- | --- |
| **확인 안 함** | 아직 확인하지 않았습니다. 서버가 비정상이라는 뜻이 아닙니다. |
| **확인 중** | 확인이 진행 중입니다. 끝날 때까지 `연결 테스트`를 다시 누를 수 없습니다. |
| **연결됨** | 주소에 도달했고 계정으로 인증에도 성공했습니다. |
| **연결 끊김** | 도달하지 못했거나 계정이 유효하지 않습니다. 실패 사유는 토스트 메시지로 표시됩니다. |

## 백업 서버 등록
`등록`을 누르면 등록 화면으로 이동합니다. 입력한 값은 저장 전에 실제로 검증됩니다. CloudiA는 주소와 계정으로 VBR에 접속해 **인증서 지문을 고정**하고 **백업 repository를 확정**한 다음에야 등록을 마칩니다. 그래서 등록이 성공했다는 것은 그 서버로 백업 작업을 만들 수 있다는 뜻입니다.

### 입력 항목
- **이름**(필수)
- **설명**(선택)
- **주소**(필수): VBR 인증서가 대표하는 이름 중 하나여야 합니다. ([등록할 주소 확인하기](#등록할-주소-확인하기))
- **포트**(필수): VBR REST API 포트. 기본값 `9419`가 채워져 있습니다.
- **사용자명**(필수)
- **비밀번호**(필수)

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
| --- | --- | --- | --- |
| **이름** | 영문, 숫자, `-`, `_` 조합의 문자열 | 필수입니다. 100자 이내로 입력합니다. | 이미 등록된 이름은 쓸 수 없습니다. |
| **설명** | 자유 문자열 | 200자 이내로 입력합니다. | |
| **주소** | 호스트명, IPv4, IPv6 주소 | 필수입니다. 포트는 함께 쓰지 않고 아래 칸에 따로 입력합니다. | 인증서가 대표하는 이름이어야 합니다. |
| **포트** | 1 ~ 65535 | 필수입니다. | VBR REST API 포트입니다. |
| **사용자명** | 영문, 숫자, `-`, `_` 조합의 문자열 | 필수입니다. 100자 이내로 입력합니다. | VBR 계정입니다. |
| **비밀번호** | 자유 문자열 | 필수입니다. | 암호화해 보관하며 화면에 다시 표시하지 않습니다. |

### 등록이 거절되는 경우
| 안내 문구 | 원인 | 조치 |
| --- | --- | --- |
| 이미 등록된 백업 서버입니다. 이름과 주소를 확인하세요. | 같은 이름 또는 같은 `주소:포트`가 이미 등록돼 있습니다. | 이름을 바꾸거나, 기존 등록을 먼저 해제합니다. |
| 인증서를 가져올 수 없습니다. | 서버에 도달할 수 없거나(방화벽·전원), 입력한 주소가 인증서에 등록된 이름과 다르거나, TLS 설정에 문제가 있습니다. | [등록할 주소 확인하기](#등록할-주소-확인하기)로 목록을 확인해 그중 하나로 입력하거나, 인증서를 재발급합니다. |
| 대상 백업 서버를 찾을 수 없습니다. | 처리 중 대상이 사라졌습니다. | 목록을 새로 고칩니다. |

> 💡 참고: 주소는 표기를 정규화한 뒤 비교합니다. 대소문자만 다른 호스트명, 대괄호 유무만 다른 IPv6 주소는 같은 주소로 봅니다.

## 백업 서버 등록 해제
`등록 해제`는 **삭제가 아닙니다.** 해제한 서버는 목록에서 사라지고 새 백업·복구 작업을 받지 않지만, 그 서버로 만든 발행·백업 기록은 그대로 남습니다. 남아 있는 마운트는 시스템이 회수합니다.

- 그 서버로 **백업이 켜진 가상머신**이 있으면 해제할 수 없습니다. 해당 인스턴스의 백업을 먼저 꺼야 합니다.
- 백업을 껐던 기록이 남아 있어도 해제되지 않습니다. 그 기록까지 정리된 뒤에 해제할 수 있습니다.
- 진행 중이거나 끝난 **디스크 발행 기록은 해제를 막지 않습니다.**
- 해제한 것과 같은 `주소:포트`로 다시 등록할 수 있습니다.

## 백업 서버 상세
목록에서 이름을 클릭하면 상세 화면으로 이동합니다. 상단에 `상세 정보`와 `진행 중인 작업`이 있고, 그 아래에 `이미지 반입`과 `발행 목록` 두 탭이 있습니다.

- `상세 정보`: 이름, ID, 주소, 사용자명, 인증서 지문(전체 값), 설명, 생성 일시
- `진행 중인 작업`: 진행 중인 반입이 있으면 `<디스크> · 이미지로 반입` 줄로 표시됩니다. 없으면 `진행 중인 작업이 없습니다.`가 표시됩니다.

> 💡 참고: 상세 화면에는 백업 서버 선택기가 없습니다. 어느 서버의 화면인지는 주소(URL)가 정합니다. 다른 서버를 보려면 목록으로 돌아가 그 서버를 선택합니다.

## 백업 디스크 이미지 반입
백업된 디스크를 CloudiA의 공용 이미지로 가져오는 기능입니다. 다른 가상화 환경에서 백업한 머신을 CloudiA 인스턴스로 옮길 때 씁니다. 반입된 이미지는 `공용 이미지 관리`에 등록되어 인스턴스 생성에 쓸 수 있습니다.

### 반입 대상 고르기
`이미지 반입` 탭에서 **백업 대상 → 복원 지점 → 디스크** 세 단계를 위에서 아래로 고릅니다.

1. `백업 대상`을 선택하면 그 대상의 `복원 지점`이 최신순으로 채워집니다.
2. `복원 지점`을 선택하면 그 시점의 `디스크` 목록이 채워집니다.
3. `디스크`를 선택하면 `이미지로 반입` 버튼이 활성화됩니다.

위 단계의 선택을 바꾸면 아래 단계의 선택은 취소됩니다. 다른 복원 지점의 디스크를 그대로 들고 요청하는 일을 막기 위해서입니다.

> ⚠️ 주의: 한 복원 지점이 디스크를 둘 이상 내놓을 수 있습니다. LVM으로 구성된 머신에서는 base 디스크와 조각이 함께 나오며, **용량이 큰 쪽이 base 디스크**입니다. 조각만 반입하면 부팅할 수 없는 이미지가 만들어집니다. 디스크가 둘 이상이면 목록 위에 경고가 표시됩니다.

### 반입 실행
`이미지로 반입`을 누르면 반입 창이 열립니다.

| 입력 항목 | 설명 |
| --- | --- |
| **디스크** | 앞에서 고른 디스크가 채워져 있으며 수정할 수 없습니다. |
| **스토리지 도메인**(필수) | 반입된 이미지를 저장할 도메인입니다. 디스크 용량 이상의 여유가 있어야 합니다. |
| **이미지 이름**(선택) | 비워 두면 이름을 자동으로 정합니다. 영숫자로 시작하고 영숫자·마침표·밑줄·하이픈만 쓸 수 있으며 최대 128자입니다. |

확인하면 디스크 발행이 시작되고, 발행이 끝나면 변환이 이어서 접수됩니다. **변환은 디스크 크기에 따라 수십 분이 걸립니다.** 창을 닫거나 다른 화면으로 가도 진행은 계속되며 `진행 중인 작업`에서 확인할 수 있습니다.

### 진행 상태 읽기
`진행 중인 작업`의 줄을 클릭하면 단계, ID, 시작 시각, 업데이트, 요청자를 볼 수 있습니다. 단계는 다음 순서로 진행됩니다.

`반입 접수` → `대상 접속` → `디스크 탐색` → `이미지 변환` → `변환 결과 확인` → `이미지 등록` → `접속 정리` → `반입 완료`

실패하면 단계가 `반입 실패`로 바뀌고 **괄호 안에 오류코드가 함께** 표시됩니다. 실패 원인에 따라 조치가 다르기 때문입니다.

| 오류코드 | 원인 | 조치 |
| --- | --- | --- |
| `CLERR-402039` | 발행된 디스크를 조립할 수 없습니다. 파티션 테이블을 가진 디스크가 하나여야 하는데 그렇지 않습니다. **조각 디스크만 고른 경우가 여기에 해당합니다.** | 같은 복원 지점의 base 디스크를 고릅니다. base 를 골랐는데도 나오면 일시적일 수 있으니 발행 목록에서 다시 시도합니다. |
| `CLERR-402040` | 조립은 됐지만 만들어진 이미지에서 운영체제를 찾지 못했습니다. **운영체제가 없는 데이터 디스크를 고른 경우가 여기에 해당합니다.** | 그 머신의 부팅 디스크를 고릅니다. |
| `CLERR-402032` | 백업 서버가 디스크 발행에 실패했습니다. | 백업 서버 상태를 확인한 뒤 다시 시도합니다. |
| `CLERR-402033` | 변환 호스트에서 백업 서버의 iSCSI 포털에 도달하지 못했습니다. | 두 호스트 사이의 네트워크 도달성을 확인합니다. |

## 발행 목록
반입을 시작하면 그 디스크의 `발행` 기록이 생깁니다. 발행은 서버에 남는 기록이라 반입 창을 닫거나 화면을 새로고침해도 사라지지 않습니다. **재시도는 이 목록에서 합니다.**

### 테이블 컬럼
| 컬럼 | 설명 |
| --- | --- |
| **ID** | 발행 고유 ID입니다. 같은 디스크로 발행이 둘 이상 설 수 있어 행을 구분하는 기준입니다. |
| **상태** | `발행 중`, `발행됨`, `해제 중`, `해제됨`, `발행 실패` 중 하나입니다. |
| **변환** | 변환이 돌지 않았으면 `-`, 진행 중이면 파란색 `변환 중`, 끝났으면 초록색 `반입 완료`, 실패면 빨간색 `반입 실패`입니다. |
| **디스크** | 발행한 디스크 이름입니다. 백업 서버가 준 이름을 그대로 보여 줍니다. |
| **복원 지점** | 그 디스크가 속한 복원 지점입니다. |
| **산출 이미지** | 반입에 성공했으면 `이미지 <ID>`로 표시되고, 클릭하면 공용 이미지 관리로 이동합니다. |
| **생성 일시** | 발행을 시작한 시각입니다. |

### 동작 조건
`이미지로 반입`과 `발행 해제`는 발행 상태에 따라 활성화됩니다.

- **`이미지로 반입`**: 상태가 `발행됨`이고, 아직 이미지를 만들지 않았으며, 변환이 돌고 있지 않을 때만 누를 수 있습니다.
- **`발행 해제`**: 상태가 `발행됨`이고 변환이 돌고 있지 않을 때만 누를 수 있습니다.

## 발행 해제
`발행 해제`는 그 디스크의 iSCSI 접속을 끊는 작업입니다. 삭제가 아닙니다.

- 해제하면 그 디스크를 더 이상 이미지로 반입할 수 없습니다.
- **이미 반입된 이미지는 해제 후에도 그대로 남습니다.** 발행 기록과 `산출 이미지` 값도 남습니다.
- 변환이 진행 중이면 해제할 수 없습니다. 변환이 끝난 뒤 다시 시도합니다.

## 참고 사항
- 백업 서버는 전 프로젝트가 공유하므로, 등록·해제는 전체 사용자의 백업 기능에 영향을 줍니다.
- 백업 잡의 스케줄·보존 정책과 repository 관리는 CloudiA가 아니라 VBR 관리자 콘솔에서 합니다.
- 인스턴스 단위로 백업을 켜고 끄는 방법은 프로젝트 사용자 매뉴얼의 인스턴스 문서를 참고합니다.

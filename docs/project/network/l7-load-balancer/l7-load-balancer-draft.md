# 어플리케이션 로드 밸런서 매뉴얼 작성 초안

## 작성 시 반영할 Cloudia UI 특이사항
- 단어/항목명은 `cloudia-web` UI(`/Users/woody/Documents/cloudiaDev/cloudia-web`)의 라벨 이름을 기준으로 표기
- LB 기능 설명은 `cloudia` 하위 기술 문서(`/Users/woody/Documents/cloudiaDev/cloudiA/src/main/java/kr/iacloud/cloudia/network/techspec`)를 참조하고, 참조 대상 문서는 `l7lb_index.md` 기준으로 확인
- 생성 화면에서 리스너를 1개 이상 추가해야 생성 가능
- 기본 작업 라벨은 반드시 UI 명칭(`타겟 그룹으로 전달`, `URL로 리디렉션`, `고정 응답 반환`)으로 표기
- 규칙 절차는 반드시 상세 화면 `규칙 정보` 흐름 기준으로 작성
- 보안 정책은 NACL이 아닌 타겟 보안그룹 기준으로 작성하고, `클라이언트 -> 타겟` 최소 허용 정책을 기본 예시로 제시
- 절차를 서술할 때, 반드시 UI 기준으로, 단계별로 작성하고 특정 버튼이나 눌러야 다음 단계로 진행되는 경우 빠짐없이 작성.

## 1) 문서 목표
- Cloudia를 처음 사용하는 운영자도 `cloudia-web`에서 `레이어: 어플리케이션` 로드 밸런서를 생성할 수 있도록 안내합니다.
- 결과적으로 사용자가 `리스너 + 기본 작업 + 규칙`까지 포함해 서비스 진입점을 만들 수 있어야 합니다.

## 2) 독자와 완료 기준
- 독자: Cloudia/로드 밸런서 경험이 많지 않은 프로젝트 운영자
- 완료 기준:
  - `레이어: 어플리케이션` 로드 밸런서 1개 생성
  - 리스너 1개 이상 생성(최대 10개)
  - 리스너 `기본 작업` 설정 완료
  - `규칙 정보`에서 규칙 1개 이상 추가/저장 완료
  - `프로토콜: HTTPS` 리스너 사용 시 `HTTPS 인증서` 등록 완료

## 3) 문서 범위
- 포함:
  - 생성 화면 기준 작성
  - 어플리케이션 리스너 추가/수정/삭제
  - 기본 작업 설정(타겟 그룹으로 전달, URL로 리디렉션, 고정 응답 반환)
  - HTTPS 인증서 등록
  - 상세 화면 `규칙 정보` 기준 규칙 추가/수정/삭제/우선 순위 조정
  - 생성 후 운영(설정 변경/모니터링/삭제)
- 제외:
  - API 직접 호출

## 4) 사전 전제 조건(필수)
### 4.1 네트워크/리소스
- `VPC`, `서브넷` 준비
- 어플리케이션 타겟 그룹 선생성(동일 VPC)
- `타입: 외부` 사용 시 외부 IP 준비
- `타입: 외부` 로드 밸런서는 생성 대상 서브넷이 `프라이빗` 서브넷이어도 외부 IP를 통해 외부에서 진입 가능
- HTTPS 리스너 사용 시 SAN 포함 인증서 도메인과 UI 업로드 가능한 PEM bundle 파일 준비(`key + cert`)
- HTTPS 도메인 검증이 필요한 경우 클라이언트 DNS 또는 `/etc/hosts`에서 인증서 도메인이 LB 외부 IP로 해석되도록 준비

### 4.2 네트워크 보안 정책(필수)
Cloudia L4/L7 로드 밸런서는 로드밸런서와 타겟이 서로 다른 서브넷에 있어도 NACL을 적용받지 않는 구조입니다. 따라서 로드 밸런서 사용을 위한 사전 점검에서 NACL은 검토 대상이 아니며, 타겟 서버에 연결된 보안그룹에서 `클라이언트 -> 타겟` 트래픽을 허용하는 정책을 수립합니다.

아래 예시는 타겟 서버 기준으로 필요한 최소 보안그룹 허용 정책입니다.

예시 조건:
- 서비스 클라이언트 CIDR: `10.20.0.0/16`
- 서비스 포트: `8080`
- 상태 검사 포트: `8080` (별도 사용 시 `18080` 예시)

#### 보안그룹 최소 허용 예시(타겟 서버에 연결된 보안그룹)
| 방향 | 프로토콜 | 포트 | 소스 | 설명 |
| --- | --- | --- | --- | --- |
| 인바운드 | TCP | 8080 | 10.20.0.0/16 | 클라이언트의 어플리케이션 트래픽 허용 |
| 인바운드 | TCP | 18080 | 10.20.0.0/16 | 상태 검사 포트를 분리한 경우만 추가 |

- 보안그룹은 상태 저장 방식이므로, 위 인바운드 허용 트래픽의 응답은 자동 허용됩니다.
- 소스 CIDR은 실제 서비스 클라이언트 또는 운영상 허용한 접근 구간으로 대체합니다.
- 운영 정책상 아웃바운드를 제한 중이라면, 애플리케이션이 실제로 필요로 하는 목적지 포트만 별도로 허용합니다.

## 7) 생성 절차 섹션 상세 설계(작성 가이드)
### 7.1 기본 정보
- 이름, 설명 입력 규칙
- 이름 작성 예시(서비스/환경/역할 포함)

### 7.2 네트워크 정보
- `VPC`, `서브넷` 선택
- `타입` 선택: `외부` 또는 `내부`
- `내부 IP 주소` 자동/수동 할당
- `타입: 외부`일 때 `외부 IP 주소` 자동/수동 할당
- `타입: 외부`는 선택한 서브넷의 `퍼블릭`/`프라이빗` 여부와 관계없이 외부 IP를 통해 외부 진입점으로 동작
- 제약:
  - 리스너가 이미 추가되면 VPC 변경 불가

### 7.3 리스너 구성
- 리스너 개수 제한: 최소 1, 최대 10
- 리스너 기본 정보:
  - `프로토콜`: `HTTP` 또는 `HTTPS`
  - `포트 번호`: `1-65535`, 같은 로드 밸런서 내 중복 불가
  - `설명`

### 7.4 기본 작업 설정
- `타겟 그룹으로 전달`
  - 타겟 그룹 최대 5개 선택
  - 각 타겟 그룹 `가중치` 입력(1~100)
  - 타겟 그룹 후보는 LB 연결 관계에 따라 노출
  - 이미 같은 LB에 연결된 타겟 그룹은 같은 LB의 다른 리스너/규칙에서 재사용 가능
  - 이미 다른 LB에 연결된 타겟 그룹은 현재 LB의 Forward 후보에서 제외
  - `세션 고정성` 설정(활성화 시 `쿠키 유효 시간` 입력)
  - 리스너 작업의 `세션 고정성`은 여러 타겟 그룹 중 선택된 타겟 그룹을 브라우저 세션별로 고정하는 기능
  - 쿠키 삭제 또는 만료 후에는 타겟 그룹이 다시 선택될 수 있음
- `URL로 리디렉션`
  - `프로토콜`(HTTP/HTTPS), `상태 코드`(301/302)
- `고정 응답 반환`
  - `상태 코드`(2xx/4xx/5xx), `Content-Type`, `메시지 본문`(최대 1024자)

### 7.5 HTTPS 인증서
- 리스너 `프로토콜: HTTPS` 선택 시 `HTTPS 인증서` 단계 노출
- `기본 인증서 파일` 1개 필수(`.pem`, `key + cert` bundle)
- `SNI 인증서 파일` 최대 25개 + `호스트 이름` 필요
- SNI 검증 시 인증서의 SAN DNS와 `호스트 이름`이 일치해야 하며, 클라이언트에서 해당 도메인이 LB 외부 IP로 해석되어야 함

### 7.6 생성 버튼 활성 조건
- 필수 입력 완료
- 리스너 1개 이상 구성
- IP 할당 방식 검증 통과

## 8) 리스너 규칙 설정 절차(같은 문서에 통합)
### 8.1 규칙 화면 진입
- 로드 밸런서 생성 후 상세 화면으로 이동
- `리스너 정보` 목록에서 대상 리스너 행의 `규칙 정보 > 보기` 클릭

### 8.2 규칙 정보 화면에서 가능한 작업
- `추가`: 새 규칙 생성
- `편집`: 선택한 규칙 수정
- `삭제`: 선택한 규칙 삭제
- `기본 작업` 행 선택 후 `편집`: 기본 작업 수정

### 8.3 규칙 추가/편집(스텝 모달)
1. `조건`
- `조건 유형`: `호스트 헤더` 또는 `경로`
- 한 규칙에서 `호스트 헤더`와 `경로`는 각각 1개씩만 사용
- 같은 조건 안에서는 값을 여러 개 넣을 수 있으며, 값은 `또는(OR)`로 처리
- 서로 다른 조건 간에는 `그리고(AND)`로 처리

2. `작업`
- 규칙 작업도 리스너 기본 작업과 동일한 UI 사용
- `타겟 그룹으로 전달` / `URL로 리디렉션` / `고정 응답 반환` 중 선택

3. `우선 순위`
- 드래그 앤 드롭으로 규칙 우선 순위 조정
- `기본 작업`은 별도 행(`*`)으로 표시되며, 어떤 규칙에도 매칭되지 않을 때 적용

### 8.4 규칙 작성 예시(문서 본문에 포함 권장)
- HTTP 리스너 기본 작업: `URL로 리디렉션(HTTPS, 301)`
- HTTPS 리스너 호스트 기반 분기: `호스트 헤더 = test.iacloud.kr` -> `타겟 그룹으로 전달(demo-tg-1)`
- HTTPS 리스너 경로 기반 분기: `경로 = /api/` -> `타겟 그룹으로 전달(demo-tg-2)`
- HTTPS 리스너 규칙 미일치 트래픽: `기본 작업` -> `고정 응답 반환(403)`

## 9) 생성 후 운영 섹션 초안
### 9.1 목록/상세 조회
- 목록 화면에서 `생성`, `편집`, `삭제` 버튼 노출
- 목록 검색/정렬:
  - 검색 필드 예시: `이름`
  - 정렬 컬럼 예시: `이름`, `ID`, `계층`, `생성 방식`, `VPC`, `서브넷`, `외부 IP 주소`, `설명`, `생성 일시`
- 버튼 활성화 규칙:
  - 항목 미선택 시 `편집`, `삭제` 비활성화
  - 수동 생성 항목 1개 선택 시 `편집`, `삭제` 활성화
  - 시스템 생성 항목은 `편집`, `삭제` 비활성화
- 상세 화면에서 확인할 정보:
  - `상세 정보`의 기본 속성(`계층`, `타입`, `VPC`, `서브넷`, `내부 IP 주소`, `외부 IP 주소`, `생성 방식`, `설명`)
  - `리스너 정보`의 `ID`, `프로토콜`, `포트 번호`, `규칙`, `HTTPS 인증서`, `설명`, `생성 일시`
  - `HTTPS 인증서` 셀의 인증서 목록 팝오버와 기본 인증서 식별
  - `규칙 정보 > 보기`를 통한 규칙 목록과 `기본 작업`(`*`) 행 확인
  - 상세 상단 `재배포` 버튼 노출

### 9.2 설정 변경
- 기본 정보 변경(이름/설명/타입/IP 할당)
- `내부 IP 주소`는 같은 VPC/서브넷에서 사용 가능한 IP 후보 중 선택
- `타입: 외부`의 `외부 IP 주소`는 할당 가능한 외부 IP 후보 중 선택
- 이름/설명/IP 변경 후에도 기존 리스너/규칙/타겟 그룹 구성은 유지됨
- 리스너 추가/수정/삭제
- 규칙 조회/추가/수정/삭제

### 9.3 재배포
- 상세 화면의 `재배포` 버튼으로 L7 로드 밸런서 설정과 런타임을 다시 반영
- 재배포 전 현재 `관리 상태`와 `런타임 상태`를 확인
- 정상 재배포 후 `관리 상태=READY`, `런타임 상태=RUNNING` 복귀 여부 확인
- `런타임 상태=RUNTIME_FAILED`인 경우 수동 재배포로 복구를 시도할 수 있음
- 재배포 진행 중에는 처리 중 표시와 상태 전이를 확인하고, 완료 전 중복 변경을 피함

### 9.4 모니터링
- 로드 밸런서 상태와 리스너/타겟 동작 지표 확인 절차
- 로드 밸런서 상태는 `관리 상태`와 `런타임 상태`를 구분해 설명
- `관리 상태`는 로드 밸런서 설정을 생성/수정/삭제/페일오버 반영하는 오케스트레이션 상태이며, 일반 수정 가능 여부를 판단하는 기준
- `런타임 상태`는 실제 로드밸런서 런타임 상태 확인 결과를 나타내는 상태이며, 장애 감지/자동 복구/재배포 판단 기준

#### 관리 상태
| UI 표시명 | 상세 설명 |
| --- | --- |
| READY | 적용 작업이 없고 설정이 정상 반영된 상태입니다. 일반 수정 작업을 진행할 수 있습니다. |
| APPLYING_CREATE | 로드 밸런서 생성 작업을 적용하는 중입니다. 작업 완료 전까지 추가 변경이 제한될 수 있습니다. |
| APPLYING_UPDATE | 로드 밸런서 설정 변경을 적용하는 중입니다. 리스너, 규칙, 인증서, 타겟 그룹 변경 반영이 포함될 수 있습니다. |
| APPLYING_DELETE | 로드 밸런서 삭제 작업을 적용하는 중입니다. 삭제 완료 전까지 조작이 제한됩니다. |
| FAILOVER_APPLYING | 페일오버 또는 동기화 작업으로 로드 밸런서 설정을 다시 반영하는 중입니다. |
| APPLY_FAILED | 설정 적용 또는 롤백에 실패한 상태입니다. 일반 수정은 제한되며 삭제 또는 재배포 절차를 검토합니다. |

#### 런타임 상태
| UI 표시명 | 상세 설명 |
| --- | --- |
| RUNNING | 로드밸런서 런타임 응답이 정상인 상태입니다. |
| RECOVERING | 런타임 응답 실패가 감지되어 자동 복구를 시도하거나 대기 중인 상태입니다. |
| RUNTIME_FAILED | 자동 복구 한계에 도달했거나 런타임 복구 실패가 확정된 상태입니다. 재배포 절차를 검토합니다. |
| UNKNOWN | 초기 상태이거나 아직 probe가 수행되지 않아 런타임 상태를 판단할 수 없는 상태입니다. |

- `규칙 정보` 변경 전후 트래픽 분기 결과 확인 방법

### 9.5 삭제
- 삭제 전 점검:
  - 연결 서비스 영향 범위
  - Public IP 유지/반납 정책
  - 대체 진입점 준비 여부
- 수동 생성 로드 밸런서는 목록에서 단일 선택 후 삭제 가능
- 시스템 생성 로드 밸런서는 삭제 버튼이 비활성화될 수 있음
- 삭제 확인 모달에서 `이름`, `ID`, `VPC`, `서브넷`, `외부 IP 주소`, `설명` 확인

## 10) 오류 대응 섹션 초안
- `리스너 미등록`으로 생성 버튼 비활성화
- 동일 포트/프로토콜 조합 중복 오류
- `타겟 그룹으로 전달` 대상 타겟 그룹 후보 비노출
- 인증서 미첨부/호스트 이름 형식 오류
- 규칙 저장 시 조건 누락 또는 우선 순위 충돌
- 타겟 `런타임 상태`가 비정상일 때:
  - 보안그룹 인바운드의 소스/CIDR/포트 재확인

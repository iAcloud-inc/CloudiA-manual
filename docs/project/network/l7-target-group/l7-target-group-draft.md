## 4) 사전 전제 조건(필수)
### 4.1 네트워크/리소스
- 프로젝트 내 `VPC` 준비
- 타겟으로 사용할 인스턴스 또는 내부 IP 준비
- 타겟이 위치한 서브넷 타입은 `퍼블릭`/`프라이빗` 여부와 관계없이 사용 가능하며, 로드 밸런서를 통해 타겟 서비스로 진입 가능
- 서비스 포트/상태 검사 경로 확정

### 4.2 네트워크 보안 정책(필수)
Cloudia L4/L7 로드 밸런서는 로드밸런서와 타겟이 서로 다른 서브넷에 있어도 NACL을 적용받지 않는 구조입니다. 따라서 타겟 그룹 사용을 위한 사전 점검에서 NACL은 검토 대상이 아니며, 타겟 서버에 연결된 보안그룹에서 `클라이언트 -> 타겟` 트래픽을 허용하는 정책을 수립합니다.

아래 예시는 타겟 서버 기준으로 필요한 최소 보안그룹 허용 정책입니다.

예시 조건:
- 서비스 클라이언트 CIDR: `10.20.0.0/16`
- 타겟 서비스 포트: `8080`
- 상태 검사 포트: `8080` (서비스 포트와 분리 시 `18080`)

#### 보안그룹 최소 허용 예시(타겟 서버 보안그룹)
| 방향 | 프로토콜 | 포트 | 소스 | 설명 |
| --- | --- | --- | --- | --- |
| 인바운드 | TCP | 8080 | 10.20.0.0/16 | 클라이언트의 서비스 트래픽 허용 |
| 인바운드 | TCP | 18080 | 10.20.0.0/16 | 상태 검사 포트 분리 시 |

- 보안그룹은 상태 저장 방식이므로 위 인바운드 허용 트래픽의 응답은 자동 허용됩니다.
- 소스 CIDR은 실제 서비스 클라이언트 또는 운영상 허용한 접근 구간으로 대체합니다.

## 7) 생성 절차 섹션 상세 설계(작성 가이드)
### 7.1 기본 정보
- 이름/설명 입력 규칙
- 이름 제약:
  - 영숫자, `-`, `_` 허용
  - `__cloudia_` 접두사 금지

### 7.2 네트워크 정보
- `VPC` 선택
- `프로토콜` 선택: `HTTP`
- `포트 번호` 입력(`1-65535`)
- 안내 포인트:
  - 기본 포트는 상태 검사/각 타겟 포트의 기본값으로 활용
  - 타겟 그룹 `포트 번호`를 수정해도 이미 등록된 타겟의 개별 `포트 번호`는 자동 변경되지 않음

### 7.3 타겟 그룹 정책
- `알고리즘`:
  - `라운드 로빈 (Round Robin)`: 정상 타겟에 요청을 순차적으로 분산. 추가 입력 없음
  - `최소 연결 (Least Connections)`: 현재 연결 수가 적은 타겟을 우선 선택. 추가 입력 없음
  - `소스 해싱 (Source Hashing)`: 클라이언트 소스 IP를 기준으로 요청을 분산하며, 타겟 상태와 구성이 유지되는 동안 같은 IP의 요청을 같은 타겟으로 전달. 예: 클라이언트 소스 IP `10.20.0.15`
  - `URI 해싱 (URI Hashing)`: URI를 기준으로 요청을 분산하며, 타겟 상태와 구성이 유지되는 동안 같은 URI의 요청을 같은 타겟으로 전달. 예: URI `/api/orders/1001`
  - `URL 파라미터 해싱 (URL Parameter Hashing)`: 지정한 URL 파라미터 값을 기준으로 요청을 분산하며, 타겟 상태와 구성이 유지되는 동안 같은 파라미터 값의 요청을 같은 타겟으로 전달. 예: `파라미터`는 `userId`, 요청은 `/orders?userId=1001`
  - `HTTP 헤더 해싱 (HTTP Header Hashing)`: 지정한 HTTP 헤더 값을 기준으로 요청을 분산하며, 타겟 상태와 구성이 유지되는 동안 같은 헤더 값의 요청을 같은 타겟으로 전달. 예: `헤더`는 `X-Tenant-ID`, 헤더 값은 `tenant-a`
- `URL 파라미터 해싱` 선택 시 `파라미터` 필수. `파라미터`에는 파라미터 이름을 입력하고, 실제 요청의 파라미터 값이 해싱 기준값으로 사용됨
- `HTTP 헤더 해싱` 선택 시 `헤더` 필수. `헤더`에는 헤더 이름을 입력하고, 실제 요청의 헤더 값이 해싱 기준값으로 사용됨
- 해싱 계열 알고리즘은 서로 다른 해싱 기준값이 반드시 서로 다른 타겟으로 가는 것이 아니라, 같은 해싱 기준값의 요청이 같은 타겟으로 유지되는지가 핵심
- 알고리즘 변경 저장 직후에는 런타임 반영 지연이 있을 수 있으므로 운영 검증 전 30~60초 대기 권장
- `서버 가중치 점진 상승 시간` 범위: `0-3600초`
- `서버 가중치 점진 상승 시간`은 장애 후 정상 복귀한 타겟에 트래픽을 즉시 최대치로 보내지 않고 설정 시간 동안 점진적으로 늘리는 기능
- `세션 고정성`:
  - 비활성화/활성화 토글
  - 활성화 시 `쿠키 유효 시간` 입력
  - 타겟 그룹 정책의 `세션 고정성`은 같은 브라우저 세션의 요청을 같은 타겟 멤버(Instance)에 고정하는 기능
  - 브라우저 세션별로 독립적으로 동작하며, 쿠키 삭제 또는 만료 후에는 타겟이 다시 선택될 수 있음

- `알고리즘`, `서버 가중치 점진 상승 시간`, `세션 고정성`, `상태 검사 설정` 변경 후 상세 화면에 변경값이 반영되는지 확인

### 9.3 타겟 변경(Target 편집)
- 타겟 추가/수정/삭제
- 타겟 교체 시 중복/가중치/포트 점검
- 로드 밸런서에 연결된 상태에서도 타겟 `가중치`와 `포트 번호` 변경 가능
- 가중치 변경 후 실제 응답 분포가 변경될 수 있음
- 잘못된 포트로 변경하면 해당 타겟의 `런타임 상태`가 비정상으로 전환되고 응답 비중이 감소하거나 제외될 수 있음
- 포트 복구 후 상태와 분산이 정상화되는지 확인

### 9.4 타겟 상태 확인
- 타겟 상태는 `관리 상태`와 `런타임 상태`를 구분해 설명
- `관리 상태`는 타겟 목록에서 확인하는 사용자의 의도 상태이며, 타겟을 트래픽 전달 대상으로 포함할지 판단하는 기준
- `런타임 상태`는 타겟 행의 `모니터링 정보 > 보기`에서 확인하는 런타임의 타겟 상태이며, 상태 검사와 실제 런타임 통계 수집 결과를 기준으로 표시
- 로드 밸런서에 연결되지 않은 타겟 그룹은 연결 트래픽 기반 모니터링 정보가 미집계 또는 미노출될 수 있음
- 로드 밸런서에 연결된 후에는 `연결된 리소스 > 타겟 > 모니터링 정보 > 보기`에서 연결 트래픽 기반 상태와 상태 검사 결과를 확인
- 타겟 모니터링 정보는 로드 밸런서 런타임에서 수집한 타겟별 통계 스냅샷 기준으로 작성
- 수집 기준:
  - 로드 밸런서에 연결된 타겟 그룹만 런타임 통계 노출
  - 연결된 로드 밸런서에서 현재 참조 중인 `ACTIVE` 타겟을 기준으로 타겟 IP 주소와 포트가 일치하는 런타임 통계를 매핑
  - 통계 미수집 또는 타겟 IP/포트 매칭 실패 시 `런타임 상태=UNKNOWN` 또는 `-` 표시 가능
  - 누적값은 런타임 통계 기준이며 로드 밸런서 재배포, 런타임 재시작, 설정 재반영 시 초기화될 수 있음
- 타겟 모니터링 정보 항목:
  - `런타임 상태`: 런타임이 판단한 타겟의 현재 상태. 예: `UP`, `DOWN`, `UNKNOWN`
  - `진단 코드`: 마지막 상태 검사 진단 결과. 예: `L7 정상`, `L4 시간 초과`, `L7 상태 오류`
  - `체크 응답 코드`: HTTP 상태 검사 응답 코드. 응답 코드가 없으면 `-`
  - `상태 검사 실패 횟수`: 상태 검사 실패 누적 횟수
  - `DOWN 전이 횟수`: 타겟이 정상 상태에서 `DOWN` 상태로 전환된 누적 횟수
  - `누적 다운 시간`: 타겟이 `DOWN` 상태였던 누적 시간. 런타임 통계는 초 단위
  - `현재 세션 수`: 현재 해당 타겟에 연결되어 처리 중인 세션 수
  - `전체 세션 수`: 런타임 통계 기준 누적 세션 수
  - `수신 바이트`: 해당 타겟 통계에서 집계된 누적 수신 바이트
  - `송신 바이트`: 해당 타겟 통계에서 집계된 누적 송신 바이트
  - `마지막 상태 변경 경과 시간`: 마지막 상태 변경 이후 경과 시간. 런타임 통계는 초 단위
  - `최종 수집 시각`: Cloudia가 해당 타겟 통계를 마지막으로 수집해 저장한 시각

#### 관리 상태
| UI 표시명 | 상세 설명 |
| --- | --- |
| ACTIVE | 타겟이 트래픽 전달 대상으로 포함된 상태입니다. |
| DRAINING | 타겟이 트래픽 전달 대상에서 제외되는 중인 상태입니다. 기존 반영이 정리된 뒤 삭제 또는 제외됩니다. |

#### 런타임 상태
| UI 표시명 | 상세 설명 |
| --- | --- |
| UP | 타겟이 정상 상태이며 트래픽 분산 대상으로 사용할 수 있습니다. |
| DOWN | 타겟이 상태 검사에 실패했거나 연결할 수 없어 트래픽 분산 대상에서 제외되는 상태입니다. |
| UNKNOWN | 런타임 통계가 아직 수집되지 않았거나 타겟과 통계가 매칭되지 않아 상태를 판단할 수 없는 상태입니다. |
| MAINT | 유지보수 또는 관리 목적의 제외 상태입니다. 표시될 경우 신규 트래픽 분산 대상으로 보지 않습니다. |
| DRAIN | 기존 연결은 처리하되 신규 분산을 제한하는 상태입니다. 표시될 경우 트래픽 제거 또는 점진 제외 상태로 해석합니다. |

#### 진단 코드
| UI 표시명 | 상세 설명 |
| --- | --- |
| 알 수 없음 | 상태 확인 결과를 알 수 없습니다. |
| 초기화 중 | 상태 확인을 초기화하는 중입니다. |
| 소켓 오류 | 상태 확인 중 소켓 오류가 발생했습니다. |
| L4 정상 | L4 연결 확인에 성공했습니다. 상위 레이어 검사는 수행되지 않았습니다. |
| L4 시간 초과 | L1~L4 구간에서 상태 확인 시간이 초과되었습니다. |
| L4 연결 실패 | 연결이 거부되었거나 대상 호스트에 도달할 수 없습니다. |
| SSL 정상 | SSL/TLS 계층 확인에 성공했습니다. |
| SSL 시간 초과 | SSL/TLS 계층에서 상태 확인 시간이 초과되었습니다. |
| SSL 응답 오류 | SSL/TLS 응답이 올바르지 않거나 프로토콜 오류가 발생했습니다. |
| L7 정상 | L7 상태 확인에 성공했습니다. |
| 조건부 정상 | 조건부로 L7 상태 확인에 성공했습니다. 예: disable-on-404 조건에서 404 응답 |
| L7 시간 초과 | HTTP/SMTP 등 L7 구간에서 상태 확인 시간이 초과되었습니다. |
| L7 응답 오류 | L7 응답이 올바르지 않거나 프로토콜 오류가 발생했습니다. |
| L7 상태 오류 | L7 응답 상태가 실패로 판단되었습니다. 예: HTTP 5xx |

- `런타임 상태`가 비정상 상태로 표시될 때 점검 순서:
  1. 애플리케이션 프로세스 응답 확인
  2. 상태 검사 경로/포트 재확인
  3. 보안그룹 인바운드 소스/CIDR/포트 재확인

### 9.5 모니터링
- `모니터링 정보 > 보기`에서 타겟별 `런타임 상태`와 상태 검사 결과 확인
- 타겟 상태 변화 추적
- 연결된 로드 밸런서 변경 전후 지표 비교
- 타겟이 Down 후 Up으로 복구되면 `서버 가중치 점진 상승 시간` 동안 복구 타겟의 트래픽 유입이 점진적으로 증가하는지 확인

### 9.6 로드 밸런서 연결/후보 노출 제약
- L7 로드 밸런서의 `기본 작업` 또는 `규칙`에서 `타겟 그룹으로 전달`을 선택할 때 후보 타겟 그룹은 LB 연결 관계에 따라 노출
- 이미 특정 L7 로드 밸런서에 연결된 타겟 그룹은 같은 LB의 새 리스너/규칙에서는 후보로 다시 노출될 수 있음
- 이미 다른 L7 로드 밸런서에 연결된 타겟 그룹은 현재 LB의 Forward 후보에서 제외
- 후보가 보이지 않으면 VPC, 레이어, 프로토콜, 기존 LB 연결 여부를 함께 점검

### 9.7 삭제 제약
- 로드 밸런서에 연결된 타겟 그룹은 삭제 불가
- `LB 적용 여부=적용` 대상은 삭제 방지
- 삭제 전 연결 해제 및 영향 범위 점검 필요

## 10) 오류 대응 섹션 초안
- `URL 파라미터 해싱`/`HTTP 헤더 해싱` 필수값 누락
- 타겟 중복 등록
- 포트/가중치 범위 오류
- 상태 검사 경로/상태코드 형식 오류
- 연결된 로드 밸런서 상태로 인한 수정 제한
- `런타임 상태`가 지속적으로 비정상 상태인 경우:
  - 클라이언트 CIDR 소스 허용 누락 여부 점검
  - 보안그룹 인바운드 포트 허용 누락 여부 점검

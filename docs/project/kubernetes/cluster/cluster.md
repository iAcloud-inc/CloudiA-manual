# 클러스터

## 화면 개요

**클러스터**는 쿠버네티스 컨트롤 플레인, 워커 노드, 네트워크, 스토리지, 리소스를 통합 관리하는 기능입니다.

## 클러스터 목록
클러스터 목록을 확인합니다.

### 주요 작업
- `생성`: 새 클러스터를 생성합니다.
- `실행`: 정지 상태(`DOWN`)의 클러스터를 다시 실행합니다.
- `종료`: `UP`·`WARNING`·`CA_ROTATE_FAILED` 상태의 클러스터를 종료합니다.
- `삭제`: 선택한 클러스터를 삭제합니다.

> 💡 **공통 조건:** 목록에서 좌측 **라디오 버튼**으로 클러스터를 선택합니다. 한 번에 **1개 클러스터만 선택**할 수 있습니다.

### 테이블 컬럼
| 컬럼 | 설명 |
|------|------|
| **이름** | 클러스터 이름입니다. 클릭하면 상세 화면으로 이동합니다. |
| **ID** | 클러스터의 고유 ID입니다. |
| **버전** | 클러스터의 쿠버네티스 버전입니다. |
| **API 서버 엔드포인트 IP** | API 서버 접근에 사용하는 엔드포인트 IP 주소입니다. |
| **상태** | 예: `ERROR`, `WARNING`, `UNKNOWN`, `DOWN`, `UP`, `POWERING_UP`, `STOPPING`, `CREATING`, `DELETING`, `DELETE_FAILED`, `DELETED`, `CA_ROTATING`, `CA_ROTATE_FAILED`, `PENDING` |
| **컨트롤 플레인** | 정상 상태의 컨트롤 플레인 수/전체 수를 `N/N` 형식으로 표시합니다. |
| **워커 노드** | 정상 상태의 워커 노드 수/전체 수를 `N/N` 형식으로 표시합니다. |
| **생성 일시** | 생성 일시를 표시합니다. |

> ⚠️ **주의:** `삭제 중(DELETING)` 상태의 클러스터는 삭제할 수 없습니다.

## 클러스터 상세
선택한 클러스터의 기본 정보와 하위 섹션을 확인합니다.

### 상단 요약
- **이름**: 클러스터 이름입니다.
- **ID**: 클러스터의 고유 ID입니다.
- **버전**: 쿠버네티스 버전입니다.
- **VPC**: `VPC 이름 (ID: VPC ID)` 형식으로 표시됩니다.
- **API 서버 엔드포인트 IP**: API 서버 접근에 사용하는 엔드포인트 IP 주소입니다.
- **상태**: 클러스터 상태입니다.
- **생성 일시**: 생성 일시입니다.
- **CA 인증서**: CA 인증서 지문과 만료일입니다. 만료 30일 이내이면 경고가 표시됩니다.

### 주요 작업
- `업그레이드`: **버전** 항목 옆의 버튼입니다. 클러스터를 다음 버전으로 업그레이드합니다. 자세한 절차는 [클러스터 업그레이드](#클러스터-업그레이드)를 참고하세요.
- `인증서 재설정`: 새 `ca.crt` 와 `ca.key` 를 업로드해 CA를 재설정합니다.

#### 인증서 재설정
- `ca.crt`, `ca.key` 를 모두 선택해야 저장할 수 있습니다.
- 재설정 중에는 상태가 `CA_ROTATING`으로 표시되며, 완료되면 다시 `UP`으로 복귀합니다.

> ⚠️ **주의:** CA 파일 재설정은 원칙적으로 **모든 노드가 정상 상태일 때만** 진행할 수 있습니다.
> 예외는 **직전 재설정이 실패한 클러스터**입니다(아래 "재설정이 실패한 경우" — 복구를 위해 다시 시도할 수 있습니다).

**업로드 파일 조건**

| 항목 | 조건 |
|------|------|
| `ca.crt` | **CA 인증서 1장**만 담아야 합니다. 인증서 여러 장(체인·번들)은 거부됩니다. |
| `ca.key` | `ca.crt` 와 **한 쌍**이어야 하며 **RSA** 키여야 합니다. `PRIVATE KEY`·`RSA PRIVATE KEY` 형식을 모두 지원합니다. |

조건에 맞지 않으면 **클러스터를 변경하기 전에** 요청이 거부됩니다. 이 경우 클러스터는 아무 영향도 받지 않으므로,
파일만 교정해 다시 시도하면 됩니다.

**재설정 중 서비스 영향**
- **쿠버네티스 API 는 재기동되지 않습니다.** API 서버를 재기동하지 않고 인증서 신뢰를 확장·축소하므로, 검증
  환경의 1초 간격 점검에서 API 중단은 관측되지 않았습니다. 컨트롤 플레인 구성 요소가 노드마다 한 번씩
  재기동되는 동안 개별 요청이 재시도될 수는 있습니다.
- 노드마다 컨트롤 플레인 구성 요소와 kubelet 이 한 번씩 재기동됩니다.
- **재설정이 사용자 워크로드(파드)를 축출하거나 다른 노드로 옮기지 않습니다.** 시스템 네임스페이스
  (`kube-system`)의 구성 요소는 새 CA 를 반영하기 위해 자동으로 재기동됩니다. 클러스터 내부에서 API 를 호출하는
  워크로드는 아래 "재설정 후 반드시 해야 하는 것" 2번에 따라 직접 재기동해야 할 수 있습니다.

**재설정 후 반드시 해야 하는 것**

1. **kubeconfig 재발급** — 기존에 내려받은 `config` 파일의 사용자 인증서는 **이전 CA** 로 서명되어 있어 재설정
   완료 후에는 접속이 거부됩니다(`x509: certificate signed by unknown authority`). **접근 관리(RBAC)** 섹션의
   `kubeconfig 발급`으로 다시 내려받으세요. CI/CD 등 자동화에 등록된 kubeconfig 도 함께 교체해야 합니다.
2. **클러스터 내부에서 API 를 호출하는 사용자 워크로드 재기동(필요 시)** — 파드 안에서 서비스 계정으로 API 를
   호출하는 애플리케이션은 시작할 때 읽은 CA 를 계속 사용합니다. 시스템 구성 요소는 자동으로 재기동되지만,
   사용자 네임스페이스의 워크로드는 서비스 영향을 고려해 자동 재기동하지 않습니다. 인증 오류가 보이면 해당
   워크로드를 재기동하세요.

   ```bash
   kubectl -n <네임스페이스> rollout restart deployment,statefulset,daemonset
   ```

> 💡 **권장 절차:** 유지보수 시간대에 ① 인증서 재설정 → ② **접근 관리(RBAC)** 의 `kubeconfig 발급`으로 kubeconfig 재발급 →
> ③ 필요한 사용자 워크로드 재기동 순서로 진행하세요.

**재설정이 실패한 경우**
- 클러스터 상태가 `CA_ROTATE_FAILED` 로 표시됩니다. 이때는 **같은 CA 파일로 다시 재설정** 하면 중단된 지점부터
  이어서 정리됩니다. 이때는 **모든 노드가 정상이 아니어도** 다시 진행할 수 있습니다(복구 경로를 막지 않기
  위한 예외입니다). 재설정과 무관한 이유로 비정상인 노드가 있으면 그 노드에서 다시 실패하므로, 반복되면 먼저
  해당 노드를 정상화하거나 클러스터에서 제거하세요.
- 재설정이 **진행 중**(`CA_ROTATING`)이면 새 요청은 거부됩니다 — 진행이 끝날 때까지 기다리세요.
- 위 예외는 **직전 재설정이 실패한 클러스터**에만 적용됩니다. 실패 이력이 없는 평상시 재설정은 `NOT_READY` 등
  비정상 노드가 하나라도 있으면 **요청 시점에 거부**됩니다 — 그 노드를 먼저 정상화하거나 클러스터에서 제거한 뒤
  시도하세요.
- 재실행으로도 복구되지 않거나 특정 노드가 `NOT_READY` 로 남으면 관리자에게 문의하세요.

### 하단 섹션
상세 화면 하단에서는 **클러스터 구성 요소**, **스토리지**, **레지스트리 신뢰**, **AI 가속기**, **쿠버네티스 리소스**, **접근 관리(RBAC)**, **이벤트** 섹션이 순서대로 표시되고, 그 아래 **모니터링 정보** 섹션이 이어집니다. 기본 정보 아래에는 **네트워크 정보** 박스가 함께 표시됩니다. 섹션 안의 목록은 좌측 사이드네비로 전환해 확인합니다.

- **클러스터 구성 요소**: `노드`, `워커 오토 스케일링 그룹`, `서비스 로드 밸런서`
- **스토리지**: `스토리지 클래스`, `PVC`, `파일 시스템`
- **레지스트리 신뢰**: 사설·사용자 레지스트리 CA 등록과 노드별 적용 현황 ([레지스트리 신뢰](#레지스트리-신뢰) 참고)
- **AI 가속기**: `AI 가속기 노드`, `NVIDIA GPU`
- **쿠버네티스 리소스**: `시스템 파드`, `디플로이먼트`, `데몬셋`, `서비스`
- **접근 관리(RBAC)**: RBAC 바인딩(`내 바인딩`·`전체 바인딩`), `내 바인딩` 뷰에서 `kubeconfig 발급`, `관리자 권한 복구`
- **이벤트**: 클러스터 이벤트
- **모니터링 정보**: 클러스터 상태와 사용량
- **네트워크 정보**: 서브넷, 보안그룹, API 서버 로드 밸런서

> ⚠️ **주의:** 클러스터 상태가 `UP`·`WARNING`·`CA_ROTATING`·`CA_ROTATE_FAILED`(실시간 가용 상태)가 아니면 **모니터링 정보** 섹션이 표시되지 않고, `AI 가속기`·`쿠버네티스 리소스`·`접근 관리(RBAC)`·`이벤트` 섹션에는 "현재 클러스터 상태에서는 실시간 정보를 표시할 수 없습니다." 안내가 표시됩니다(정지 계열 `DOWN`·`STOPPING`·`POWERING_UP`이면 "클러스터가 정지되어 실시간 리소스·모니터링 정보를 표시하지 않습니다."). `스토리지` 섹션은 표시되나 `스토리지 클래스`·`PVC` 사이드네비가 비활성화됩니다(파일 시스템은 DB 정보라 생성 중을 제외하고 사용 가능). `클러스터 구성 요소`(노드 등)·`레지스트리 신뢰`·`네트워크 정보`는 이 안내와 무관하게 표시됩니다. 다만 `레지스트리 신뢰`의 적용 현황은 마지막으로 확인된 값이라는 안내가 함께 표시됩니다.

#### 모니터링 정보
클러스터 상태와 사용량을 모니터링합니다.

##### 주요 작업
- `새로고침`: 최신 데이터를 다시 조회합니다.
- `자동 새로고침`: 일정 주기로 데이터를 자동 갱신합니다.

##### 주요 표시 영역
- **컨트롤 플레인 평균 부하**: CPU, Memory, Disk 사용률
- **파드 상태**: `Running`, `Pending`, `Succeed`, `Failed`, `Unknown`
- **워커 노드 사용량**: CPU, Memory, `Network rx`, `Network tx`
- **노드 상태**: 컨트롤 플레인/워커의 정상 수와 전체 수

> 💡 **참고:** CPU 사용 제한이나 메모리 부족 위험이 감지되면 경고 문구가 함께 표시될 수 있습니다.

#### 노드
컨트롤 플레인과 워커 노드 목록을 확인하고, 워커 노드 관련 작업을 수행합니다.

##### 주요 작업
- `워커 노드 추가`: 새 워커 노드를 추가합니다.
- `워커 노드 삭제`: 선택한 워커 노드를 삭제합니다.

##### 테이블 컬럼
| 컬럼 | 설명 |
|------|------|
| **역할** | `컨트롤 플레인` 또는 `워커 노드`입니다. |
| **노드 이름** | 클릭 시 VM 인스턴스 상세로 이동합니다. |
| **ID** | 노드의 고유 ID입니다. |
| **버전** | 쿠버네티스 버전입니다. |
| **기본 인터페이스 IP 주소** | 노드 IP 주소입니다. |
| **인스턴스 타입** | 연결된 인스턴스 타입입니다. |
| **상태** | 예: `ERROR`, `DOWN`, `UP`, `POWERING_UP`, `CREATING`, `DELETING`, `DELETED`, `PENDING`, `CA_ROTATING`, `CA_ROTATE_FAILED`, `READY`, `NOT_READY`, `UNKNOWN`, `MACHINE_DOWN`, `ORPHANED` |
| **생성 일시** | 생성 일시입니다. |

> ⚠️ **주의:** 컨트롤 플레인 노드는 삭제할 수 없습니다.

> ⚠️ **주의:** `PENDING`, `CREATING`, `DELETING` 상태의 워커 노드는 삭제할 수 없습니다.

> ⚠️ **주의:** 생성 중이거나 삭제 중인 노드는 상세 화면으로 이동할 수 없습니다.

#### 워커 오토 스케일링 그룹
워커 오토 스케일링 그룹 목록을 확인하고 관리합니다.

##### 주요 작업
- `생성`: 워커 오토 스케일링 그룹을 생성합니다.
- `삭제`: 목록에서 선택한 그룹을 삭제합니다.

##### 테이블 컬럼
| 컬럼 | 설명 |
|------|------|
| **이름** | 그룹 이름입니다. 클릭하면 상세 화면으로 이동합니다. |
| **ID** | 그룹의 고유 ID입니다. |
| **인스턴스 상태** | `정상 수/전체 수개` 형식으로 표시합니다(예: `3/5개`). |
| **상태** | 예: `UP`, `CREATING`, `DELETING`, `SCALING_OUT`, `SCALING_IN` |
| **생성 일시** | 생성 일시입니다. |

#### 스토리지
스토리지 클래스, PVC, 파일 시스템을 좌측 사이드네비로 전환해 조회하고 생성합니다.

##### 주요 작업
- `스토리지 클래스 생성`
- `PVC 생성`
- `파일시스템 연결`: 프로젝트의 파일 시스템을 이 클러스터에 미리 연결합니다.
- `파일시스템 연결 해제`: 선택한 파일 시스템의 연결을 해제합니다.

##### 스토리지 클래스 목록 컬럼
| 컬럼 | 설명 |
|------|------|
| **이름** | 스토리지 클래스 이름입니다. |
| **경과 시간** | 생성 후 경과 시간(`age`)입니다. |
| **볼륨 확장 허용** | `allowVolumeExpansion` 여부입니다. |
| **서버** | `parameters.server` 값입니다. |
| **공유 경로** | `parameters.share` 값입니다. |
| **프로비저너** | `provisioner` 값입니다. |
| **반환 정책** | `Delete` 또는 `Retain`입니다. |
| **볼륨 바인딩 모드** | `volumeBindingMode` 값입니다. |
| **기본** | 기본 스토리지 클래스 여부입니다. |

##### PVC 목록 컬럼
| 컬럼 | 설명 |
|------|------|
| **이름** | PVC 이름입니다. |
| **경과 시간** | 생성 후 경과 시간(`age`)입니다. |
| **상태** | 예: `Pending`, `Bound` |
| **스토리지 클래스** | 연결된 스토리지 클래스입니다. |
| **볼륨** | 바인딩된 볼륨입니다. |
| **설정 용량** | 요청한 용량입니다. |
| **접근 모드** | 접근 모드입니다. |

##### 파일 시스템 목록 컬럼
| 컬럼 | 설명 |
|------|------|
| **이름** | 파일 시스템 이름입니다. |
| **경로** | 공유 경로입니다. |
| **크기** | 파일 시스템 크기입니다. |
| **생성 일시** | 생성 일시입니다. |

##### 파일 시스템 연결
스토리지 클래스를 만들면 그 파일 시스템이 클러스터에 자동으로 연결됩니다. 미리 연결해 두려면 다음 절차를 따릅니다.

1. `스토리지` 섹션에서 좌측 사이드네비의 **파일 시스템**을 선택합니다.
2. `파일시스템 연결`을 클릭합니다.
3. 목록에서 연결할 파일 시스템을 선택합니다.
4. `연결`을 클릭해 적용합니다.

> 💡 **참고:** 연결할 수 있는 파일 시스템은 **NFS 타입**만입니다.

> 💡 **참고:** 연결 목록에는 클러스터와 같은 VPC의 파일 시스템만 표시됩니다. 클러스터에 VPC 정보가 없으면 `파일시스템 연결` 버튼이 활성화되지 않습니다.

##### 파일 시스템 연결 해제
1. **파일 시스템** 목록에서 해제할 항목을 1개 선택합니다.
2. `파일시스템 연결 해제`를 클릭합니다.
3. 확인 창에서 이 클러스터의 사용 현황을 확인합니다. 사용 중인 스토리지 클래스·볼륨이 있으면 목록으로 표시됩니다.
4. `해제`를 클릭해 적용합니다.

> ⚠️ **주의:** 클러스터에 연결된 파일 시스템은 **연결을 해제하기 전까지 삭제할 수 없습니다.** `스토리지 > 파일 시스템`에서 삭제하려면 먼저 이 화면에서 연결을 해제하세요.

> ⚠️ **주의:** 연결을 해제해도 클러스터에 이미 만들어진 스토리지 클래스와 볼륨은 삭제되지 않습니다. 해제 후 파일 시스템을 삭제하면 남아 있는 볼륨의 마운트가 깨집니다.

> 💡 **참고:** 클러스터에 확인할 수 없는 상태(정지·오류 등)에서는 사용 중 여부를 알 수 없다는 안내가 표시되며, 연결 해제는 그대로 진행할 수 있습니다.

> 💡 **참고:** 스토리지 섹션에서는 스토리지 클래스와 PVC를 조회하고 생성할 수 있고, 파일 시스템은 연결·해제할 수 있습니다. 클러스터에 연결된 네트워크 정보(서브넷, 보안그룹, API 서버 로드 밸런서)는 상세 화면 기본 정보 아래 **네트워크 정보** 박스에서 확인합니다.

#### 쿠버네티스 리소스
시스템 파드, 디플로이먼트, 데몬셋, 서비스를 좌측 사이드네비로 전환해 조회합니다.

##### 표시 항목
- **시스템 파드**: 이름, 준비 상태(`Ready`), 상태, 재시작 횟수, 경과 시간, 파드 IP, 노드 이름
- **디플로이먼트**: 이름, 네임스페이스, Replicas(`readyReplicas/replicas`), 경과 시간, Ready, 상태, Strategy
- **서비스**: 이름, 네임스페이스, Type, Cluster IP, External IP, Ports, 경과 시간, 상태
- **데몬셋**: 이름, 네임스페이스, Desired Nodes, Available Nodes, 경과 시간, Ready Pods, 상태, Update Strategy

> ⚠️ **주의:** 쿠버네티스 리소스 섹션은 조회 전용입니다.

#### 이벤트
클러스터 이벤트 목록을 별도 섹션으로 제공합니다.

- **표시 항목**: 경과 시간, Type, 네임스페이스, Reason, Message

> ⚠️ **주의:** 이벤트 섹션은 조회 전용입니다.

#### 접근 관리(RBAC)
RBAC 바인딩을 관리하고 kubeconfig를 발급합니다.

- **`내 바인딩`·`전체 바인딩`**: RBAC 바인딩을 좌측 사이드네비로 전환해 확인합니다.
- **`kubeconfig 발급`**: 서비스 계정의 kubeconfig를 발급하고 다운로드합니다.
- **`관리자 권한 복구`**: cluster-admin 바인딩이 유실된 경우 관리자 권한을 복구합니다.

## 클러스터 생성
클러스터를 생성할 때 기본 정보, 네트워크, 컨트롤 플레인, 사용자 계정, CA 파일을 입력합니다.

> 💡 **참고:** 필수 항목을 모두 입력하면 **생성** 버튼이 활성화됩니다.

### 기본 정보
- **클러스터 이름**을 입력합니다.

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **클러스터 이름** | 소문자, 숫자, `-` | 최대 `40자`, 첫 글자 숫자 불가 | **필수** |

### VPC 및 서브넷 설정
- **VPC**를 먼저 선택합니다.
- 선택한 VPC에 맞는 **서브넷**을 선택합니다.
- 필요한 경우 **추가 보안그룹**을 선택합니다.

> 💡 **참고:** 기본 보안그룹은 클러스터 생성 과정에서 자동으로 준비됩니다.

> ⚠️ **주의:** 추가 보안그룹은 최대 `4개`까지 선택할 수 있습니다.

### 컨트롤 플레인 설정
- **인스턴스 구성**을 선택합니다.
- **버전**을 선택합니다.
- **컨트롤 플레인 수**를 선택합니다.

#### 고급 옵션
버전을 선택하면 **고급 옵션**을 펼칠 수 있습니다. 고급 옵션에서는 다음 항목을 설정합니다.

- **디스크 크기 설정**을 입력합니다.
- **스토리지 도메인**을 선택합니다. (선택)

> 💡 **참고:** 선택할 수 있는 **버전**은 관리자가 등록한 쿠버네티스 이미지에 따라 결정됩니다. 현재 제공 버전은 `1.36`, `1.37` 입니다(`1.35` 이하는 제공하지 않습니다).

> 💡 **참고:** 컨트롤 플레인 수는 `1` 또는 `3` 중에서 선택합니다.

> 💡 **참고:** 고급 옵션은 **버전을 먼저 선택**해야 펼칠 수 있습니다.

> 💡 **참고:** 스토리지 도메인을 선택하면 해당 도메인에 인스턴스가 배치됩니다. 선택하지 않으면 시스템이 자동으로 배치합니다.

> ⚠️ **주의:** 디스크 크기 설정은 최소 `32 GB` 이상 입력합니다.

### 사용자 계정 및 인증 방식
- **사용자 이름**을 입력합니다.
- 인증 방식은 비밀번호 또는 SSH 키를 사용할 수 있습니다.
- 비밀번호를 사용하는 경우 비밀번호와 확인 값을 모두 입력합니다.

### CA 파일 설정
- **CA 인증서(`ca.crt`)**
- **개인 키(`ca.key`)**

`선택` 버튼을 클릭해 열리는 모달에서 파일을 첨부하고, 모달의 `추가` 버튼으로 확인합니다. 두 파일을 모두 선택하거나, 모두 선택하지 않을 수 있습니다. CA 파일을 첨부하지 않으면 시스템이 자동으로 CA를 생성합니다.

> ⚠️ **주의:** CA 인증서와 개인 키 중 하나만 첨부할 수 없습니다. 둘 다 첨부하거나 둘 다 첨부하지 않아야 합니다.

#### CA 파일 직접 생성 예시
CA 파일을 직접 준비하려면 `openssl`로 개인 키와 자체 서명 인증서를 생성할 수 있습니다.

```bash
# 개인 키(ca.key) 생성
openssl genrsa -out ca.key 4096

# 자체 서명 CA 인증서(ca.crt) 생성 (유효기간 10년)
openssl req -x509 -new -nodes -key ca.key -days 3650 -subj "/CN=kubernetes-ca" -out ca.crt
```

> 💡 **참고:** 생성된 `ca.key`(개인 키)와 `ca.crt`(CA 인증서)를 CA 파일 설정에서 각각 첨부합니다.

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **VPC** | 프로젝트 내 VPC 1개 | 선택 필요 | **필수** |
| **서브넷** | 선택 가능한 서브넷 1개 | 선택 필요 | **필수** |
| **추가 보안그룹** | 선택 가능한 보안그룹 | 최대 `4개` 선택 가능 | 선택 |
| **인스턴스 구성** | 인스턴스 타입 또는 직접 입력 | 유효한 값 선택 필요 | **필수** |
| **버전** | 사용 가능한 쿠버네티스 버전 | 선택 필요 | **필수** |
| **컨트롤 플레인 수** | `1` 또는 `3` | 값 중 하나를 선택해야 함 | **필수** |
| **디스크 크기 설정** | 정수 | 최소 `32 GB` 이상 | **필수** (고급 옵션) |
| **스토리지 도메인** | 사용 가능한 스토리지 도메인 | 선택 가능 | 선택 (고급 옵션) |
| **CA 인증서/개인 키** | 파일 업로드 | 둘 다 첨부하거나 둘 다 미첨부 | 선택 |
| **사용자 계정/인증 방식** | 사용자명 + 비밀번호 또는 SSH 키 | 유효성 검사 통과 필요 | **필수** |

### 생성 결과
- 생성 요청 직후 목록에 새 클러스터가 `CREATING` 상태로 표시됩니다.
- 완료되면 `UP` 상태로 전환됩니다.
- 클러스터 생성과 함께 컨트롤 플레인 노드, 로드밸런서, 타겟 그룹이 자동으로 준비됩니다.

> ⚠️ **주의:** 프로젝트 자원이나 서브넷의 사용 가능 IP가 부족하면 생성이 실패할 수 있습니다.

## 클러스터 업그레이드
실행 중인 클러스터를 다음 쿠버네티스 버전으로 업그레이드합니다.

### 전제 조건
- 클러스터 상태가 `UP` 또는 `WARNING` 이어야 합니다. 그 외 상태(정지·전이·오류)에서는 `업그레이드` 버튼이 비활성화됩니다.
- 관리자가 **다음 버전의 이미지를 등록**해 두어야 합니다. 등록된 상위 버전이 없으면 업그레이드는 성공으로 끝나지만 노드는 교체되지 않습니다.
- 업그레이드 중 노드가 한 대씩 추가되므로, 프로젝트에 **노드 1대 분량의 여유 자원**(vCPU·메모리·디스크)이 있어야 합니다.
- 대상 이미지는 **클러스터가 놓인 스토리지 도메인**에 등록된 것만 후보입니다. 도메인을 판정하지 못하면 사전 점검에서 실패해 업그레이드가 중단됩니다.

### 절차
1. 클러스터 상세 화면으로 이동합니다.
2. 상단 요약의 **버전** 항목 옆 `업그레이드` 버튼을 클릭합니다.
3. 열린 창에서 대상 클러스터의 이름, ID, 현재 버전, API 서버 엔드포인트 IP, 생성 일시를 확인합니다.
4. `업그레이드`를 클릭합니다.

### 진행 방식과 소요 시간
- 요청은 즉시 접수되고, 클러스터 상태가 `UPDATING` 으로 바뀝니다. 완료되면 다시 `UP` 으로 돌아옵니다.
- **컨트롤 플레인을 한 대씩 순차 교체**한 뒤, 같은 방식으로 **워커 노드를 교체**합니다.
- 각 교체는 새 노드를 먼저 추가해 `Ready` 가 될 때까지 기다린 다음, 기존 노드를 드레인하고 제거합니다. 이때 워커 위의 워크로드는 다른 노드로 **재스케줄**됩니다.
- 클러스터 규모에 따라 **수 분에서 수십 분**이 걸립니다.

> 💡 **참고:** 대상 버전은 현재 마이너 버전의 최신 이미지가 있으면 그 이미지(패치 업그레이드), 없으면 다음 마이너 버전(예: `1.36` → `1.37`)의 최신 이미지입니다.

> 💡 **참고:** 이미 대상 이미지로 동작 중인 노드는 건너뜁니다. 중간에 멈춘 업그레이드를 다시 실행하면 멈춘 지점부터 이어집니다.

> ⚠️ **주의:** **워커 오토 스케일링 그룹이 관리하는 워커는 교체되지 않습니다.** 그룹이 자체 시작 템플릿으로 멤버를 다시 만들기 때문입니다. 그룹의 시작 템플릿 이미지를 갱신해 교체하세요.

> ⚠️ **주의:** 교체하지 못한 워커가 남아도 업그레이드는 실패로 처리되지 않습니다. 클러스터 버전은 컨트롤 플레인을 따라가며, 남은 워커는 kubelet 버전 차이 허용 범위 안에서 계속 동작하다가 다음 업그레이드에서 다시 시도됩니다.

> ⚠️ **주의:** 이미 최신 버전이면 노드가 교체되지 않고 버전도 그대로입니다.

> 💡 **참고:** 업그레이드 중에는 워크로드가 노드 간에 이동하므로, 서비스 영향이 적은 유지보수 시간대에 진행하는 것을 권장합니다.

## 레지스트리 신뢰
사설 레지스트리나 사용자 레지스트리의 **CA 인증서를 클러스터 노드의 containerd 에 신뢰 등록**합니다. 등록하면 그 레지스트리에서 이미지를 받을 때 TLS 검증이 통과합니다.

레지스트리 신뢰는 클러스터 상세 화면의 **레지스트리 신뢰** 섹션에서 관리합니다.

### 테이블 컬럼
| 컬럼 | 설명 |
|------|------|
| **레지스트리 호스트** | 신뢰를 적용할 레지스트리 호스트입니다(예: `harbor.example.com`). |
| **이름** | 식별용 표시 이름입니다. |
| **CA** | 등록된 CA 인증서 장수입니다. |
| **가장 이른 만료** | 등록된 CA 중 가장 먼저 만료되는 인증서의 만료일입니다. |
| **적용 상태** | `적용된 노드 수 / 적용 대상 노드 수` 입니다. 괄호 안 붉은 숫자는 적용에 실패한 노드 수입니다. |
| **생성 일시** | 등록 일시입니다. |

**적용 상태 읽는 법**
- 정지·생성 중처럼 지금 적용할 수 없는 노드는 분모에서 빠집니다.
- 적용되지 않은 노드에 뜬 파드는 이 레지스트리에서 이미지를 받지 못합니다.
- `격리됨` 으로 표시되면 노드 agent 가 그 CA 를 거부해 전송 목록에서 제외한 상태입니다. 다른 항목의 적용은 계속됩니다.

### 주요 작업
- `생성`: 레지스트리 호스트와 CA 인증서를 등록합니다.
- `편집`: 이름과 CA 인증서를 변경합니다.
- `삭제`: 선택한 신뢰 항목을 삭제합니다. 노드에서도 해당 CA 가 제거됩니다.
- `노드별 적용 상태`: 노드별 적용 결과를 확인하고 `재적용`을 실행합니다.

> 💡 **공통 조건:** 목록에서 항목을 **1개 선택**해야 `편집`·`삭제`·`노드별 적용 상태` 버튼이 활성화됩니다.

### 등록
1. **레지스트리 신뢰** 섹션에서 `생성`을 클릭합니다.
2. **레지스트리 호스트**를 입력합니다. 입력한 값이 저장 형태로 정규화되어 안내됩니다.
3. (선택) **이름**을 입력합니다.
4. **CA 인증서**를 PEM 형식으로 붙여넣습니다. 여러 장을 이어 붙일 수 있습니다.
5. `추가`를 클릭합니다.

등록 후 적용은 백그라운드에서 진행되며, 적용 상태가 갱신될 때까지 잠시 기다립니다.

### 편집
1. 항목을 선택하고 `편집`을 클릭합니다.
2. 이름과 CA 인증서를 변경합니다.
3. `편집`을 클릭합니다.

> ⚠️ **주의:** **호스트는 변경할 수 없습니다.** 바꾸려면 삭제 후 다시 등록하세요.

> 💡 **참고:** CA 인증서를 비워 두면 현재 CA 를 그대로 유지합니다. 새로 붙여넣으면 기존 CA 를 대체하고 모든 노드에 다시 적용합니다.

### 노드별 적용 상태와 재적용
1. 항목을 선택하고 `노드별 적용 상태`를 클릭합니다.
2. 노드, 상태(`적용됨`·`대기 중`·`실패`), 적용 세대, 사유, 수정 일시를 확인합니다. 격리된 항목은 `격리됨`, 적용 대상이 아닌 노드는 `적용 대상 아님`으로 표시됩니다.
3. 실패한 노드가 있으면 `재적용`을 클릭합니다. 모든 노드에 현재 신뢰 목록을 다시 밀어넣으며, 적용은 백그라운드에서 진행됩니다.

> ⚠️ **주의:** 클러스터가 CA 회전·전원 전이·생성/삭제 중이면 노드 조정이 안전하지 않아 `재적용`이 비활성화됩니다.

> ⚠️ **주의:** **격리된 항목은 재적용으로 풀리지 않습니다.** CA 를 교체하면 격리가 해제되고 다시 적용됩니다.

### 삭제
1. 항목을 선택하고 `삭제`를 클릭합니다.
2. 호스트, 이름, CA 장수를 확인한 뒤 삭제를 진행합니다.

> 💡 **참고:** 정지·오류 상태의 클러스터에서도 신뢰 항목을 삭제할 수 있습니다. 유출된 CA 를 즉시 폐기할 수 있도록 하기 위함입니다.

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **레지스트리 호스트** | 레지스트리 호스트명(선택적으로 `:포트`) | 필수입니다. 플랫폼 예약 호스트는 등록할 수 없습니다. 등록 후에는 변경할 수 없습니다. | 예약 호스트: `k8s-registry.cloudia.internal`, `object-storage.cloudia.internal`, `docker.io`, `registry-1.docker.io`, `quay.io`, `registry.k8s.io`, `ghcr.io` 및 `cloudia.internal` 자체와 그 하위 전체, punycode(`xn--`) 라벨, `_` 로 시작하는 값 |
| **이름** | 자유 문자열 | 선택입니다. 최대 `255자`. | 식별용 표시 이름 |
| **CA 인증서** | PEM 형식 인증서 | 등록 시 필수입니다. `CERTIFICATE` 블록만 허용하며, `BEGIN`·`END` 가 짝을 이뤄야 합니다. | 여러 장을 이어 붙일 수 있습니다. 개인 키는 붙여넣지 마세요. |

> ⚠️ **주의:** CA 신뢰는 **TLS 검증만** 해결합니다. 인증이 필요한 레지스트리라면 네임스페이스별로 `imagePullSecret` 을 따로 만들어야 합니다.

| **타겟 그룹** | 클러스터 생성 시 자동으로 준비된 타겟 그룹이 삭제됩니다. |
| **클러스터 네트워크 구성** | 클러스터에 연결된 네트워크 구성이 정리됩니다. |

## 워커 노드 추가
상세 화면의 **노드**에서 워커 노드를 추가합니다.

> 💡 **참고:** 클러스터 상태가 `UP`일 때만 **워커 노드 추가** 버튼이 활성화됩니다.

### 기본 정보
- **인스턴스 구성**: 인스턴스 타입 선택 또는 직접 입력 방식으로 vCPU, 메모리를 설정합니다. GPU 인스턴스 타입을 선택하면 GPU 패스스루가 적용됩니다. 가속기를 사용하는 워커 노드를 추가할 때는 대상 호스트의 가속기 가용 용량을 검증하며, 가용 용량이 부족하면 노드 추가가 차단됩니다.
- **워커 노드 수**: 추가할 워커 노드 수를 입력합니다.
- **디스크 크기 설정**: 부팅 디스크 크기를 입력합니다.
- **스토리지 도메인**: 인스턴스를 배치할 스토리지 도메인을 선택합니다. (선택)

### 사용자 계정
- 사용자 계정과 인증 방식을 입력합니다.
- 비밀번호 또는 SSH 키를 사용할 수 있습니다.

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **인스턴스 구성** | 인스턴스 타입 또는 직접 입력 | 유효한 값 선택 필요 | **필수** |
| **워커 노드 수** | 정수 | 최소 `1`, 최대 `5`(가용 IP 범위 내) | **필수** |
| **디스크 크기 설정** | 정수 | 최소 `32 GB` 이상 | **필수** |
| **스토리지 도메인** | 사용 가능한 스토리지 도메인 | 선택 가능 | 선택 |
| **사용자 계정/인증 방식** | 사용자명 + 비밀번호 또는 SSH 키 | 유효성 검사 통과 필요 | **필수** |

> 💡 **참고:** 생성 후 상태는 `CREATING` 을 거쳐 `READY` 로 바뀔 수 있습니다.

## 워커 노드 삭제
상세 화면의 **노드**에서 워커 노드를 선택한 뒤 삭제할 수 있습니다.

1. **워커 노드 선택:** 노드에서 삭제하려는 워커 노드를 선택한 뒤 **워커 노드 삭제** 버튼을 클릭합니다.
2. **삭제 확인:** 노드 삭제 확인 창이 나타납니다.
3. **삭제 실행:** 삭제 대상 노드를 다시 확인한 뒤 **삭제** 버튼을 눌러 진행합니다.

> ⚠️ **주의:** 컨트롤 플레인 노드는 삭제 대상이 아닙니다.

> ⚠️ **주의:** `PENDING`, `CREATING`, `DELETING` 상태의 워커 노드는 삭제할 수 없습니다.

## 워커 오토 스케일링 그룹 생성
워커 오토 스케일링 그룹 생성 화면에서 시작 템플릿, 타겟 그룹, 그룹 정보, 조정 정책을 입력합니다.

### 기본 정보
- **이름**: 그룹 이름을 입력합니다.

### 시작 템플릿
- **인스턴스 구성**: 인스턴스 타입 선택 또는 직접 입력 방식으로 vCPU, 메모리를 설정합니다.
- **무중단 증설**: 인스턴스 구성 바로 아래에 있습니다. `사용함`(기본값)이면 그룹이 만드는 워커 노드가 노드를 종료하지 않고 vCPU·메모리를 늘릴 수 있는 헤드룸을 받고, `사용 안 함`이면 헤드룸 없이 현재 사양 그대로 만들어집니다. 상한 산정 기준은 [인스턴스 > 무중단 증설 상한 산정 기준](../../vm/instance/instance.md#무중단-증설-상한-산정-기준)과 같습니다.
- **디스크 크기 설정**: 부팅 디스크 크기를 입력합니다.
- **스토리지 도메인**: 인스턴스를 배치할 스토리지 도메인을 선택합니다. (선택)
- **사용자 계정 및 인증 방식**: 사용자 이름, 비밀번호 또는 SSH 키를 설정합니다.

### 타겟 그룹 설정
- 타겟 그룹 생성 여부를 선택합니다.
- 생성하는 경우 프로토콜과 포트 번호를 입력합니다.

### 그룹 정보
- **원하는 용량**: 최소~최대 사이 값
- **최소 용량**
- **최대 용량**
- **스케일 간격** (최소 `180`초)

### 조정 정책
- **지표 유형**: `CPU 평균 사용량` 또는 `메모리 평균 사용량`
- **스케일 인 대상값**
- **스케일 아웃 대상값**

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **이름** | 영문/숫자/`-`/`_` | 최대 `80자` | **필수** |
| **설명** | 문자열 | 최대 `200자` | 선택 |
| **인스턴스 구성** | 인스턴스 타입 또는 직접 입력 | 유효한 값 선택 필요 | **필수** |
| **디스크 크기 설정** | 정수 | 최소 `32 GB` 이상 | **필수** |
| **스토리지 도메인** | 사용 가능한 스토리지 도메인 | 선택 가능 | 선택 |
| **사용자 계정/인증 방식** | 사용자명 + 비밀번호 또는 SSH 키 | 유효성 검사 통과 필요 | **필수** |
| **타겟 그룹 포트** | 1~65535 | 타겟 그룹 생성 시 입력 | 조건부 필수 |
| **그룹 정보** | 원하는/최소/최대 용량, 스케일 간격 | 최소 용량은 `1` 이상, 최대 용량은 최소 용량보다 커야 함, 스케일 간격은 `180`초 이상 | **필수** |
| **조정 정책** | 지표 유형, 스케일 인/아웃 대상값 | 스케일 아웃 값은 스케일 인 값보다 커야 함 | **필수** |

> 💡 **참고:** 워커 오토 스케일링 그룹의 노드는 클러스터와 같은 버전과 네트워크 구성을 따릅니다.

## 스토리지 클래스 생성
스토리지 섹션에서 스토리지 클래스를 생성합니다.

1. **스토리지 섹션 이동:** 클러스터 상세 화면 하단의 **스토리지** 섹션을 선택합니다.
2. **사이드네비 전환:** 좌측 사이드네비에서 `스토리지 클래스`를 선택합니다.
3. **생성 페이지 이동:** **스토리지 클래스 생성** 버튼을 클릭합니다.
4. **정보 입력:** 이름, 파일 시스템, 반환 정책을 입력합니다.
5. **생성:** **생성** 버튼을 눌러 스토리지 클래스를 생성합니다.

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **이름** | 소문자, 숫자, `-` | 최대 `60자` | **필수** |
| **파일 시스템** | 선택 가능한 파일 시스템 | 선택 필요 | **필수** |
| **반환 정책** | `Delete` \| `Retain` | 값 중 하나를 선택해야 함 | **필수** |

> 💡 **참고:** 파일 시스템은 클러스터와 연결된 네트워크에서 사용할 수 있는 항목만 선택할 수 있습니다.

## PVC 생성
스토리지 섹션에서 PVC를 생성합니다.

1. **스토리지 섹션 이동:** 클러스터 상세 화면 하단의 **스토리지** 섹션을 선택합니다.
2. **사이드네비 전환:** 좌측 사이드네비에서 `PVC`를 선택합니다.
3. **생성 페이지 이동:** **PVC 생성** 버튼을 클릭합니다.
4. **정보 입력:** 이름, 용량, 스토리지 클래스, 네임스페이스, 접근 모드를 입력합니다.
5. **생성:** **생성** 버튼을 눌러 PVC를 생성합니다.

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **이름** | 소문자, 숫자, `-` | 최대 `60자` | **필수** |
| **용량** | 정수 + 단위 | 최소 `1 GB` 이상 | **필수** |
| **스토리지 클래스** | 기존 스토리지 클래스 1개 | 선택 필요 | **필수** |
| **네임스페이스** | 선택 가능한 네임스페이스 1개 | 선택 필요 | **필수** |
| **접근 모드** | `ReadOnlyMany` \| `ReadWriteMany` | 값 중 하나를 선택해야 함 | **필수** |

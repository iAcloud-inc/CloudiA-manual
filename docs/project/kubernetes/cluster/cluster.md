# 클러스터

## 화면 개요

**클러스터**는 쿠버네티스 클러스터를 만들고, 노드·워크로드·네트워크·스토리지·접근 권한을 관리하는 화면입니다. LNB의 `쿠버네티스 > 클러스터`에서 들어갑니다.

| 화면 | 설명 |
|------|------|
| 목록 | 클러스터 상태를 확인하고 생성, 삭제, 실행, 종료, 생성 실패 복구를 시작합니다. |
| 생성 | `간편 생성` 또는 `직접 설정`으로 클러스터를 만듭니다. |
| 상세 | 탭 9개로 클러스터를 살펴보고 노드·스토리지·접근 권한·인증서 같은 후속 작업을 합니다. |

> 💡 **참고:** 권한이 없으면 버튼이 비활성화되고, 버튼에 마우스를 올리면 "권한이 없습니다. 관리자에게 권한을 요청하세요."가 표시됩니다. 다른 이유로 비활성화된 버튼도 마우스를 올리면 막힌 이유가 표시됩니다.

## 클러스터 목록

클러스터 목록을 확인합니다. 한 페이지에 10개씩 표시하며, 기본 정렬은 생성 일시 내림차순입니다.

> 💡 **공통 조건:** 목록 왼쪽의 **라디오 버튼**으로 클러스터를 1개 선택한 뒤 상단 버튼으로 작업합니다. 행별 메뉴는 없습니다.

### 테이블 컬럼
| 컬럼 | 설명 |
|------|------|
| **이름** | 클러스터 이름입니다. 클릭하면 상세 화면(개요 탭)으로 이동합니다. |
| **ID** | 클러스터의 고유 ID입니다. |
| **버전** | 클러스터의 쿠버네티스 버전입니다. |
| **API 서버 엔드포인트 IP** | API 서버 접근에 쓰는 엔드포인트 IP 주소입니다. 정렬할 수 없습니다. |
| **상태** | 클러스터 상태입니다. 아래 [상태 라벨](#상태-라벨)을 참고하세요. |
| **컨트롤 플레인** | `정상 수/목표 수` 형식입니다(예: 목표 3대 중 2대만 정상이면 `2/3`). 목표 수는 클러스터를 만들 때 고른 컨트롤 플레인 수입니다. |
| **워커 노드** | `정상 워커 수/전체 워커 수` 형식입니다. |
| **생성 일시** | 생성 일시입니다. |

### 상단 버튼
버튼 순서는 `생성` | `삭제` ‖ `실행` | `종료` 입니다. `생성 실패` 상태의 클러스터를 고르면 `실행`·`종료` 자리에 `생성 실패 복구` 버튼 하나만 표시됩니다.

| 버튼 | 활성 조건 | 비활성일 때 표시되는 이유 |
|------|------|------|
| `생성` | 생성 권한 | 권한 없음 |
| `삭제` | 삭제 권한 + 클러스터 1개 선택 | "선택된 항목이 없습니다." |
| `실행` | 선택한 클러스터가 `정지됨` | `실행 중`·`경고`·`CA 인증서 갱신 실패`: "이미 실행 중입니다." / 작업 중인 상태: "다른 작업을 처리하는 중입니다. 끝난 뒤 다시 시도하세요." / 그 밖: "현재 상태에서는 사용할 수 없습니다." |
| `종료` | 선택한 클러스터가 `실행 중`·`경고`·`CA 인증서 갱신 실패`·`에러`·`알 수 없음` | `정지됨`: "이미 정지되어 있습니다." / 작업 중인 상태: "다른 작업을 처리하는 중입니다. 끝난 뒤 다시 시도하세요." / 그 밖: "현재 상태에서는 사용할 수 없습니다." |
| `생성 실패 복구` | `생성 실패` 상태의 클러스터를 골랐을 때만 표시 | 권한 없음 |

> 💡 **참고:** "작업 중인 상태"는 `생성 중`·`삭제 중`·`종료 중`·`부팅 중`·`CA 인증서 갱신 중`·`업데이트 중`·`대기 중`입니다.

각 작업 절차는 [클러스터 생성](#클러스터-생성), [클러스터 삭제](#클러스터-삭제), [클러스터 실행·종료](#클러스터-실행종료), [생성 실패 복구](#생성-실패-복구)를 참고하세요.

### 상태 라벨
| 상태 | 색 | 의미 |
|------|------|------|
| `실행 중` | 초록 | 클러스터가 동작 중입니다. |
| `경고` | 노랑 | 동작 중이지만 확인할 문제가 있습니다(예: 컨트롤 플레인 수가 목표와 다름). |
| `에러` | 빨강 | 오류 상태입니다. |
| `알 수 없음` | 회색(속 빈 점) | 상태를 판정하지 못했습니다. |
| `정지됨` | 회색 | 모든 노드 VM이 종료된 상태입니다. |
| `부팅 중` | 노랑 | 클러스터를 다시 시작하는 중입니다. |
| `종료 중` | 노랑 | 클러스터를 정지하는 중입니다. |
| `생성 중` | 파랑 | 생성 또는 생성 실패 복구가 진행 중입니다. |
| `생성 실패` | 빨강 | 생성에 실패했습니다. [생성 실패 복구](#생성-실패-복구)로 이어서 만들 수 있습니다. |
| `업데이트 중` | 파랑 | 업그레이드 같은 변경 작업이 진행 중입니다. |
| `대기 중` | 파랑 | 작업을 기다리거나 마무리하는 중입니다. |
| `삭제 중` | 주황 | 삭제가 진행 중입니다. |
| `삭제 실패` | 빨강 | 삭제에 실패했습니다. |
| `삭제됨` | 회색 | 삭제되었습니다. |
| `CA 인증서 갱신 중` | 파랑 | 인증서 재설정이 진행 중입니다. |
| `CA 인증서 갱신 실패` | 빨강 | 인증서 재설정에 실패했습니다. |

> 💡 **참고:** `실행`·`종료`·`생성 실패 복구`를 누르면 응답을 기다리지 않고 상태가 바로 `부팅 중`·`종료 중`·`생성 중`으로 바뀝니다. 작업이 끝나면 실제 상태로 돌아옵니다.

## 클러스터 생성

목록에서 `생성`을 클릭하면 **클러스터 생성** 화면이 열립니다. 맨 위에서 생성 방식을 고릅니다.

- **간편 생성**(기본): 꼭 필요한 항목만 입력하고 나머지는 권장값으로 만듭니다.
- **직접 설정**: 모든 항목을 직접 지정합니다.

두 방식은 입력값을 공유합니다. 직접 설정에서 바꾼 값은 간편 생성으로 돌아와도 유지되고 그대로 생성 요청에 들어갑니다.

> 💡 **참고:** 필수 항목(클러스터 이름, 쿠버네티스 버전, 디스크 크기, VPC, 서브넷, 노드 사양, 컨트롤 플레인 노드 수, 사용자 계정)을 모두 채워야 하단 `생성` 버튼이 활성화됩니다. `취소`를 누르면 목록으로 돌아갑니다.

### 간편 생성
위에서부터 다음 항목을 입력합니다.

1. **기본 정보**: **클러스터 이름**을 입력합니다.
2. **네트워크**: **VPC**와 **서브넷**을 고릅니다. 서브넷은 VPC를 고른 뒤에 선택할 수 있습니다. 서브넷을 고르면 "이 서브넷에서 쓸 수 있는 IP {{available}}개 · 클러스터가 {{required}}개를 사용합니다." 안내가 표시됩니다. 클러스터는 컨트롤 플레인 노드 수보다 1개 많은 IP를 씁니다.
3. **운영 방식**: 카드 2장 중 하나를 고릅니다.
   - `개발·테스트용`: 컨트롤 플레인 노드 1대. 그 1대가 멈추면 클러스터 전체가 멈춥니다.
   - `운영용 (고가용성)`(기본): 컨트롤 플레인 노드 3대. 1대가 멈춰도 클러스터는 계속 동작합니다.
4. **노드 사양**: 컨트롤 플레인 노드 1대당 사양을 고릅니다.

   | 카드 | vCPU · 메모리 |
   |------|------|
   | `소형` | vCPU 2 · 4 GB |
   | `중형`(권장, 기본) | vCPU 4 · 8 GB |
   | `대형` | vCPU 8 · 16 GB |

   같은 vCPU·메모리의 인스턴스 타입이 있으면 카드 설명이 `타입이름 (vCPU n · m GB)`로 바뀌고 그 타입으로 만듭니다. 없으면 vCPU·메모리를 직접 지정해 만듭니다.
5. **사용자 계정**: **사용자 이름**과 **인증 방식**을 입력합니다. [사용자 계정](#사용자-계정)과 같습니다.
6. **권장값 요약**: 나머지 항목에 적용될 값을 보여 줍니다. 항목마다 `변경` 링크가 있고, 누르면 **직접 설정**으로 바뀌면서 해당 섹션으로 이동합니다. 직접 바꾼 항목에는 `변경됨` 배지가 붙습니다.

   | 항목 | 권장값 |
   |------|------|
   | 쿠버네티스 버전 | 등록된 버전 중 가장 높은 버전 |
   | 디스크 크기 설정 | 32 GB |
   | 스토리지 도메인 | `자동 선택` |
   | 추가 보안그룹 | `없음` |
   | 선호도 그룹 | `없음` |
   | CA 인증서 | `등록 안 함` |

> 💡 **참고:** 서브넷의 가용 IP가 `노드 수 + 1`보다 적으면 해당 운영 방식 카드가 비활성화됩니다.

> 💡 **참고:** 간편 생성은 무중단 증설을 항상 `사용함`으로 만듭니다. 관리자 정책이 무중단 증설을 꺼 두었으면 `사용 안 함`으로 만들어집니다.

### 직접 설정
왼쪽에 입력 폼, 오른쪽에 섹션 이동 목록(기본 정보 / 네트워크 / 컨트롤 플레인 / 사용자 계정 / 고급 설정)이 있습니다. 섹션을 다 채우면 완료 표시가 붙습니다.

#### 기본 정보
- **클러스터 이름**을 입력합니다.

#### 네트워크
- **VPC**를 고릅니다. 생성 후에는 바꿀 수 없습니다.
- **서브넷**을 고릅니다. VPC를 먼저 골라야 합니다. 생성 후에는 바꿀 수 없습니다.
- 필요하면 **추가 보안그룹**을 고릅니다(최대 4개). 클러스터 동작에 필요한 규칙은 자동으로 적용됩니다.

> 💡 **참고:** VPC를 바꾸면 서브넷과 보안그룹 선택이 풀립니다.

#### 컨트롤 플레인
1. **인스턴스 구성**: `인스턴스 타입 선택` 또는 `직접 입력`으로 노드 사양을 정합니다. 직접 입력은 최소 vCPU 2, 메모리 2048 MiB입니다. 인스턴스 타입 목록에서는 메모리 1 GiB 타입, vCPU 1개 타입, GPU·NPU가 붙은 타입이 빠집니다.
2. **무중단 증설**: `사용함`이면 노드를 종료하지 않고 vCPU·메모리를 늘릴 수 있습니다. 상한은 생성 후 바꿀 수 없습니다. 관리자 정책이 꺼져 있으면 "이 클러스터에서는 무중단 증설을 사용할 수 없습니다. 관리자에게 문의하세요."가 표시됩니다.
3. **쿠버네티스 버전**: 가장 높은 버전 뒤에 `(권장)`이 붙습니다.
4. **디스크 크기 설정**, **스토리지 도메인**: 아래 [디스크 및 스토리지 도메인](#디스크-및-스토리지-도메인)을 참고하세요.
5. **컨트롤 플레인 노드 수**: `1` 또는 `3`을 고릅니다. 생성 후에는 바꿀 수 없습니다. 서브넷 가용 IP가 `값 + 1`보다 적은 항목은 비활성화됩니다. 워커 노드는 생성 후에 추가합니다.

> 💡 **참고:** 선택할 수 있는 **쿠버네티스 버전**은 관리자가 등록한 쿠버네티스 이미지에 따라 정해집니다. 현재 제공 버전은 `1.36`, `1.37` 입니다(`1.35` 이하는 제공하지 않습니다).

##### 디스크 및 스토리지 도메인
- **디스크 크기 설정**: 노드 VM의 디스크 크기입니다. 노드 운영체제와 컨테이너 이미지가 여기에 저장됩니다. 최소·기본값은 `32 GB`입니다.
- **스토리지 도메인**(선택): 노드 디스크가 저장될 곳입니다. 어디에 저장하느냐에 따라 노드가 놓일 물리 서버가 정해집니다. 쿠버네티스 버전을 먼저 골라야 선택할 수 있습니다. 고르지 않으면 사용 가능한 위치 중에서 자동으로 고릅니다.

> 💡 **참고:** 스토리지 도메인을 자동으로 고르게 두면, 컨트롤 플레인 VM 이 호스트 자원 부족 등으로 실행되지 않을 때 다음 순위 스토리지 도메인의 이미지 사본으로 그 노드를 다시 만듭니다. 이미 실행된 노드는 그대로 둡니다.

> ⚠️ **주의:** 스토리지 도메인을 한 곳으로 지정하면 컨트롤 플레인 노드가 모두 그 위치를 쓰는 물리 서버에 묶입니다. 그 서버가 멈추면 고가용성이 의미를 잃습니다. 또 다른 도메인으로 넘어가지 않으므로, VM 을 실행하지 못하면 생성이 실패하고 요청 내역에 원인과 "리소스를 정리하거나 다른 스토리지 도메인을 골라 다시 시도하세요." 안내가 남습니다. 이때는 [생성 실패 복구](#생성-실패-복구)로 이어서 만들 수 있습니다.

#### 사용자 계정
- **사용자 이름**을 입력합니다. 이 계정으로 노드 VM에 처음 로그인합니다.
- **인증 방식**은 비밀번호와 SSH 키 중 1개 이상을 등록합니다.
  - 비밀번호: `등록`을 눌러 **새 비밀번호**와 **비밀번호 확인**을 입력합니다. 등록한 뒤에는 `변경`·`삭제`할 수 있습니다.
  - SSH 키: 최대 5개까지 고를 수 있습니다.

#### 고급 설정
선택 항목입니다.

- **선호도 그룹**: `추가`로 프로젝트의 선호도 그룹을 고릅니다. 노드를 서로 다른 호스트에 분산하려면 빈 VM 반선호(anti-affinity) 그룹을 만들어 고르세요. 생성되는 노드는 고른 그룹에 자동 등록됩니다.
- **CA 인증서**: 클릭하면 **CA 인증서 설정** 창이 열립니다. **CA 인증서**(`.crt` 파일)와 **개인 키**(`.key` 파일)를 모두 고른 뒤 `추가`를 클릭합니다. 등록하면 입력칸에 `CA파일명 / 키파일명`이 표시됩니다. CA 를 등록하지 않으면 시스템이 자동으로 만듭니다.

> ⚠️ **주의:** 강제(enforcing) 선호도 그룹은 조건을 충족하는 가용 호스트가 없으면 클러스터·노드 생성이 실패할 수 있습니다. 강제는 선호도 규칙을 충족할 수 없으면 노드를 실행하지 않고, 비강제는 충족하지 못해도 실행합니다.

> ⚠️ **주의:** CA 인증서와 개인 키 중 하나만 등록할 수 없습니다.

##### CA 파일 직접 생성 예시
CA 파일을 직접 준비하려면 `openssl`로 개인 키와 자체 서명 인증서를 생성할 수 있습니다.

```bash
# 개인 키(ca.key) 생성
openssl genrsa -out ca.key 4096

# 자체 서명 CA 인증서(ca.crt) 생성 (유효기간 10년)
openssl req -x509 -new -nodes -key ca.key -days 3650 -subj "/CN=kubernetes-ca" -out ca.crt
```

> 💡 **참고:** 생성한 `ca.crt`(CA 인증서)와 `ca.key`(개인 키)를 **CA 인증서 설정** 창에서 각각 고릅니다. 같은 파일로 [인증서 재설정](#인증서-재설정)도 할 수 있습니다.

### 생성 확인 창
`생성`을 누르면 바로 생성되지 않고 **클러스터 생성** 확인 창이 열립니다.

- 이름, VPC, 서브넷, 컨트롤 플레인 노드 수, 노드 사양, 무중단 증설, 사용자명, 쿠버네티스 버전, 디스크 크기 설정, 스토리지 도메인, 추가 보안그룹, 선호도 그룹, CA 인증서 순으로 표시됩니다.
- 표 아래에 합계 "컨트롤 플레인 노드 {{count}}대 · 합계 {{vcpu}} vCPU · {{memory}}"가 표시됩니다.
- "위 구성으로 클러스터를 생성하시겠습니까?"에서 `생성`을 누르면 생성이 시작되고 목록으로 돌아갑니다. `취소`를 누르면 입력값을 유지한 채 생성 화면으로 돌아갑니다.

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **클러스터 이름** | 영문 소문자, 숫자, `-` | 최대 `40자`. `-`나 숫자로 시작할 수 없음 | **필수** |

| **인스턴스 구성** | 인스턴스 타입 또는 직접 입력 | 직접 입력은 최소 vCPU `2`, 메모리 `2048 MiB` | **필수** |

| **사용자 이름** | 영문 소문자, 숫자, `_`, `-` | 영문 소문자로 시작, `4~20자`, 시스템 예약어 불가 | **필수** |
| **비밀번호** | 영문, 숫자, 특수문자(`!@#$%^&*()_+-=~[]{}<>?,.` 와 공백) | `4~20자`, 확인 값과 일치 | 비밀번호·SSH 키 중 1개 이상 **필수** |
| **SSH 키** | 등록된 SSH 키 | 최대 `5개` | 비밀번호·SSH 키 중 1개 이상 **필수** |
| **CA 인증서/개인 키** | `.crt` / `.key` 파일 | 둘 다 등록하거나 둘 다 비움 | 선택 |

### 생성 결과
- 생성 요청 직후 목록에 새 클러스터가 `생성 중` 상태로 표시됩니다.
- 완료되면 `실행 중` 상태로 바뀝니다.
- 클러스터와 함께 컨트롤 플레인 노드, 로드밸런서, 타겟 그룹이 자동으로 준비됩니다.

> ⚠️ **주의:** 프로젝트 자원이나 서브넷의 사용 가능 IP가 부족하면 생성이 실패할 수 있습니다.

> 💡 **참고:** 생성에 실패하면 상태가 `생성 실패`로 표시됩니다. 지우고 다시 만들지 않아도 [생성 실패 복구](#생성-실패-복구)로 이어서 만들 수 있습니다.

## 클러스터 상세

목록에서 클러스터 이름을 클릭하면 **클러스터 상세** 화면이 열립니다.

### 헤더
스크롤해도 화면 위에 고정됩니다.

- 클러스터 이름과 상태
- CA 인증서 만료가 30일 이내이면 `인증서 만료 D-n` 표시(만료 후에는 `인증서 만료됨`). 7일 이하면 빨강, 그 밖에는 노랑입니다.

> 💡 **참고:** 헤더에는 작업 버튼이 없습니다. 실행·종료·삭제는 [클러스터 목록](#클러스터-목록)에서, 업그레이드는 개요 탭 위 알림 줄과 `유지 관리` 탭에서, 인증서 재설정과 레지스트리 신뢰는 `유지 관리` 탭에서, kubeconfig 발급은 `접근 관리` 탭에서 합니다.

### 탭 구성
| 순서 | 탭 | 내용 | 클러스터가 실시간 상태가 아닐 때 |
|------|------|------|------|
| 1 | `개요` | 이슈·지표·노드·구성 요소 요약 | 탭은 열리지만 본문 대신 안내 문구 표시 |
| 2 | `노드` | 노드, 워커 오토 스케일링 그룹 | 열림(실시간 정보 제외) |
| 3 | `워크로드` | 파드, 디플로이먼트, 데몬셋 | 탭 비활성 |
| 4 | `네트워크` | 네트워크 정보, 쿠버네티스 서비스, 서비스 로드 밸런서 | 열림(실시간 정보 제외) |
| 5 | `스토리지` | 스토리지 클래스, PVC | 열림(목록 대신 안내 문구 표시) |
| 6 | `AI 가속기` | 가속기 노드, 가속기 Operator | 탭 비활성 |
| 7 | `접근 관리` | kubeconfig 발급, 접근 권한 | 탭 비활성 |
| 8 | `이벤트` | 쿠버네티스 이벤트 | 탭 비활성 |
| 9 | `유지 관리` | 기본 정보, 버전·업그레이드, 인증서, 레지스트리 신뢰 | 열림 |

실시간 상태는 클러스터 상태가 `실행 중`·`경고`·`CA 인증서 갱신 중`·`CA 인증서 갱신 실패`일 때입니다. 그 밖의 상태에서는 다음 안내가 표시됩니다.

- `정지됨`·`종료 중`·`부팅 중`: "클러스터가 정지되어 실시간 리소스·모니터링 정보를 표시하지 않습니다."
- 그 밖: "현재 클러스터 상태에서는 실시간 정보를 표시할 수 없습니다."

> 💡 **참고:** 클러스터가 `생성 중`·`삭제 중`·`종료 중`·`부팅 중`·`CA 인증서 갱신 중`이면 상세 정보를 30초마다 다시 읽습니다.

> 💡 **참고:** 워크로드·네트워크·스토리지·접근 관리·이벤트 탭의 네임스페이스 필터 선택은 탭을 옮겨도 유지됩니다. 다른 클러스터로 이동하면 초기화됩니다.

### 개요 탭 위 알림 줄
개요 탭 본문 위에 상황에 따라 다음 줄이 표시됩니다.

| 알림 줄 | 표시 조건 | 내용 |
|------|------|------|
| **진행 중 작업** | 상태가 `업데이트 중`·`CA 인증서 갱신 중`·`종료 중`·`부팅 중`·`삭제 중` | 작업 이름(예: "버전 업그레이드 진행 중")과 진행 상황. 업그레이드면 대상 버전과 "컨트롤 플레인 교체 중 n/m" 또는 "워커 노드 교체 중 · 남은 n대"가 표시됩니다. 작업이 끝나면 사라집니다. |
| **워커 버전 뒤처짐** | 워커 노드 그룹 소속 노드가 클러스터 버전보다 낮을 때 | 뒤처진 노드 수와 옮기는 방법을 안내합니다. [클러스터 업그레이드](#클러스터-업그레이드)를 참고하세요. |
| **업그레이드 가능** | 업그레이드할 버전이 있을 때 | "{{version}} 버전으로 업그레이드할 수 있습니다."와 `업그레이드` 버튼. 멈춘 업그레이드가 있으면 `업그레이드 이어서 진행` 버튼이 표시됩니다. |
| **생성 실패** | 상태가 `생성 실패` | `생성 실패 복구` 버튼 |
| **구성 어긋남** | 컨트롤 플레인 수가 목표와 다를 때 | "컨트롤 플레인이 {{healthy}}/{{total}}개이고 목표는 {{desired}}개입니다."와 `구성 맞추기` 버튼 |

> 💡 **참고:** 진행 중 작업이 있으면 워커 버전 뒤처짐·업그레이드 가능·구성 어긋남 줄은 표시되지 않습니다.

### 개요
클러스터가 실시간 상태일 때 표시됩니다. 대부분의 값은 30초마다 갱신됩니다.

| 영역 | 내용 |
|------|------|
| **이슈 요약** | 문제가 없으면 `정상` 배지와 "주의할 항목이 없습니다."가 표시됩니다. 문제가 있으면 "주의가 필요한 항목 n건" 아래에 항목별 설명과 해당 탭으로 가는 버튼이 표시됩니다. 항목 종류: 노드 불일치, 노드 NotReady, 노드 리소스 압박, 노드 디스크, 파드 수 상한 임박, 문제 파드, 가용성 저하, PVC 대기, 인증서, 수집 불가, API 서버, 클러스터 상태 |
| **핵심 지표** | `노드 Ready`, `CPU 사용률`, `메모리 사용률`, `디스크 사용률`, `AI 가속기 할당`, `경고 이벤트` 카드. CPU·메모리 카드의 `추이 보기 ›`를 누르면 **리소스 추이** 창이 열리고, AI 가속기·경고 이벤트 카드를 누르면 해당 탭으로 이동합니다. |
| **노드 상태** | 노드별 VM 상태, 쿠버네티스 상태, CPU·메모리·디스크 사용률. 컨트롤 플레인과 워커 노드로 나눠 표시합니다. `전체 보기`를 누르면 노드 탭으로 이동합니다. |
| **컨트롤 플레인** | API 서버, etcd, 스케줄러, 컨트롤러 매니저, CoreDNS, CNI, CSI의 상태와 컨트롤 플레인 평균 부하(CPU·메모리·디스크) |
| **워크로드** | 파드·디플로이먼트·데몬셋·스테이트풀셋 개수와 문제 수. 항목을 누르면 워크로드 탭의 해당 목록으로 이동합니다(스테이트풀셋 제외). |
| **문제 파드** | 문제가 있는 파드. 없으면 "문제 파드가 없습니다." |
| **최근 경고 이벤트** | 최근 Warning 이벤트. `전체 보기`를 누르면 이벤트 탭으로 이동합니다. |

**리소스 추이** 창에서는 CPU·메모리·네트워크 탭과 기간(`1시간`·`6시간`·`24시간`·`7일`)을 골라 평균과 최대 노드의 사용량 추이를 봅니다. 아래에는 그 기간의 작업·경고가 함께 표시됩니다.

> 💡 **참고:** 클러스터에 metrics-server 가 없으면 CPU·메모리는 노드 VM 게스트 메트릭으로 채우며, 값 옆에 `노드 VM 기준`이 표시됩니다.

| **메모리** | 메모리 크기입니다. |

- 문제가 있으면 맨 위에 경고가 표시됩니다(예: "NotReady: 노드가 Ready 상태가 아니라 새 파드가 배치되지 않습니다.").

### 워크로드
파드, 디플로이먼트, 데몬셋을 조회합니다. 조회 전용이라 생성·삭제 버튼은 없습니다.

- 상단 왼쪽의 `파드`·`디플로이먼트`·`데몬셋` 버튼으로 종류를 고릅니다. 버튼 라벨 뒤에 개수가 붙습니다.
- 상단 오른쪽에서 **네임스페이스**를 거르고 `이름` 또는 `상태`로 검색합니다. 클러스터 agent 가 구버전이면 검색과 네임스페이스 필터가 숨겨집니다.
- 상태는 쿠버네티스 값을 그대로 표시하고, 앞의 점 색으로 정상(초록)·진행(노랑)·오류(빨강)를 구분합니다.

| 종류 | 컬럼 |
|------|------|
| 파드 | 이름, 네임스페이스, 상태, 준비, 재시작, 소유자, 노드, 파드 IP, 경과 시간 |
| 디플로이먼트 | 이름, 네임스페이스, 준비, 최신, 상태, 배포 전략, 경과 시간 |
| 데몬셋 | 이름, 네임스페이스, 준비, 최신, 상태, 업데이트 전략, 경과 시간 |

- 파드 이름을 클릭하면 파드 상세 창(네임스페이스·노드·IP·QoS, 컨테이너 상태, 최근 이벤트 5건)이 열립니다.
- 디플로이먼트·데몬셋 이름을 클릭하면 상세 창(준비·최신·사용 가능 수, 소속 파드, 최근 이벤트 5건)이 열립니다.
- 파드의 **소유자**가 디플로이먼트·데몬셋이면 클릭해 해당 목록으로 이동할 수 있습니다.

> 💡 **참고:** 전체 파드 목록을 가져올 수 없는 환경이나 agent 가 구버전인 클러스터에서는 `kube-system` 파드만 표시된다는 안내가 나옵니다.

### 스토리지
`스토리지 클래스` 카드와 `PVC` 카드가 위아래로 표시됩니다. 클러스터가 `생성 중`이거나 실시간 상태가 아니면 두 카드 모두 목록 대신 안내 문구가 표시됩니다.

#### 스토리지 클래스 카드
- 상단 버튼: `생성`([스토리지 클래스 생성](#스토리지-클래스-생성)), `삭제`(1개 선택)

| 컬럼 | 설명 |
|------|------|
| **이름** | 스토리지 클래스 이름입니다. 기본 스토리지 클래스이면 `기본` 배지가 붙습니다. |
| **파일 시스템** | NFS 서버가 같은 CloudiA 파일 시스템이 있으면 그 이름입니다. 클릭하면 파일 시스템 상세로 이동합니다. 없으면 `-`입니다. |
| **경로** | `server:share` 형태의 NFS 경로입니다. |
| **프로비저너** | `provisioner` 값입니다. |
| **반환 정책** | `Delete` 또는 `Retain`입니다. |
| **볼륨 바인딩 모드** | `volumeBindingMode` 값입니다. |
| **볼륨 확장 허용** | `가능` 또는 `불가능`입니다. |
| **경과 시간** | 생성 후 경과 시간입니다. |

**스토리지 클래스 삭제**: 항목을 고르고 `삭제`를 클릭하면 확인 창이 열립니다. 이미 바인딩된 PVC와 볼륨은 그대로 사용할 수 있습니다.

### AI 가속기
GPU·NPU가 붙은 노드와 가속기 Operator 를 관리합니다.

- **요약 카드**: `AI 가속기 노드`(GPU·NPU 노드 수), `가속기 장수`, `인식된 장수`(Operator 가 인식한 장수 / 판정 가능 장수), `가속기 Operator`(설치된 수 / 필요한 수)
- **AI 가속기 노드**: 가속기가 붙은 노드만 표시합니다. 컬럼은 노드, 노드 풀, 타입(`GPU`·`NPU`), AI 가속기(제품명 × 장수), 가속기 Operator, Operator 인식(`인식 안 됨`이면 노랑)입니다. 노드가 없으면 "GPU·NPU 가 붙은 워커 노드를 추가하면 여기서 가속기와 Operator 를 관리할 수 있습니다."가 표시됩니다.
- **가속기 Operator**: 왼쪽 목록에서 Operator 를 고르면 오른쪽에 상세가 표시됩니다. 목록은 `주의 필요`, `설치됨`, `대상 노드 없음`, `관리 미지원` 순으로 묶입니다.

| Operator 상태 | 의미 |
|------|------|
| `미설치` | 설치되지 않았습니다. |
| `직접 설치됨` | CloudiA 가 설치하지 않은 Operator 가 감지되었습니다. CloudiA 는 조회만 하고 설정·제거하지 않습니다. |
| `설치 중` | 설치가 진행 중입니다. 설치 중에는 설정·제거를 할 수 없습니다. |
| `정상` | 설치되었고 Operator 파드가 모두 실행 중입니다. |
| `주의` | 설치되었지만 실패한 파드 등 확인할 문제가 있습니다. |

> 💡 **참고:** 관리할 수 있는 Operator 는 **NVIDIA GPU Operator** 하나입니다. NPU 등 다른 제조사 가속기는 `관리 미지원`으로 표시되며, 드라이버·장치 플러그인은 노드에서 직접 관리해야 합니다.

설치·설정·제거 절차는 [AI 가속기 Operator 관리](#ai-가속기-operator-관리)를 참고하세요.

### 접근 관리
클러스터 접근 권한(RBAC 바인딩)과 kubeconfig 를 관리합니다.

- **관리자 권한 복구**: 클러스터에 사용 가능한 관리자가 없고 내가 복구할 수 있을 때만 표시됩니다.
- **내 접근**: `kubeconfig 발급`, `연결 방법 보기` 버튼과 내 권한 목록(범위, 역할, 설명, 상태, 부여 일시)
- **멤버 권한**: 내가 활성 `cluster-admin`일 때만 표시됩니다. 다른 멤버의 권한을 추가·편집·회수합니다. 컬럼은 사용자, 범위, 역할, 설명, 상태, 부여 일시입니다.

| 권한 상태 | 색 |
|------|------|
| `활성화` | 초록 |
| `사용 안 함` | 회색 |
| `회수됨` | 회색 |
| `불일치` | 노랑 |
| `누락` | 주황 |
| `에러` | 빨강 |

`연결 방법 보기`를 누르면 다음 접속 예시가 펼쳐집니다.

```bash
# 내려받은 kubeconfig 로 접속
export KUBECONFIG=<kubeconfig>
kubectl get nodes
# API 엔드포인트
https://{클러스터 엔드포인트 IP}:6443
```

절차는 [접근 권한](#접근-권한)을 참고하세요.

- 네임스페이스 필터와 `검색어` 검색을 쓸 수 있고, agent 가 지원하면 `타입`(전체·Warning·Normal)으로도 거릅니다.
- 컬럼: 마지막 발생, 타입(`Warning`은 주황), 네임스페이스, 대상, 사유, 메시지, 횟수
- **사유**를 클릭하면 이벤트 상세 창이 열립니다. `같은 대상의 이벤트 보기`로 같은 대상의 이벤트만 거를 수 있습니다.
- 개요의 경고 이벤트 카드에서 들어오면 `Warning`으로 걸러진 채 열립니다.

### 유지 관리
**기본 정보**, **버전**, **인증서** 카드로 구성됩니다.

#### 기본 정보
클러스터 ID와 생성 일시를 표시합니다.

#### 버전
현재 쿠버네티스 버전과 노드 버전 요약(예: "노드 n개 모두 1.37")을 표시합니다. 그 아래 업그레이드 행에는 상황에 따라 다음이 표시됩니다.

| 상황 | 표시 | 버튼 |
|------|------|------|
| 업그레이드 가능 | `{{version}} 업그레이드 가능` 배지, "노드를 한 대씩 새 버전 노드로 교체합니다." | `업그레이드` |
| 멈춘 업그레이드 | "이전 업그레이드가 끝나지 않았습니다. 남은 노드 교체를 이어서 진행합니다." | `업그레이드 재개` |
| 진행 중 | "업그레이드가 진행 중입니다." | 없음 |
| `실행 중`·`경고`가 아님 | "지금 클러스터 상태에서는 업그레이드할 수 없습니다." | 없음 |
| 최신 | "최신 버전입니다." | 없음 |
| 이미지 없음 | "다음 버전 이미지가 이 클러스터의 스토리지 도메인에 없습니다. 이미지를 등록하면 업그레이드할 수 있습니다." | 없음 |
| 대상 불허 | "다음 버전은 업그레이드 대상으로 허용되지 않습니다." | 없음 |
| 사전 점검 차단 | "사전 점검에서 업그레이드가 막혔습니다. 노드 버전 차이 등 클러스터 상태를 확인하세요." | 없음 |
| 판단 불가 | "업그레이드 가능 여부를 판단할 수 없습니다." 또는 "업그레이드 가능 여부를 확인하지 못했습니다." | 없음 |

절차는 [클러스터 업그레이드](#클러스터-업그레이드)를 참고하세요.

#### 인증서
- **곧 만료되는 인증서**: 클러스터 CA 나 레지스트리 CA 가 30일 안에 만료되면 맨 위에 표시됩니다. 7일 이하이거나 만료되면 빨강입니다.
- **클러스터 인증서 (CA)**: 만료일(D-n, 남은 기간 막대)과 지문(SHA-256)을 표시합니다. `복사`로 지문을 복사합니다. `인증서 재설정` 버튼으로 CA 를 교체합니다([인증서 재설정](#인증서-재설정)).
- **레지스트리 신뢰**: 사설 레지스트리 CA 를 등록하고 노드별 적용 상태를 확인합니다([레지스트리 신뢰](#레지스트리-신뢰)).

> 💡 **참고:** 클러스터 CA 는 API 서버와 노드가 서로를 믿는 근거입니다. 만료되면 클러스터에 접속할 수 없습니다. 인증서 정보는 클러스터가 실시간 상태일 때만 볼 수 있습니다.

## 클러스터 실행·종료

클러스터의 모든 노드 VM을 한꺼번에 정지하거나 다시 시작합니다.

### 절차
1. 클러스터 목록에서 클러스터를 1개 고릅니다.
2. `종료` 또는 `실행`을 클릭합니다.
3. 확인 창에서 이름, ID, 버전, API 서버 엔드포인트 IP, 생성 일시를 확인합니다.
   - **클러스터 종료**: "선택한 클러스터를 정지하시겠습니까?" 아래에 "클러스터의 모든 노드 VM 이 종료됩니다." 경고가 표시됩니다.
   - **클러스터 실행**: "선택한 클러스터를 다시 시작하시겠습니까?"가 표시됩니다.
4. `종료` 또는 `실행`을 클릭합니다.

- 종료하면 상태가 `종료 중`을 거쳐 `정지됨`으로, 실행하면 `부팅 중`을 거쳐 `실행 중`으로 바뀝니다.
- 버튼별 활성 조건은 [상단 버튼](#상단-버튼)을 참고하세요.

> ⚠️ **주의:** 워커 그룹이 생성·수정·스케일 중이면 종료가 거절되고 "워커 그룹이 생성·수정·스케일 중이라 클러스터를 정지할 수 없습니다. 작업이 끝난 뒤 다시 정지해 주세요."가 표시됩니다.

## 클러스터 업그레이드
실행 중인 클러스터를 상위 쿠버네티스 버전으로 업그레이드합니다.

### 전제 조건
- 클러스터 상태가 `실행 중` 또는 `경고`여야 합니다.
- 관리자가 **다음 버전의 이미지를 등록**해 두어야 합니다. 대상 이미지는 **클러스터가 놓인 스토리지 도메인**에 등록된 것만 후보입니다. 이미지가 없으면 `유지 관리` 탭에 그 사유가 표시되고 `업그레이드` 버튼이 나타나지 않습니다.
- 업그레이드 중 노드가 한 대씩 추가되므로, 프로젝트에 **노드 1대 분량의 여유 자원**(vCPU·메모리·디스크)이 있어야 합니다.
- 강제 반선호도(anti-affinity) 그룹을 쓰는 클러스터는 컨트롤 플레인을 교체하는 동안 노드가 한 대 더 필요하므로, 그룹 멤버가 없는 호스트가 하나 이상 있어야 합니다.

### 절차
1. 클러스터 상세 화면에서 다음 중 한 곳의 버튼을 클릭합니다.
   - **개요** 탭 위 `업그레이드 가능` 알림 줄의 `업그레이드`
   - **유지 관리** 탭 **버전** 카드의 `업그레이드`
2. **클러스터 업그레이드** 창에서 이름, ID, 버전(`현재 → 대상`), 교체 대상(컨트롤 플레인·워커 대수)을 확인합니다.
3. 후보 버전이 2개 이상이면 **업그레이드 대상**을 고릅니다.
   - `{{version}} (다음 마이너 버전)`(기본)
   - `{{version}} (현재 마이너 최신 패치)`
4. `업그레이드`를 클릭합니다.

### 진행 방식과 소요 시간
- 요청하면 상태가 바로 `업데이트 중`으로 바뀌고, 완료되면 `실행 중`으로 돌아옵니다. 진행 상황은 개요 탭 위 **진행 중 작업** 줄에서 확인합니다.
- **컨트롤 플레인을 한 대씩 순차 교체**한 뒤, 같은 방식으로 **워커 노드를 교체**합니다.
- 각 교체는 새 노드를 먼저 만들어 합류시킨 뒤 기존 노드를 드레인하고 제거합니다. 이때 워커 위의 워크로드는 다른 노드로 **재스케줄**됩니다.
- 클러스터 규모에 따라 **수 분에서 수십 분**이 걸립니다.

> 💡 **참고:** 이미 대상 이미지로 동작 중인 노드는 건너뜁니다. 업그레이드가 중간에 멈추면 `업그레이드 이어서 진행`(개요) 또는 `업그레이드 재개`(유지 관리)로 남은 노드 교체를 이어서 진행합니다.

> ⚠️ **주의:** **워커 노드 그룹(워커 오토 스케일링 그룹) 소속 노드는 교체되지 않고 지금 버전에 남습니다.** 업그레이드가 성공으로 끝나도 이 노드는 올라가지 않습니다. 새 워커 노드 그룹을 만든 뒤 옛 그룹을 삭제하거나, 워커 노드를 개별로 추가해 옮기세요.

> ⚠️ **주의:** 교체하지 못한 워커가 남아도 업그레이드는 실패로 처리되지 않습니다. 클러스터 버전은 컨트롤 플레인을 따라가며, 남은 워커는 kubelet 버전 차이 허용 범위 안에서 계속 동작합니다.

> 💡 **참고:** 업그레이드 중에는 워크로드가 노드 간에 이동하므로, 서비스 영향이 적은 유지보수 시간대에 진행하는 것을 권장합니다.

## 인증서 재설정
클러스터 CA 를 새 CA 파일(인증서·개인 키)로 교체합니다.

### 절차
1. 클러스터 상세 화면의 `유지 관리` 탭으로 이동합니다.
2. **인증서** 카드의 **클러스터 인증서 (CA)** 옆 `인증서 재설정`을 클릭합니다.
3. **CA 인증서 재설정** 창에서 **CA 인증서**(`.crt` 파일)와 **개인 키**(`.key` 파일)를 고릅니다.
4. `저장`을 클릭합니다.

- 재설정 중에는 상태가 `CA 인증서 갱신 중`으로 표시되고, 완료되면 다시 `실행 중`으로 돌아옵니다.
- `인증서 재설정` 버튼은 클러스터가 실시간 상태일 때만 활성화됩니다. 정지되어 있으면 "클러스터가 실행 중이 아닙니다. 클러스터를 실행한 뒤 다시 시도하세요.", 다른 작업 중이면 "다른 작업을 처리하는 중입니다. 끝난 뒤 다시 시도하세요."가 표시됩니다.

> ⚠️ **주의:** CA 재설정은 원칙적으로 **모든 노드가 정상 상태일 때만** 진행할 수 있습니다.
> 예외는 **직전 재설정이 실패한 클러스터**입니다(아래 "재설정이 실패한 경우" — 복구를 위해 다시 시도할 수 있습니다).

**업로드 파일 조건**

| 항목 | 조건 |
|------|------|
| CA 인증서 | **CA 인증서 1장**만 담아야 합니다. 인증서 여러 장(체인·번들)은 거부됩니다. |
| 개인 키 | CA 인증서와 **한 쌍**이어야 하며 **RSA** 키여야 합니다. `PRIVATE KEY`·`RSA PRIVATE KEY` 형식을 모두 지원합니다. |

조건에 맞지 않으면 **클러스터를 변경하기 전에** 요청이 거부됩니다. 이 경우 클러스터는 아무 영향도 받지 않으므로 파일만 고쳐 다시 시도하면 됩니다. CA 파일 만드는 방법은 [CA 파일 직접 생성 예시](#ca-파일-직접-생성-예시)를 참고하세요.

### 재설정 중 서비스 영향
- **쿠버네티스 API 는 재기동되지 않습니다.** API 서버를 재기동하지 않고 인증서 신뢰를 확장·축소하므로, 검증 환경의 1초 간격 점검에서 API 중단은 관측되지 않았습니다. 컨트롤 플레인 구성 요소가 노드마다 한 번씩 재기동되는 동안 개별 요청이 재시도될 수는 있습니다.
- 노드마다 컨트롤 플레인 구성 요소와 kubelet 이 한 번씩 재기동됩니다.
- **재설정이 사용자 워크로드(파드)를 축출하거나 다른 노드로 옮기지 않습니다.** 시스템 네임스페이스(`kube-system`)의 구성 요소는 새 CA 를 반영하려고 자동으로 재기동됩니다. 클러스터 안에서 API 를 호출하는 워크로드는 아래 2번에 따라 직접 재기동해야 할 수 있습니다.

### 재설정 후 반드시 해야 하는 것
1. **kubeconfig 재발급** — 기존에 내려받은 kubeconfig 의 사용자 인증서는 **이전 CA** 로 서명되어 있어 재설정 완료 후에는 접속이 거부됩니다(`x509: certificate signed by unknown authority`). `접근 관리` 탭의 `kubeconfig 발급`으로 다시 내려받으세요. CI/CD 등 자동화에 등록된 kubeconfig 도 함께 교체해야 합니다.
2. **클러스터 안에서 API 를 호출하는 사용자 워크로드 재기동(필요 시)** — 파드 안에서 서비스 계정으로 API 를 호출하는 애플리케이션은 시작할 때 읽은 CA 를 계속 씁니다. 시스템 구성 요소는 자동으로 재기동되지만, 사용자 네임스페이스의 워크로드는 서비스 영향을 고려해 자동으로 재기동하지 않습니다. 인증 오류가 보이면 해당 워크로드를 재기동하세요.

   ```bash
   kubectl -n <네임스페이스> rollout restart deployment,statefulset,daemonset
   ```

> 💡 **권장 절차:** 유지보수 시간대에 ① 인증서 재설정 → ② `접근 관리` 탭의 `kubeconfig 발급`으로 kubeconfig 재발급 → ③ 필요한 사용자 워크로드 재기동 순서로 진행하세요.

### 재설정이 실패한 경우
- 클러스터 상태가 `CA 인증서 갱신 실패`로 표시됩니다. 이때는 **같은 CA 파일로 다시 재설정**하면 중단된 지점부터 이어서 정리됩니다. 이때는 **모든 노드가 정상이 아니어도** 다시 진행할 수 있습니다(복구 경로를 막지 않기 위한 예외입니다). 재설정과 무관한 이유로 비정상인 노드가 있으면 그 노드에서 다시 실패하므로, 반복되면 먼저 해당 노드를 정상화하거나 클러스터에서 제거하세요.
- 재설정이 **진행 중**(`CA 인증서 갱신 중`)이면 새 요청은 거부됩니다. 진행이 끝날 때까지 기다리세요.
- 위 예외는 **직전 재설정이 실패한 클러스터**에만 적용됩니다. 실패 이력이 없는 평상시 재설정은 `NotReady` 등 비정상 노드가 하나라도 있으면 **요청 시점에 거부**됩니다. 그 노드를 먼저 정상화하거나 클러스터에서 제거한 뒤 시도하세요.
- 다시 실행해도 복구되지 않거나 특정 노드가 `NotReady` 로 남으면 관리자에게 문의하세요.

## 생성 실패 복구
생성에 실패한 클러스터를 지우지 않고 이어서 만들거나, 저장된 설정으로 처음부터 다시 만듭니다.

### 전제 조건
- 클러스터 상태가 `생성 실패`여야 합니다. 다른 상태에서는 버튼이 나타나지 않습니다.

### 절차
1. 다음 중 한 곳에서 `생성 실패 복구`를 클릭합니다.
   - **클러스터 목록:** `생성 실패` 상태의 클러스터를 고르면 `실행`·`종료` 자리에 `생성 실패 복구` 버튼이 나타납니다.
   - **클러스터 상세:** 개요 탭 위 `생성 실패` 알림 줄의 `생성 실패 복구` 버튼입니다.
2. 열린 창에서 복구 방식을 고릅니다. 기본값은 `이어서 만들기`입니다.
3. (선택) **스토리지 도메인(선택)**을 고릅니다. 비워 두려면 `선택 해제`를 클릭합니다.
4. `생성 실패 복구`를 클릭합니다.

### 복구 방식
| 방식 | 동작 |
|------|------|
| `이어서 만들기` | 이미 join 된 컨트롤 플레인과 업로드한 CA 를 그대로 두고, 목표 수에서 모자란 컨트롤 플레인만 추가합니다. |
| `처음부터 다시 만들기` | 이미 join 된 컨트롤 플레인까지 모든 노드를 삭제하고 저장된 설정으로 다시 만듭니다. 네트워크와 로드밸런서는 유지하고, 업로드한 CA 는 버리고 새로 만듭니다. |

**이어서 만들기**
- 클러스터가 아직 초기화되지 않았다면(VM 또는 초기화 단계에서 실패) 컨트롤 플레인을 자동으로 다시 만듭니다. 이 경우 CA 도 새로 만들어집니다.
- 상태를 판단할 수 없으면(agent 무응답, VM 전원 꺼짐) 아무것도 바꾸지 않고 실패합니다. 컨트롤 플레인 VM 의 전원을 켠 뒤 다시 시도하거나 `처음부터 다시 만들기`를 고르세요.
- cluster-admin 바인딩은 요청자가 **프로젝트 소유자**일 때만 만듭니다. 소유자가 아니면 바인딩을 건너뛰므로, 소유자가 `접근 관리` 탭의 `관리자 권한 복구`로 만들면 됩니다.

> ⚠️ **주의:** `처음부터 다시 만들기`는 되돌릴 수 없습니다. 이미 join 된 컨트롤 플레인과 업로드한 CA 를 잃습니다.

### 스토리지 도메인 선택
| 선택 | 동작 |
|------|------|
| 비움 | 생성할 때처럼 자동으로 고릅니다. 고른 도메인에서 VM 을 실행하지 못하면 다음 순위 도메인으로 넘어갑니다. `이어서 만들기`에서 생성 때 이미지를 직접 지정했다면 그 이미지를 그대로 씁니다. |
| 특정 도메인 | 그 도메인만 씁니다. 실행하지 못해도 다른 도메인으로 넘어가지 않습니다. |

> 💡 **참고:** 고를 수 있는 이미지가 없는 등 서버가 요청을 거절하면 창이 열린 채 사유가 표시됩니다. 이때 클러스터 상태는 바뀌지 않습니다.

### 진행 결과
- 요청하면 상태가 바로 `생성 중`으로 바뀌고, 끝나면 `실행 중`으로 바뀝니다.
- 복구에 실패하면 다시 `생성 실패`로 돌아옵니다. 사유는 요청 내역에서 확인합니다.

## 구성 맞추기
컨트롤 플레인 수를 클러스터의 목표 수로 맞춥니다. 목표 수는 클러스터를 만들 때 고른 컨트롤 플레인 수(`1` 또는 `3`)이며, 클러스터가 이 값을 기억합니다.

### 구성 어긋남 알림 줄
컨트롤 플레인 수가 목표와 다르거나 정리할 고아 노드가 있으면 클러스터 상태가 `경고`로 바뀝니다. 이때 개요 탭 위에 `구성 어긋남` 알림 줄이 나타나 현재 수와 목표 수를 보여 주고 `구성 맞추기` 버튼을 제공합니다.

> 💡 **참고:** 컨트롤 플레인 수는 목표와 같은데 일부가 `NotReady` 인 경우에는 알림 줄이 나타나지 않습니다. 수를 맞출 일이 아니므로, 기다리거나 [노드 교체](#노드-교체)로 복구합니다.

> 💡 **참고:** 유령 etcd 멤버(노드 없이 etcd 에만 남은 멤버)는 상태 판정에 들어가지 않아, 그것만 남은 경우에는 알림 줄이 나타나지 않습니다. 컨트롤 플레인 수나 고아 노드 때문에 구성 맞추기를 실행하면 계획에 함께 들어가 정리됩니다.

> 💡 **참고:** 업그레이드 등 다른 작업이 진행 중이면 알림 줄이 나타나지 않습니다.

### 전제 조건
- 클러스터 상태가 `실행 중`·`경고`·`에러`·`알 수 없음` 중 하나여야 합니다.
- 업그레이드·노드 교체·정지·기동 등 다른 작업이 진행 중이면 실행할 수 없습니다.
- 노드 agent 가 구성 맞추기를 지원해야 합니다. 오래된 골든 이미지로 만든 노드처럼 지원하지 않는 agent 이면 거절되고 agent 갱신을 안내합니다.

> 💡 **참고:** `생성 실패` 상태의 클러스터는 구성 맞추기 대상이 아닙니다. [생성 실패 복구](#생성-실패-복구)를 사용하세요.

### 절차
1. 개요 탭 위 `구성 어긋남` 알림 줄에서 `구성 맞추기`를 클릭합니다.
2. 열린 창에서 이름, ID, 컨트롤 플레인 수(`정상/목표`)를 확인합니다.
3. 창에 표시되는 계획을 확인합니다. 계획은 실행 순서대로 표시됩니다.
4. `구성 맞추기`를 클릭합니다.

**계획에 나오는 단계**

| 단계 | 설명 |
|------|------|
| `멤버인 노드의 상태를 되돌립니다` | 실제로는 클러스터에 참여해 있는데 고아·생성 중으로 남은 노드의 상태를 되돌립니다. |
| `고아 노드 삭제` | 클러스터에 참여하지 못한 컨트롤 플레인 노드와 그 VM 을 지웁니다. |
| `유령 etcd 멤버 제거` | 대응하는 노드 없이 etcd 에만 남은 멤버를 지웁니다. 괄호 안에 멤버 주소가 함께 표시됩니다. |
| `초과 컨트롤 플레인 제거` | 목표보다 많은 컨트롤 플레인을 지웁니다. `NotReady` 인 노드, 클러스터 이미지와 다른 이미지의 노드, 가장 나중에 만든 노드 순으로 고릅니다. |
| `컨트롤 플레인 추가` | 목표보다 모자란 만큼 컨트롤 플레인을 추가합니다. |

> 💡 **참고:** 맞출 것이 없으면 "맞출 항목이 없습니다."가 표시되고 버튼이 비활성화됩니다.

### 진행 방식
- 한 번에 한 단계만 처리합니다. 단계마다 클러스터를 다시 관측해 계획을 새로 세우고, 계획이 빌 때까지 이어 갑니다. 그래서 실제로 처리한 단계는 창에서 본 미리보기와 다를 수 있습니다.
- 끝나면 상태가 `대기 중`을 거쳐 `실행 중`으로 돌아옵니다.
- 한 단계가 실패하면 그 단계만 되돌리고 멈춥니다. 이미 끝난 단계는 되돌리지 않습니다. 다시 실행하면 현재 상태부터 계획을 새로 세워 이어 갑니다.

### 거절되는 경우
다음과 같으면 그 단계를 실행하지 않고 거절합니다. 계획을 세울 때 드러나면 창에 사유가 표시되고 버튼이 비활성화됩니다. 실행 도중 드러나면 그 단계 앞에서 멈추고 요청 내역에 사유가 남습니다.

- 단계를 실행하면 etcd 정족수가 깨지거나, 지금 이미 정족수가 없는 경우
- agent 가 응답하지 않는 등 etcd 상태를 판단할 수 없는 경우
- Cloud:iA 가 관리하지 않는 컨트롤 플레인 노드가 있거나, 반쯤만 참여한 노드처럼 사람이 확인해야 하는 노드가 있는 경우
- 컨트롤 플레인을 추가해야 하는데 사양을 이어받을 정상 컨트롤 플레인이 없는 경우

> 💡 **참고:** 구성 맞추기는 컨트롤 플레인의 **개수**와 고아·유령 멤버 정리만 맡습니다. 참여는 해 있지만 `NotReady` 인 컨트롤 플레인은 교체하지 않습니다.

## 레지스트리 신뢰
사설 레지스트리나 사용자 레지스트리의 **CA 인증서를 클러스터 노드의 containerd 에 신뢰 등록**합니다. 등록하면 그 레지스트리에서 이미지를 받을 때 TLS 검증이 통과합니다.

레지스트리 신뢰는 클러스터 상세 `유지 관리` 탭의 **인증서** 카드 안 **레지스트리 신뢰**에서 관리합니다.

### 테이블 컬럼
| 컬럼 | 설명 |
|------|------|
| **레지스트리 호스트** | 신뢰를 적용할 레지스트리 호스트입니다(예: `harbor.example.com`). |
| **이름** | 식별용 표시 이름입니다. |
| **CA** | 등록된 CA 인증서 장수입니다. |
| **가장 이른 만료** | 등록된 CA 중 가장 먼저 만료되는 인증서의 만료일과 D-n 입니다. 만료되면 `인증서 만료됨`으로 표시됩니다. |
| **적용 상태** | `적용됨`, `일부 적용`, `실패`, `대기 중`, `격리됨`, `알 수 없음`과 `적용된 노드 수 / 적용 대상 노드 수`입니다. 괄호 안 붉은 숫자는 적용에 실패한 노드 수입니다. |
| **생성 일시** | 등록 일시입니다. |

**적용 상태 읽는 법**
- 정지·생성 중처럼 지금 적용할 수 없는 노드는 분모에서 빠집니다.
- 적용되지 않은 노드에 뜬 파드는 이 레지스트리에서 이미지를 받지 못합니다.
- `격리됨`으로 표시되면 노드 agent 가 그 CA 를 거부해 전송 목록에서 제외한 상태입니다. 다른 항목의 적용은 계속됩니다.
- 클러스터가 실시간 상태가 아니면 적용 현황은 마지막으로 확인된 값입니다.

### 주요 작업
- `생성`: 레지스트리 호스트와 CA 인증서를 등록합니다.
- `편집`: 이름과 CA 인증서를 변경합니다.
- `삭제`: 선택한 신뢰 항목을 삭제합니다. 노드에서도 해당 CA 가 제거됩니다.
- `노드별 적용 상태`: 노드별 적용 결과를 확인하고 `재적용`을 실행합니다.

> 💡 **공통 조건:** 목록에서 항목을 **1개 선택**해야 `편집`·`삭제`·`노드별 적용 상태` 버튼이 활성화됩니다.

### 등록
1. **레지스트리 신뢰**에서 `생성`을 클릭합니다.
2. **레지스트리 신뢰 추가** 창에서 **레지스트리 호스트**를 입력합니다. 입력한 값이 정규화되면 "{{host}} 로 저장됩니다."가 표시됩니다.
3. (선택) **이름**을 입력합니다.
4. **CA 인증서**를 PEM 형식으로 붙여넣습니다. 여러 장을 이어 붙일 수 있습니다.
5. `추가`를 클릭합니다.

등록 후 적용은 백그라운드에서 진행되며, 적용 상태가 갱신될 때까지 잠시 기다립니다.

### 편집
1. 항목을 선택하고 `편집`을 클릭합니다.
2. **레지스트리 신뢰 편집** 창에서 이름과 CA 인증서를 변경합니다.
3. `편집`을 클릭합니다.

> ⚠️ **주의:** **호스트는 변경할 수 없습니다.** 바꾸려면 삭제 후 다시 등록하세요.

> 💡 **참고:** CA 인증서를 비워 두면 현재 CA 를 그대로 유지합니다. 새로 붙여넣으면 기존 CA 를 대체하고 모든 노드에 다시 적용합니다.

### 노드별 적용 상태와 재적용
1. 항목을 선택하고 `노드별 적용 상태`를 클릭합니다.
2. 노드, 상태, 적용 세대, 사유, 수정 일시를 확인합니다. 적용 대상이 아닌 노드는 `적용 대상 아님`으로 표시됩니다.
3. 실패한 노드가 있으면 `재적용`을 클릭합니다. 모든 노드에 현재 신뢰 목록을 다시 밀어넣으며, 적용은 백그라운드에서 진행됩니다.

> ⚠️ **주의:** 클러스터가 CA 회전·전원 전이·생성/삭제 중이면 노드 조정이 안전하지 않아 재적용할 수 없습니다.

> ⚠️ **주의:** **격리된 항목은 재적용으로 풀리지 않습니다.** CA 를 교체하면 격리가 해제되고 다시 적용됩니다.

### 삭제
1. 항목을 선택하고 `삭제`를 클릭합니다.
2. **레지스트리 신뢰 삭제** 창에서 레지스트리 호스트, 이름, CA 를 확인하고 `삭제`를 클릭합니다.

> 💡 **참고:** 정지·오류 상태의 클러스터에서도 신뢰 항목을 삭제할 수 있습니다. 유출된 CA 를 즉시 폐기할 수 있도록 하기 위함입니다.

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **레지스트리 호스트** | 레지스트리 호스트명(선택적으로 `:포트`) | 필수입니다. 플랫폼 예약 호스트는 등록할 수 없습니다("플랫폼이 사용하는 예약 호스트라 등록할 수 없습니다."). 등록 후에는 변경할 수 없습니다. | 예약 호스트: `k8s-registry.cloudia.internal`, `object-storage.cloudia.internal`, `docker.io`, `registry-1.docker.io`, `quay.io`, `registry.k8s.io`, `ghcr.io` 및 `cloudia.internal` 자체와 그 하위 전체, punycode(`xn--`) 라벨, `_` 로 시작하는 값 |
| **이름** | 자유 문자열 | 선택입니다. 최대 `255자`. | 식별용 표시 이름 |
| **CA 인증서** | PEM 형식 인증서 | 등록 시 필수, 편집 시 선택입니다. 최대 `32 KiB`. `CERTIFICATE` 블록만 허용하며 `BEGIN`·`END` 가 짝을 이뤄야 합니다. | 여러 장을 이어 붙일 수 있습니다. 개인 키는 붙여넣지 마세요. |

> ⚠️ **주의:** CA 신뢰는 **TLS 검증만** 해결합니다. 인증이 필요한 레지스트리라면 네임스페이스별로 `imagePullSecret` 을 따로 만들어야 합니다.

## 클러스터 삭제
클러스터와 클러스터에 연결된 리소스를 함께 삭제합니다.

1. **클러스터 선택:** 목록에서 삭제하려는 클러스터를 선택한 뒤 `삭제` 버튼을 클릭합니다.
2. **삭제 확인:** **클러스터 삭제** 창에서 이름, ID, 버전, API 서버 엔드포인트 IP, 생성 일시를 확인합니다.
3. **삭제 실행:** `삭제` 버튼을 눌러 진행합니다.

> ⚠️ **주의:** 클러스터를 삭제하면 클러스터에 연결된 리소스도 함께 정리됩니다. 삭제된 클러스터는 복구할 수 없습니다.

> ⚠️ **주의:** `삭제 중`인 클러스터는 삭제할 수 없습니다. 정지·기동·노드 교체·구성 맞추기·생성 실패 복구가 진행 중이면 삭제가 거절됩니다. 진행 중인 작업이 끝난 뒤 다시 시도하세요.

### 함께 정리되는 리소스
| 리소스 | 설명 |
|------|------|
| **컨트롤 플레인 노드** | 클러스터에 속한 모든 컨트롤 플레인 인스턴스가 삭제됩니다. |
| **워커 노드** | 클러스터에 속한 모든 워커 노드 인스턴스가 삭제됩니다. |
| **워커 오토 스케일링 그룹** | 클러스터에 연결된 워커 오토 스케일링 그룹과 하위 노드가 삭제됩니다. |
| **로드밸런서** | 클러스터 생성 시 자동으로 준비된 로드밸런서가 삭제됩니다. |
| **타겟 그룹** | 클러스터 생성 시 자동으로 준비된 타겟 그룹이 삭제됩니다. |
| **클러스터 네트워크 구성** | 클러스터에 연결된 네트워크 구성이 정리됩니다. |

## 워커 노드 추가
`노드` 탭의 `워커 노드 생성`을 클릭하면 **워커 노드 생성** 화면이 열립니다.

> 💡 **참고:** 클러스터 상태가 `실행 중`·`경고`일 때만 `워커 노드 생성` 버튼이 활성화됩니다. 정지되어 있으면 "클러스터가 실행 중이 아닙니다. 클러스터를 실행한 뒤 다시 시도하세요."가 표시됩니다.

### 기본 정보
- **인스턴스 구성**: 인스턴스 타입 선택 또는 직접 입력 방식으로 vCPU, 메모리를 설정합니다. 인스턴스 타입 목록에서는 메모리 1 GiB 타입, vCPU 1개 타입, GPU·NPU가 붙은 타입이 빠집니다.
- **무중단 증설**: 노드를 종료하지 않고 vCPU·메모리를 늘릴 수 있는 상한을 정합니다.
- **워커 노드 수**: 추가할 워커 노드 수를 입력합니다.
- **디스크 크기 설정**: 노드 디스크 크기를 입력합니다.
- **스토리지 도메인**: 노드 디스크를 둘 스토리지 도메인을 고릅니다. (선택)

### AI 가속기
GPU·NPU를 쓰는 워커 노드를 만들려면 이 섹션에서 장치를 지정합니다. 대상 호스트의 가속기 가용 용량을 검증하며, 가용 용량이 부족하면 노드 추가가 차단됩니다.

### 사용자 계정
- 사용자 이름과 인증 방식(비밀번호 또는 SSH 키)을 입력합니다. 사용자 이름을 비워 두면 `cloudia`로 만듭니다.

### 선호도 그룹
- (선택) 노드를 등록할 선호도 그룹을 고릅니다.

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **인스턴스 구성** | 인스턴스 타입 또는 직접 입력 | 직접 입력은 최소 vCPU `2`, 메모리 `2 GiB` | **필수** |
| **워커 노드 수** | 정수 | 최소 `1`, 최대 `5`(사용 가능한 IP 수 이하) | **필수** |
| **디스크 크기 설정** | 숫자 + 단위 | 최소 `32 GB` | **필수** |
| **스토리지 도메인** | 사용 가능한 스토리지 도메인 | 선택 가능 | 선택 |
| **사용자 계정/인증 방식** | 사용자명 + 비밀번호 또는 SSH 키 | 유효성 검사 통과 필요 | **필수** |

`생성`을 클릭하면 노드 탭으로 돌아갑니다. 새 노드는 `생성 중`을 거쳐 `Ready`로 바뀝니다.

## 노드 삭제
1. `노드` 탭에서 삭제할 워커 노드를 고르고 `노드 삭제`를 클릭합니다.
2. **노드 삭제** 창에서 이름, ID, 역할, 버전, 기본 인터페이스 IP 주소, 생성 일시를 확인합니다.
3. `삭제`를 클릭합니다.

> ⚠️ **주의:** 컨트롤 플레인은 삭제할 수 없습니다. 문제가 생긴 컨트롤 플레인은 [노드 교체](#노드-교체)로 복구하세요.

> ⚠️ **주의:** `대기 중`, `생성 중`, `삭제 중` 상태의 노드는 삭제할 수 없습니다.

## 노드 실행
`정지됨`·`머신 종료` 상태의 노드를 다시 켭니다.

1. `노드` 탭에서 노드를 고르고 `노드 실행`을 클릭합니다.
2. **노드 실행** 창에서 노드 정보를 확인하고 `실행`을 클릭합니다.

## 노드 교체
문제가 생긴 노드를 새 노드로 바꿉니다. 노드 상태가 `에러`·`NotReady`·`머신 종료`·`연결 끊김`·`정지됨`일 때만 교체할 수 있습니다. 정상 노드를 고르면 "문제가 생긴 노드만 교체할 수 있습니다."가 표시됩니다.

1. `노드` 탭에서 노드를 고르고 `노드 교체`를 클릭합니다.
2. **노드 교체** 창에서 경고와 노드 정보를 확인합니다.
3. 필요하면 강제 진행 체크박스를 선택합니다.
4. `노드 교체`를 클릭합니다.

| 역할 | 동작 | 강제 진행 |
|------|------|------|
| 컨트롤 플레인 | 새 컨트롤 플레인 노드를 만들어 이 노드를 대신합니다. 이 노드가 꺼져 있거나 VM 이 없으면 먼저 걷어낸 뒤 새 노드를 합류시킵니다. | 노드에 접속할 수 없어도 진행합니다. VM 과 Node 오브젝트가 모두 없으면 etcd 정리를 건너뛰므로, 살아 있는 컨트롤 플레인에서 그 노드의 etcd 멤버를 먼저 지운 뒤 사용하세요. |
| 워커 | 새 워커 노드를 만들어 합류시킨 뒤 이 노드를 지웁니다. | 노드에 접속할 수 없으면 워크로드를 대피시키지 않고 퇴출합니다. |

> ⚠️ **주의:** 새 노드는 같은 사양과 계정 설정을 이어받지만 노드 ID 와 이름이 바뀌고, 기존 노드 VM 의 로컬 디스크 내용은 사라집니다.

> 💡 **참고:** 노드 삭제·실행·교체는 클러스터 상태가 `실행 중`·`경고`·`에러`·`알 수 없음`·`CA 인증서 갱신 실패`·`생성 실패`일 때 할 수 있습니다.

## 노드 사양 변경
`노드` 탭에서 노드를 고르고 `리소스 변경`을 클릭합니다. 워커 노드를 고르면 **노드 사양 변경**, 컨트롤 플레인을 고르면 **컨트롤 플레인 사양 변경** 화면이 열립니다. 컨트롤 플레인 사양은 모든 컨트롤 플레인 노드에 같은 사양으로, 한 대씩 적용됩니다.

### 전제 조건
- 클러스터가 `실행 중`·`경고`여야 합니다.
- 워커: 노드가 Ready 상태여야 합니다. 워커 노드 그룹 소속 노드는 사양을 바꿀 수 없습니다(그룹이 새로 만드는 노드가 옛 사양으로 떠 그룹 안에서 사양이 갈리기 때문입니다).
- 컨트롤 플레인: 컨트롤 플레인 노드가 모두 Ready 상태여야 합니다. Ready 가 아닌 컨트롤 플레인은 [노드 교체](#노드-교체)로 먼저 복구하세요.

### 변경 방식
| 방식 | 동작 | 제약 |
|------|------|------|
| `무중단 변경` | 노드를 멈추지 않고 vCPU·메모리를 늘립니다. | 늘리기만 할 수 있고 무중단 증설 한도 안에서만 됩니다. 무중단 증설 설정은 바꿀 수 없습니다. 무중단 증설을 쓰지 않는 노드는 고를 수 없습니다. |
| `재시작 후 변경` | 컨트롤 플레인은 한 대씩 재시작하며 바꿉니다. 워커는 노드를 비우고(drain) 재시작합니다. | 줄이거나 무중단 증설 한도를 바꾸려면 이 방식을 고릅니다. 컨트롤 플레인이 2대이면 한 대를 재시작할 때 etcd 과반을 잃으므로 고를 수 없습니다. |

무중단 변경이 가능하면 `무중단 변경`이 기본으로 선택됩니다. 방식을 바꾸면 사양 입력이 현재 값으로 초기화됩니다.

### 절차
1. **변경 방식**을 고릅니다.
2. **인스턴스 구성**과 **무중단 증설**에 새 사양을 입력합니다. 입력칸 아래에 `사양 {{from}} → {{to}}` 형식으로 변경 내용이 표시됩니다.
3. `무중단 적용` 또는 `재시작하고 적용`을 클릭합니다. `재시작하고 적용`은 확인 창이 한 번 더 열립니다.

> ⚠️ **주의:** 컨트롤 플레인 재시작은 etcd 과반이 남을 때만 한 대씩 멈추고 바꾼 뒤 다시 켭니다. 컨트롤 플레인이 1대면 재시작하는 동안 Kubernetes API를 쓸 수 없고, 새 사양으로도 원래 사양으로도 다시 켜지 못하면 클러스터 전체가 멈춘 채 남을 수 있습니다.

> 💡 **참고:** 컨트롤 플레인 사양이 서로 다르면 적용할 때 모두 같은 사양으로 맞춥니다.

> 💡 **참고:** 쿠버네티스 노드는 최소 2 vCPU · 2 GiB 가 필요합니다. 무중단 증설로 메모리를 늘릴 때는 1024 MiB 단위로만 늘릴 수 있습니다.

## 워커 오토 스케일링 그룹 생성
`노드` 탭의 **워커 오토 스케일링 그룹** 카드에서 `생성`을 클릭하면 **워커 오토 스케일링 그룹 생성** 화면이 열립니다.

### 기본 정보
- **이름**: 그룹 이름을 입력합니다.
- **설명**: 그룹 설명을 입력합니다. (선택)

### 시작 템플릿
- **인스턴스 구성**: 인스턴스 타입 선택 또는 직접 입력 방식으로 vCPU, 메모리를 설정합니다. 인스턴스 타입 목록에서는 메모리 1 GiB 타입, vCPU 1개 타입, GPU·NPU가 붙은 타입이 빠집니다.
- **무중단 증설**: 인스턴스 구성 바로 아래에 있습니다. `사용함`이면 그룹이 만드는 워커 노드가 노드를 종료하지 않고 vCPU·메모리를 늘릴 수 있는 헤드룸을 받고, `사용 안 함`이면 헤드룸 없이 현재 사양 그대로 만들어집니다. 상한 산정 기준은 [인스턴스 > 무중단 증설 상한 산정 기준](../../vm/instance/instance.md#무중단-증설-상한-산정-기준)과 같습니다.
- **디스크 크기 설정**: 노드 디스크 크기를 입력합니다.
- **스토리지 도메인**: 노드 디스크를 둘 스토리지 도메인을 고릅니다. (선택)

### AI 가속기 · 사용자 계정
- 필요하면 AI 가속기 장치를 지정합니다.
- 사용자 이름과 인증 방식(비밀번호 또는 SSH 키)을 입력합니다.

### 타겟 그룹
- **타겟 그룹**을 `생성`으로 바꾸면 **프로토콜**(`TCP`·`UDP`)과 **포트 번호**를 입력합니다. 기본값은 `생성 안 함`입니다.

### 그룹 정보
- **최소 용량**, **최대 용량**
- **원하는 용량**: 최소~최대 사이 값입니다. 최소·최대 용량을 먼저 입력해야 입력할 수 있습니다.
- **스케일 간격**: 기본 `180`초

### 조정 정책
- **지표 유형**: `CPU 평균 사용량` 또는 `메모리 평균 사용량`
- **스케일 인 대상값**, **스케일 아웃 대상값**: `%` 단위

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **이름** | 영문 대/소문자, 숫자, `-`, `_` | 최대 `80자` | **필수** |
| **설명** | 문자열 | 최대 `200자` | 선택 |
| **인스턴스 구성** | 인스턴스 타입 또는 직접 입력 | 직접 입력은 최소 vCPU `2`, 메모리 `2 GiB` | **필수** |
| **디스크 크기 설정** | 숫자 + 단위 | 최소 `32 GB` | **필수** |
| **스토리지 도메인** | 사용 가능한 스토리지 도메인 | 선택 가능 | 선택 |
| **사용자 계정/인증 방식** | 사용자명 + 비밀번호 또는 SSH 키 | 유효성 검사 통과 필요 | **필수** |
| **프로토콜** | `TCP` \| `UDP` | 타겟 그룹 생성 시 선택 | 조건부 필수 |
| **포트 번호** | 정수 | `1~65535` | 조건부 필수 |
| **최소 용량** | 정수 | `1` 이상 | **필수** |
| **최대 용량** | 정수 | 최소 용량 이상 | **필수** |
| **원하는 용량** | 정수 | 최소 용량 이상, 최대 용량 이하 | **필수** |
| **스케일 간격** | 정수(초) | `180` 이상 | **필수** |
| **스케일 인 대상값** | 정수(%) | `0~100` | **필수** |
| **스케일 아웃 대상값** | 정수(%) | 스케일 인 대상값보다 크고 `100` 이하 | **필수** |

> 💡 **참고:** 워커 오토 스케일링 그룹의 노드는 클러스터와 같은 버전과 네트워크 구성을 따릅니다.

## 워커 오토 스케일링 그룹 상세
그룹 이름을 클릭하거나 노드 상세 창의 노드 풀 링크를 누르면 **워커 오토 스케일링 그룹 상세** 화면이 열립니다. 이 화면에는 수정·삭제 버튼이 없습니다.

### 상세 정보
- **이름**, **클러스터 ID**, **상태**
- **인스턴스 상태**: `준비 수/전체 수개` 형식입니다(예: `3/5개`).
- **시작 템플릿**: 시작 템플릿 이름과 ID입니다.
- **사용자 계정**: 비밀번호·SSH 키 사용 여부입니다.
- **타겟 그룹**: 연결된 타겟 그룹입니다.
- **그룹 정보**: 최소 용량, 최대 용량, 스케일 간격입니다.
- **생성 일시**, **설명**

### 컴퓨트
그룹에 속한 노드 목록입니다. 컬럼은 역할, 노드 이름, 버전, 기본 인터페이스 IP 주소, 인스턴스 타입, 상태, 생성 일시입니다. 노드 이름을 클릭하면 인스턴스 상세 화면으로 이동합니다.

## 워커 오토 스케일링 그룹 삭제
1. **그룹 선택:** **워커 오토 스케일링 그룹** 카드에서 그룹을 선택한 뒤 `삭제`를 클릭합니다.
2. **삭제 확인:** **워커 오토 스케일링 그룹 삭제** 창에서 이름, ID, 시작 템플릿, 인스턴스 상태, 생성 일시를 확인합니다.
3. **삭제 실행:** `삭제`를 클릭합니다.

> ⚠️ **주의:** 그룹 삭제 시 해당 그룹의 워커 노드도 함께 정리될 수 있습니다. 그룹 삭제는 되돌릴 수 없습니다.

## 서비스 로드 밸런서 관리
`네트워크` 탭의 **서비스 로드 밸런서**에서 클러스터 노드로 트래픽을 보내는 L4 로드 밸런서를 만들고 관리합니다.

### 서비스 로드 밸런서 생성
1. **서비스 로드 밸런서**에서 `생성`을 클릭합니다.
2. **기본 정보**: **이름**과 **설명**(선택)을 입력합니다.
3. **네트워크 정보**: **타입**(`외부`·`내부`)을 고르고, **내부 IP 주소**와 **외부 IP 주소**의 할당 방식(`자동 할당`·`수동 할당`)을 고릅니다. VPC·서브넷은 클러스터 네트워크로 고정됩니다. 타입이 `내부`이면 외부 IP 주소는 비활성화됩니다.
4. **타겟 그룹**: **타겟 그룹 이름**, **타겟 그룹 설명**(선택), **프로토콜**, **리스너 포트**, **타겟 그룹 포트**를 입력합니다.
5. **타겟 추가**: **자동 포함 범위**를 고르거나 `추가`로 타겟을 직접 고릅니다.
6. `생성`을 클릭합니다. 생성되면 `네트워크` 탭으로 돌아갑니다.

| 자동 포함 범위 | 동작 |
|------|------|
| `사용 안 함`(기본) | `추가`로 고른 타겟만 씁니다. 타겟을 1개 이상 골라야 합니다. |
| `모든 수동 워커` | 수동으로 만든 워커 노드를 모두 포함합니다. |
| `모든 워커` | 모든 워커를 포함합니다. |

`추가`를 누르면 **타겟 선택** 창에서 이 클러스터의 컨트롤 플레인, 워커 노드, 워커 오토 스케일링 그룹 중에서 고릅니다.

> 💡 **참고:** **타겟 그룹 포트**를 쿠버네티스 서비스의 NodePort 와 같게 정하면, 쿠버네티스 서비스 목록의 **로드 밸런서** 칸에 이 로드 밸런서가 연결되어 표시됩니다.

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **이름** | 영문 대/소문자, 숫자, `-`, `_` | 최대 `60자` | **필수** |
| **설명** | 문자열 | 최대 `200자` | 선택 |
| **타입** | `외부` \| `내부` | 기본 `외부` | **필수** |
| **타겟 그룹 이름** | 영문 대/소문자, 숫자, `-`, `_` | 최대 `60자` | **필수** |
| **타겟 그룹 설명** | 문자열 | 최대 `200자` | 선택 |
| **프로토콜** | `TCP` \| `UDP` | 기본 `TCP` | **필수** |
| **리스너 포트** | 정수 | `1~65535` | **필수** |
| **타겟 그룹 포트** | 정수 | `1~65535` | **필수** |
| **타겟** | 컨트롤 플레인, 워커 노드, 워커 오토 스케일링 그룹 | 자동 포함 범위가 `사용 안 함`이면 1개 이상 | 조건부 필수 |

### 서비스 로드 밸런서 상세와 리스너
목록에서 이름을 클릭하면 **서비스 로드 밸런서 상세**가 열립니다. **상세 정보**(이름, ID, 타입, 내부·외부 IP 주소, 설명, 생성 일시)와 **리스너 정보**가 표시됩니다.

- `추가`: **리스너 추가** 화면에서 타겟 그룹과 타겟을 입력해 리스너를 추가합니다. 입력 항목은 생성 화면의 타겟 그룹·타겟 추가와 같습니다.
- `편집`: **리스너 편집** 화면에서 자동 포함 범위와 타겟만 바꿀 수 있습니다. 타겟 그룹 항목은 바꿀 수 없습니다.
- `삭제`: 리스너를 삭제합니다.

> ⚠️ **주의:** 리스너가 2개 이상인 경우에만 삭제할 수 있습니다. 마지막 리스너는 삭제할 수 없습니다.

### 서비스 로드 밸런서 편집
목록에서 1개를 고르고 `편집`을 클릭하면 네트워크 메뉴의 **서비스 로드 밸런서 편집** 화면이 열립니다. 이름, 설명, 타입, 내부·외부 IP 주소를 바꿀 수 있고 VPC·서브넷은 바꿀 수 없습니다. 자세한 동작은 [로드 밸런서](../../network/load-balancer/load-balancer.md) 문서와 같습니다.

> 💡 **참고:** 편집 화면은 네트워크 메뉴의 로드 밸런서 편집 권한도 필요합니다.

### 서비스 로드 밸런서 삭제
목록에서 1개를 고르고 `삭제`를 클릭합니다. **서비스 로드 밸런서 삭제** 창에서 정보를 확인하고 `삭제`를 클릭합니다.

## 스토리지 클래스 생성
1. 클러스터 상세 화면의 `스토리지` 탭으로 이동합니다.
2. **스토리지 클래스** 카드에서 `생성`을 클릭합니다.
3. **이름**을 입력합니다.
4. **파일 시스템** 입력칸을 클릭해 **파일 시스템 선택** 창에서 파일 시스템을 고르고 `선택`을 클릭합니다.
5. **반환 정책**(`Delete`·`Retain`)을 고릅니다.
6. `생성`을 클릭합니다. 생성되면 `스토리지` 탭으로 돌아갑니다.

**파일 시스템 선택** 창에는 클러스터와 같은 VPC의 파일 시스템이 표시됩니다(이름, ID, 크기, 경로, 생성 일시).

> ⚠️ **주의:** 고른 파일 시스템은 스토리지 클래스를 만들 때 이 클러스터에 연결됩니다. 클러스터에 연결된 파일 시스템은 `스토리지 > 파일 시스템`에서 삭제할 수 없습니다. 그 파일 시스템을 쓰는 스토리지 클래스를 모두 삭제하면 연결이 해제됩니다. 스토리지 클래스는 클러스터가 실시간 상태일 때만 삭제할 수 있습니다.

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **이름** | 영문 소문자, 숫자, `-` | 최대 `60자`. `-`나 숫자로 시작할 수 없음 | **필수** |
| **파일 시스템** | 클러스터와 같은 VPC의 파일 시스템 | 선택 필요 | **필수** |
| **반환 정책** | `Delete` \| `Retain` | 값 중 하나를 선택해야 함 | **필수** |

## PVC 생성
1. 클러스터 상세 화면의 `스토리지` 탭으로 이동합니다.
2. **PVC** 카드에서 `생성`을 클릭합니다.
3. **이름**, **용량**, **스토리지 클래스**, **네임스페이스**, **접근 모드**를 입력합니다.

> ⚠️ **주의:** PVC 용량은 실제 스토리지 여유와 대조하지 않아, 데이터를 쓸 때 용량이 부족할 수 있습니다. 파일 시스템의 가용 용량을 먼저 확인하세요.

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **이름** | 영문 소문자, 숫자, `-` | 최대 `60자`. `-`나 숫자로 시작할 수 없음 | **필수** |
| **용량** | 숫자 + 단위(`MB`·`GB`·`TB`) | 최소 `1 GB`(1024 MiB) | **필수** |

| **접근 모드** | `ReadOnlyMany` \| `ReadWriteMany` | 값 중 하나를 선택해야 함 | **필수** |

## 접근 권한
클러스터 상세 `접근 관리` 탭에서 kubeconfig 를 발급하고 멤버 권한을 관리합니다.

### kubeconfig 발급
1. **내 접근** 카드에서 `kubeconfig 발급`을 클릭합니다.
2. **유효 기간**(`1일`·`1달`·`1년`, 기본 `1일`)을 고릅니다.
3. `발급 및 다운로드`를 클릭합니다. kubeconfig 파일이 내려받아집니다.

> 💡 **참고:** 내 권한 중 `활성화` 상태가 하나도 없으면 `kubeconfig 발급`이 비활성화됩니다. 권한이 없으면 클러스터 관리자에게 요청하세요.

> 💡 **참고:** 권한 변경(추가·수정·회수)은 기존 kubeconfig에 자동 반영됩니다. 단, 마지막 바인딩을 회수하면 kubeconfig가 무효화됩니다.

### 권한 추가·편집·회수
**멤버 권한** 카드는 내가 활성 `cluster-admin`일 때만 표시됩니다. 네임스페이스 필터와 `사용자` 검색으로 목록을 거를 수 있습니다.

- **권한 추가**: `권한 추가`를 클릭하고 **접근 권한 추가** 창에서 아래 항목을 입력한 뒤 `추가`를 클릭합니다.
- **권한 편집**: 행을 1개 고르고 `편집`을 클릭합니다. **접근 권한 편집** 창에서 사용자를 뺀 항목과 **상태**(`활성화`·`사용 안 함`)를 바꾸고 `편집`을 클릭합니다.
- **권한 회수**: 행을 1개 고르고 `회수`를 클릭합니다. **권한 회수** 창에서 사용자, 역할 이름, 네임스페이스를 확인하고 `회수`를 클릭합니다.

| 필드 | 설명 |
|------|------|
| **사용자** | 프로젝트 사용자를 고릅니다. 편집에서는 바꿀 수 없습니다. |
| **범위** | `클러스터`(기본) 또는 `네임스페이스`. 네임스페이스를 고르면 네임스페이스를 고르거나 `직접 입력`합니다. |
| **역할 종류** | `ClusterRole`(클러스터 전역 역할) 또는 `Role`(특정 네임스페이스의 커스텀 역할). 범위가 `클러스터`면 `ClusterRole`만 고를 수 있습니다. |
| **역할 이름** | `cluster-admin`(클러스터 범위 전용), `view`(읽기 전용), `edit`(읽기·쓰기, 역할·RBAC 변경 제외), `admin`(네임스페이스 전권), 또는 `직접 입력` |
| **설명** | 선택 입력입니다. |

> ⚠️ **주의:** `cluster-admin`은 클러스터 범위에서만 부여할 수 있습니다. 클러스터 범위로 `cluster-admin`을 부여받은 사용자는 모든 바인딩을 부여·박탈할 수 있습니다.

> ⚠️ **주의:** 본인의 권한을 회수할 때 그 권한이 마지막 `cluster-admin`이면 이 클러스터의 권한 관리를 더 할 수 없습니다.

#### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
|------|------|------|------|
| **네임스페이스**(직접 입력) | 영문 소문자, 숫자, `-` | 영숫자로 시작·종료, 최대 `63자` | 범위가 `네임스페이스`일 때 **필수** |
| **역할 이름**(직접 입력) | 영숫자, `.`, `_`, `:`, `-` | 영숫자로 시작, 최대 `253자` | **필수** |

### 관리자 권한 복구
클러스터에 사용 가능한 관리자가 없으면, 프로젝트 소유자는 `접근 관리` 탭 맨 위의 `관리자 권한 복구`로 자신에게 `cluster-admin` 권한을 복구할 수 있습니다. 확인 창 없이 바로 진행됩니다.

## AI 가속기 Operator 관리
클러스터 상세 `AI 가속기` 탭의 **가속기 Operator**에서 NVIDIA GPU Operator 를 설치·설정·제거합니다.

### 설치
1. 왼쪽 목록에서 **NVIDIA GPU Operator**를 고릅니다.
2. **드라이버**를 고릅니다.
   - `Operator 가 설치`(기본): GPU Operator가 노드에 NVIDIA 드라이버를 배포합니다.
   - `노드에 이미 있음`: 노드 이미지에 드라이버가 이미 들어 있는 경우
3. `NVIDIA GPU Operator 설치`를 클릭합니다. 확인 창 없이 바로 요청됩니다.

- 설치 중에는 `설치 요청 접수` → `Operator 배포` → `파드 시작` → `가속기 노드 인식` 단계가 표시됩니다. 드라이버 설치에 수 분 걸립니다.
- GPU 노드가 없으면 설치할 수 없습니다. GPU 워커 노드를 먼저 추가하세요.

> ⚠️ **주의:** 상태가 `직접 설치됨`일 때 여기서 설치하면 Operator 가 두 개가 될 수 있습니다. 이미 설치된 Operator 를 제거했거나, 예전 설치의 라벨만 남은 경우에만 설치하세요.

### 설정
설치가 끝나면(`정상`·`주의`) `개요`·`설정`·`구성 요소`·`제거` 탭이 표시됩니다. `설정` 탭에서 다음을 바꾸고 섹션별 `적용`을 클릭합니다. `취소`를 누르면 저장된 값으로 되돌립니다.

| 섹션 | 필드 | 설명 |
|------|------|------|
| **Time-slicing** | **가상 GPU 개수(replicas)** | GPU 한 장을 파드 여러 개가 시간 단위로 나눠 씁니다. 메모리는 격리되지 않습니다. `1~10` 정수이며, 1 이하이면 공유를 해제합니다. |
| **MIG** | **MIG 전략** | `single`: 노드의 모든 GPU 를 같은 프로필로 / `mixed`: GPU 마다 다른 프로필(Time-slicing 과 함께 쓸 수 없음) |
| | **MIG 프로파일** | 모든 GPU 노드에 적용되는 파티셔닝 프로파일입니다. `all-disabled`, `all-1g.5gb`, `all-1g.10gb`, `all-2g.20gb`, `all-3g.40gb`, `all-balanced`, `직접 입력` 중에서 고릅니다. `all-disabled`를 고르면 MIG를 해제합니다. |

> ⚠️ **주의:** MIG 전략이 `mixed`이면 Time-slicing 을 쓸 수 없고, Time-slicing 을 쓰는 중에는 MIG 전략을 `mixed`로 바꿀 수 없습니다. 이 경우 경고가 표시되고 `적용`이 비활성화됩니다.

### 제거
1. `제거` 탭에서 `삭제`를 클릭합니다.
2. **GPU Operator 제거** 창에서 `삭제`를 클릭합니다.

> ⚠️ **주의:** 제거하면 GPU 리소스가 사라져 가속기를 쓰는 파드가 새로 스케줄되지 않고, 실행 중인 파드도 영향을 받을 수 있습니다. 설정도 함께 지워집니다.

# 인스턴스

CloudiA의 `인스턴스` 메뉴에서는 가상머신을 생성하고, 상태를 확인하고, 전원과 스냅샷, 연결된 리소스를 관리합니다. 이 문서는 실제 UI 사용 절차를 먼저 설명하고, 운영자 성격의 고급 내용은 뒤쪽 `운영 참고`와 `부록`으로 분리합니다.

## 인스턴스 개요

### 메뉴에서 할 수 있는 일

- 프로젝트의 인스턴스 목록을 확인합니다.
- 인스턴스를 생성하고 편집합니다.
- 인스턴스를 실행, 종료, 재부팅, 삭제합니다.
- 허용된 상태의 인스턴스에 콘솔(그래픽 콘솔, 직렬 콘솔)로 접속하고, 상태와 무관하게 콘솔 로그를 내려받습니다.
- 상세 화면에서 네트워크, 디스크, 스냅샷, 연결 리소스, 모니터링 정보를 확인합니다.
- 인스턴스 스냅샷을 생성, 편집, 삭제, 롤백합니다.
- 인스턴스의 부팅 디스크를 다른 스토리지 도메인으로 이동(스토리지 마이그레이션)합니다.

### 화면 구성

| 화면 | 설명 |
| --- | --- |
| `목록` | 인스턴스 상태를 확인하고 생성, 편집, 전원 제어, 삭제를 시작합니다. |
| `생성` | 이름, 스펙, 설치 유형, 네트워크, 사용자 계정, 선택 설정을 입력해 인스턴스를 만듭니다. |
| `편집` | 생성과 같은 화면 구성을 사용합니다. 다만 생성 후 변경할 수 없는 항목은 잠기며, 실행 중에는 일부 항목만 수정할 수 있습니다. |
| `상세` | 현재 상태와 연결된 리소스를 확인하고, 콘솔 접속, 디스크 부팅 순서 변경, 스냅샷 관리 같은 후속 작업을 수행합니다. |

### 상태 이해하기

| 상태 | 의미 | 사용자 안내 |
| --- | --- | --- |
| `생성 중` | 인스턴스 생성 작업이 진행 중입니다. | 작업이 끝날 때까지 기다립니다. |
| `부팅 중` | 전원이 인가되고 게스트 OS가 올라오는 중입니다. | 상태가 안정될 때까지 기다립니다. |
| `실행 중` | 게스트 OS가 동작 중입니다. | 콘솔 접속과 전원 제어가 가능합니다. |
| `재부팅 중` | 재부팅 작업이 진행 중입니다. | 작업이 끝날 때까지 기다립니다. |
| `업데이트 중` | 라이브 업데이트 작업이 진행 중입니다. (예: `vCPU`/`메모리` 핫 변경, 실행 중 NIC·디스크 변경) | 작업이 끝날 때까지 기다립니다. |
| `종료 중` | 종료 작업이 진행 중입니다. | 작업이 끝날 때까지 기다립니다. |
| `종료됨` | 전원이 꺼진 상태입니다. | `실행`할 수 있습니다. |
| `정지됨` | 전원이 꺼진 상태입니다. | `실행`할 수 있습니다. `종료`로 정상 종료 상태로 정리할 수도 있습니다. |
| `일시 중지` | 실행 상태가 일시 중지되었습니다. | `실행`으로 재개할 수 있습니다. 그 외 일부 작업은 제한됩니다. |
| `마이그레이션 대기` | 노드가 한 번에 옮길 수 있는 수를 넘어 마이그레이션 차례를 기다리는 중입니다. 순서를 알면 `마이그레이션 대기 · n번째`로 표시됩니다. 기다리는 동안 인스턴스는 원래 노드에서 그대로 실행됩니다. | 차례가 되면 자동으로 시작합니다. 상태 옆 안내 아이콘에서 목적지 노드와 대기 기한을 확인합니다. |
| `마이그레이션 중` | 호스트 간 이동 작업이 진행 중입니다. 진행률을 알면 `마이그레이션 중 n%`로 표시됩니다. | 작업이 끝날 때까지 기다립니다. 상태 옆 안내 아이콘에서 목적지 노드와 남은 메모리, 경과 시간을 확인합니다. |
| `삭제 중` | 삭제 작업이 진행 중입니다. | 완료될 때까지 기다립니다. |
| `에러` | 생성 또는 운영 중 오류가 발생했습니다. 배치할 수 있는 호스트가 없어 기동하지 못한 경우, 배치 정보가 어긋난 경우도 이 상태로 표시됩니다. | 상태 옆 안내 아이콘에서 원인을 확인합니다. `실행`은 비활성이지만 `종료`는 할 수 있으며, `종료` 후 `실행`이 직접 재시도 경로입니다. |

> 중요
>
> `에러` 상태에서는 시스템이 자동으로 복구를 시도합니다. 상태 옆 안내 아이콘의 문구로 현재 상황을 구분합니다.
>
> - `자동 복구 시도 중`, `자동 재시도 중`: 원인이 해소되면 시스템이 스스로 인스턴스를 되살립니다. 기다려도 됩니다.
> - `저장장치가 복구되면 자동 재시도`, `배치 조건을 만족하는 호스트 없음`: 원인이 인스턴스 밖에 있습니다. 저장장치·호스트 자원이 회복되면 자동으로 다시 시도합니다.
> - `자동 복구를 중단함 · 반복 실패로 관리자 확인 필요`: 자동 재시도가 반복 실패해 멈춘 상태입니다. 관리자에게 원인 확인을 요청하고, 원인을 제거한 뒤 `종료` 후 `실행`으로 다시 시도합니다.
> - `호스트에 같은 이름의 네트워크 장치가 남아 있음 · 관리자 확인 필요`: 인스턴스가 쓰던 네트워크 장치가 노드에 남아 있어 기동하지 못했습니다. 관리자에게 노드 확인을 요청합니다.
> - `메모리 부족으로 강제 종료됨 · 원인은 이벤트에서 확인 (인스턴스 메모리 상한 초과 또는 노드 메모리 부족)`: 메모리가 부족해 인스턴스가 종료됐습니다. 이벤트의 `인스턴스 메모리 부족 종료`(ERROR)에서 원인을 확인합니다. 원인은 `인스턴스가 메모리 상한을 넘음`, `노드의 인스턴스용 메모리 부족`, `노드 메모리 부족` 중 하나로 표시됩니다. 이 이벤트는 관리자와 프로젝트 구성원에게 전달됩니다.
>
> 자동 복구가 중단되어도 `실행`과 `종료`는 그대로 사용할 수 있습니다. 멈추는 것은 시스템의 자동 재시도뿐입니다.
>
> 자동 복구는 원래 노드에서 먼저 다시 시작합니다. 원래 노드에 자리가 없거나 배치 조건이 맞지 않으면 조건을 만족하는 다른 노드에서 시작합니다. 메모리 부족으로 강제 종료된 인스턴스는 반대로 다른 노드를 먼저 시도하고, 받을 노드가 없거나 다른 노드에서 시작하지 못하면 원래 노드에서 시작합니다. 가상 TPM을 쓰는 인스턴스는 TPM 데이터를 함께 옮길 수 없으면 원래 노드에서만 시작하며, 원래 노드가 받을 수 없으면 받을 수 있을 때까지 기다립니다. 결과는 이벤트 `인스턴스 재시작`(INFO) 또는 `인스턴스 재시작 실패`(ERROR)로 남고, 어느 노드에서 시작했는지는 인스턴스 상세 `기본 정보`의 `물리 머신`에서 확인합니다.

> 중요
>
> `종료됨`과 `정지됨`은 모두 전원이 꺼진 상태이지만, 내부 상태 정의는 다릅니다.
>
> - `종료됨`: 현재 어떤 호스트에도 배치되어 있지 않은 종료 상태
> - `정지됨`: 시스템 내부에서 정지 상태로 관리되는 종료 상태
>
> 사용자 관점에서는 두 상태 모두 `실행`할 수 있습니다. 운영 판단이나 장애 분석이 필요할 때는 상태명을 구분해 확인합니다.

> 참고
>
> 이름을 클릭해 상세 화면에 들어갈 수 없는 상태는 `생성 중`, `삭제 중`입니다.

### 관리 대상 구분

| 생성 방식 | 관리 방식 |
| --- | --- |
| `수동 생성` | 이 메뉴에서 생성, 편집, 전원 제어, 삭제, 스냅샷 작업을 수행합니다. |
| `오토 스케일링 그룹`, `쿠버네티스`, `파일 시스템`, `Gen:iA` 등 | 상태와 상세 정보 확인, 편집, 전원 제어는 이 메뉴에서 할 수 있습니다(활성화는 아래 상태 조건과 동일). `삭제`는 할 수 없으며, 원래 생성한 서비스 화면에서 정리합니다. 나머지 관리도 서비스 상태 정합을 위해 원래 생성한 서비스 화면에서 하는 것을 권장합니다. |

> 참고
>
> `편집`·`실행`·`종료`·`재부팅` 버튼의 활성화는 인스턴스 **상태**로만 판단하며, 생성 방식(수동/관리형)으로 구분하지 않습니다.
>
> `삭제`만 예외입니다. `생성 방식`이 `수동 생성`인 인스턴스만 삭제할 수 있습니다.

## 목록에서 할 수 있는 작업

### 목록에서 먼저 확인할 항목

| 항목 | 확인할 내용 |
| --- | --- |
| `번호` | 프로젝트 내 생성 순서를 나타내는 고정 순번입니다(1부터 시작). |
| `이름` | 인스턴스 표시 이름입니다. 이름을 클릭하면 상세 화면으로 이동합니다. |
| `생성 방식` | `수동 생성`인지, 상위 서비스에서 생성된 인스턴스인지 확인합니다. |
| `IP 주소` | NIC에 할당된 IPv4 주소를 표시합니다. NIC가 여러 개면 쉼표로 구분해 함께 표시합니다. |
| `상태` | 현재 전원 상태와 작업 가능 범위를 확인합니다. |
| `vCPU`, `메모리` | 현재 할당된 기본 스펙을 확인합니다. |
| `생성 일시` | 생성 시점을 확인합니다. |

> 참고
>
> 목록의 `IP 주소` 컬럼에서 가장 앞에 표시되는 IPv4 주소는 기본 네트워크 인터페이스의 IPv4 주소입니다.

### 검색과 정렬

- 검색 조건은 `이름`입니다.
- 목록의 모든 컬럼을 정렬할 수 있습니다. `번호` 정렬은 `생성 일시` 기준 정렬과 동일하게 동작하고,
  `IP 주소` 정렬은 기본 네트워크 인터페이스의 IPv4 주소를 숫자 크기 순으로 비교합니다(문자열
  순서가 아닙니다).
- 기본 정렬은 `생성 일시` 기준입니다.
- 페이지당 10개를 표시합니다.
- 목록에서는 좌측 라디오 버튼으로 인스턴스 1개만 선택할 수 있습니다.

### 작업 버튼 사용 기준

아래 표는 목록 화면의 대표 버튼을 같은 기준으로 정리한 것입니다.

- `버튼 표시`: 버튼이 화면에 보이는지
- `버튼 활성화`: 현재 선택한 인스턴스 기준으로 버튼을 클릭할 수 있는지
- `실제 작업 성공`: 버튼 클릭 후 작업이 실제로 완료되기 위한 조건

| 작업 | 버튼 표시 | 버튼 활성화 조건 | 실제 작업 성공 조건 |
| --- | --- | --- | --- |
| `생성` | 항상 표시 | 항상 활성화 | 필수 입력값과 자원 검증을 통과해야 합니다. |
| `편집` | 항상 표시 | 인스턴스 1개를 선택하고, 상태가 `종료됨`, `정지됨`, `실행 중`이어야 합니다. 단, `ISO 파일` 설치 유형은 `실행 중`일 때 비활성화됩니다. | 편집 화면에서 수정 가능한 항목만 저장할 수 있습니다. 실행 중 편집은 라이브 업데이트 가능 항목만 반영됩니다. |
| `실행` | 항상 표시 | 인스턴스 1개를 선택하고, 상태가 `종료됨`, `정지됨`, `일시 중지` 중 하나여야 합니다. | 호스트 배치 조건과 연결 리소스 조건을 만족해야 합니다. `일시 중지` 상태에서 `실행`하면 중지되기 전의 실행 상태로 재개됩니다. |
| `종료` | 항상 표시 | 인스턴스 1개를 선택하고, 상태가 `실행 중`, `일시 중지`, `정지됨`, `에러` 중 하나여야 합니다. `종료됨`에서는 비활성화됩니다. | 종료 요청이 정상 처리되어야 합니다. `에러` 상태 중 배치 정보까지 잃은 인스턴스는 종료가 실패할 수 있으며, 이때는 관리자 확인이 필요합니다. |
| `재부팅` | 항상 표시 | 인스턴스 1개를 선택하고, 상태가 `실행 중`이어야 합니다. `설치 유형`(`OS 이미지`·`ISO 파일`)과는 관계없습니다. | 보안 유형과 시스템 정책에서 재부팅을 허용해야 하며, 재부팅 요청이 정상 처리되어야 합니다. 재부팅은 인스턴스를 지금 노드에서 다시 시작하므로 노드가 바뀌지 않습니다. `ISO 파일` 설치 유형은 설치 CD가 붙어 있어도 설치를 마친 디스크로 부팅합니다. 게스트 OS가 재부팅 신호에 응답하지 않으면 잠시 기다린 뒤 강제로 다시 시작하므로, OS 설치나 파일 저장 중에는 게스트 안에서 재시작하는 편이 안전합니다. |
| `삭제` | 항상 표시 | 인스턴스 1개를 선택하고, `생성 중`, `실행 중`, `부팅 중`, `재부팅 중`, `종료 중`, `삭제 중`, `스냅샷 처리 중` 상태가 아니어야 합니다. | `생성 방식`이 `수동 생성`이고 연결된 인스턴스 스냅샷이 0개여야 합니다. 두 조건을 **모두** 만족해야 확인 창의 `삭제` 버튼이 활성화됩니다. 스냅샷 개수를 조회하지 못했을 때도 `삭제` 버튼이 잠기며, 잠시 후 다시 시도하라는 안내가 표시됩니다. 마이그레이션이 진행 중인 인스턴스는 요청이 거부됩니다. |
| `더보기 > 스토리지 마이그레이션` | 메뉴에 표시 | 인스턴스 1개를 선택하고, 상태가 `실행 중`, `일시 중지`, `정지됨`, `종료됨` 중 하나여야 합니다. | 대상 `스토리지 도메인`을 선택해야 합니다. 콜드/라이브는 인스턴스 상태에 따라 자동으로 갈립니다. 자세한 내용은 [스토리지 마이그레이션](#스토리지-마이그레이션)을 확인합니다. |
| `더보기 > 인스턴스 복제` | 메뉴에 표시 | 인스턴스 1개를 선택하고, 상태가 `실행 중` 또는 `종료됨`이어야 합니다. | 이름 검증과 복제 가능 여부 점검(시스템 인스턴스·추가 블록 연결·할당량 등)을 통과해야 합니다. 네트워크 설정(IP·MAC 주소), 파일 시스템, vTPM 상태는 복제되지 않습니다. 자세한 내용은 [인스턴스 복제](#인스턴스-복제)를 확인합니다. |
| `더보기 > 시작 템플릿으로 변환` | 메뉴에 표시 | 인스턴스 1개를 선택하고, 상태가 `실행 중` 또는 `종료됨`이어야 합니다. | 이름 검증을 통과해야 합니다. 보존 여부는 토글로 선택하며 일부 항목은 항상 보존됩니다. 자세한 내용은 [시작 템플릿으로 변환](#시작-템플릿으로-변환)을 확인합니다. |

> 참고
>
> 스냅샷 생성은 목록 화면 버튼이 아니라 인스턴스 상세 화면의 스냅샷 탭에서 수행합니다. 자세한 내용은 [인스턴스 스냅샷](#인스턴스-스냅샷)을 확인합니다. 아래 "상태별 빠른 기준" 표의 `스냅샷 생성` 열도 이 기준을 따릅니다.
>
> 이 문서에서 `조건부`는 현재 상태는 허용되지만 추가 조건을 더 확인해야 함을 뜻합니다. `삭제`의 추가 조건은 `생성 방식`이 `수동 생성`이고 스냅샷이 0개인 것입니다. 확인 창에도 "수동 생성이면서 스냅샷이 없는 인스턴스만 삭제할 수 있습니다."가 안내됩니다.
>
> 따라서 `오토 스케일링 그룹`·`쿠버네티스`·`파일 시스템`·`Gen:iA`가 만든 관리형 인스턴스는 이 메뉴에서 삭제할 수 없습니다. 원래 만든 서비스 화면에서 정리합니다.

## 인스턴스 생성

### 생성 전에 준비할 항목

- 인스턴스가 연결될 `VPC`를 준비합니다.
- 각 NIC가 연결될 `서브넷`을 준비합니다.
- 접속 방식을 `비밀번호`, `SSH 키`, 또는 둘 다 사용할지 결정합니다.
- `OS 이미지`로 만들지, `ISO 파일`로 직접 설치할지 결정합니다.
- 추가 `블록`, `파일 시스템`, `AI 가속기`, `사용자 스크립트`가 필요한지 확인합니다.

### 1. 기본 정보 입력

- `인스턴스 이름`을 입력합니다.
- 스펙은 `인스턴스 타입 선택` 또는 `직접 입력`으로 지정합니다.
- 필요하면 `vCPU 상세 설정`에서 하이퍼스레딩 사용 여부와 코어 수를 조정합니다.

| 항목 | 입력 기준 | 비고 |
| --- | --- | --- |
| `인스턴스 이름` | 영문 대/소문자, 숫자, `-`, `_` | 최대 80자, 첫 글자 숫자 불가, 공백 및 기타 특수문자 불가 |
| `인스턴스 타입 선택` | 사전 정의된 스펙 선택 | 선택한 타입의 `vCPU`, `메모리`, 최대 NIC 수가 자동 적용됩니다. |
| `직접 입력` | `vCPU`와 `메모리` 직접 입력 | 필요한 스펙을 직접 지정합니다. |
| `vCPU 상세 설정` | 기본값 사용 또는 옵션 지정 | 적용된 `vCPU = CPU 코어당 스레드 수 × 코어 수`입니다. |

| 필드 | 입력 기준 | 비고 |
| --- | --- | --- |
| `vCPU` | 1 이상의 정수 | 실행 중 편집에서는 현재 값보다 줄일 수 없습니다. |
| `메모리` | 크기 입력 + 단위 선택 | 실행 중 증설은 1GB 단위입니다. 이보다 작은 단위(예: 512MB)는 거부됩니다. |
| `메모리 회수 허용` | 토글(`사용함` / `사용 안 함`) | 인스턴스 사양 바로 아래, `무중단 증설` 위의 한 줄에 있습니다. 새 인스턴스는 `사용함`이 기본입니다. 켜면 메모리 크기의 50%를 보장합니다. 회수할 수 없는 인스턴스는 `사용 안 함`으로 고정되고 사유가 표시됩니다. 자세한 내용은 [메모리 회수 허용](#메모리-회수-허용)을 확인합니다. |

> 참고
>
> `vCPU`와 `메모리`는 목록에서 고르는 것이 아니라 값을 직접 입력합니다. 입력 상한은 **인스턴스를 올릴 수 있는 물리 호스트 한 대의 물리 자원**입니다. 인스턴스 하나는 여러 호스트에 걸쳐 실행될 수 없으므로, 컴퓨트 노드에 오버커밋 비율을 올려 두었더라도 그 배수만큼 큰 인스턴스를 만들 수는 없습니다(오버커밋은 여러 인스턴스를 한 호스트에 겹쳐 얹는 설정입니다).
>
> 쿠버네티스 노드는 최소 사양이 있어 `vCPU` 2, `메모리` 2GB 미만을 입력할 수 없습니다.

### 2. 설치 유형 선택

| 설치 유형 | 사용할 때 | 알아둘 점 |
| --- | --- | --- |
| `OS 이미지` | 표준 이미지로 빠르게 인스턴스를 만들 때 사용합니다. | Cloud-init 기반 사용자 계정과 초기 설정을 함께 적용할 수 있습니다. 생성 후 이미지 변경은 불가합니다. |
| `ISO 파일` | OS를 직접 설치하거나 골든 이미지를 만들기 위한 초기 VM을 만들 때 사용합니다. | 설치 자유도는 높지만 제한사항이 많습니다. 생성 후 ISO 변경은 불가합니다. |

> 중요
>
> `ISO 파일` 설치 유형은 일반적인 사용자 워크로드보다 OS 설치 후 골든 이미지를 만드는 초기 작업에 적합합니다. 일반적인 인스턴스 생성은 `OS 이미지` 사용을 권장합니다.
>
> `ISO 파일` 설치 유형의 주요 제한사항은 다음과 같습니다.
>
> - `고급 설정`에서 `보안 유형`과 `오브젝트 스토리지`를 사용할 수 없습니다. `부팅 펌웨어`·`Secure Boot`·`vTPM (TPM 2.0)`, 추가 `블록`, `사용자 스크립트`는 사용할 수 있고, `무중단 증설`(고급 설정 밖)도 사용할 수 있습니다.
> - `사용자 계정`과 `사용자 스크립트`는 입력할 수 있지만 **필수가 아닙니다.** 게스트에 cloud-init이 설치되어 있어야 적용되는데, ISO는 어떤 매체를 올릴지 사용자가 정하므로 설치를 보장할 수 없기 때문입니다. 자세한 내용은 아래 `5. 사용자 계정 설정`을 확인합니다.
> - Windows 계열 `ISO 파일`은 추가 `블록`을 3개까지만 연결할 수 있습니다. 자세한 이유는 아래 `참고`를 확인합니다.
> - 실행 중에는 `편집`할 수 없습니다. 추가 `블록` 연결과 해제는 `종료됨` 상태에서만 가능합니다.
> - `종료됨` 상태에서 편집할 때도 `파일 시스템`, `AI 가속기`, `가상 CPU 피닝`은 변경할 수 없습니다. 생성할 때만 지정할 수 있으며, 편집 화면에서는 각 항목에 변경할 수 없다는 안내가 표시됩니다.
> - 편집 화면에서 `ISO 파일`을 변경할 수 없습니다.
> - `CEPH`(RBD) 스토리지 도메인은 지원하지 않습니다. Ceph 클러스터를 쓰면 `CEPHFS` 도메인에 `ISO 파일`을 올려 사용합니다.

> 참고
>
> Windows 계열 게스트는 모든 디스크가 `SATA` 방식으로 연결되고, 인스턴스 하나가 쓸 수 있는 `SATA` 포트는 6개입니다. `ISO 파일` 설치 유형은 설치 ISO와 드라이버 ISO 두 개가 CD/DVD 드라이브로 함께 연결되어 포트를 사용하므로, 부팅 디스크 1개를 제외하면 추가 `블록`은 3개까지 연결할 수 있습니다. 이 개수를 넘기면 생성 또는 편집 단계에서 거부됩니다. 설치를 마치고 ISO를 분리하면 그만큼 여유가 생겨 더 많은 `블록`을 연결할 수 있습니다.
>
> 생성 화면에서 `CD/DVD 드라이브`를 직접 연결하면 그 수만큼 포트를 더 사용하므로 추가 `블록` 한도가 함께 줄어듭니다. `OS 이미지` 설치 유형에서도 Windows 계열이면 같은 규칙이 적용됩니다.
>
> Linux 계열 게스트는 디스크 연결 방식이 달라 이 제한이 적용되지 않습니다.

> 참고
>
> Windows를 `ISO 파일`로 설치할 때 부팅 장치 선택 화면이 보이면 `QEMU DVD-ROM` 항목을 선택합니다. Windows 11의 네트워크 요구 사항 우회와 VirtIO 드라이버 설치 예시는 [윈도우 가상머신 ISO 생성 및 콘솔 확인](../../../user-guide/examples-and-labs/04-create-windows-instance-from-iso-and-open-console.md)을 확인합니다.

> 운영체제별 상세 기준은 [부록 A. ISO 기반 부팅 디스크 기준](#appendix-a-boot-disk-criteria)을 확인합니다.

### 4. 네트워크 인터페이스 구성

- 인스턴스에는 최소 1개의 네트워크 인터페이스가 필요합니다.
- 인스턴스는 하나의 `VPC`에 속합니다.
- 첫 번째 NIC가 기본 네트워크 인터페이스가 됩니다.

| 항목 | 입력 방법 | 비고 |
| --- | --- | --- |
| `서브넷` | 선택한 VPC에 속한 서브넷을 선택합니다. | NIC마다 1개씩 선택합니다. |
| `IP 주소 - 자동 할당` | 사용 가능한 IPv4를 자동으로 할당합니다. | 권장 기본값입니다. |
| `IP 주소 - 수동 할당` | 선택한 서브넷의 CIDR 안에서 IPv4를 직접 입력합니다. | 서브넷 선택 후 사용할 수 있습니다. |
| `보안그룹` | NIC에 적용할 보안그룹을 선택합니다. | NIC당 최대 5개를 선택합니다. |

`오브젝트 스토리지`를 활성화하면 네트워크 인터페이스 목록 맨 앞에 시스템용 `Managed VNIC`가 자동으로 추가됩니다. 이 NIC는 오브젝트 스토리지 내부 접근에 필요한 연결을 제공하며, 사용자가 직접 추가, 수정, 삭제하는 일반 NIC와는 다르게 동작합니다.

> 중요
>
> `오브젝트 스토리지`를 사용하더라도 사용자 NIC는 최소 1개 이상 필요합니다. `Managed VNIC`만으로 인스턴스를 구성할 수는 없습니다.

> 참고
>
> NIC가 여러 개여도 게스트 OS에는 기본 네트워크 인터페이스의 DNS만 자동으로 적용됩니다. 추가 NIC에 필요한 DNS는 게스트 OS에서 직접 설정합니다.

### 5. 사용자 계정 설정

`사용자 계정`은 게스트에 cloud-init이 설치되어 있어야 적용됩니다. 그래서 입력 가능 여부는 `설치 유형`이 아니라 **게스트의 OS 계열**로 갈립니다.

| 게스트 OS 계열 | 입력 가능 여부 | 화면 동작 |
| --- | --- | --- |
| Linux 계열 + `OS 이미지` | 입력 가능, **필수** | `사용자 이름`과 인증 방법(`비밀번호` 또는 `SSH 키`)을 반드시 입력합니다. |
| Linux 계열 + `ISO 파일` | 입력 가능, **선택** | 섹션 위에 `이 계정·인증 설정은 게스트에 cloud-init 이 설치되어 있어야 적용됩니다.` 안내가 표시됩니다. 전부 비워 두고 저장할 수 있습니다. |
| `Windows 10`·`Windows 11`·`Windows Server 2019` 이상 | 입력 불가 | `설치 유형`과 무관하게 섹션 전체가 비활성화되고 `이 게스트는 cloud-init 이 부착되지 않아 계정·스크립트 입력이 반영되지 않습니다.` 안내가 표시됩니다. |
| `Windows Server 2016` 이하 | 입력은 되지만 적용되지 않음 | 섹션이 열려 있어 값을 넣을 수 있으나, Windows 게스트에는 cloud-init 이 부착되지 않아 입력한 계정·스크립트가 게스트에 반영되지 않습니다. 설치 과정에서 계정을 직접 만듭니다. |

| 항목 | 입력 기준 | 비고 |
| --- | --- | --- |
| `사용자 이름` | 4~20자, 첫 글자 영문 소문자, 소문자/숫자/`_`/`-` | 예약어는 사용할 수 없습니다. |
| `비밀번호` | 4~20자, 허용된 영문/숫자/특수문자 | 계정이 필수인 조합에서 `SSH 키`를 선택하지 않으면 입력해야 합니다. |
| `SSH 키` | 현재 프로젝트에 등록된 SSH 키 선택 | 최대 5개까지 선택합니다. 계정이 필수인 조합에서 `비밀번호`를 사용하지 않으면 1개 이상 선택해야 합니다. |

> 중요
>
> `ISO 파일` 설치 유형에서 `사용자 계정`을 입력하면, 설치할 OS에 cloud-init이 준비되어 있을 때만 게스트에 반영됩니다. OS를 직접 설치하면서 계정을 따로 만들 계획이면 이 섹션은 비워 둡니다.
>
> `사용자 이름`을 비운 채 `비밀번호`나 `SSH 키`만 입력할 수는 없습니다. 계정이 성립하지 않아 저장되지 않습니다.

> 참고
>
> `사용자 계정`에 지정한 계정은 게스트 OS의 기본 사용자 계정(UID 1000)으로 만들어지며, CloudiA가 관리하는 계정은 이 하나뿐입니다. `SSH 키` 추가나 `비밀번호` 변경처럼 cloud-init을 다시 실행하는 설정 변경이나 재부팅이 발생해도 이 계정은 그대로 유지됩니다.
>
> 추가 계정이 필요하면 인스턴스에 접속한 뒤 게스트 OS에서 직접 `useradd`로 만듭니다. 이렇게 만든 추가 계정은 CloudiA가 관리하지 않지만, 위와 같은 설정 변경이나 재부팅에도 삭제되지 않고 유지되며, 생성·삭제·권한 관리는 사용자가 직접 수행합니다.
>
> Windows 계열 게스트는 `OS 이미지`든 `ISO 파일`이든 cloud-init이 붙지 않습니다. `OS 이미지`로 만든 Windows 인스턴스는 이미지에 미리 설정된 계정으로 로그인하고, `ISO 파일`로 설치하는 Windows 인스턴스는 설치 과정에서 계정을 직접 만듭니다.

### 6. 선택 설정 검토

필요한 경우 아래 항목을 함께 설정합니다.

| 항목 | 설명 | 비고 |
| --- | --- | --- |
| `블록` | 프로젝트의 블록 자원을 인스턴스에 연결합니다. | 운영 데이터와 OS 디스크를 분리할 때 사용합니다. |
| `CD/DVD 드라이브` | 데이터 CD 같은 사용자 `ISO 파일`을 연결합니다. | 설치 미디어와 드라이버 CD는 플랫폼이 자동으로 연결하므로 여기에 넣지 않습니다. `CEPH`(RBD) 스토리지 도메인의 `ISO 파일`은 선택할 수 없습니다. Ceph 클러스터의 `ISO 파일`은 `CEPHFS` 도메인에 올려 사용합니다. 생성 이후에는 상세 화면 `인스턴스 구성 요소 > 디스크 및 CD/DVD`에서 `ISO 파일`을 연결·해제할 수 있고, 이 작업은 `실행 중`에도 가능합니다. 드라이브 추가·제거는 인스턴스를 정지한 뒤 같은 화면에서 하며, `종료됨` 상태라면 편집 화면에서도 할 수 있습니다. |
| `파일 시스템` | 파일 시스템 자원을 선택하고 마운트 포인트를 지정합니다. | `NFS`, `virtiofs` 같은 공유 저장소 연결에 사용합니다. Windows 이미지는 자동 마운트를 지원하지 않아 이 항목을 사용할 수 없으며, 게스트에서 직접 마운트해야 합니다. |
| `오브젝트 스토리지` | 오브젝트 스토리지 접근용 네트워크를 함께 사용하도록 설정합니다. | 활성화하면 네트워크 인터페이스 목록 맨 앞에 `Managed VNIC`가 자동 추가됩니다. 별도 디스크를 붙이는 기능은 아닙니다. `ISO 파일` 설치 유형에서는 사용할 수 없습니다. |
| `AI 가속기` | AI 가속기를 연결합니다. | `GPU` 또는 `NPU` 가속기를 선택할 수 있습니다. 인스턴스 스펙을 `직접 입력`으로 구성할 때 선택할 수 있으며, 카드 수는 장치별 `노드당 최대 카드 수`까지만 입력할 수 있습니다. 자세한 내용은 상세 화면의 `AI 가속기 탭`을 참고합니다. |
| `선호도 그룹` | 인스턴스를 배치할 선호(preferred) 또는 반선호(anti-affinity) 그룹을 선택합니다. | 선호 그룹은 지정한 인스턴스들을 같은 호스트에 배치하고, 반선호 그룹은 서로 다른 호스트에 배치합니다. 자세한 내용은 [선호도 그룹](../affinity-group/affinity-group.md)을 확인합니다. |
| `Secure Boot` | 토글을 켜면 인스턴스가 Secure Boot로 부팅합니다. | `부팅 펌웨어`가 `UEFI`일 때만 화면에 나타납니다. Windows 이미지는 UEFI로 동작하며 Secure Boot가 기본 활성화됩니다. Windows 11은 하드웨어 요구 사항에 따라 비활성화할 수 없으며, 그 외 Windows는 필요 시 비활성화할 수 있습니다. |
| `vTPM (TPM 2.0)` | 토글을 켜면 인스턴스에 가상 TPM 2.0 장치를 제공합니다. | `부팅 펌웨어`가 `UEFI`일 때만 화면에 나타납니다. Windows 11 이미지에는 하드웨어 요구 사항에 따라 vTPM 2.0이 필수로 적용됩니다. 그 외 이미지에서는 직접 켜고 끌 수 있습니다. |
| `백업 연동` | VBR 백업 계정을 넣는 데 쓰는 명령 실행을 게스트의 `QEMU Guest Agent`가 열어 줄지 고릅니다. | `고급 설정`을 펼친 `보안 설정` 맨 아래에서 `미허용(기본)`과 `허용` 카드 중 하나를 고릅니다. 기본값은 `미허용(기본)`입니다. 부팅 펌웨어와 상관없이 나타나지만 `ISO 파일` 설치 유형에서는 나타나지 않습니다. 미허용이면 CloudiA가 쓰는 기능 10개만 열리고, 허용으로 바꾸면 거기에 명령 실행(`guest-exec`, `guest-exec-status`)만 더 열립니다. 파일 읽기·쓰기나 계정 비밀번호·SSH 키 변경 같은 나머지 기능은 어느 쪽이든 막혀 있습니다. VBR 백업을 쓰려면 허용으로 바꿔야 합니다. **만든 뒤에도 인스턴스를 정지하고 편집에서 바꿀 수 있으며, 바꾼 값은 다음 시작부터 적용됩니다.** `Rocky Linux 9·10`, `Ubuntu 22.04·24.04`에만 적용됩니다. 자세한 내용은 [백업 연동](#백업-연동)을 확인합니다. |
| `하드웨어 시계` | 인스턴스가 부팅할 때 읽는 시계의 기준을 `자동`, `현지 시각`, `UTC` 중에서 고릅니다. | `고급 설정`을 펼친 `보안 설정` 맨 아래에 있습니다. 기본값은 `자동`이며, Windows 면 현지 시각, 다른 운영체제면 UTC 를 씁니다. `현지 시각`은 컴퓨트 노드의 시간대를 따릅니다. `ISO 파일` 설치 유형에서도 고를 수 있습니다. 만든 뒤에도 인스턴스를 정지하고 편집에서 바꿀 수 있으며, 바꾼 값은 다음 시작부터 적용됩니다. 자세한 내용은 [가상머신 시계](#가상머신-시계)를 확인합니다. |
| `부팅 펌웨어` | 부팅 방식을 `기본값`, `BIOS`, `UEFI` 중에서 선택합니다. | `기본값`은 선택한 이미지가 선언한 펌웨어를 그대로 따릅니다. 보안 인스턴스(`SEV` 등)는 `BIOS`를 선택할 수 없고, Windows 11 이미지는 `UEFI`만 지원합니다. 이미지가 선언한 펌웨어와 다른 값을 선택하면 부팅에 실패할 수 있다는 경고가 화면에 표시됩니다. |
| `무중단 증설` | 토글을 켜면 인스턴스를 종료하지 않고 vCPU·메모리를 늘릴 수 있습니다. | `고급 설정` 안이 아니라 인스턴스 사양 바로 아래에 있습니다. 기본값은 `사용함`이며, 이때 상한은 현재 사양의 4배로 자동 산정됩니다. `SEV-ES`·`SEV-SNP`를 선택하면 사용할 수 없고, 시스템 정책으로 꺼진 환경에서도 켤 수 없습니다. |
| `고급 설정` | `보안 설정`, `스토리지 추가`, `AI 가속기`, `가상 CPU 피닝`, `선호도 그룹`, `사용자 스크립트`를 이 순서로 설정합니다. | 자세한 의미와 운영 기준은 [고급 설정 항목](#고급-설정-항목)을 확인합니다. `ISO 파일` 설치 유형에서는 `보안 유형`과 `오브젝트 스토리지`를 사용할 수 없고, `백업 연동`은 화면에 나타나지 않습니다. |
| `사용자 스크립트` | 부팅 시 자동으로 실행할 작업을 등록합니다. | `고급 설정`의 마지막 항목입니다. cloud-init이 동작하는 게스트에서 사용하므로 Windows 계열 게스트에서는 비활성화됩니다. `ISO 파일` 설치 유형은 Linux 계열이면 등록할 수 있지만, 설치할 OS에 cloud-init이 준비되어 있어야 실제로 실행됩니다. |

> 참고
>
> `NFS` 파일 시스템이 연결된 경우에는 일반적인 경우보다 종료 시간이 길어질 수 있습니다.
>
> `오브젝트 스토리지`를 활성화하면 생성 화면의 네트워크 인터페이스 목록에도 `Managed VNIC`가 함께 표시됩니다. 이 항목은 사용자가 선택, 수정, 삭제할 수 없습니다.
>
> vTPM이 활성화된 인스턴스는 라이브 마이그레이션이 지원되지 않습니다. 무중단 이전 대신 콜드 마이그레이션을 사용합니다.
>
> 게스트에서 디스크 암호화 키를 TPM에 봉인할 때(Windows BitLocker, Linux LUKS `systemd-cryptenroll` 등)는 `PCR 0`을 봉인 기준으로 사용하지 않습니다. `PCR 0`은 인스턴스의 메모리 크기를 변경하거나 하드웨어 구성이 다른 호스트에서 다시 시작되면 값이 달라져, 봉인한 키가 자동으로 해제되지 않습니다. 이때는 복구 키를 직접 입력해야 접근을 회복할 수 있으므로, 복구 키는 반드시 인스턴스 외부에 별도로 보관합니다.
>
> Secure Boot를 함께 사용하는 인스턴스에서는 `PCR 7`을 봉인 기준으로 사용합니다. Secure Boot를 사용하지 않는 인스턴스에서는 `PCR 7`에 Secure Boot가 비활성 상태라는 사실만 기록되어, 부트로더나 커널이 교체되어도 값이 그대로입니다. 따라서 이 구성에서는 `PCR 7` 하나만으로 봉인하지 말고 부팅 구성요소를 함께 측정하는 PCR을 추가하거나 별도의 인증 수단을 사용합니다.
>
> 연결할 수 있는 CD/DVD 드라이브 수는 `SATA` 포트 6개를 `블록`·설치 미디어·드라이버 CD와 나눠 쓰는 만큼으로 정해집니다. 남은 포트가 없으면 `추가` 버튼이 비활성화되며, 추가 `블록`을 줄이면 다시 연결할 수 있습니다. 자세한 배경은 아래 `SATA 포트와 추가 블록 개수` 참고를 확인합니다.
>
> 이미지·`ISO 파일`·`블록`·`파일 시스템`은 각각 특정 호스트에 전속된 스토리지 도메인에 속할 수 있습니다. 이미 선택한 항목과 같은 호스트에 둘 수 없는 항목은 선택 목록에서 비활성화되며, 모달 제목 옆 `ⓘ` 아이콘에 마우스를 올리면 안내 문구를 확인할 수 있습니다.

### 7. 사용자 스크립트 입력

반복되는 초기 설정이 있으면 `사용자 스크립트`로 자동화합니다. 입력란은 `고급 설정`의 마지막 항목입니다.

| 항목 | 설명 |
| --- | --- |
| `실행 순서` | 여러 스크립트를 등록한 경우 실행 순서를 지정합니다. |
| `파일 이름` | 스크립트 파일 이름을 입력합니다. |
| `단계` | 실행 시점을 선택합니다. |
| `내용` | 스크립트 본문을 입력합니다. |

| 단계 | 실행 시점 | 한 줄 요약 |
| --- | --- | --- |
| `PER_BOOT` | 부팅할 때마다 | 재부팅하면 반드시 다시 실행됩니다. |
| `PER_INSTANCE` | instance-id가 바뀔 때 1회 | 최초 부팅 시 실행됩니다. CloudiA에서 instance-id 변경 트리거(아래 목록)가 발생하면 instance-id가 갱신되어 다시 실행됩니다. |
| `PER_ONCE` | cloud-init 상태 기준 딱 1회 | 최초 부팅 이후에는 재부팅이나 CloudiA 설정 변경과 무관하게 다시 실행되지 않습니다. 재실행하려면 `cloud-init clean` 후 재부팅해야 합니다. |

`PER_INSTANCE`와 `PER_ONCE`는 모두 "한 번"처럼 보이지만 CloudiA 설정 변경 시 동작이 다릅니다.

| 상황 | `PER_BOOT` | `PER_INSTANCE` | `PER_ONCE` |
| --- | --- | --- | --- |
| 최초 부팅 | 실행 | 실행 | 실행 |
| 단순 재부팅 | 실행 | 실행 안 함 | 실행 안 함 |
| CloudiA에서 instance-id 변경 트리거 발생 후 부팅 | 실행 | **다시 실행** | 실행 안 함 |
| `cloud-init clean` 후 재부팅 | 실행 | 실행 | 실행 |

#### instance-id 변경 트리거

`PER_INSTANCE` 스크립트는 cloud-init instance-id가 바뀐 다음 부팅에서 다시 실행됩니다. CloudiA는 아래 변경이 발생하면 instance-id를 새 버전으로 발급합니다.

- `사용자 스크립트` 추가·수정·삭제
- `SSH 키` 추가·삭제
- `NIC` 추가·삭제
- `비밀번호` 추가·변경·삭제
- `파일 시스템`(`NFS`, `virtiofs`) 연결·해제 또는 마운트 포인트 변경
- 기본 NIC가 속한 `서브넷`의 `DNS 서버` 변경

> 참고
>
> instance-id 버저닝은 cloud-init이 붙는 인스턴스에만 적용됩니다. Windows 계열 게스트와, `사용자 계정`·`사용자 스크립트`를 입력하지 않은 `ISO 파일` 인스턴스는 cloud-init이 붙지 않아 해당하지 않습니다. `인스턴스 이름`, `사용자 이름`, `vCPU`·`메모리` 변경은 트리거가 아닙니다.
>
> 게스트에서 현재 instance-id는 `cloud-init query instance-id`로 확인할 수 있습니다. 변경 트리거 후 이 값이 달라졌다면 다음 부팅에서 `PER_INSTANCE` 스크립트가 다시 실행됩니다.

> 참고
>
> 사용자 스크립트는 게스트 OS 안에서 실행됩니다. 패키지 관리자와 서비스 이름은 게스트 OS에 맞게 작성합니다.
>
> **단계 선택 기준:**
> - 부팅마다 상태를 보정하거나 마운트를 확인해야 하면 `PER_BOOT`를 사용합니다. 반드시 idempotent하게 작성합니다.
> - 새 인스턴스를 만들 때마다 초기화 작업이 필요하면 `PER_INSTANCE`를 기본으로 사용합니다.
> - 스크립트 변경 여부와 무관하게 단 한 번만 실행되어야 하는 이미지 생명주기 작업에만 `PER_ONCE`를 사용합니다. 일반적인 초기화에는 `PER_INSTANCE`가 더 적합합니다.
>
> Linux 인스턴스를 골든 이미지로 만들기 전에 `PER_ONCE` 스크립트가 이미 실행된 상태라면, 그 실행 이력이 이미지에 포함될 수 있습니다. 골든 이미지 생성 전에는 게스트 OS에서 `cloud-init clean`을 수행한 뒤 종료하는 절차를 표준으로 권장합니다. 자세한 예시는 [스냅샷 이미지 생성으로 골든 이미지 만들기 및 인스턴스 실행](../../../user-guide/examples-and-labs/16-create-golden-image-from-snapshot.md)을 확인합니다.

#### 시스템 스크립트

`파일 시스템`(`NFS`)을 생성하면 CloudiA가 NFS 서버 인스턴스를 만들고, 그 인스턴스에 필요한 스크립트를 자동으로 주입합니다. 이 스크립트는 무엇이 주입되어 있는지 확인할 수 있도록 `사용자 스크립트` 목록에 표시되지만 **조회만 할 수 있습니다** — NFS 서버 인스턴스는 상위 서비스가 관리하는 시스템 인스턴스라서 편집 자체가 허용되지 않습니다. 자세한 내용은 [상위 서비스 인스턴스 관리](#상위-서비스-인스턴스-관리)를 확인합니다.

## 인스턴스 편집

### 편집을 시작하기

- 목록에서 인스턴스 1개를 선택합니다.
- `편집`을 클릭합니다.
- 편집 화면은 생성 화면과 같은 구성을 사용합니다.
- 생성 후 변경할 수 없는 항목은 잠겨 있습니다.

> 중요
>
> `편집` 버튼은 인스턴스를 하나만 선택하고, 상태가 `실행 중`·`정지됨`·`종료됨`일 때 활성화됩니다. 단, `ISO`로 부팅해 `실행 중`인 인스턴스는 편집할 수 없습니다.

> 참고
>
> 편집 화면의 `블록` 목록에는 `스냅샷` 열이 있습니다. 해당 블록을 사용하는 인스턴스 스냅샷이 있으면 "N건 사용 중"으로 표시되고(마우스를 올리면 스냅샷 이름 확인) 선택을 해제할 수 없습니다. 이 블록을 분리하려면 먼저 해당 스냅샷을 삭제합니다. 나중에 분리할 블록이면 스냅샷을 만들 때 그 블록을 제외해 두면 막히지 않습니다([스냅샷 생성](#스냅샷-생성) 참고). 스냅샷 목록을 조회하지 못한 경우에도 스냅샷이 남아 있으면 저장 시 분리가 거부됩니다.
>
> 목록에서 뺀 블록은 저장할 때 분리됩니다. 리눅스 게스트의 `/etc/fstab` 에 뺀 블록의 항목이 남아 있으면 인스턴스를 다시 시작할 때 부팅하지 못할 수 있습니다. 붙어 있던 블록을 목록에서 빼면 화면에도 같은 안내가 표시됩니다. 저장하기 전에 게스트 `/etc/fstab` 에서 뺀 블록의 항목을 지우거나 `nofail` 을 붙입니다.

### 종료 상태에서 편집

`종료됨` 상태에서는 편집 화면에 들어가 수정 가능한 항목을 저장할 수 있습니다.

`정지됨` 상태에서도 편집 화면은 열리지만 저장은 실패합니다. 저장하려면 먼저 `종료`를 실행해 `종료됨` 상태로 정리합니다.

- 생성 시에만 결정되는 항목은 계속 잠겨 있습니다.
- 대표적으로 `설치 유형`, `OS 이미지`, `ISO 파일`은 생성 후 변경할 수 없습니다.
- `부팅 펌웨어`, `Secure Boot`, `vTPM (TPM 2.0)`도 생성 시에만 지정할 수 있습니다. 전원 상태와 무관하게 편집 화면에서 잠기며, 화면에 `펌웨어·Secure Boot·vTPM 은 생성 시에만 지정할 수 있습니다. 설치된 게스트의 부트로더와 짝이라 사후 변경이 성립하지 않습니다.`가 안내됩니다.
- `부팅 디스크 크기`는 값을 줄일 수는 없지만, 전원 종료 상태에서는 현재 값 이상으로 증설(확대)할 수 있습니다. 자세한 내용은 아래 `부팅 디스크 증설`을 확인합니다.
- `메모리 회수 허용`은 종료 상태에서 바꿀 수 있습니다. 실행 중에도 바꿀 수 있습니다. 자세한 내용은 [메모리 회수 허용](#메모리-회수-허용)을 확인합니다.
- `오브젝트 스토리지` 토글은 종료 상태에서 변경할 수 있습니다. 단 `ISO 파일` 설치 유형에서는 사용할 수 없습니다.
- `오브젝트 스토리지`를 활성화하면 네트워크 인터페이스 목록 맨 앞에 `Managed VNIC`가 자동 추가되고, 비활성화하면 해당 NIC가 자동 제거됩니다.
- `백업 연동`은 종료 상태에서 허용·미허용으로 바꿀 수 있습니다. 바꾼 값은 다음 시작부터 적용됩니다. 단 `ISO 파일` 설치 유형에서는 사용할 수 없습니다. 자세한 내용은 [백업 연동](#백업-연동)을 확인합니다.
- `하드웨어 시계`는 종료 상태에서 바꿀 수 있습니다. 바꾼 값은 다음 시작부터 적용됩니다. `자동`이 골라져 있으면 라디오 아래에 다음 시작부터 쓸 기준이 한 줄로 보입니다. 자세한 내용은 [가상머신 시계](#가상머신-시계)를 확인합니다.
- `CD/DVD 드라이브`는 종료 상태에서 추가·제거할 수 있습니다. 자세한 내용은 아래 `CD/DVD 드라이브 편집`을 확인합니다.

#### CD/DVD 드라이브 편집

`종료됨` 상태에서는 편집 화면의 `스토리지` 영역에서 `CD/DVD 드라이브` 목록을 그대로 관리합니다. 목록에 남긴 상태가 저장 시점의 최종 상태가 되므로, 필요한 드라이브만 남기고 나머지는 목록에서 지웁니다.

- 목록에는 사용자가 연결한 드라이브만 표시됩니다. 설치 미디어와 드라이버 CD는 플랫폼이 관리하므로 목록에 나오지 않고, 편집으로 지워지지도 않습니다.
- 매체를 해제해 비워 둔 드라이브는 목록에 나오지 않지만 자리는 계속 차지합니다. 연결 가능한 개수를 셀 때 함께 계산됩니다. 이 화면에서는 지울 수 없으므로, 자리를 되찾으려면 상세 화면 `인스턴스 구성 요소 > 디스크 및 CD/DVD`에서 드라이브 자체를 제거합니다.
- `CEPH`(RBD) 스토리지 도메인의 `ISO 파일`은 선택할 수 없습니다. `CEPHFS` 도메인에 올린 `ISO 파일`을 사용합니다.
- 인스턴스가 아직 호스트에 배치되지 않았다면, 연결한 `ISO 파일` 전체를 한 호스트에서 볼 수 있어야 합니다. 이미 고른 `ISO 파일`과 한 호스트에서 함께 볼 수 없는 `ISO 파일`은 선택 목록에서 비활성으로 표시되며, 사유는 모달 제목 옆 `ⓘ` 아이콘에서 확인합니다.

> 참고
>
> 기존 연결 정보를 불러오는 동안에는 이 항목을 편집할 수 없습니다. 불러오기가 끝나지 않은 상태로 저장하면 변경이 반영되지 않기 때문입니다.
>
> 연결할 수 있는 드라이브 수는 `SATA` 포트 6개를 나눠 쓰는 만큼으로 정해집니다. 설치 미디어·드라이버 CD·매체를 해제해 비워 둔 드라이브처럼 목록에 보이지 않는 것도 포트를 차지하며, Windows 게스트에서는 추가 `블록`도 함께 씁니다.

#### 부팅 디스크 증설

`종료됨` 상태에서는 편집 화면의 `디스크 크기 설정`에서 `부팅 디스크 크기`를 현재 값 이상으로 늘릴 수 있습니다. 증설(확대)만 가능하며 크기를 줄일 수는 없고, 저장 후 다음 실행 시점에 블록 디바이스가 확대됩니다. cloud-init(Linux)·Cloudbase-init(Windows) 같은 확장 도구가 포함된 이미지는 게스트 OS의 파티션과 파일 시스템이 부팅 시 자동으로 확장됩니다. 루트가 LVM으로 구성된 인스턴스(RHEL·Rocky 계열 설치 기본 구성)도 자동 확장 대상입니다. 도구가 없는 이미지는 게스트에서 수동으로 확장해야 합니다.

> 참고
>
> 증설 절차와 게스트 OS별(Linux/Windows) 수동 확장 방법, 필요한 패키지는 [인스턴스 부팅 디스크 증설하기](../../../user-guide/examples-and-labs/22-grow-boot-disk.md)를 확인합니다.

### 실행 중 편집

실행 중 편집은 라이브 업데이트로 처리합니다. 화면 상단에 경고 배너가 표시될 수 있습니다.

#### 실행 중에도 가능한 작업

- `vCPU` 늘리기
- `메모리` 늘리기
- `메모리 회수 허용` 켜기·끄기
- 네트워크 인터페이스 추가, 편집, 삭제
- 기본 NIC는 `보안그룹`만 변경할 수 있습니다. `서브넷`과 `내부 IP 주소`는 변경할 수 없고, 삭제도 할 수 없습니다.
- 추가 블록 디스크 연결 또는 제거

#### 실행 중에는 제한되는 작업

- `인스턴스 이름`
- `인스턴스 타입 선택`과 `직접 입력` 전환
- 하이퍼스레딩 변경
- `설치 유형`, `OS 이미지`, `ISO 파일`
- `부팅 펌웨어`, `Secure Boot`, `vTPM (TPM 2.0)` (전원 상태와 무관하게 편집에서 잠깁니다)
- `부팅 디스크 크기` (실행 중에는 변경할 수 없습니다. 전원 종료 상태에서는 증설할 수 있으며, `종료 상태에서 편집`의 `부팅 디스크 증설`을 확인합니다.)
- `VPC` 변경
- 기본 NIC의 `서브넷`·`내부 IP 주소` 변경 또는 삭제 (`보안그룹` 변경은 가능합니다)
- `사용자 계정`
- `보안 유형`, `무중단 증설`
- `파일 시스템`
- `오브젝트 스토리지`
- `백업 연동` (항목은 보이지만 잠깁니다)
- `하드웨어 시계` (항목은 보이지만 잠깁니다)
- `AI 가속기`
- `가상 CPU 피닝`
- `사용자 스크립트` 등록
- `CD/DVD 드라이브` 추가·제거 (정지 상태에서만 가능합니다. `실행 중`의 `ISO` 연결·해제는 상세 화면 `디스크 및 CD/DVD`에서 합니다)

> 중요
>
> `ISO 파일` 설치 유형의 인스턴스는 `실행 중` 상태에서 편집할 수 없습니다.
>
> `오브젝트 스토리지` 토글은 실행 중 편집에서 변경할 수 없습니다. 따라서 실행 중에는 `Managed VNIC`를 추가하거나 제거할 수 없습니다.
>
> `백업 연동`과 `하드웨어 시계`도 실행 중 편집에서는 잠겨 있습니다. 바꾸려면 인스턴스를 정지한 뒤 편집합니다.

> 참고
>
> 실행 중 편집에서는 현재 값보다 작은 `vCPU` 또는 `메모리`로 줄일 수 없습니다.
>
> - `vCPU`: 현재 값 이상, `무중단 증설` 상한 이하
> - `메모리`: 현재 값 이상, `무중단 증설` 상한 이하. 1GB 단위로만 늘릴 수 있으며, 화면에는 "재기동 없이 N회 더 늘릴 수 있습니다(1GB 단위)."로 남은 증설 가능 횟수가 표시됩니다. N은 인스턴스마다 다릅니다(남은 슬롯 수).
>
> 하이퍼스레딩을 사용하는 인스턴스는 실행 중 `vCPU` 증설 시 짝수 단위로만 늘릴 수 있습니다.
>
> 보안 유형에 따라 라이브 업데이트가 제한될 수 있습니다. `SEV-ES`, `SEV-SNP`는 실행 중 재부팅, `vCPU` 증설, 메모리 증설이 모두 제한됩니다.
>
> `메모리 회수 허용`을 켜는 것은 노드 여유와 상관없이 할 수 있습니다. 끄면 보장 메모리가 메모리 전체로 늘어나므로, 메모리 오버커밋을 켠 노드에 여유가 없으면 노드 여유 부족으로 거절됩니다. 이때는 인스턴스를 종료한 뒤 바꾸거나, 인스턴스를 다른 노드로 옮긴 뒤 바꿉니다. 인스턴스를 옮기는 중에는 바꿀 수 없습니다.

> 주의
>
> 실행 중에 NIC나 블록 디스크를 추가해도 게스트 OS 내부 설정이 자동으로 끝나지 않을 수 있습니다. 인터페이스, IP, 라우팅, DNS, 디스크 인식 상태는 게스트 OS에서 직접 확인합니다. 자세한 점검 예시는 [부록 B. 다중 NIC 운영 참고](#appendix-b-multi-nic-ops)와 [부록 D. 추가 블록 디스크와 파일 시스템 확인 명령](#appendix-d-block-disk-and-filesystem-checks)을 확인합니다.

- `생성 중`, `삭제 중` 상태에서는 상세 화면에 들어갈 수 없습니다.

> 참고
>
> `연결된 리소스 > 백업`에서 하는 작업은 [백업](#백업)에서 따로 설명합니다.
>
> `인스턴스 타입`을 지정하지 않고 만든 인스턴스는 `인스턴스 타입` 항목이 표시되지 않습니다. `오브젝트 스토리지` 항목도 VPC 구성에 따라 표시되지 않을 수 있습니다.
>
> `메모리 회수 허용`은 `활성화` 또는 `비활성화` 배지로 표시됩니다. 회수할 수 없는 사유가 있는 인스턴스는 저장된 값과 관계없이 `비활성화`로 표시되고, 배지 아래에 사유가 함께 표시됩니다. 값을 알 수 없으면 `-`가 표시됩니다.
>
> `Secure Boot`, `vTPM (TPM 2.0)`은 `활성화` 또는 `비활성화` 배지로, `백업 연동`은 `허용` 또는 `미허용` 배지로 표시되는 읽기 전용 값입니다. `백업 연동`은 상세 화면에서 바꿀 수 없고, 정지한 상태에서 인스턴스 `편집`으로 바꿉니다. 항목 이름 옆 `ⓘ`에서 허용하면 무엇이 열리는지 볼 수 있고, 값을 알 수 없으면 배지 대신 `-`가 표시됩니다. 자세한 내용은 [백업 연동](#백업-연동)을 확인합니다.
>
> `하드웨어 시계`는 고른 값을 보여 줍니다. `자동`이면 다음 시작부터 쓸 기준을 함께 보여 줍니다(예: `자동 · 현지 시각`). 실행 중인 인스턴스는 마지막으로 시작할 때의 기준으로 돌고 있습니다. 처음 시작하기 전에는 `자동`만 보입니다.

### 상세 화면의 작업 버튼

상세 화면 상단에도 `실행`, `종료`, `재부팅` 버튼이 있습니다. 활성 조건은 목록 화면과 같습니다(위 `작업 버튼 사용 기준` 참고). 구분선 오른쪽의 `콘솔` 버튼은 창을 여는 방식이라 따로 놓입니다.

`편집`과 `삭제`는 상세 화면에 없습니다. 목록 화면에서 수행합니다. 부팅 순서 변경은 `인스턴스 구성 요소 > 디스크 및 CD/DVD`에서 합니다.

### 콘솔 접속

인스턴스 상세 화면 상단의 `콘솔` 버튼을 클릭하면 팝오버 메뉴가 열리고, `그래픽 콘솔`, `직렬 콘솔`, `콘솔 로그 다운로드` 세 가지 중 하나를 선택할 수 있습니다. 상세 정보를 불러오는 중이거나 다른 요청을 처리하는 중에는 `콘솔` 버튼이 잠깁니다.

| 항목 | 용도 | 열리는 방식 |
| --- | --- | --- |
| `그래픽 콘솔` | 게스트 화면(VNC)을 직접 보고 마우스·키보드로 조작합니다. `SSH 키`나 네트워크 접속이 준비되지 않은 초기 단계, `ISO 파일`로 OS를 직접 설치할 때 유용합니다. | 새 창 |
| `직렬 콘솔` | 텍스트 기반 직렬 포트로 접속합니다. 그래픽 화면 없이 부팅 로그 확인이나 셸 작업을 할 때 사용합니다. | 새 창 |
| `콘솔 로그 다운로드` | 지금까지 기록된 콘솔 출력을 파일로 저장합니다(화면 표시 없음). | 파일 저장 |

메뉴 하단에는 "직렬 콘솔 세션 입출력도 함께 담깁니다."라는 안내가 항상 표시됩니다. 권한이 없어도 세 항목은 사라지지 않고 비활성으로 표시되며, 비활성 사유가 문구로 안내됩니다.

**상태별 활성 조건**

| 상태 | `그래픽 콘솔` | `직렬 콘솔` | `콘솔 로그 다운로드` |
| --- | --- | --- | --- |
| `실행 중`, `부팅 중`, `재부팅 중`, `종료 중`, `일시 중지` | 활성 | 활성 | 활성 |
| `마이그레이션 중` | 활성 | 비활성 | 활성 |
| 그 외 모든 상태(`업데이트 중`, `스냅샷 처리 중`, `종료됨`, `정지됨`, `에러`) | 비활성 | 비활성 | 활성 |

`업데이트 중`에는 게스트가 동작하고 있어도 두 콘솔이 모두 비활성입니다. 구성이 바뀌는 도중이라 세션이 끊길 수 있어 열어주지 않습니다. `생성 중`과 `삭제 중`은 상세 화면 자체에 들어갈 수 없어 콘솔 메뉴가 보이지 않습니다.

`콘솔 로그 다운로드`는 인스턴스 상태와 무관하게 항상 활성이며(권한만 검사), `종료됨` 상태에서도 내려받을 수 있습니다. 부팅에 실패해 인스턴스가 멈춘 경우에도 로그를 내려받아 원인을 진단할 수 있습니다.

**필요 권한**

| 항목 | 필요 권한 |
| --- | --- |
| `그래픽 콘솔`, `직렬 콘솔` | `instanceconsole-edit` |
| `콘솔 로그 다운로드` | `instanceconsole-view` |

#### 그래픽 콘솔(VNC)

전원이 인가된 인스턴스는 그래픽 콘솔(VNC)로 직접 접속해 게스트 화면을 확인하고 조작할 수 있습니다. `SSH 키`나 네트워크 접속이 아직 준비되지 않은 초기 단계나, `ISO 파일`로 OS를 직접 설치할 때 유용합니다.

- 새 브라우저 창으로 열리고 자동으로 연결됩니다. 같은 인스턴스의 그래픽 콘솔을 다시 열면 기존 창을 재사용합니다.
- 암호화(HTTPS) 연결로 동작합니다.
- 콘솔 자격 증명을 조회하는 동안에는 `콘솔` 버튼이 `처리 중`으로 표시되며 잠시 비활성화됩니다.
- 창이 열리지 않으면 브라우저의 팝업 차단을 해제합니다.
- 한 인스턴스에 여러 사람이 동시에 접속할 수 있으며, 같은 화면을 함께 봅니다. 다만 동시에 열 수 있는 그래픽 콘솔은 인스턴스당 **최대 32개**입니다.

> 참고
>
> 동시 접속이 32개에 도달하면 `열려 있는 그래픽 콘솔이 너무 많습니다.` 안내가 표시되고 새 콘솔이 열리지 않습니다. 이미 접속해 있는 콘솔은 끊기지 않습니다. 사용하지 않는 콘솔 창을 닫으면 그 자리가 곧 반환되며, 열어 두기만 하고 실제로 접속하지 않은 경우에는 약 2분 뒤에 반환됩니다.

> 중요
>
> 그래픽 콘솔에 로그인하려면 게스트 OS 계정의 `비밀번호`가 필요합니다. `OS 이미지`로 생성하는 인스턴스는 `비밀번호` 없이 `SSH 키`만 설정하면 콘솔로 로그인할 수 없습니다. 콘솔 접속이 필요하면 생성 시 반드시 `비밀번호`를 설정합니다. `ISO 파일` 설치 유형은 OS 설치 과정에서 계정을 직접 만들므로 이 제약을 받지 않습니다.

> 참고
>
> Windows를 `ISO 파일`로 설치하면서 그래픽 콘솔로 설치 과정을 확인하는 예시는 [윈도우 가상머신 ISO 생성 및 콘솔 확인](../../../user-guide/examples-and-labs/04-create-windows-instance-from-iso-and-open-console.md)을 확인합니다.

#### 직렬 콘솔

텍스트 기반으로 게스트에 접속합니다.

- 새 창으로 열리며, 개설 응답을 기다리는 동안 창에 "연결 중"이 표시됩니다.
- 팝업이 차단되면 "브라우저가 콘솔 창을 차단했습니다. 팝업을 허용한 뒤 다시 시도해 주세요." 안내가 뜹니다.
- 인스턴스당 한 세션만 허용됩니다. 이미 다른 세션이 연결되어 있으면 인계 확인 모달("콘솔이 이미 사용 중입니다")이 뜨며, `인계`를 선택하면 기존 세션은 즉시 종료됩니다.
- 연결이 끊기면 자동으로 재연결되지 않습니다. 창을 닫고 다시 엽니다.
- Windows 게스트는 직렬 콘솔(EMS)을 기본으로 쓰지 않습니다. 게스트에서 직접 활성화해야 하며, 그래픽 화면이 필요하면 그래픽 콘솔을 사용합니다.

#### 콘솔 로그 다운로드

메뉴에서 클릭하면 확인 절차 없이 즉시 요청이 전송되고 파일로 저장됩니다(화면에는 표시되지 않습니다). 파일명은 `<인스턴스 이름>-console-<마지막 콘솔 출력 시각 UTC>Z.log` 형식이며, 시각은 내려받은 시점이 아니라 로그가 마지막으로 갱신된 시각입니다.

로그에는 부팅 출력, 런타임 커널 메시지, 직렬 콘솔 세션에서 게스트가 출력한 내용이 담기며, 게스트가 화면에 되돌려 보낸 입력도 함께 남습니다. **그래픽 콘솔 세션은 담기지 않습니다.** 자격 증명 등 비밀을 다루는 작업은 직렬 콘솔 대신 그래픽 콘솔이나 SSH로 진행하는 것이 안전합니다.

인스턴스 상태와 무관하게 항상 내려받을 수 있으므로, `종료됨` 상태에서도 부팅 실패 원인을 진단하는 데 활용할 수 있습니다. 인스턴스를 껐다 켜도 같은 호스트에서 다시 실행되면 로그가 초기화되지 않고 이어서 기록됩니다. 다만 내려받는 파일에는 최근 기록만 담깁니다 — 기록이 일정 크기를 넘으면 오래된 부분은 빠지고, 인스턴스가 다른 호스트에서 다시 실행되면 이전 호스트에 남은 기록은 함께 내려받아지지 않습니다. 진단에 필요한 로그는 그때그때 내려받아 보관합니다.

> 참고
>
> 게스트가 직렬 콘솔로 출력하도록 설정되어 있지 않으면 로그가 비어 있을 수 있습니다. Linux는 커널 파라미터 `console=ttyS0`, Windows는 EMS(Emergency Management Services) 활성화가 필요합니다.

### 네트워크 인터페이스 탭

| 항목 | 설명 |
| --- | --- |
| `서브넷` | NIC가 연결된 서브넷 |
| `보안그룹` | NIC에 적용된 보안그룹 |
| `IP 주소` | NIC의 IPv4 주소 |
| `기본 게이트웨이` | 해당 NIC의 게이트웨이 |
| `DNS 서버` | 화면에 표시되는 DNS 정보 |
| `기본 인터페이스` | 기본 NIC 여부 |
| `MAC 주소` | NIC의 MAC 주소 |

`오브젝트 스토리지`를 사용 중인 인스턴스는 이 탭에서 사용자 NIC와 함께 시스템이 자동으로 추가한 `Managed VNIC`를 확인할 수 있습니다. 상세 화면에서는 이를 통해 오브젝트 스토리지용 네트워크 인터페이스가 연결되어 있는지 먼저 확인합니다.

> 참고
>
> NIC가 여러 개여도 게스트 OS에는 기본 NIC의 DNS만 자동으로 적용됩니다. 추가 NIC에 필요한 DNS는 게스트 OS에서 직접 설정합니다.

### 디스크 탭

| 항목 | 설명 |
| --- | --- |
| `부팅 순서` | 부팅 시도 순서 |
| `타입` | 디스크 유형 |
| `장치 레이블` | 게스트 OS에 연결되는 디스크 레이블 |
| `버스 타입` | 디스크 버스 종류 |
| `크기` | 디스크 크기 |
| `소스 타입 / 소스 이름` | 디스크 원본 정보 |
| `스토리지 도메인` | 디스크 또는 `ISO 파일`이 놓인 `스토리지 도메인` |

디스크 목록에는 연결된 CD/DVD 드라이브도 함께 표시됩니다. `소스 이름`에는 연결된 `ISO 파일` 이름과 매체 역할(`설치 미디어`, `드라이버 CD`, `시스템`)이 함께 표시되고, 비어 있는 드라이브는 `미디어 없음`으로 표시됩니다. `스토리지 도메인`이 없는 항목(`미디어 없음`, `시스템`)은 `-`로 표시됩니다.

#### CD/DVD 드라이브 관리

`인스턴스 구성 요소 > 디스크 및 CD/DVD`에서 CD/DVD 드라이브를 관리합니다.

| 작업 | 설명 | 가능한 상태 |
| --- | --- | --- |
| `ISO 마운트` | `ISO 파일`을 CD/DVD 드라이브에 연결합니다. 비어 있는 드라이브가 있으면 재사용하고, 없으면 새로 만들어 연결합니다. `실행 중`에는 새 드라이브를 만들 수 없어 비어 있는 드라이브가 있을 때만 가능합니다. | `정지됨`, `종료됨`, `실행 중`(비어 있는 드라이브가 있을 때) |
| `ISO 해제` | 연결된 `ISO 파일`을 분리합니다. 드라이브는 비어 있는 상태로 남습니다. | `정지됨`, `종료됨`, `실행 중` |
| `드라이브 제거` | 드라이브를 제거합니다. `ISO 파일`이 연결되어 있으면 함께 해제됩니다. | `정지됨`, `종료됨` |
| `드라이버 CD 부착` | Windows 게스트에 VirtIO 드라이버 CD를 연결합니다. 이미 연결되어 있거나 Windows 계열이 아니면 버튼이 표시되지 않습니다. | `정지됨`, `종료됨`, `실행 중`(비어 있는 드라이브가 있을 때) |

> 주의
>
> `CEPH`(RBD) 타입 스토리지 도메인의 `ISO 파일`은 CD/DVD 드라이브에 연결할 수 없습니다. `ISO 파일`은 `NFS`·`GFS2`·`CEPHFS` 같은 파일 스토리지 도메인에 올려 사용합니다. 연결할 수 없는 `ISO 파일`은 목록에서 비활성으로 표시되며, 모달 제목 옆 `ⓘ` 아이콘에서 사유를 확인할 수 있습니다. 인스턴스의 디스크와 같은 호스트에 둘 수 없는 스토리지 도메인의 `ISO 파일`도 같은 방식으로 비활성 처리됩니다. 로컬 스토리지처럼 특정 호스트에만 있는 도메인을 쓰면 선택할 수 있는 `ISO 파일`이 제한됩니다.
>
> 플랫폼이 연결한 매체를 제거하면 동작이 달라질 수 있습니다. `설치 미디어`를 OS 설치 완료 전에 제거하면 설치가 중단되고, `드라이버 CD`를 Windows 설치 완료 전에 제거하면 다음 시작 시 OS 종류 판정이 달라져 부팅에 실패할 수 있습니다. 두 경우 모두 제거 확인 창에 경고가 표시됩니다.
>
> `실행 중`에는 `ISO` 연결·해제만 할 수 있습니다. 바꾼 매체는 바로 게스트에 반영되고 다음 시작에도 유지됩니다. 게스트가 매체를 사용 중이면(마운트 등) 먼저 게스트에서 해제하세요. 사용 중인 매체를 바꾸면 게스트에서 입출력 오류가 날 수 있습니다. 드라이브 추가·제거는 인스턴스를 정지한 뒤 수행하며 다음 시작 시 반영됩니다. 설치 미디어를 바꿔야 하면 `실행 중`에 `ISO 해제`로 뗀 뒤 `ISO 마운트`로 새 매체를 연결하거나, 정지하고 교체한 다음 시작합니다.

### 디스크 부팅 순서 변경

저장 장치가 2개 이상 연결된 인스턴스는 부팅 순서를 변경할 수 있습니다. 개수는 디스크와 CD/DVD 드라이브를 함께 셉니다.

1. 인스턴스 상세 화면으로 이동합니다.
2. `인스턴스 구성 요소 > 디스크 및 CD/DVD`를 선택합니다.
3. 인스턴스가 `정지됨` 또는 `종료됨` 상태인지 확인합니다.
4. `부팅 순서 변경`을 클릭합니다.
5. 장치를 드래그해 순서를 바꾸고, 필요하면 부팅 포함 여부를 조정합니다.
6. `저장`을 클릭합니다.

> 참고
>
> `부팅 순서 변경` 버튼이 비활성이면 사유를 확인합니다. 저장 장치가 하나뿐이면 `부팅 순서를 변경하려면 저장 장치가 2개 이상이어야 합니다.`, 전원이 켜져 있으면 인스턴스를 정지하라는 안내가 표시됩니다.
>
> 변경한 순서는 다음 시작 시점에 반영됩니다. 재부팅으로는 반영되지 않습니다.

> 주의
>
> 부팅 불가능한 디스크를 가장 높은 우선순위로 두면 게스트 OS가 정상 부팅되지 않을 수 있습니다. 운영체제가 설치된 부팅 디스크를 상단에 둡니다.

상세 화면 `인스턴스 구성 요소 > 호스트 장치`에서 인스턴스에 연결된 호스트 장치(패스스루 장치) 목록을 **조회**합니다.

| 항목 | 설명 |
| --- | --- |
| `장치 종류` | 장치의 분류입니다. |
| `공급업체` | 장치 제조사입니다. |
| `제품명` | 장치 모델명입니다. |

- 이 탭은 조회 전용입니다. 호스트 장치의 추가·삭제는 이 화면에서 제공하지 않습니다.

### AI 가속기 탭

상세 화면 `인스턴스 구성 요소 > AI 가속기`에서 인스턴스에 연결된 가속기를 조회하고, `GPU`/`NPU` 가속기를 추가하거나 삭제합니다.

| 항목 | 설명 |
| --- | --- |
| `공급업체` | 가속기 제조사입니다. |
| `제품명` | 가속기 모델명입니다. |
| `장치 유형` | 가속기 장치 유형입니다. |
| `수량` | 연결된 가속기 수입니다. |

주요 작업:

- `GPU 추가`: GPU 가속기를 추가합니다.
- `NPU 추가`: NPU 가속기를 추가합니다.
- `삭제`: 선택한 가속기를 제거합니다.

활성화 조건:

- 인스턴스가 `종료됨` 상태여야 합니다.
- `ISO 파일` 설치 유형 인스턴스에서는 사용할 수 없습니다.
- 인스턴스 스펙을 `직접 입력`으로 만든 경우에만 추가·삭제할 수 있습니다. `인스턴스 타입`을 선택해 만든 인스턴스는 상세 화면에서 가속기를 변경할 수 없습니다.
- `오토 스케일링 그룹`, `쿠버네티스` 등 상위 서비스가 생성한 시스템 인스턴스는 AI 가속기를 추가하거나 삭제할 수 없습니다. 가속기 구성은 상위 서비스(시작 템플릿 등)에서 관리합니다. [상위 서비스 인스턴스 관리](#상위-서비스-인스턴스-관리)를 확인합니다.
- 한 인스턴스에는 `GPU`와 `NPU` 중 한 종류의 가속기만 연결할 수 있습니다. `GPU`와 `NPU`를 동시에 연결할 수 없습니다.
- `GPU 추가`·`NPU 추가`는 연결된 가속기가 없을 때 사용할 수 있습니다.
- `삭제`는 목록에서 가속기를 선택했을 때 사용할 수 있습니다.

> 참고
>
> 가속기는 **카드 단위**로 할당됩니다. 한 카드에 속한 기능(예: GPU + 오디오)은 함께 연결·해제되며, 카드가 아닌 장치가 같은 IOMMU 그룹에 섞인 카드는 할당 대상에서 제외됩니다.
>
> 패스스루는 한 호스트 안에서만 성립하므로, 장치 선택 목록의 `노드당 최대 카드 수`(단일 노드에서 현재 할당할 수 있는 최대 카드 수)를 넘는 수량은 입력할 수 없습니다. 입력란 아래에 "단일 노드 기준 최대 N장까지 할당할 수 있습니다. (전체 M장 보유)"가 표시되며, 전체 보유량이 충분해도 여러 노드에 흩어져 있으면 N이 작아집니다. 에이전트 연결이 끊긴 호스트의 카드는 집계에서 제외됩니다.

### 사용자 스크립트 탭

상세 화면 `인스턴스 구성 요소 > 사용자 스크립트`에서 인스턴스에 등록된 스크립트를 조회합니다. 각 스크립트의 `실행 순서`, `파일 이름`, `경로`, `단계`, `내용`을 확인할 수 있습니다.

- 스크립트 추가와 수정은 `편집` 화면의 `사용자 스크립트`에서 수행합니다.
- `실행 중`(라이브 업데이트) 상태에서는 사용자 스크립트를 등록하거나 변경할 수 없습니다. 변경하려면 인스턴스를 종료한 뒤 편집합니다.
- 단계(`PER_BOOT`, `PER_INSTANCE`, `PER_ONCE`)별 실행 시점과 동작 차이는 생성 단계의 `7. 사용자 스크립트 입력`을 확인합니다.
- 시스템 스크립트도 이 목록에 표시되며, 조회만 할 수 있습니다. [시스템 스크립트](#시스템-스크립트)를 확인합니다.

### 모니터링 정보

상세 화면 맨 아래 `모니터링 정보`에서 인스턴스의 사용량 추이를 확인합니다. 그래프는 13종이며, 네트워크 송수신 합계를 보여 주는 표가 함께 표시됩니다.

| 그래프 | 표시 단위 |

| `CPU 대기율` | 백분율 |
| `메모리 사용률` | 메모리 크기를 100%로 둔 백분율 |
| `디스크 읽기` | 초당 바이트(B/s·KiB/s·MiB/s, 1024 기준) |
| `디스크 쓰기` | 초당 바이트(B/s·KiB/s·MiB/s, 1024 기준) |

| `받기 패킷` | packets/sec |
| `보내기 패킷` | packets/sec |
| `받기 드롭` | 칸별 개수 |
| `보내기 드롭` | 칸별 개수 |
| `받기 오류` | 칸별 개수 |
| `보내기 오류` | 칸별 개수 |

`CPU 대기율`은 인스턴스가 물리 CPU를 기다린 시간의 비율입니다. 5% 이상이 계속되면 같은 노드의 다른 부하 때문에 느려질 수 있으므로 관리자에게 문의합니다.

`CPU 사용률`, `CPU 대기율`, `디스크 읽기`, `디스크 쓰기`, `네트워크 입력`, `네트워크 출력` 그래프는 진한 선이 칸마다의 평균이고, 같은 색의 옅은 선이 칸마다의 최대입니다. 디스크나 네트워크 인터페이스가 여럿이어도 장치마다 한 색으로 진한 평균 선과 옅은 최대 선을 그립니다. 범례에서 장치 이름에 마우스를 올리면 그 그래프에서 그 장치만 진하게 보이고 나머지는 흐려집니다. 장치 이름을 클릭할 때마다 그 장치를 고르거나 풀며, 여러 장치를 함께 고를 수 있습니다. 네트워크 인터페이스를 고르면 네트워크 입력·출력과 아래 패킷·드롭·오류 그래프가 모두, 디스크를 고르면 디스크 읽기·쓰기 그래프가 함께 그 장치만 진하게 보이고, 그래프 위에 마우스를 올려도 그 장치의 값만 보입니다. 고른 장치의 자료가 없는 그래프는 모든 선이 흐려지고 값이 표시되지 않습니다. 고른 이름을 다시 클릭하면 풀립니다. 조회 기간이 길면 한 칸이 5분이나 1시간이 되어 평균 선에서는 짧은 순간의 높은 값이 묻히므로, 최대에서 칸마다 가장 높았던 값을 확인합니다.

그래프의 칸 길이는 조회 기간이 2일 이하이면 1분, 10일 이하이면 5분, 그보다 길면 1시간입니다. 1분 단위 자료는 15일, 5분 단위 자료는 63일 동안 보관되므로, 시작 시각이 그보다 오래되면 한 단계 긴 칸으로 표시됩니다.

**그래프 값 보기**

- 그래프에 마우스를 올리면 커서 오른쪽, 범례 바로 아래에 그 시각의 값이 표로 표시됩니다. 장치마다 한 줄에 `평균`과 `최대`가 나오고, 값이 큰 장치부터 나옵니다. 화면 오른쪽 끝에서는 커서 왼쪽에 표시됩니다.
- 한 그래프에 마우스를 올리면 다른 그래프에도 같은 시각에 세로선이 그려집니다. 같은 시각의 CPU·메모리·디스크·네트워크 값을 견줄 때 씁니다.
- 그래프를 클릭하면 그 시각의 값이 고정되어 마우스를 옮겨도 남습니다(`고정됨 · Esc 해제`). `Esc` 키를 누르거나 같은 점을 다시 클릭하면 풀리고, 다른 그래프를 클릭하면 그 그래프로 옮겨 갑니다. 조회 기간이나 브라우저 창 크기를 바꾸면 풀립니다.
- 달력과 `CSV` 오른쪽의 `최댓값 표시`를 끄면 모든 그래프에서 최대 선과 값 표의 `최대` 열을 숨기고, `메모리 사용률` 그래프에서는 최대 선·범례의 `최대`·값 상자의 `최대` 줄을 숨깁니다. 이 설정은 사용하는 브라우저에 기억됩니다.
- 같은 장치는 어느 그래프에서나 같은 색으로 그려집니다. 디스크는 이름순(sda, sdb …)으로 색이 정해집니다.

**메모리 사용률 그래프**

`메모리 사용률`은 다른 그래프와 같은 칸 너비로 표시되고, 메모리 크기를 100%로 둔 하나의 축에 다음 값을 함께 그립니다. 크기(GB)는 100% 선 오른쪽 위의 `전체`(메모리 크기)와 점선 오른쪽 위의 `보장` 글자, 그리고 툴팁에 표시됩니다.

| 표시 | 의미 |
| --- | --- |
| `사용 중` (선) | 인스턴스가 실제로 사용 중인 메모리입니다. |
| `최대` (옅은 선) | 칸마다 가장 높았던 사용 중 메모리입니다. `최댓값 표시`를 끄면 보이지 않습니다. |
| `현재 크기` (선) | 인스턴스가 현재 쓸 수 있도록 내준 메모리 크기입니다. 회수한 만큼 메모리 크기보다 작아지며, 100%와의 차이가 회수한 양입니다. |
| `보장 메모리` (점선) | 회수하지 않는 메모리입니다. 현재 크기는 이 아래로 내려가지 않습니다. |

- `메모리 회수 허용`을 끈 인스턴스는 `사용 중`과 `최대`만 표시됩니다.
- `메모리 회수 허용`을 켠 인스턴스는 제목 옆 안내 아이콘에 `메모리 크기 대비 사용률입니다. 현재 크기는 회수한 뒤 남은 크기이고, 100%와의 차이가 회수한 양입니다.`가 표시됩니다.
- 그래프에 마우스를 올리면 시각별 `사용 중`, `최대`, `현재 크기` 값이 표시되고, 회수한 양이 있으면 `회수 중` 값도 표시됩니다.

**패킷·드롭·오류 그래프**

- 인터페이스가 여럿이면 범례에서 클릭해 고른 인터페이스만 볼 수 있습니다(여러 개 가능). 위 네트워크 입력·출력 그래프와 같이 바뀝니다.
- `받기 패킷`, `보내기 패킷` 그래프는 초당 패킷 수이며, 인터페이스마다 한 선으로 표시됩니다. 진행 중인 칸과 끝난 지 2분이 지나지 않은 칸은 값이 덜 찼으므로 비워 둡니다(1분 칸이면 3칸).
- `받기 드롭`, `보내기 드롭`, `받기 오류`, `보내기 오류` 그래프는 한 칸 동안 발생한 개수입니다. 제목 뒤에 칸 길이가 `(개/1분)` 처럼 붙으며, 칸 길이는 위 그래프와 같습니다. 맨 끝 점은 아직 수집 중이라 실제보다 작게 보일 수 있고, 다시 조회하면 늘어날 수 있습니다.

**네트워크 기간 합계**

화면 맨 아래의 `네트워크 기간 합계` 표에서 선택한 기간에 인터페이스(NIC MAC 주소)별로 주고받은 양을 한눈에 확인합니다.

| 열 | 내용 |
| --- | --- |
| `인터페이스` | 네트워크 인터페이스의 MAC 주소 |
| `받은 바이트`, `보낸 바이트` | 기간 동안 받고 보낸 바이트 합계 |
| `받은 패킷`, `보낸 패킷` | 기간 동안 받고 보낸 패킷 수 합계 |
| `받기 드롭`, `보내기 드롭` | 기간 동안 버려진 패킷 수 합계 |
| `받기 오류`, `보내기 오류` | 기간 동안 발생한 오류 패킷 수 합계 |

- 합계를 구할 수 없는 칸은 `-` 로 표시됩니다.
- `받기 드롭`, `보내기 드롭`, `받기 오류`, `보내기 오류` 칸은 합계가 0보다 크면 빨간색으로 표시됩니다. 네트워크에서 패킷이 버려지거나 오류가 있었다는 뜻이므로 시점과 인터페이스를 그래프에서 확인합니다.
- 합계는 선택한 기간 동안 오간 양이며, 기동 후 누적값이 아닙니다. 재시작으로 카운터가 0부터 다시 올라가도 합계는 이어서 더합니다.
- 수집이 끊긴 동안 오간 양은 합계에만 들어가고 그래프에는 그려지지 않아, 합계가 그래프 값을 더한 것보다 클 수 있습니다.

- 그래프 영역 왼쪽 위의 달력에서 조회 기간을 지정합니다. 기간을 바꾸면 13종과 합계 표가 함께 갱신됩니다.
- 달력 오른쪽 드롭다운에서 그래프를 자동으로 다시 읽는 주기를 `꺼짐`, `30초`, `1분`, `5분` 중에서 고릅니다. 기본은 `30초`입니다. 켜 두면 주기마다 조회 기간의 끝을 지금으로 옮겨 갱신합니다. 최근 몇 시간을 골랐으면 그 길이를, 오늘을 골랐으면 자정 시작을 그대로 둡니다. 달력을 열어 둔 동안과 브라우저 탭이 가려진 동안에는 갱신하지 않고, 탭으로 돌아오면 바로 갱신합니다.
- 달력에서 기간을 직접 고르거나 최근에 조회한 기간을 고르면 주기가 `꺼짐`으로 바뀝니다. 이때 주기를 다시 고르면 같은 길이의 최근 기간으로 바뀌어 자동 갱신이 이어집니다.
- 드롭다운 오른쪽의 `새로고침` 버튼을 클릭하면 주기를 기다리지 않고 바로 갱신합니다. 기간을 직접 고른 경우에는 같은 기간을 다시 조회합니다.
- 달력 오른쪽의 `CSV` 버튼을 클릭하면 `인스턴스 모니터링 CSV 다운로드` 창이 열립니다. 위 그래프에 대응하는 항목 중 **하나**를 골라 현재 지정한 기간의 값을 파일로 내려받습니다. `CPU 대기율`은 평균 값을 내려받습니다.
- CSV 는 남아 있는 가장 촘촘한 단위로 내려받습니다. 시작 시각이 15일 이내면 1분, 63일 이내면 5분, 그 이전은 1시간 단위입니다. 그래서 그래프보다 촘촘한 간격으로 받을 수 있고, 이때 행 값은 그래프의 같은 시각 값과 다를 수 있습니다.
- 네트워크 카운터는 `받은 바이트(구간 증가분)`, `보낸 바이트(구간 증가분)`, `받은 패킷(구간 증가분)`, `보낸 패킷(구간 증가분)`, `받기 드롭(구간 증가분)`, `보내기 드롭(구간 증가분)`, `받기 오류(구간 증가분)`, `보내기 오류(구간 증가분)` 의 8개 항목으로 내려받습니다. 파일에는 칸별 증가분만 담기며 합계 행은 없습니다.
- 바이트 항목은 대응하는 그래프가 없고 `네트워크 기간 합계` 표의 바이트 값과 짝이 됩니다. 패킷 항목은 칸별 개수이고, 그래프는 이를 초당 값으로 바꿔 보여 줍니다. 드롭·오류 항목도 칸별 개수이며, 칸 길이는 그래프가 아니라 CSV 단위를 따릅니다.

> 참고
>
> `CSV 다운로드`는 한 번에 지표 하나만 내려받습니다. 여러 지표가 필요하면 지표를 바꿔 가며 반복합니다.

## 스토리지 마이그레이션

스토리지 마이그레이션은 인스턴스의 부팅 디스크를 다른 `스토리지 도메인`으로 이동하는 기능입니다. 스토리지 도메인 교체, 용량 재배치, 유지보수 준비 등에 사용합니다. 인스턴스에 연결된 블록(데이터 디스크)은 `스토리지 > 블록` 메뉴에서 개별적으로 이동합니다.

같은 `스토리지 마이그레이션` 버튼이 인스턴스 상태에 따라 다르게 동작합니다.

| 인스턴스 상태 | 동작 방식 | 설명 |
| --- | --- | --- |
| `종료됨`, `정지됨` | 콜드 스토리지 마이그레이션 | 정지 상태에서 부팅 디스크를 대상 스토리지 도메인으로 이동합니다. |
| `실행 중`, `일시 중지` | 라이브 스토리지 마이그레이션 | 인스턴스 중단을 최소화하면서 부팅 디스크를 이동합니다. |

수행 절차는 다음과 같습니다.

1. 인스턴스 목록 화면에서 인스턴스 1개를 선택합니다.
2. `더보기 > 스토리지 마이그레이션`을 클릭합니다.
3. 대상 `스토리지 도메인`을 선택합니다. 다음 도메인은 목록에 보이지만 선택할 수 없습니다.
   - 부팅 디스크가 현재 사용 중인 도메인
   - 사용할 수 없는(`UP`이 아닌) 도메인
   - 이 프로젝트에 배정되지 않은 도메인. 안내 영역에 "이 프로젝트에 배정된 스토리지 도메인만 대상으로 고를 수 있습니다."가 표시됩니다.
   - 라이브 스토리지 마이그레이션(`실행 중`, `일시 중지`)일 때, 인스턴스가 실행 중인 호스트가 접근할 수 없는 도메인(다른 노드 전용 `LOCAL` 등). 안내 영역에 "인스턴스가 실행 중인 호스트에서 접근할 수 없는 스토리지 도메인은 라이브 마이그레이션 대상으로 고를 수 없습니다."가 표시됩니다.
4. `실행`을 클릭해 마이그레이션을 시작합니다.
5. 작업이 끝나면 인스턴스 상세 화면의 `인스턴스 구성 요소 > 디스크 및 CD/DVD`에서 부팅 디스크의 `스토리지 도메인`이 대상 도메인으로 바뀌었는지 확인합니다.

> 참고
>
> `더보기` 메뉴에는 `스토리지 마이그레이션`, `인스턴스 복제`, `시작 템플릿으로 변환`이 함께 들어 있습니다. 인스턴스를 선택하지 않으면 메뉴 자체가 열리지 않습니다.

> 중요
>
> 스냅샷이 있는 디스크는 라이브 스토리지 마이그레이션을 수행할 수 없습니다. 스냅샷을 삭제하거나 인스턴스를 종료한 뒤 콜드 스토리지 마이그레이션으로 수행합니다. 콜드 스토리지 마이그레이션에서도 스냅샷이 있는 디스크는 유형이 다른 스토리지 도메인으로는 이동할 수 없습니다.
>
> vTPM이 활성화된 인스턴스의 부팅 디스크는 라이브 스토리지 마이그레이션이 지원되지 않습니다. 인스턴스를 종료한 뒤 콜드 스토리지 마이그레이션으로 수행합니다.

> 참고
>
> 콜드 스토리지 마이그레이션 시 vTPM 데이터는 부팅 디스크와 함께 자동으로 이동됩니다. 별도 조치는 필요하지 않습니다.
>
> 콜드 스토리지 마이그레이션 도중 CloudiA 가 재시작되면 시스템이 중단된 작업을 자동으로 정리합니다. 디스크 전환 전에 중단됐으면 원래 스토리지 도메인에 그대로 남고 요청은 실패로 끝나며, 전환 뒤에 중단됐으면 대상 스토리지 도메인으로 이전이 완료됩니다. 정리가 끝나기 전에는 인스턴스를 시작·삭제하거나 같은 디스크를 다시 마이그레이션할 수 없습니다. 요청하면 `409` 오류로 실패합니다.

## 인스턴스 복제

인스턴스 복제는 기존 인스턴스의 스펙과 부팅 디스크 내용을 그대로 가진 새 인스턴스를 만드는 기능입니다. 비슷한 환경을 여러 개 준비할 때 사용합니다.

수행 절차는 다음과 같습니다.

1. 목록에서 인스턴스 1개를 선택합니다.
2. `더보기 > 인스턴스 복제`를 클릭합니다.
3. 화면 상단의 안내 문구를 확인합니다. 복제할 수 없는 인스턴스는 여기에 사유가 표시되고 `복제`가 비활성화됩니다. 복제할 수 있으면 복제되지 않는 항목이 표시됩니다.
4. 복제할 인스턴스의 요약 정보를 확인합니다.
5. 새 인스턴스 이름을 입력합니다.
6. `복제`를 클릭합니다.

> 중요
>
> `인스턴스 복제`는 인스턴스 1개를 선택하고, 상태가 `실행 중` 또는 `종료됨`일 때 활성화됩니다.
>
> 창이 열리면 복제 가능 여부를 서버에서 점검합니다. 점검이 끝나기 전이나 점검에 실패한 경우에도 `복제`는 비활성화되며, 실패 시에는 잠시 후 다시 시도합니다.
>
> 복제가 끝날 때까지 원본 인스턴스의 상태(실행 중·종료됨)는 그대로지만 시작·정지·재부팅·삭제·스냅샷 생성·마이그레이션을 할 수 없고, 같은 원본을 다시 복제할 수도 없습니다. `종료됨` 원본은 편집도 할 수 없습니다. 요청하면 다른 작업이 진행 중이라는 안내가 표시됩니다. `실행 중` 원본의 편집(실행 중에 바꿀 수 있는 항목)은 막지 않으며, 복제본에는 반영되지 않습니다. 부팅 디스크가 클수록 복제가 오래 걸립니다.
>
> `실행 중` 원본은 스냅샷을 만들 때처럼 게스트의 파일 시스템을 잠시 동결한 뒤 복제합니다. 동결 중 게스트가 마운트 지점을 열지 못하면 복제가 실패하고 스냅샷과 같은 안내가 토스트로 표시됩니다. 원인과 조치는 [파일 시스템 동결 실패](#파일-시스템-동결-실패)를 확인합니다.

### 복제할 수 없는 경우

| 사유 | 안내 문구 |
| --- | --- |
| 시스템 인스턴스(파일 시스템·오토 스케일링 그룹·쿠버네티스가 생성) 또는 추가 블록(데이터 디스크)이 연결됨 | 시스템 인스턴스, 추가 블록이 연결된 인스턴스는 복제할 수 없습니다. |
| ISO 로 설치한 인스턴스 | 템플릿 이미지 없이 만든 VM(ISO 설치 등) — 아직 복제를 지원하지 않습니다 |
| cloud-init 이 없음 | cloud-init 없음 — 복제본이 전원을 켤 수 없습니다 |
| 프로젝트 할당량 부족 | vCPU 할당량 초과 — N vCPU 필요 / 메모리 할당량 초과 / 스토리지 할당량 초과 — N MiB 필요 |
| 부팅 디스크가 없음 | 부트 디스크가 없어 복제할 수 없습니다. |
| 상태 조건을 벗어남 | 실행 중(UP) 또는 정지(TERMINATED) 상태에서만 복제할 수 있습니다. |

사유가 여러 개면 한 가지만 표시되고, 그 사유를 해소하면 다음 사유가 표시됩니다. 추가 블록이 연결된 인스턴스를 복제하려면 먼저 인스턴스 편집에서 해당 블록을 분리합니다.

> 참고
>
> 원본 게스트의 `/etc/fstab` 에 분리한 블록의 항목이 남아 있으면, 복제본의 `/etc/fstab` 에서는 분리한 블록의 항목이 자동 마운트(`noauto,x-systemd.automount,x-systemd.device-timeout=5`)로 바뀌고 바로 위에 `# CloudiA clone:` 으로 시작하는 주석이 추가됩니다. 복제본은 분리한 블록 없이 부팅합니다. 블록을 연결하지 않은 동안 분리한 블록의 마운트 지점(예: `/data`)에 접근하면 약 5초 뒤 실패합니다. 분리한 블록을 복제본에 연결하면 다음에 마운트 지점에 접근할 때 마운트됩니다.
>
> 복제본 `/etc/fstab` 정리는 파일 기반 스토리지 도메인(로컬·NFS·GFS2·CephFS)에 있는 리눅스 인스턴스에만 적용됩니다. Ceph(RBD) 스토리지 도메인의 인스턴스는 복제 전에 원본 게스트의 `/etc/fstab` 에서 분리한 블록 항목을 지우거나 `nofail` 을 붙입니다.
>
> 복제본 `/etc/fstab` 정리 때문에 복제가 30초 정도까지 더 걸릴 수 있습니다. 정리에 실패하면 복제가 중단되고 만들던 복제본은 삭제됩니다. 화면에 복제본의 `/etc/fstab` 을 정리하지 못했다는 안내가 표시되면 관리자에게 문의합니다.

> 주의
>
> 복제본은 원본의 사양·부팅 디스크 내용·`오브젝트 스토리지` 사용 여부를 그대로 가져오지만, 다음 항목은 복제되지 않습니다.
>
> - 네트워크 설정(IP 주소·MAC 주소): 복제본의 네트워크 인터페이스는 원본과 같은 서브넷·보안그룹으로 새로 생성되고 IP 주소는 자동 할당됩니다.
> - 파일 시스템 연결: 복제본에는 연결되지 않으므로 필요하면 복제 후 다시 연결합니다.
> - vTPM 상태: 복제본은 빈 TPM 으로 기동합니다. BitLocker 등 TPM 에 키를 봉인한 게스트는 복구 키를 미리 확보합니다.
> - GPU/NPU 패스스루 장치: 복제본은 가속기 없이 생성되므로, AI 워크로드가 필요하면 복제 후 별도로 연결합니다.

## 시작 템플릿으로 변환

시작 템플릿으로 변환은 기존 인스턴스의 설정을 바탕으로 새 시작 템플릿을 만드는 기능입니다. 자주 사용하는 구성을 템플릿으로 저장해 이후 인스턴스 생성이나 오토 스케일링 그룹에서 재사용할 때 사용합니다.

수행 절차는 다음과 같습니다.

1. 목록에서 인스턴스 1개를 선택합니다.
2. `더보기 > 시작 템플릿으로 변환`을 클릭합니다.
3. 화면 상단의 안내 문구를 확인합니다. 변환할 수 없는 인스턴스는 여기에 사유가 표시되고 `생성`이 비활성화됩니다.
4. 변환할 인스턴스의 요약 정보(이름, ID, 이미지, vCPU, 메모리, 네트워크)를 확인합니다.
5. 템플릿에 담을 항목을 토글로 선택합니다.
6. 새 시작 템플릿 이름을 입력합니다.
7. `생성`을 클릭합니다.

생성된 시작 템플릿은 `시작 템플릿` 메뉴에서 확인하고 관리합니다. 자세한 내용은 [시작 템플릿](../launch-template/launch-template.md)을 확인합니다.

### 템플릿에 담을 항목

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| `IP 주소` | 사용 안 함 | 켜면 원본에 현재 붙어 있는 IP 주소를 템플릿에 고정값으로 저장합니다. 끄면 이 템플릿으로 인스턴스를 생성할 때 IP 주소가 자동 할당됩니다. |
| `파일 시스템` | 사용함 | 켜면 원본에 연결된 파일 시스템을 마운트 포인트와 함께 템플릿에 담습니다. 파일 시스템 자원 자체를 가리키므로, 그 파일 시스템이 삭제되면 이 템플릿으로 인스턴스를 생성할 수 없습니다. |
| `GPU/NPU(호스트 디바이스)` | 사용함 | 켜면 원본에 연결된 GPU 또는 NPU의 **사양**(제조사·모델·개수)을 템플릿에 담습니다. 원본에 붙어 있던 장치 자체를 가리키는 것은 아니므로, 같은 사양의 가속기 여유가 있는 호스트가 있으면 인스턴스를 생성할 수 있습니다. |

각 토글 아래에는 대상 자원의 목록이 표시됩니다. 담을 자원이 없으면 `없음`으로 표시되고 토글이 비활성화되어 `사용 안 함`으로 고정됩니다.

> 중요
>
> `시작 템플릿으로 변환`은 인스턴스 1개를 선택하고, 상태가 `실행 중` 또는 `종료됨`일 때 활성화됩니다.
>
> 변환이 끝날 때까지 원본 인스턴스는 시작·정지·재부팅·삭제·스냅샷 생성·마이그레이션을 할 수 없고, 같은 원본을 다시 변환할 수도 없습니다. `종료됨` 원본은 편집도 할 수 없습니다. 요청하면 다른 작업이 진행 중이라는 안내가 표시됩니다. `실행 중` 원본의 편집(실행 중에 바꿀 수 있는 항목)은 막지 않으며, 만들어지는 시작 템플릿에는 반영되지 않습니다.
>
> `실행 중` 원본은 스냅샷을 만들 때처럼 게스트의 파일 시스템을 잠시 동결한 뒤 부팅 디스크를 캡처합니다. 동결 중 게스트가 마운트 지점을 열지 못하면 변환이 실패하고 스냅샷과 같은 안내가 토스트로 표시됩니다. 원인과 조치는 [파일 시스템 동결 실패](#파일-시스템-동결-실패)를 확인합니다.

> 주의
>
> `IP 주소`와 `파일 시스템`은 **자원을 복사하지 않고 원본이 쓰던 자원을 그대로 가리킵니다.** 가리킨 자원을 쓸 수 없게 되면 이 템플릿으로는 인스턴스를 생성할 수 없습니다.
>
> - `IP 주소`를 켜면 원본 인스턴스가 살아 있는 동안에는 그 IP 주소가 이미 사용 중이므로 인스턴스 생성이 실패합니다. 원본을 유지하면서 같은 구성의 인스턴스를 반복 생성하려면 `IP 주소`를 꺼서 IP 주소가 자동 할당되도록 합니다.
> - `파일 시스템`을 켠 뒤 그 파일 시스템을 삭제하면 인스턴스 생성이 실패합니다.
>
> `GPU/NPU(호스트 디바이스)`는 장치가 아니라 사양만 담기므로 이 제약을 받지 않습니다. 대신 인스턴스를 생성할 때 같은 사양의 가속기를 내줄 수 있는 호스트가 없으면 실행이 실패할 수 있습니다.

> 주의
>
> MAC 주소와 실행 상태는 템플릿에 보존되지 않습니다. 원본에 vTPM 이 있으면 vTPM 상태도 보존되지 않아 이 템플릿으로 생성한 인스턴스는 빈 TPM 으로 기동하므로, BitLocker 등 TPM 을 사용하는 디스크 암호화를 켜 두었다면 복구 키가 필요합니다.
>
> 네트워크 인터페이스와 보안그룹은 토글과 무관하게 항상 템플릿에 보존되고, 부팅 디스크는 새 이미지로 캡처됩니다. 사용자 계정·`SSH 키`·`사용자 스크립트`(cloud-init)도 함께 보존되지만, **Windows 인스턴스는 cloud-init 을 쓰지 않으므로 이 항목과 `파일 시스템`이 템플릿에 담기지 않습니다.**

### 변환할 수 없는 경우

다음에 해당하면 변환 가능 여부 점검에서 걸러져 `생성`이 비활성화됩니다.

| 사유 | 안내 문구 |
| --- | --- |
| 시스템 인스턴스이거나 추가 블록(데이터 디스크)이 연결되어 있음 | 시스템 인스턴스, 추가 블록이 연결된 인스턴스는 시작 템플릿으로 변환할 수 없습니다. |
| Windows ISO 로 설치한 인스턴스 | Windows ISO 로 설치한 VM — cloud-init 을 받지 않아 시작 템플릿 변환을 지원하지 않습니다 |
| cloud-init 이 없음 | cloud-init 없음 — 파생 인스턴스가 전원을 켤 수 없습니다. |
| 사용할 수 있는 네트워크 인터페이스가 없음 | 사용 가능한 네트워크 인터페이스가 없습니다(사용자 서브넷과 보안 그룹을 가진 NIC 필요). |
| 부팅 디스크가 없음 | 부트 디스크가 없어 변환할 수 없습니다. |
| 상태 조건을 벗어남 | 실행 중(UP) 또는 정지(TERMINATED) 상태에서만 변환할 수 있습니다. |

> 참고
>
> 추가 블록(데이터 디스크)이 붙은 인스턴스를 변환하려면 먼저 인스턴스 편집에서 해당 블록을 분리합니다. 분리한 블록은 삭제되지 않습니다.
>
> 원본 게스트의 `/etc/fstab` 에 분리한 블록의 항목이 남아 있으면 변환한 시작 템플릿으로 만든 인스턴스가 모두 부팅하지 못할 수 있습니다. 시작 템플릿 변환은 복제와 달리 분리한 블록의 항목을 고치지 않습니다. 변환하기 전에 원본 게스트의 `/etc/fstab` 에서 분리한 블록의 항목을 지우거나 `nofail` 을 붙입니다.
>
> Linux 계열 ISO 로 설치한 인스턴스는 cloud-init 이 붙어 있으면 변환할 수 있습니다. 생성할 때 `사용자 계정`과 `사용자 스크립트`를 비워 두어 cloud-init 이 붙지 않았으면 `cloud-init 이 없음` 사유로 막힙니다. 이때는 인스턴스를 종료한 뒤 편집에서 `사용자 계정`을 입력하면 cloud-init 이 붙어 변환할 수 있습니다. 이 템플릿으로 만든 인스턴스에 계정이 적용되려면 게스트에 cloud-init 이 설치되어 있어야 합니다.

## 인스턴스 스냅샷

인스턴스 스냅샷은 특정 시점의 디스크 상태를 저장하고 이후 롤백에 사용할 수 있는 기능입니다.

> v1.5.0부터 인스턴스 스냅샷 작업(생성·편집·삭제·롤백·이미지 생성)은 모두 **인스턴스 상세 화면의 `인스턴스 구성 요소 > 스냅샷`** 에서 수행합니다. 기존의 독립 `스토리지 > 스냅샷` 목록 메뉴는 제거되었습니다. 블록(디바이스) 자체의 스냅샷은 [스토리지 > 블록 - 블록 스냅샷](../../storage/block/block.md#블록-스냅샷)에서 관리합니다.

### 스냅샷으로 할 수 있는 작업

| 작업 | 수행 위치 | 상태 조건 |
| --- | --- | --- |
| `스냅샷 생성` | 상세 화면 `인스턴스 구성 요소 > 스냅샷` | 인스턴스가 `실행 중` 또는 `종료됨`. `실행 중`이면 게스트 에이전트(`QEMU Guest Agent`)가 응답해야 함 |
| `스냅샷 상세 조회` | 상세 화면 `인스턴스 구성 요소 > 스냅샷` | 스냅샷 1개 선택 |
| `스냅샷 편집` | 상세 화면 `인스턴스 구성 요소 > 스냅샷` | 스냅샷 1개 선택 |
| `스냅샷 삭제` | 상세 화면 `인스턴스 구성 요소 > 스냅샷` | 스냅샷 1개 선택 |
| `스냅샷 롤백` | 상세 화면 `인스턴스 구성 요소 > 스냅샷` | 인스턴스가 `종료됨` 상태 |
| `이미지 생성` | 상세 화면 `인스턴스 구성 요소 > 스냅샷` | 부팅 가능한 스냅샷 1개 선택 |

### 스냅샷 생성

1. 인스턴스 상세 화면에서 `인스턴스 구성 요소 > 스냅샷`을 선택합니다.
2. `생성`을 클릭합니다.
3. 스냅샷 이름과 설명을 입력합니다.
4. `스냅샷에 포함할 블록`에서 담을 블록을 확인합니다. 처음에는 모든 블록이 선택되어 있으며, 스냅샷에서 뺄 추가 블록만 체크를 해제합니다.
5. `사전 점검`에서 항목별 결과를 확인합니다. 하나라도 `실패`이면 `생성`이 비활성화됩니다.
6. `생성`을 클릭합니다.

`사전 점검`은 스냅샷을 만들 수 있는지 아래 항목을 미리 확인해 `정상` 또는 `실패`로 보여 줍니다. `실패`인 항목 아래에는 사유와 조치 안내가 함께 표시됩니다.

| 항목 | 확인하는 내용 | `실패`일 때 조치 |
| --- | --- | --- |
| `인스턴스 상태` | 인스턴스가 `실행 중` 또는 `종료됨`인지 확인합니다. | 다른 작업이 진행 중이면 끝난 뒤 다시 시도합니다. |
| `게스트 에이전트` | 게스트 에이전트(`QEMU Guest Agent`)가 응답하고 파일 시스템 정지를 허용하는지 확인합니다. 인스턴스가 `실행 중`일 때만 표시됩니다. | 응답하지 않으면 게스트에 `qemu-guest-agent`가 설치되어 실행 중인지 확인하거나, 인스턴스를 정지한 뒤 만듭니다. 파일 시스템 정지를 허용하지 않으면 이미지의 게스트 에이전트 허용 목록에서 정지·해제 명령을 엽니다([부록 C](#appendix-c-guest-agent-and-windows) 참고). |
| `부트 디스크` | 부팅 디스크가 연결되어 있는지 확인합니다. | 부팅 디스크가 없는 인스턴스는 스냅샷을 만들 수 없습니다. |
| `vTPM` | vTPM 을 쓰는 인스턴스면 vTPM 상태를 스냅샷에 담을 수 있는지 확인합니다. | 부팅 디스크가 LUN 인 vTPM 인스턴스는 스냅샷을 만들 수 없습니다. |

사전 점검 결과를 불러오지 못하면 `사전 점검을 확인하지 못했습니다. 생성을 눌러 다시 시도할 수 있습니다.`가 표시되고 `생성`은 활성화된 채로 남습니다. `생성`을 누르면 같은 점검을 다시 하고, 통과하지 못한 항목이 있으면 그 사유와 함께 생성이 거절됩니다.

> 참고
>
> - 부트 디스크는 항상 포함되며 체크를 해제할 수 없습니다.
> - 제외한 디스크는 이 스냅샷으로 롤백해도 복원되지 않고 현재 내용이 그대로 남습니다.
> - 스냅샷에 담긴 디스크는 그 스냅샷을 삭제하기 전까지 인스턴스에서 분리할 수 없습니다. 제외한 디스크는 이 스냅샷 때문에 분리가 막히지 않습니다. 나중에 분리할 데이터 디스크가 있으면 제외하고 만듭니다.
> - 다른 인스턴스와 함께 쓰는 공유 블록은 인스턴스 스냅샷에 담을 수 없어 체크 해제된 채로 표시됩니다. 공유 블록은 [블록 스냅샷](../../storage/block/block.md#블록-스냅샷)으로 관리합니다.
> - 목록의 `포함 블록 개수`로 스냅샷에 담긴 디스크 수를 확인할 수 있습니다.

> 참고
>
> vTPM이 활성화된 인스턴스의 스냅샷은 디스크와 함께 TPM 상태(vTPM state)도 함께 저장됩니다. 별도 설정 없이 자동으로 처리되며, BitLocker 등 TPM으로 봉인된 데이터가 있는 인스턴스도 스냅샷 시점 그대로 복원할 수 있습니다. 단 부팅 디스크가 LUN 인 vTPM 인스턴스는 TPM 상태를 담을 수 없어 스냅샷을 만들 수 없습니다.

#### 파일 시스템 동결 실패

`실행 중`인 인스턴스의 스냅샷은 게스트 에이전트로 게스트의 파일 시스템을 잠시 동결(freeze)해 쓰기를 멈춘 상태에서 만듭니다. 이때 게스트가 마운트 지점을 열지 못하면(권한 거부) 동결이 실패해 스냅샷을 만들지 못하고, 다음 안내가 토스트로 표시됩니다.

`게스트 파일시스템 freeze 중 마운트 포인트를 열지 못했습니다. SELinux 라벨을 확인하거나, 인스턴스를 정지한 뒤 다시 시도하세요.`

실패한 스냅샷은 목록에 `에러` 상태로 남고, 상태 옆 안내 아이콘에 열지 못한 마운트 지점의 경로가 표시됩니다. 게스트 에이전트가 정상으로 응답하는 상태에서 나는 실패라 `사전 점검`에서는 걸러지지 않습니다.

SELinux 를 쓰는 게스트(Rocky Linux 등)에서 디스크를 새로 포맷해 마운트하면 마운트 지점에 SELinux 라벨이 없어 이렇게 실패합니다. 게스트에서 `ls -Zd <마운트 지점>`의 결과가 `unlabeled_t` 이면 이 경우입니다. 다음 중 하나로 조치합니다.

- 게스트에서 `restorecon -v <마운트 지점>`으로 라벨을 붙인 뒤 다시 만듭니다.
- 인스턴스를 `종료`한 뒤 `종료됨` 상태에서 만듭니다. 이때는 파일 시스템을 동결하지 않습니다.

### 스냅샷 상세 조회

1. 인스턴스 상세 화면에서 `인스턴스 구성 요소 > 스냅샷`을 선택합니다.
2. 조회할 스냅샷의 이름을 클릭합니다.
3. 스냅샷에 포함된 블록별 상세 정보를 확인합니다.

### 스냅샷 편집

1. 인스턴스 상세 화면에서 `인스턴스 구성 요소 > 스냅샷`을 선택합니다.
2. 수정할 스냅샷 1개를 선택합니다.
3. `편집`을 클릭합니다.
4. 이름과 설명을 수정합니다.

### 스냅샷 삭제

1. 인스턴스 상세 화면에서 `인스턴스 구성 요소 > 스냅샷`을 선택합니다.
2. 삭제할 스냅샷 1개를 선택합니다.
3. `삭제`를 클릭합니다.

### 스냅샷 롤백

1. 인스턴스가 `종료됨` 상태인지 확인합니다.
2. `인스턴스 구성 요소 > 스냅샷`을 선택합니다.
3. 롤백할 스냅샷 1개를 선택합니다.
4. `롤백`을 클릭합니다.

> 참고
>
> 롤백은 스냅샷에 담긴 디스크만 그 시점으로 되돌립니다. 스냅샷을 만들 때 제외한 디스크와 스냅샷 이후에 연결한 디스크는 현재 내용 그대로 남습니다. 이런 디스크가 있으면 롤백 확인 창에 이름과 크기로 안내됩니다.

> 주의
>
> vTPM이 활성화된 인스턴스는 TPM 상태가 포함되지 않은 스냅샷으로 롤백할 수 없습니다. 이런 스냅샷은 디스크 롤백이 시작되기 전에 요청이 거부되고 오류 안내가 표시됩니다(인스턴스와 디스크는 그대로 유지됨). 다음 두 경우에 해당할 수 있습니다.
>
> - 이 기능이 추가되기 전에 생성한 vTPM 인스턴스 스냅샷
> - 콜드 스토리지 마이그레이션 이후에 롤백하려는, 마이그레이션 이전에 생성된 스냅샷(TPM 상태 사본은 마이그레이션 대상에 포함되지 않습니다)

### 스냅샷으로 이미지 생성(이미지화)

부팅 가능한 인스턴스 스냅샷을 기반으로 새 OS 이미지(골든 이미지)를 생성할 수 있습니다. (기존 `스토리지 > 스냅샷` 목록 화면의 이미지 생성 기능이 이 위치로 이동했습니다.)

1. 인스턴스 상세 화면에서 `인스턴스 구성 요소 > 스냅샷`을 선택합니다.
2. 부팅 가능한 스냅샷 1개를 선택합니다.
3. `이미지 생성`을 클릭하고 저장할 `스토리지 도메인`과 이미지 이름을 지정합니다.
4. 생성된 이미지는 `스토리지 > 이미지` 메뉴에서 확인하며 인스턴스 생성 시 사용할 수 있습니다.

> 이미지는 스냅샷의 부트 디스크 하나로만 만들어집니다. 스냅샷에 추가(데이터) 디스크가 들어 있으면 이미지 생성 창 위에 이미지에 들어가지 않는 디스크가 이름과 크기로 안내됩니다.

> 이미지 생성 완료에는 몇 분이 걸릴 수 있으며, 서버에서 생성 중인 이미지는 OS 타입 `알 수 없음`, 크기 `0GB`로 표시될 수 있습니다. `ISO 파일`로 설치한 인스턴스의 스냅샷으로 만든 이미지는 생성이 끝나면 설치에 쓴 ISO의 OS 타입으로 표시됩니다.

> 참고
>
> 스냅샷을 기반으로 만든 이미지는 이후 인스턴스를 생성할 때 사용할 수 있습니다. 이미지 관리에 대한 자세한 내용은 [이미지](../../storage/image/image.md)를 확인합니다.

> 중요
>
> 실행 중 스냅샷은 파일 시스템 동결에 `QEMU Guest Agent`를 쓰므로, 게스트 에이전트가 응답하지 않으면 스냅샷 만들기가 실패합니다. 스냅샷을 만들기 전에 `QEMU Guest Agent` 설치 여부를 먼저 확인합니다. `종료됨` 상태에서 만드는 스냅샷은 게스트 에이전트가 없어도 됩니다. `ISO 파일` 설치 유형뿐 아니라 Linux 게스트 기본 이미지에도 게스트 에이전트가 없을 수 있습니다. `Rocky Linux 9·10`, `Ubuntu 22.04·24.04` 이미지로 만든 인스턴스는 정지한 뒤 다시 시작할 때 `QEMU Guest Agent`가 없으면 CloudiA가 설치합니다. 설치 예시는 [부록 C. 게스트 에이전트와 Windows 참고](#appendix-c-guest-agent-and-windows)를 확인합니다.

## 백업

`백업`은 인스턴스 단위로 백업을 켜고 끄며, 잡 상태와 마지막 실행 결과를 확인하는 기능입니다. 인스턴스 상세의 `연결된 리소스 > 백업`에서 사용합니다.

백업 자체를 만드는 것은 Veeam Backup & Replication(이하 VBR)이고, CloudiA는 대상 지정과 상태 표시를 담당합니다. 관리자가 `스토리지 > 백업 서버`에 VBR을 등록해 두어야 사용할 수 있습니다.

> 💡 참고: 백업은 **스냅샷과 다릅니다.** 스냅샷은 같은 스토리지 안에 시점을 남기는 기능이고, 백업은 별도의 백업 서버로 데이터를 복사해 보관합니다.

### 화면 구성
`백업` 탭은 세 구역으로 나뉩니다. 백업이 켜져 있든 꺼져 있든 같은 골격이며, 상태에 따라 버튼과 표시 항목만 달라집니다.

| 구역 | 내용 |
| --- | --- |
| `백업 설정` | 백업 서버 선택. 우측에 동작 버튼이 놓입니다. |
| `백업 상태` | 현재 상태와 잡 실행 정보. |
| `사전 점검` | 백업을 켜기 전 확인해야 할 5개 항목. 머리 오른쪽의 `새로고침`으로 다시 점검합니다. 백업이 켜져 있을 때는 표시되지 않습니다. |

> ⚠️ 주의: **백업 범위는 머신 전체(연결된 모든 디스크)로 고정됩니다.** 볼륨이나 파일 단위를 고르는 입력이 없습니다. 파티션·마운트 경로는 게스트 운영체제가 정하는 이름이라 CloudiA가 보장할 수 없고, 게스트 안에서 구성이 바뀌면 지정된 볼륨을 건너뛴 채 잡이 성공으로 끝나 백업이 조용히 줄어들기 때문입니다. 머신 전체를 백업해도 복구는 머신·볼륨·파일 수준을 고를 수 있습니다.

### 백업 켜기
1. `백업 서버`를 선택합니다. 선택하면 `사전 점검` 결과가 표시됩니다.
2. 5개 항목이 모두 `정상`이면 `백업 켜기` 버튼이 활성화됩니다.
3. `백업 켜기`를 누르면 접수되고, VBR이 게스트에 백업 에이전트를 원격 설치합니다. **수 분이 걸립니다.**

#### 사전 점검 항목
| 항목 | 확인 내용 |
| --- | --- |
| **백업 repository** | 그 백업 서버에 백업을 저장할 repository가 정해져 있는지 확인합니다. |
| **게스트 에이전트** | 게스트 에이전트가 응답하고 명령을 실행할 수 있는지 확인합니다. `백업 연동`이 미허용인 인스턴스는 명령 실행이 막혀 이 항목이 `실패`로 표시됩니다. 이때는 [백업 연동이 미허용인 인스턴스](#백업-연동이-미허용인-인스턴스)를 확인합니다. |
| **게스트 운영체제** | 백업 에이전트를 배포할 수 있는 운영체제인지 확인합니다. |
| **보안 그룹** | 백업 서버가 게스트에 원격으로 도달할 수 있는 규칙이 열려 있는지 확인합니다. 빠진 규칙이 있으면 항목 아래에 하나씩 나열됩니다. |
| **등록 주소** | 그 주소가 백업 서버에 다른 머신으로 이미 등록되어 있지 않은지 확인합니다. |

실패한 항목 아래에는 사유와 조치 안내가 함께 표시됩니다. 같은 항목이라도 원인에 따라 조치가 다르므로 문구를 그대로 확인합니다.

> ⚠️ 주의: `등록 주소`는 **켜기 전에 해결해야 합니다.** 백업을 켠 뒤에는 백업 서버가 등록 정보를 지우는 수단을 제공하지 않아 되돌릴 수 없습니다.

#### 백업 연동이 미허용인 인스턴스
백업을 켤 때 VBR이 게스트에 백업 전용 계정을 만들려면 게스트 에이전트의 **명령 실행** 기능이 열려 있어야 하고, 이 기능은 [백업 연동](#백업-연동)이 허용인 인스턴스에서만 열립니다. 그래서 이 기능이 들어온 뒤 `OS 이미지`로 만든 Linux 인스턴스(배포판은 상관없습니다)와, qemu-ga가 없어서 CloudiA가 설치한 인스턴스에서 `백업 연동`이 미허용이면 `게스트 에이전트` 항목이 `실패`로 표시되고 사유는 `게스트 에이전트가 명령 실행을 허용하지 않습니다.`입니다. 항목 아래 안내는 다음과 같으며, **이 상태에서는 백업을 켤 수 없습니다.** `백업 켜기`도 비활성입니다.

> `'백업 연동' 설정이 미허용입니다. 인스턴스를 정지한 뒤 허용으로 바꾸세요.`

이 안내는 인스턴스에 저장된 `백업 연동` 값으로 정해집니다. 게스트가 응답하는지와 상관없이 같은 안내가 나오고, 정지한 인스턴스에서도 `게스트 에이전트가 응답하지 않습니다.` 대신 이 안내가 보입니다. 백업 계정이 이미 들어 있는 인스턴스, 예를 들어 예전에 백업을 켰다가 끈 인스턴스도 `백업 연동`이 미허용이면 다시 켤 수 없습니다.

이런 인스턴스에서 백업을 쓰는 방법은 둘입니다.

- **`백업 연동`을 허용으로 바꿔 인스턴스를 다시 만듭니다.**
- **인스턴스를 정지한 뒤 편집에서 `백업 연동`을 허용으로 바꾸고 시작합니다.** 순서는 다음과 같습니다.

1. 인스턴스 목록에서 `종료`를 눌러 `종료됨`을 확인합니다. `백업 연동`은 정지한 상태에서만 바꿀 수 있고, 실행 중 편집에서는 항목이 잠겨 있습니다.
2. 인스턴스를 선택하고 `편집`을 눌러 `고급 설정` > `보안 설정`의 `백업 연동`에서 `허용` 카드를 고른 뒤 저장합니다.
3. `실행`으로 시작합니다. 바꾼 값은 이 시작부터 적용됩니다. 게스트 안에서 재부팅하거나 `재부팅` 버튼을 누르는 것은 시작이 아니라서 값을 다시 싣지 않습니다.
4. 인스턴스 상세의 `연결된 리소스 > 백업`에서 `사전 점검` 섹션 머리의 `새로고침`을 누릅니다. 사전 점검은 화면을 열 때와 백업 서버를 바꿀 때만 자동으로 다시 돌고, 시작처럼 화면 밖에서 바뀐 상태는 스스로 확인하지 않습니다. 값을 허용으로 바꾼 뒤에는 이 항목이 다시 게스트의 답으로 판정되므로, 게스트가 부팅을 마치기 전에는 `게스트 에이전트가 응답하지 않습니다.`가 보일 수 있습니다. 잠시 뒤 다시 누릅니다. 시작한 직후에는 게스트가 허용 값을 적용하는 데 잠시 걸려 `게스트 에이전트`가 아직 `실패`일 수 있습니다. 이때 항목 아래 안내는 `백업 연동 설정이 가상머신 인스턴스에 아직 적용되지 않았습니다. 인스턴스를 정지한 뒤 다시 시작하세요.`입니다. 잠시 뒤 `새로고침`을 다시 누르고, 몇 분이 지나도 계속 막혀 있을 때만 게스트가 적용하지 못한 것이므로 정지 후 시작을 한 번 더 합니다.
5. 5개 항목이 모두 `정상`이면 `백업 켜기`를 누릅니다.

**이 안내가 나오지 않는 경우:** 이 기능이 들어오기 전에 만들었고 CloudiA가 qemu-ga를 설치하지 않은 인스턴스, `ISO 파일`로 설치한 인스턴스, 쿠버네티스 노드·파일 시스템 서버·패키지 저장소 같은 플랫폼 인스턴스는 `백업 연동`을 바꿔도 게스트에 적용되지 않으며 이 값으로 백업이 막히지도 않습니다. 이런 인스턴스에는 `이미지의 게스트 에이전트 허용 목록에 명령 실행이 열려야 합니다. 지원 배포판(Rocky 9·10, Ubuntu 22.04·24.04)이 아니거나 CloudiA 가 설정을 맡지 않은 VM 은 게스트의 qemu-ga 설정을 직접 열어야 합니다.` 안내가 표시되며, 게스트 안의 qemu-ga 설정에서 명령 실행(`guest-exec`, `guest-exec-status`)을 허용 목록에 넣거나 차단 목록에서 빼야 합니다.

**지원 배포판이 아닌 인스턴스:** 이 기능이 들어온 뒤 `OS 이미지`로 만든 `Rocky Linux 8`, `RHEL`, `Debian` 같은 인스턴스도 `백업 연동`이 미허용이면 위 안내로 막힙니다. 다만 이런 인스턴스는 CloudiA가 게스트의 qemu-ga 설정을 바꾸지 못하므로 `백업 연동`을 허용으로 바꾼 뒤에도 게스트 안의 qemu-ga 설정에서 명령 실행을 직접 열어야 백업을 켤 수 있습니다. 값을 허용으로 바꾸고 나면 이 항목은 다시 게스트의 답으로 판정되어, 열기 전까지는 `이미지의 게스트 에이전트 허용 목록에 명령 실행이 열려야 합니다…` 안내가 표시됩니다.

### 백업 상태
| 상태 | 색 | 의미 |
| --- | --- | --- |
| **켜짐** | 초록 | 백업이 동작 중입니다. |
| **켜는 중** | 파랑 | 에이전트를 배포하고 잡을 만드는 중입니다. |
| **VM 시작 대기** | 노랑 | 인스턴스가 꺼져 있어 켜기가 멈춰 있습니다. 인스턴스를 시작하면 이어집니다. **실패가 아닙니다.** |
| **첫 실행 대기** | 노랑 | 백업은 켜졌지만 아직 한 번도 실행되지 않았습니다. `지금 실행`을 눌러 첫 백업을 시작합니다. 첫 실행이 끝나면 `켜짐`으로 바뀝니다. |
| **끄는 중** | 주황 | 잡과 보호그룹 멤버십을 회수하는 중입니다. |
| **꺼짐** | 회색 | 백업이 꺼져 있습니다. 지금까지 만들어진 백업 데이터는 백업 서버에 남아 있습니다. |
| **켜기 실패** | 빨강 | 켜기가 성립하지 못했습니다. `백업 끄기`로 남은 자원을 정리한 뒤 다시 켭니다. |
| **연결 끊김** | 노랑 | 백업 서버 쪽 잡이나 보호그룹이 외부에서 제거됐습니다. 백업을 다시 켜야 합니다. |

`켜기 실패`와 `연결 끊김`에서는 화면 상단에 조치를 안내하는 경고가 표시되고, `백업 켜기` 옆에 `백업 끄기` 버튼이 함께 나타납니다. **끄기가 남은 자원을 치우는 유일한 경로입니다.**

#### 실행 정보
| 항목 | 설명 |
| --- | --- |
| **등록된 주소** | 백업 서버에 이 인스턴스가 등록된 주소입니다. |
| **잡 상태** | VBR 잡의 현재 상태입니다. |
| **마지막 실행** | 가장 최근 실행 시각입니다. |
| **마지막 실행 결과** | 가장 최근 실행의 결과입니다. |
| **진행률** | 실행 중인 잡의 진행률입니다. |
| **처리량 / 전송량** | 읽은 양과 실제로 보낸 양입니다. |

실행 정보가 하나도 없으면 여섯 항목 대신 `실행 기록` 한 줄에 `표시할 실행 정보가 없습니다.`가 표시됩니다.

> 💡 참고: 이 표시는 "아직 실행된 적이 없다"는 뜻이 **아닙니다.** 잡이 아직 만들어지지 않은 경우와, 백업 서버가 일시적으로 답하지 않는 경우가 같은 모양으로 오기 때문에 화면은 확인된 사실까지만 표시합니다.

### 백업 수동 실행
`지금 실행`을 누르면 백업을 즉시 한 번 실행합니다.

- 잡이 이미 돌고 있으면 `지금 실행`이 비활성화됩니다.
- `첫 실행 대기` 상태에서 누르면 첫 백업이 시작되고, 끝나면 배지가 `켜짐`으로 바뀝니다.
- 실행 이력 목록은 제공하지 않습니다. 성공한 실행만 백업을 남기므로 백업 목록의 간격이 곧 실패 이력이며, 실행 이력 열람은 백업 서버 관리자 영역입니다.

### 백업 끄기
`백업 끄기`를 누르면 확인 창이 열립니다.

- 백업 잡과 보호그룹 멤버십이 회수되고 이 인스턴스는 더 이상 백업되지 않습니다.
- **지금까지 만들어진 백업 데이터는 삭제되지 않습니다.** 백업 서버에 그대로 남습니다.
- 실행 중인 잡이 있으면 멈출 때까지 시간이 걸립니다.
- 끈 뒤에도 백업 기록이 남아 있어 그 백업 서버는 관리자 화면에서 `등록 해제`되지 않습니다.

인스턴스를 삭제하면 백업도 함께 정리되므로, 삭제 전에 백업을 따로 끌 필요는 없습니다.

### 알아둘 점
- 백업 잡의 **일정과 보존 정책은 CloudiA에서 바꿀 수 없습니다.** VBR 관리자 콘솔에서 관리합니다.
- 백업을 켠 뒤에는 백업 서버를 바꿀 수 없습니다. 바꾸려면 끄고 다시 켭니다.
- 이 화면에는 복구 진입점이 없습니다. 복구는 잡이 아니라 개별 백업에 대한 동작이라 별도 화면에서 시작합니다.

## 운영 참고

### 상위 서비스 인스턴스 관리

- `오토 스케일링 그룹`
- `쿠버네티스`
- `파일 시스템`
- `Gen:iA`

위와 같이 상위 서비스가 생성한 인스턴스는 이 메뉴에서도 상태·상세 정보 확인뿐 아니라 `편집`과 전원 제어(`실행`/`종료`/`재부팅`)를 수행할 수 있습니다(1.6.0부터 이 버튼들의 활성화는 인스턴스 **상태**로만 판단하며, 생성 방식으로 구분하지 않음).

`삭제`는 예외입니다. 이 메뉴에서는 `생성 방식`이 `수동 생성`인 인스턴스만 삭제할 수 있으므로, 상위 서비스가 만든 인스턴스는 원래 만든 서비스 화면에서 정리합니다. 인스턴스의 생성·수명 주기를 상위 서비스가 관리하므로, 상위 서비스(예: 오토 스케일링 그룹, 클러스터)를 삭제하면 아래 인스턴스도 함께 삭제될 수 있습니다.

운영자가 인스턴스 메뉴에서 직접 전원 제어하면 상위 서비스 구성과 상태가 어긋날 수 있으니, 관리는 최대한 상위 서비스 화면에서 수행하고 이 메뉴는 상태 확인·긴급 조치로 사용하세요.

### 인스턴스 실행이 실패할 때 확인할 항목

인스턴스를 `실행`할 때 배치 가능한 물리 호스트는 시스템이 자동으로 선택합니다. 아래 조건을 만족하는 호스트가 없으면 실행이 실패할 수 있습니다.

| 확인 항목 | 설명 |
| --- | --- |
| `인스턴스 구성` | 호스트가 요청한 `vCPU`와 `메모리`를 수용할 수 있어야 합니다. 인스턴스 하나의 `vCPU`·`메모리`는 그 호스트의 **물리** 자원을 넘을 수 없습니다 — 오버커밋 비율은 여러 인스턴스를 겹쳐 얹는 데만 적용되므로, 물리 용량보다 큰 인스턴스는 어느 호스트에도 배치되지 않습니다. 또한 인스턴스 예약 메모리(보장 메모리와 가상화 오버헤드의 합)가 호스트의 할당 가능 메모리 안에 들어야 합니다. |
| `설치 유형` | 호스트가 필요한 OS 이미지 또는 ISO 파일을 제공할 수 있어야 합니다. |
| `스토리지` | 연결된 블록, 파일 시스템 등 필요한 스토리지 자원을 제공할 수 있어야 합니다. |
| `AI 가속기` | 요청한 NPU 장치 유형이나 카드 수를 충족할 수 있어야 합니다. |
| `보안 유형` | 인스턴스의 보안 유형을 지원해야 합니다. |
| `가상 CPU 피닝` | 지정한 논리 CPU 범위를 수용할 수 있어야 합니다. |
| `선호도 그룹` | 선호 또는 반선호 규칙을 만족해야 합니다. |
| `호스트 상태` | 호스트 연결 상태, 에이전트 상태, 내부 네트워크 상태가 정상이어야 합니다. |

> 참고
>
> 자원 여유 판단은 모니터링 화면의 실시간 사용률과 동일하지 않을 수 있습니다. 시스템 내부 배치 기준으로 판단합니다.

### 메모리 회수 허용

`메모리 회수 허용`은 노드 메모리가 부족할 때 인스턴스가 쓰지 않는 메모리를 노드가 가져가도 되는지 정하는 설정입니다. 노드에는 인스턴스를 더 많이 배치할 수 있고, 인스턴스에는 보장 메모리 안에서 메모리를 그대로 보장합니다.

| 설정 | 보장 메모리 | 동작 |
| --- | --- | --- |
| `사용함` | 메모리 크기의 50% | 노드 메모리가 부족하면 보장 메모리 위에서 인스턴스가 쓰지 않는 메모리를 회수합니다. |
| `사용 안 함` | 메모리 크기 전체 | 메모리를 회수하지 않습니다. |

- 보장 비율 50%는 바꿀 수 없습니다.
- 회수는 보장 메모리 아래로 내려가지 않고, 인스턴스가 실제로 쓰는 메모리는 가져가지 않습니다.
- 회수는 [컴퓨트 노드](../../../administrator/host-machine/compute-node/compute-node.md#메모리-오버커밋-규칙)에서 메모리 오버커밋을 켠 노드에서만 일어납니다. 메모리 오버커밋을 끈 노드에서는 `사용함`이어도 메모리 크기 전체를 예약하고 회수하지 않습니다.
- 노드 메모리가 바닥나 인스턴스를 강제로 종료해야 할 때는 메모리 회수 허용 인스턴스가 먼저 대상이 됩니다. `사용 안 함`인 인스턴스도 그 노드의 할당 가능 메모리 대부분을 쓰고 있으면 먼저 종료될 수 있습니다.
- 메모리 크기를 늘리면 보장 메모리도 같은 비율로 함께 늘어납니다.
- 시작 템플릿에도 같은 항목이 있고, 템플릿으로 만든 인스턴스가 그 값을 그대로 이어받습니다.

**기본값**

- 새 인스턴스와 새 시작 템플릿은 `사용함`이 기본입니다.
- 이전 버전에서 만든 인스턴스는 업데이트한 뒤에도 `사용 안 함`으로 남습니다. 필요하면 인스턴스 편집에서 하나씩 켭니다.

**켤 수 없는 인스턴스**

아래 인스턴스는 토글이 `사용 안 함`으로 고정되고 토글 아래에 사유가 표시됩니다.

| 대상 | 표시되는 사유 |
| --- | --- |
| `SEV`, `SEV-ES`, `SEV-SNP` 보안 인스턴스, GPU·NPU 패스스루 인스턴스 | `보안 인스턴스와 GPU·NPU 패스스루 인스턴스는 메모리를 회수할 수 없습니다.` |
| Windows 인스턴스 | `Windows 인스턴스는 아직 지원하지 않습니다.` |
| 쿠버네티스 노드 인스턴스 | `쿠버네티스 노드 인스턴스는 메모리를 회수할 수 없습니다.` |
| 게스트 운영체제에 메모리 회수 장치(드라이버)가 없는 인스턴스 | 메모리를 회수할 수 없다는 안내가 표시됩니다. 대부분의 Linux 배포판에는 장치가 들어 있습니다. |

> 참고
>
> 메모리 회수 장치가 없는지는 인스턴스를 만들 때는 알 수 없습니다. `사용함`으로 실행한 인스턴스가 약 10분이 지나도 장치에서 응답을 받지 못하면 회수 대상에서 빠지고 "게스트가 메모리 회수를 지원하지 않습니다." 안내가 표시됩니다. 이 인스턴스는 다음 전원을 켤 때부터 `사용 안 함`으로 다룹니다.

**설정 바꾸기**

- 인스턴스 편집에서 바꿉니다. 종료 상태와 실행 중 모두 바꿀 수 있습니다.
- `사용함`으로 바꾸면 예약하는 메모리가 줄거나 그대로이므로 노드 여유와 상관없이 바꿀 수 있습니다.
- `사용 안 함`으로 바꾸면 보장 메모리가 메모리 크기 전체로 늘어납니다. 메모리 오버커밋을 켠 노드에 여유가 없으면 노드 여유 부족으로 거절됩니다. 이때는 인스턴스를 종료한 뒤 바꾸거나, 다른 노드로 옮긴 뒤 바꿉니다. 인스턴스를 옮기는 중에는 바꿀 수 없습니다.

**인스턴스 안에서 보이는 변화**

노드가 메모리를 회수하는 동안에는 인스턴스 안에서 다음이 달라 보일 수 있습니다.

- 사용 가능한 메모리가 줄어 보입니다. 운영체제의 메모리 사용량 표시가 평소보다 높게 나옵니다.
- 디스크 캐시가 줄어 디스크 읽기가 늘 수 있습니다. 캐시에 크게 기대는 데이터베이스나 파일 서버는 평소보다 느려질 수 있습니다.
- 메모리를 갑자기 많이 쓰면 노드가 회수한 메모리를 돌려줍니다. 돌려받는 동안 잠깐 느려질 수 있습니다.

성능이 중요한 워크로드나 캐시에 크게 기대는 워크로드는 `사용 안 함`으로 두기를 권장합니다. 회수 중인 크기와 보장 메모리는 상세 화면의 [모니터링 정보](#모니터링-정보)에서 확인합니다.

### 고급 설정 항목

고급 설정은 일반 사용자보다 운영 정책이 있는 워크로드에서 주로 사용합니다. 생성·편집 화면에서 `고급 설정`을 펼치면 아래 순서대로 나타납니다.

| 순서 | 영역 | 포함 항목 |
| --- | --- | --- |
| 1 | `보안 설정` | `보안 유형`, `부팅 펌웨어`, `Secure Boot`, `vTPM (TPM 2.0)`, `백업 연동`(설치 유형이 이미지일 때만), `하드웨어 시계` |
| 2 | `스토리지 추가` | `오브젝트 스토리지`, `블록`, `CD/DVD 드라이브`, `파일 시스템` |
| 3 | `AI 가속기` | `GPU` 또는 `NPU` 가속기 |
| 4 | `가상 CPU 피닝` | `vCPU`와 호스트 논리 CPU 범위의 매핑 |
| 5 | `선호도 그룹` | 선호(preferred) 또는 반선호(anti-affinity) 그룹 |
| 6 | `사용자 스크립트` | 부팅 시 실행할 스크립트 |

| 항목 | 설명 |
| --- | --- |
| `보안 유형` | `사용 안 함`, `SEV`, `SEV-ES`, `SEV-SNP` 중에서 선택합니다. |
| `가상 CPU 피닝` | 인스턴스 `vCPU`를 호스트의 논리 CPU 범위에 고정합니다. |

> 중요
>
> `Secure Boot`와 `vTPM (TPM 2.0)`은 `부팅 펌웨어`가 `UEFI`일 때만 화면에 나타납니다. `BIOS`를 선택하면 두 항목이 화면에서 사라지고 설정도 함께 꺼집니다. 두 기능이 필요하면 `부팅 펌웨어`를 `UEFI`로 둡니다.

> 참고
>
> 화면에 표시되는 보안 유형 옵션은 호스트(컴퓨트 노드)의 지원 범위에 따라 달라질 수 있습니다. 일부 환경에서는 `SEV-ES`, `SEV-SNP`가 표시되지 않을 수 있습니다.

### 백업 연동

`백업 연동`은 게스트 안의 `QEMU Guest Agent`(qemu-ga)가 호스트에 열어 주는 기능(RPC)에 VBR 백업 계정을 넣는 데 쓰는 명령 실행을 더할지 정하는 값입니다. 생성 화면과 편집 화면의 `고급 설정` > `보안 설정` 맨 아래에 `미허용(기본)`과 `허용` 카드로 있고, 카드마다 그 단계에서 CloudiA가 인스턴스 안에서 할 수 있는 일이 짧게 적혀 있습니다.

| 단계 | 열리는 기능 |
| --- | --- |
| `미허용`(기본) | CloudiA가 쓰는 **10개**만 열립니다. 응답 확인, 스냅샷 전 파일시스템 정지·해제, 에이전트를 통한 종료·재부팅, OS 정보 조회입니다. |
| `허용` | 위 10개에 더해 **명령 실행 2개**(`guest-exec`, `guest-exec-status`)가 열립니다. VBR 백업 계정을 넣는 데 씁니다. |

어느 단계에서도 파일 읽기·쓰기, 계정 비밀번호와 SSH 키 변경, 일시정지·CPU·메모리·시간 변경, 게스트 상태 조회는 막혀 있습니다. 단계별로 열리는 RPC 이름은 [부록 C. 게스트 에이전트와 Windows 참고](#appendix-c-guest-agent-and-windows)에 있습니다.

**언제 허용하나요?** VBR 백업을 쓰려면 `허용`이어야 합니다. 이 기능이 들어온 뒤 `OS 이미지`로 만든 인스턴스와 CloudiA가 qemu-ga를 설치한 인스턴스는 `미허용`이면 백업을 켤 수 없습니다. 게스트가 응답하는지, 인스턴스가 정지해 있는지, 백업 계정이 이미 들어 있는지와 상관없이 같고, 예전에 백업을 켰다가 끈 인스턴스도 다시 켤 수 없습니다. 만들 때 허용으로 바꾸거나, 이미 만든 인스턴스는 정지한 뒤 편집에서 허용으로 바꾸고 시작합니다. 순서는 [백업 연동이 미허용인 인스턴스](#백업-연동이-미허용인-인스턴스)를 확인합니다.

- **적용 대상은 지원 배포판입니다.** `Rocky Linux 9·10`, `Ubuntu 22.04·24.04`로 `OS 이미지`를 선택해 만든 인스턴스에 적용되며, 같은 단계는 배포판과 상관없이 같은 기능을 엽니다. 그 밖의 배포판(Rocky Linux 8, RHEL, Debian 등), `ISO 파일`로 설치한 인스턴스, 쿠버네티스 노드·파일 시스템 서버·패키지 저장소 같은 플랫폼 인스턴스는 이 값과 상관없이 이미지 기본값을 따릅니다. 다만 이 기능이 들어온 뒤 `OS 이미지`로 만든 그 밖의 배포판 인스턴스는 이 값이 미허용이면 VBR 백업을 켤 수 없고, 허용으로 바꿔도 게스트의 qemu-ga 설정을 직접 열어야 합니다. 이 기능이 들어오기 전에 만든 인스턴스는 바뀌지 않으며, 편집에서 값을 바꿔도 게스트에 적용되지 않습니다. 다만 qemu-ga가 없어서 CloudiA가 설치한 인스턴스는 그때부터 CloudiA가 설정을 맡아 `미허용`으로 둡니다.
- **만든 뒤에도 정지한 상태에서 편집으로 바꿀 수 있습니다.** `종료됨` 상태의 인스턴스에서 `편집`을 열어 `백업 연동`을 허용 또는 미허용으로 바꾸고 저장합니다. 실행 중 편집에서는 항목이 보이지만 잠겨 있고 카드 아래에 그 이유가 표시되며, 상세 화면에서는 읽기 전용 배지로만 확인합니다. 바꾼 값은 다음 시작(정지 후 시작)부터 적용되며, `재부팅` 버튼이나 게스트 안의 재부팅은 반영하지 않습니다. 자세한 내용은 [종료 상태에서 편집](#종료-상태에서-편집)을 확인합니다.
- **미허용으로 바꾼 뒤 첫 시작에는 잠깐의 틈이 있습니다.** `백업 연동`이 허용인 채 시작한 적이 있는 인스턴스에서 값을 미허용으로 바꾸고 시작하면, 그 첫 부팅은 게스트가 새 단계를 적용하기 전까지 몇 초 동안 명령 실행이 열린 채로 시작합니다. 적용이 끝나면 `미허용` 단계로 돌아옵니다.
- **라이브 마이그레이션이나 게스트 안 재부팅 뒤에도 고른 단계가 그대로입니다.** 단계 정보가 인스턴스에 실려 라이브 마이그레이션을 따라가고, 게스트가 부팅할 때마다 같은 단계를 다시 적용하기 때문입니다.
- **CloudiA가 설정을 맡는 인스턴스에서는 게스트 안에서 바꾼 qemu-ga 설정이 다음 부팅에 되돌아갑니다.** 이 기능이 들어온 뒤 만든 지원 배포판 인스턴스와 CloudiA가 qemu-ga를 설치한 인스턴스가 해당하며, 열리는 기능의 범위는 `백업 연동` 값으로 정해집니다.
- **`백업 연동`이 허용인 채 시작한 적이 있는 인스턴스로는 이미지를 만들지 않는 편이 안전합니다.** 이런 인스턴스로 이미지를 만들면(예: 스냅샷에서 이미지 생성) 열려 있는 명령 실행 설정이 이미지에 함께 담깁니다. 그 이미지로 만든 인스턴스는 `백업 연동`을 허용으로 바꾸지 않았어도 첫 부팅에서 CloudiA가 정책을 적용하기 전까지 잠시 명령 실행이 열려 있습니다. `Rocky Linux`에서는 부팅 중 cloud-init의 `bootcmd` 단계가 실행될 때까지입니다. 이를 피하려면 `미허용`으로만 시작한 인스턴스로 이미지를 만듭니다.

> 중요
>
> 명령 실행이 열려 있으면 호스트는 게스트 안에서 `root`로 명령을 실행할 수 있습니다. CloudiA에서 게스트 명령 실행을 쓰는 곳은 VBR 백업 계정을 넣는 단계 하나뿐이므로, 백업할 인스턴스에만 `백업 연동`을 허용으로 바꿉니다. `미허용`(기본)에서는 호스트가 게스트 안에서 명령을 실행할 수 없습니다.

### 가상머신 시계

인스턴스의 하드웨어 시계(RTC)는 부팅할 때 운영체제가 처음 읽는 시각입니다. 생성·편집 화면의 `하드웨어 시계`에서 그 기준을 고릅니다.

| 값 | 부팅할 때 하드웨어 시계 |
| --- | --- |
| `자동`(기본) | Windows 면 현지 시각, 다른 운영체제면 UTC |
| `현지 시각` | 컴퓨트 노드의 시간대 기준 시각(한국 시각). 다른 제품의 local time(libvirt `localtime`, Proxmox 'Use local time for RTC')과 같습니다 |
| `UTC` | UTC 기준 시각 |

Windows 는 하드웨어 시계를 자기 시간대의 현지 시각으로 읽고, Linux 는 UTC 로 읽습니다. 그래서 `자동`이면 Windows 인스턴스도 부팅 직후부터 시간 동기화(NTP)를 기다리지 않고 바른 시각을 보여 줍니다.

- **Windows 인지 언제 정하나요?** 처음 시작할 때 정합니다. Windows 설치 ISO 를 붙여 만든 인스턴스는 OS 를 설치하기 전에도 Windows 로 정해지고, 나중에 ISO 를 빼도 그대로입니다. 게스트 에이전트가 켜진 인스턴스는 게스트가 알려 준 운영체제로 다시 맞춥니다. 예를 들어 virtio 드라이버 ISO 를 붙인 Linux 가 Windows 로 잘못 정해졌다면 게스트 에이전트가 응답한 뒤 다음 시작부터 UTC 로 켜집니다. 반대로 OS 종류를 모르는 이미지로 만든 Windows 가 Windows 로 정해지지 않았다면, 게스트 에이전트가 응답한 뒤 다음 시작부터 현지 시각으로 켜집니다. 게스트 에이전트가 없으면 `하드웨어 시계`를 직접 고릅니다.
- **바꾸는 방법:** 인스턴스를 정지하고 `편집`에서 고른 뒤 저장합니다. 다음 시작부터 적용됩니다. 실행 중 편집에서는 항목이 잠겨 있습니다.
- **게스트 안에서 바꾼 시각:** 게스트 안에서 시각이나 시간대를 바꾸면 그 실행 동안과 게스트 안의 재부팅까지는 유지됩니다. 인스턴스를 정지했다가 시작하면 `하드웨어 시계` 기준으로 돌아갑니다. 시각은 시간 동기화(NTP)로 맞추는 것을 권장합니다.
- **복제·템플릿:** [복제](#인스턴스-복제)한 인스턴스는 원본의 `하드웨어 시계`와 Windows 판정을 이어받습니다. [시작 템플릿으로 변환](#시작-템플릿으로-변환)하거나 시작 템플릿으로 만든 인스턴스는 `하드웨어 시계` 값을 이어받습니다.
- **컴퓨트 노드 시간대:** `현지 시각`은 인스턴스가 켜지는 컴퓨트 노드의 시간대를 따릅니다. 모든 컴퓨트 노드의 시간대는 같아야 합니다.

> ⚠️ **주의:** 게스트에 `RealTimeIsUniversal` 레지스트리 값을 넣었거나 게스트 시간대를 UTC 로 둔 Windows 는 `자동`에서 시각이 9시간 빠르게 보입니다. 인스턴스를 정지하고 `하드웨어 시계`를 `UTC` 로 바꿉니다. 도메인 컨트롤러는 다시 켜기 전에 바꿉니다. 이 값은 관리자 권한 명령 프롬프트에서 `reg query HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation /v RealTimeIsUniversal`로 확인합니다.

### 무중단 증설 상한 산정 기준

`무중단 증설`은 `고급 설정` 안이 아니라 인스턴스 사양 바로 아래에 있습니다.

> 참고
>
> `무중단 증설` 상한은 인스턴스를 만든 뒤에는 바뀌지 않습니다. 그래서 실행 중 편집에서는 토글이 표시되지 않고, 지금 얼마나 더 늘릴 수 있는지만 안내됩니다("종료 없이 최대 8 vCPU · 16GB까지 늘릴 수 있습니다." / 여력을 모두 쓴 경우 "증설 한도에 도달했습니다. 더 늘리려면 인스턴스를 종료하고 사양을 변경하세요."). 상한 자체를 바꾸려면 인스턴스를 종료한 뒤 편집합니다.

- `무중단 증설`을 `사용함`으로 설정하면 상한은 **현재 사양의 4배**로 자동 산정됩니다. 메모리 상한은 1GiB 슬롯 단위로 내림합니다(예: 현재 `4GB` → 상한 `16GB`, 현재 `6GB` → 상한 `24GB`).
- 4배 산정값에는 천장이 있습니다. 메모리는 **추가로 늘릴 수 있는 양(헤드룸)** 이 최대 `256GiB`(1GiB 슬롯 256개)이므로 상한은 `현재 메모리 + 최대 256GiB` 입니다(예: 현재 `512GB` → 상한 `768GB`). `vCPU` 상한의 플랫폼 천장은 `4096`입니다.
- `종료됨` 상태에서 사양(`vCPU`, 메모리)을 변경하면 상한도 새 사양 기준으로 다시 계산됩니다. 다만 이전에 사용자가 직접 지정해 둔 상한이 있다면 그 값은 보존됩니다.
- 실제로 증설할 수 있는 크기는 이 상한과 **인스턴스가 올라가 있는 호스트의 물리 자원** 중 작은 쪽입니다. 상한이 남아 있어도 그 호스트의 물리 `vCPU`·메모리를 넘는 증설은 거부됩니다. 더 키우려면 인스턴스를 종료한 뒤 더 큰 호스트로 옮겨 실행합니다.

#### 시스템 정책으로 꺼져 있는 경우

`무중단 증설`은 클러스터 정책으로 꺼둘 수 있습니다. 꺼진 환경에서는 여유분을 새로 부여하지 않으므로, 여유분이 없는 인스턴스는 토글이 꺼진 채 잠깁니다. 이미 여유분이 있는 인스턴스는 토글을 꺼서 여유분을 회수할 수 있습니다.

| 상황 | 화면 동작 | 표시되는 안내 |
| --- | --- | --- |
| 정책이 꺼져 있고, 인스턴스에 여유분도 없음 | 토글이 `사용 안 함`으로 고정됩니다. | `이 클러스터에서는 무중단 증설을 사용할 수 없습니다. 관리자에게 문의하세요.` |
| 정책이 꺼져 있지만, 인스턴스가 이미 여유분을 가지고 있음 | 토글을 켜고 끌 수 있습니다. 여유분은 그대로 유지되며, `사용 안 함`으로 저장하면 회수됩니다. | `이 클러스터에서는 무중단 증설을 새로 부여하지 않습니다. 이 인스턴스가 이미 가진 여유분은 유지되며, 원하면 여기서 회수할 수 있습니다.` |

> 주의
>
> 여유분을 한 번 회수하면 정책이 꺼져 있는 동안에는 다시 부여할 수 없습니다. 회수 전에 실행 중 증설이 더 필요하지 않은지 확인합니다.

#### 보안 유형별 제약

`SEV` 계열 보안 유형은 보호 수준에 따라 실행 중 작업과 호스트 요구 사항이 다릅니다.

| 보안 유형 | 보호 수준 | 실행 중 재시작 | `vCPU` 증설 | 메모리 증설 | 호스트 요구 사항 |
| --- | --- | --- | --- | --- | --- |
| `사용 안 함` | 적용 안 함 | 가능 | 가능 | 가능 | 별도 요구 사항 없음 |
| `SEV` | 메모리 암호화 | 가능 | 가능 | 가능 | SEV 지원 호스트 |
| `SEV-ES` | 메모리 + 레지스터 상태 암호화 | 불가 | 불가 | 불가 | IOMMU 지원 호스트 |
| `SEV-SNP` | 메모리 + 상태 + 무결성 보호 | 불가 | 불가 | 불가 | IOMMU 지원 호스트 |

> 중요
>
> `SEV-ES`, `SEV-SNP` 인스턴스는 실행 중 재부팅, `vCPU` 증설, 메모리 증설이 모두 불가합니다. 이 두 보안 유형을 선택하면 화면에서 `무중단 증설` 토글이 비활성화되고 "SEV-ES · SEV-SNP 인스턴스는 무중단 증설을 지원하지 않습니다."가 표시되며, 재시작 버튼도 비활성화됩니다. 또한 SEV 계열(`SEV`, `SEV-ES`, `SEV-SNP`)은 모두 라이브 마이그레이션을 지원하지 않습니다. 실행 중 스펙 변경이나 무중단 이전이 필요한 워크로드라면 보안 유형 선택 시 이 점을 함께 고려합니다.

### 추가 블록 디스크와 파일 시스템 연결 확인

추가 리소스를 연결한 뒤에는 화면과 게스트 OS를 함께 확인합니다.

### 오브젝트 스토리지 사용 시 확인할 항목

- `오브젝트 스토리지`는 인스턴스에 별도 디스크를 추가하는 기능이 아닙니다.
- 이 옵션을 활성화하면 오브젝트 스토리지 접근용 네트워크 인터페이스와 내부 DNS 설정이 함께 적용됩니다.
- 인스턴스 상세의 `상단 정보`에서 사용 여부를 확인하고, `네트워크 인터페이스` 탭에서 `Managed VNIC` 존재 여부를 함께 확인합니다.
- 인스턴스 안에서 실제 이름 해석이 되는지 확인하려면 `object-storage.cloudia.internal` 조회 결과를 점검합니다.

#### 추가 블록 디스크

- 상세 화면의 `디스크` 탭에서 `장치 레이블`과 디스크 정보를 확인합니다.
- 게스트 OS에서 실제 디스크가 인식됐는지 확인합니다.
- Linux에서는 장치 이름만 보지 말고 `SERIAL` 값과 `장치 레이블`을 함께 비교합니다.
- Windows에서는 디스크가 `Offline` 또는 `RAW`인지 함께 확인합니다.

#### 파일 시스템

- 상세 화면의 `연결된 리소스 > 파일 시스템`에서 연결 상태를 확인합니다.
- 게스트 OS에서 실제 마운트 여부와 읽기/쓰기 여부를 확인합니다.
- `NFS`는 관련 패키지가 설치되어 있어야 합니다.
- 게스트 OS에 `NFS` 클라이언트 패키지가 없으면 `/etc/fstab`에 항목이 있어도 자동 마운트가 완료되지 않을 수 있습니다.
- 이 경우 패키지를 설치한 뒤 `mount -a`로 기존 `fstab` 항목을 적용합니다.
- `virtiofs`는 마운트 여부뿐 아니라 읽기/쓰기 테스트까지 확인합니다.

> 참고
>
> Linux와 Windows에서 사용하는 상세 명령 예시는 [부록 D. 추가 블록 디스크와 파일 시스템 확인 명령](#appendix-d-block-disk-and-filesystem-checks)을 확인합니다. NFS 공유 볼륨 구성, 패키지 설치, `fstab` 적용, 마운트 확인을 순서대로 따라 하려면 [파일 시스템을 통한 인스턴스 간 공유 볼륨 구성하기](../../../user-guide/examples-and-labs/17-share-volumes-between-instances-with-nfs.md)를 확인합니다.

### 가상 CPU 피닝 편집

1. 인스턴스 상세 화면으로 이동합니다.
2. 인스턴스가 `종료됨` 또는 `정지됨` 상태인지 확인합니다.
3. `인스턴스 구성 요소 > 가상 CPU 피닝`을 선택합니다.
4. `편집`을 클릭합니다.
5. 규칙을 추가하거나 삭제합니다.
6. `vCPU ID`와 `논리 CPU 범위(시작, 끝)`를 입력합니다.
7. `편집`을 클릭해 저장합니다.

> 참고
>
> 가상 CPU 피닝 설정은 다음 실행 시점에 반영되는지 확인한 뒤 작업합니다.

### 부록 A. ISO 기반 부팅 디스크 기준

이 부록은 `ISO 파일` 설치 유형에서 사용하는 부팅 디스크 기준을 자세히 정리한 것입니다.

- `최소값`: CloudiA가 허용하는 최소 부팅 디스크 크기
- `CloudiA 기본값`: 생성 화면에서 기본으로 제안하는 값
- `공급사 문서 기준 권장값`: 운영체제 공급사 문서에서 따로 안내하는 권장값

#### 운영체제 계열별 기본 정책 요약

| 운영체제 계열 | 최소값 | CloudiA 기본값 |
| --- | --- | --- |
| `Unknown` | 4 GB | 10 GB |
| `RHEL 계열` | 10 GB | 15 GB |
| `Ubuntu` | 5 GB | 15 GB |
| `Debian` | 4 GB | 8 GB |
| `Windows 10` | 32 GB | 64 GB |

<a id="appendix-b-multi-nic-ops"></a>
### 부록 B. 다중 NIC 운영 참고

#### 같은 서브넷, 다른 서브넷, 외부 네트워크

| 통신 구간 | 일반적인 동작 | 함께 확인할 항목 |
| --- | --- | --- |
| `같은 서브넷` | 상대 인스턴스의 사설 IP로 직접 통신합니다. | 보안그룹, 게스트 OS 방화벽, 서비스 리슨 주소 |
| `같은 VPC의 다른 서브넷` | 각 서브넷의 게이트웨이를 통해 통신합니다. | 보안그룹, 게이트웨이, 게스트 OS 라우팅, 네트워크 정책 |
| `다른 VPC 또는 외부 네트워크` | 별도 연결 정책 없이 직접 통신하지 않습니다. | 라우팅, NAT 또는 플로팅 IP, 보안 정책 |

#### 비대칭 라우팅이 발생하는 경우

비대칭 라우팅은 요청이 들어온 인터페이스와 응답이 나가는 인터페이스가 다른 경우입니다. 다중 NIC 환경에서는 다음 조건에서 자주 발생합니다.

- 여러 NIC에 기본 게이트웨이가 동시에 설정된 경우
- 특정 NIC의 IP로 수신한 요청에 대해 다른 NIC의 기본 경로가 선택된 경우
- 소스 IP 기준 라우팅이 필요한데 기본 라우팅 테이블만 사용하는 경우
- Linux의 `rp_filter`가 strict 모드로 설정된 경우

#### 점검 항목

다중 NIC에서 통신이 되지 않으면 Linux 게스트에서 다음 항목을 함께 점검합니다.

1. 인터페이스별 IP와 라우팅
2. `ip rule` 기반 정책 기반 라우팅(PBR)
3. `rp_filter` 설정
4. 기본 게이트웨이 중복 여부

자주 사용하는 명령은 다음과 같습니다.

```bash
ip addr
ip route
ip route show table all
ip rule

sysctl net.ipv4.conf.all.rp_filter
sysctl net.ipv4.conf.default.rp_filter
sysctl net.ipv4.conf.<인터페이스명>.rp_filter
```

#### 수동 IP 설정 예시(Linux)

실행 중 편집으로 NIC를 추가한 뒤 게스트 OS에서 새 인터페이스를 직접 구성해야 할 수 있습니다.

```bash
IFACE=eth1
IPADDR=10.0.0.66/24
GW=10.0.0.1
DNS1=10.0.0.2

nmcli con add type ethernet ifname "$IFACE" con-name "$IFACE" ip4 "$IPADDR" gw4 "$GW"
nmcli con modify "$IFACE" ipv4.dns "$DNS1" ipv4.method manual
nmcli con up "$IFACE"
```

> 참고
>
> 기본 NIC가 아닌 인터페이스에 게이트웨이를 추가하면 별도의 default route가 생길 수 있습니다. 다중 NIC 환경에서는 경로 우선순위와 정책 기반 라우팅을 함께 확인합니다.

### 부록 C. 게스트 에이전트와 Windows 참고

#### 게스트 에이전트 단계별로 열리는 RPC

`백업 연동`(생성·편집 화면에서 고르는 값)에 따라 지원 배포판(`Rocky Linux 9·10`, `Ubuntu 22.04·24.04`)의 qemu-ga가 여는 RPC는 다음과 같습니다. 적용 대상과 동작은 [백업 연동](#백업-연동)을 확인합니다.

**`미허용`(기본) — CloudiA가 쓰는 기능에 필요한 10개**

| RPC | 용도 |
| --- | --- |
| `guest-sync` | libvirt가 모든 에이전트 명령 앞에 보내는 동기화입니다. |
| `guest-sync-delimited` | 같은 동기화의 구분자 방식입니다. 지금은 쓰지 않지만 프로토콜 동기화에 필요해 열어 둡니다. |

| `guest-info` | 켜진 RPC 목록을 읽습니다. 스냅샷과 백업 사전 점검이 사용합니다. |

| `guest-fsfreeze-freeze`, `guest-fsfreeze-thaw` | 스냅샷 전후에 파일시스템을 정지하고 해제합니다. |

**`허용` — 위 10개와 아래 2개**

| RPC | 용도 |
| --- | --- |
| `guest-exec` | 게스트 안에서 명령을 실행합니다. VBR 백업 계정을 만들고 그 계정에 SSH 공개 키를 넣는 데 씁니다. |
| `guest-exec-status` | 실행한 명령이 끝났는지와 그 출력을 읽습니다. |

| 묶음 | RPC |

| 조회 | `guest-get-disks`, `guest-get-fsinfo`, `guest-get-host-name`, `guest-get-memory-block-info`, `guest-get-memory-blocks`, `guest-get-time`, `guest-get-timezone`, `guest-get-users`, `guest-get-vcpus`, `guest-network-get-interfaces`, `guest-get-cpustats`, `guest-get-diskstats`, `guest-get-load`, `guest-network-get-route` |

> 참고
>
> 게스트의 qemu-ga가 지원하는 RPC는 버전마다 다릅니다. `Ubuntu 22.04`(qemu-ga 6.2)에는 `guest-get-cpustats`, `guest-get-diskstats`, `guest-get-load`, `guest-network-get-route`가 없고, `Ubuntu 24.04`(8.2)에는 `guest-get-load`, `guest-network-get-route`가 없습니다. 이후 버전이 RPC를 더해도 그 RPC는 어느 단계에서도 막힙니다.

#### Linux 게스트에서 QEMU Guest Agent 설치

> 참고
>
> `Rocky Linux 9·10`, `Ubuntu 22.04·24.04` 이미지로 만든 인스턴스는 정지한 뒤 다시 시작할 때 qemu-ga가 없으면 CloudiA가 설치합니다(자세한 내용은 [패키지 저장소](../../../administrator/repository/package/package.md) 참고). 이 기능이 들어온 뒤 만든 인스턴스와 CloudiA가 qemu-ga를 설치한 인스턴스는 CloudiA가 설정을 맡아 위 단계의 범위로 열며, 게스트 안에서 설정 파일(예: Rocky Linux의 `/etc/sysconfig/qemu-ga`)을 바꿔도 다음 부팅에 되돌아갑니다. 아래 수동 설치와 설정은 지원 배포판이 아니거나 CloudiA가 설정을 맡지 않는 인스턴스에 합니다.

`Rocky Linux` 또는 `RHEL` 계열에서는 다음 명령을 사용합니다.

```bash
sudo dnf install -y qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent
sudo systemctl status qemu-guest-agent
```

`Ubuntu`에서는 다음 명령을 사용합니다.

```bash
sudo apt-get update
sudo apt-get install -y qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent
sudo systemctl status qemu-guest-agent
```

### 부록 D. 추가 블록 디스크와 파일 시스템 확인 명령

#### Linux에서 추가 블록 디스크 확인

1. 상세 화면에서 추가 블록 디스크의 `장치 레이블`을 확인합니다.
2. 게스트 OS에서 다음 명령을 실행합니다.

```bash
lsblk -o NAME,SERIAL
```

3. `SERIAL` 값과 상세 화면의 `장치 레이블` 숫자를 함께 비교합니다.

> 참고
>
> 디스크가 여러 개 연결된 경우에는 `/dev/vdb`, `/dev/vdc` 같은 장치 이름만으로 식별하지 말고 `SERIAL` 값과 `장치 레이블`을 함께 확인합니다.

#### Windows에서 추가 블록 디스크 확인

```powershell
Get-Disk
Get-Partition
Get-Volume
```

새 디스크가 `Offline` 또는 `RAW`로 보이면 초기화, 파티션 생성, 포맷, 드라이브 문자 할당을 순서대로 진행합니다.

#### Linux에서 NFS 준비 사항 확인

| 게스트 OS | 확인할 패키지 | 확인 명령 |
| --- | --- | --- |
| `Rocky Linux`, `RHEL` 계열 | `nfs-utils` | `rpm -q nfs-utils` |
| `Ubuntu` | `nfs-common` | `dpkg -l nfs-common` |

필요한 패키지가 없으면 다음 명령으로 설치합니다.

```bash
# Rocky Linux / RHEL 계열
sudo dnf install -y nfs-utils

# Ubuntu
sudo apt-get update
sudo apt-get install -y nfs-common
```

패키지를 설치한 뒤에는 `/etc/fstab`에 이미 기록된 NFS 항목을 적용합니다.

```bash
sudo mount -a
```

```bash
sudo sh -c 'echo "Hello ---" > /mnt/virtiofs/test-file.txt'
```


### 부록 E. 외부 접속 또는 내부 통신 점검

통신이 되지 않으면 다음 순서로 확인합니다.

1. 인스턴스 상태가 `실행 중`인지 확인합니다.
2. 필요한 NIC에 올바른 IP가 설정됐는지 확인합니다.

# 블록

`블록`은 인스턴스에 연결해 사용하는 블록 스토리지를 생성하고 관리하는 화면입니다. 사용자는 블록을 생성한 뒤 인스턴스에 연결하거나, 필요 시 크기를 늘리거나 삭제할 수 있습니다.

## 화면 개요
- `목록 화면`: 블록 현황을 조회하고 생성, 편집, 삭제 작업을 시작합니다.
- `상세 화면`: 블록의 기본 정보와 연결된 인스턴스 상태를 확인하고, `스냅샷` 섹션에서 블록 스냅샷을 관리합니다.
- `생성/편집 화면`: 이름, 스토리지 도메인, 크기, 설명을 입력하거나 수정합니다.
- `업로드 화면`: 데이터가 담긴 디스크 파일을 올려 블록으로 등록합니다.
- `스토리지 마이그레이션`: 블록을 다른 스토리지 도메인으로 이동합니다.
- `블록 공유`: 한 블록을 여러 인스턴스에 함께 연결합니다. 자세한 내용은 [블록 공유](#블록-공유)를 참고하세요.

## 블록 목록
### 주요 작업
- `생성`: 새 블록을 추가합니다.  
- `편집`: 선택한 블록의 이름, 크기, 설명을 수정합니다. 연결된 인스턴스가 실행 중인 경우에는 편집할 수 없습니다.
- `삭제`: 선택한 블록을 삭제합니다. 연결된 인스턴스가 하나도 없는 경우에만 삭제할 수 있습니다.
- `업로드`: 데이터가 담긴 디스크 파일을 올려 블록으로 등록합니다.

### 테이블 컬럼
블록 목록 화면에서는 다음 정보를 칼럼으로 표시합니다.

| 컬럼 | 설명 |
|------|------|
| **이름** | 블록의 이름을 나타냅니다. |
| **ID** | 블록의 ID를 나타냅니다. |
| **크기** | 블록의 디스크 크기를 나타냅니다. |
| **연결된 인스턴스** | 블록을 사용 중인 인스턴스의 상태를 나타냅니다. 공유 블록이 여러 인스턴스에 연결돼 있으면 연결 수를 표시합니다.<br>(인스턴스에 관한 상세 정보는 인스턴스 사용자 가이드 > 인스턴스 상세 참고) |
| **공유 방식** | `공유 안 함` / `읽기 전용 공유` / `읽기·쓰기 공유` 중 하나입니다. 공유 블록은 배지로 표시합니다. |
| **스토리지 도메인** | 블록이 사용중인 스토리지 도메인을 나타냅니다. |
| **설명** | 블록에 대한 설명을 나타냅니다. |
| **생성 일시** | 블록이 생성된 일시를 나타냅니다. |

## 블록 상세
블록 상세 화면에서는 선택한 블록의 상세 정보를 확인할 수 있습니다.

### 상단 요약
- **이름**: 블록의 이름을 나타냅니다.
- **ID**: 블록의 ID를 나타냅니다.
- **타입**: 블록의 실제 타입을 나타냅니다. (`QCOW` / `RBD` )
- **크기**: 블록의 디스크 크기를 나타냅니다.
- **스토리지 도메인**: 블록이 사용중인 스토리지 도메인을 나타냅니다.
- **공유 방식**: 블록의 공유 방식을 나타냅니다.
- **연결된 인스턴스**: 블록을 사용 중인 인스턴스의 이름, ID, 상태를 나타냅니다. 공유 블록은 연결된 인스턴스를 모두 보이며, 리눅스 인스턴스에는 `게스트 장치 경로`도 함께 표시합니다.
- **설명**: 블록에 대한 설명을 나타냅니다.
- **생성 일시**: 블록이 생성된 일시를 나타냅니다.
- **수정 일시**: 블록의 정보가 수정된 일시를 나타냅니다.

## 블록 생성 및 편집
블록 생성 화면에서는 새로운 블록을 생성할 수 있으며, 편집 화면에서는 기존 블록의 일부 정보를 수정할 수 있습니다.  
블록 생성 시 선택 가능한 `스토리지 도메인`이 사전에 준비되어야 합니다.

### 기본 정보
- **이름**: 블록의 이름을 입력합니다.
- **스토리지 도메인**: 블록이 사용할 스토리지 도메인을 선택합니다.
- **크기**: 블록의 디스크 크기를 입력합니다. 크기 단위는 MB, GB, TB입니다.
- **설명**: 블록에 대한 설명을 입력합니다.
- **공유 방식**: 생성 시 `공유 안 함` 또는 `읽기·쓰기 공유`를 고릅니다. 빈 블록은 읽을 내용이 없어 `읽기 전용 공유`로 만들 수 없습니다. 편집 시에는 세 가지 중에서 바꿀 수 있습니다. [블록 공유](#블록-공유) 참고.

### 입력 필드 유효성
| 필드 | 허용 값 | 검증 규칙 | 비고 |
| --- | --- | --- | --- |
| **이름** | 영문, 숫자, `-`, `_` 조합의 문자열 | 필수입니다. 80자 이내로 입력합니다. | 블록 식별용 이름입니다. |
| **스토리지 도메인** | 현재 프로젝트에서 선택 가능한 스토리지 도메인 | 필수입니다. 생성 시 1개를 선택합니다. | 편집 시 변경할 수 없습니다. |
| **크기** | 0 이상의 숫자 + 단위 | 필수입니다. 단위와 함께 입력합니다. | 편집 시 축소는 지원하지 않습니다. |
| **설명** | 최대 200자 문자열 | 선택 입력입니다. 200자를 초과할 수 없습니다. | 운영 메모용입니다. |

### 편집 시 주의사항
- 연결된 인스턴스가 없거나, 연결된 인스턴스가 `종료됨` 또는 `정지됨` 상태인 경우에만 편집할 수 있습니다.
- 편집 화면에서는 이름, 크기, 설명, 공유 방식을 수정할 수 있습니다.
- 블록 크기는 기존 값 이상으로만 수정할 수 있습니다.
- `읽기 전용 공유` 블록은 크기를 늘릴 수 없습니다. 같은 편집에서 공유 방식을 `공유 안 함`으로 바꾸면 늘릴 수 있습니다.
- 공유 방식을 바꾸는 조건은 [블록 공유 > 공유 방식 바꾸기](#공유-방식-바꾸기)를 참고하세요.

## 블록 업로드
이미 데이터가 들어 있는 디스크 파일을 올려 블록으로 등록합니다. 업로드한 파일 자체가 하나의 블록이 되므로, 다른 곳에서 만들어 둔 데이터셋을 인스턴스에 그대로 붙여 쓸 수 있습니다.

`블록 생성`과는 다음이 다릅니다.

| | 블록 생성 | 블록 업로드 |
| --- | --- | --- |
| 내용 | 비어 있는 블록 | 업로드한 파일의 내용 |
| 크기 | 직접 입력합니다. | 입력하지 않습니다. 업로드한 파일의 **가상 크기**로 확정됩니다. |
| 이름 | 직접 입력합니다. | 업로드한 파일 이름에서 정해집니다. |
| 완료 시점 | 즉시 | 변환이 끝난 뒤 |

> 운영체제가 설치된 **부팅 이미지는 이 경로로 등록하지 않습니다.** `이미지` 화면의 이미지 업로드를 이용하세요. 업로드한 블록은 데이터 디스크로만 쓰이며 부팅 이미지 목록에는 나타나지 않습니다.

### 업로드 절차
1. 블록 목록에서 `업로드` 버튼을 누릅니다.
2. `스토리지 도메인`을 선택합니다.
3. `블록 파일`을 선택합니다. `.qcow2`, `.img` 파일을 올릴 수 있습니다.
4. `공유 방식`을 고릅니다. 같은 데이터를 여러 인스턴스에 나눠 줄 때는 `읽기 전용 공유`를 고릅니다.
5. `업로드` 버튼을 누르면 등록이 접수되고 블록 목록으로 이동합니다.

### 입력 필드
| 필드 | 허용 값 | 검증 규칙 | 비고 |
| --- | --- | --- | --- |
| **스토리지 도메인** | 현재 프로젝트에서 선택 가능한 스토리지 도메인 | 필수입니다. 1개를 선택합니다. | 업로드한 블록이 저장될 위치입니다. |
| **블록 파일** | `.qcow2`, `.img` | 필수입니다. | 데이터만 담긴 디스크 파일이어야 합니다. |
| **공유 방식** | `공유 안 함` / `읽기 전용 공유` / `읽기·쓰기 공유` | 필수입니다. 기본값은 `공유 안 함`입니다. | `읽기·쓰기 공유`는 Ceph 스토리지 도메인에서만 고를 수 있습니다. |

### 변환 중 동작
업로드는 접수 후 백그라운드에서 변환됩니다. 변환이 끝나기 전까지는 다음과 같이 동작합니다.

- 블록 목록에 나타나지만 상태가 `생성 중`으로 표시되고 크기가 확정되지 않습니다.
- 인스턴스에 디스크를 추가할 때 **후보 목록에 나타나지 않습니다.** 내용이 아직 채워지지 않은 디스크가 인스턴스에 연결되는 것을 막기 위함입니다.

변환이 끝나면 `생성 중` 표시가 사라지고 크기가 확정되며, 인스턴스 디스크 추가 후보에 나타납니다. 변환에 걸리는 시간은 파일에 실제로 들어 있는 데이터 양에 비례합니다.

### 운영체제가 담긴 디스크를 올린 경우
데이터만 담긴 파일을 올리는 것이 정상적인 사용법이지만, 장애가 난 인스턴스에서 데이터를 꺼내야 하는 경우처럼 운영체제가 통째로 들어 있는 디스크를 올려야 할 때가 있습니다.

이때 CloudiA는 등록 전에 **파일시스템 식별자(UUID)를 새로 발급**합니다. 업로드가 끝나면 그 사실을 알리는 메시지가 표시됩니다.

**왜 필요한가요?**
같은 원본에서 복제된 디스크들은 파일시스템 식별자가 서로 같습니다. 그런 디스크를 인스턴스에 데이터 디스크로 붙이면, 인스턴스의 부팅 디스크와 식별자가 겹칩니다. 리눅스는 이 식별자로 루트 파일시스템을 찾기 때문에, 같은 식별자를 가진 디스크가 둘이면 **어느 쪽을 루트로 쓸지가 재부팅마다 달라질 수 있습니다.** 잘못 선택되면 인스턴스가 엉뚱한 디스크로 부팅되고, 두 디스크에 동시에 쓰기가 일어나면 파일시스템이 손상됩니다.

**식별자를 새로 발급하면 그 디스크는 더 이상 부팅에 쓸 수 없습니다.** 데이터 블록은 원래 부팅에 쓰이지 않으므로(부팅 이미지 목록에 나타나지 않습니다) 사용에는 지장이 없습니다. **파일 내용은 그대로 보존**되므로 인스턴스에 붙여 데이터를 읽는 용도는 그대로 쓸 수 있습니다.

부팅까지 되는 이미지가 필요하다면 이 경로가 아니라 `이미지` 화면의 이미지 업로드를 이용하세요.

**다음 경우에는 등록이 거부됩니다.**

| 사유 | 조치 |
| --- | --- |
| btrfs·NTFS 파일시스템 | 식별자를 새로 발급할 수 없습니다. 이미지 업로드를 이용하거나 데이터만 담긴 파일로 다시 만드세요. |
| 인스턴스를 정상 종료하지 않고 만든 이미지 | 파일시스템 로그가 정리되지 않아 실패합니다. 인스턴스를 정상 종료한 뒤 다시 만들어 올리세요. |
| 디스크 검사 자체가 실패 | 잠시 후 다시 시도하세요. 반복되면 관리자에게 문의하세요. |

### 주의사항
- 프로젝트에 **업로드한 파일의 가상 크기만큼** 사용 가능한 디스크 할당량이 있어야 합니다. 파일 크기가 작아도 가상 크기가 크면 그만큼 할당량을 사용합니다.
- 업로드 화면의 용량 안내는 파일 크기를 기준으로 한 사전 안내입니다. 실제 판정은 등록 시 서버가 가상 크기로 수행하므로, 안내를 통과해도 할당량이 부족하면 등록이 거부될 수 있습니다.
- 업로드에는 블록 편집 권한이 필요합니다.

## 블록 삭제
- 연결된 인스턴스가 없는 블록을 여러 개 선택해 일괄 삭제할 수 있습니다. 공유 블록은 연결이 하나라도 남아 있으면 삭제할 수 없습니다.
- 삭제 전에 인스턴스와의 연결 상태를 먼저 확인해야 합니다.

## 블록 스냅샷
블록 상세 화면 하단의 `스냅샷` 섹션에서 해당 블록의 스냅샷을 생성·롤백·삭제할 수 있습니다.

> 스냅샷 조회 권한이 없는 역할에서는 이 섹션이 표시되지 않습니다. 생성·롤백에는 스냅샷 편집 권한, 삭제에는 스냅샷 삭제 권한이 필요합니다.

### 주요 작업
- `생성`: 현재 블록의 스냅샷을 1개 생성합니다.
- `롤백`: 선택한 스냅샷 시점으로 블록을 되돌립니다.
- `삭제`: 선택한 스냅샷을 삭제합니다.

### 테이블 컬럼
| 컬럼 | 설명 |
| --- | --- |
| **이름** | 스냅샷 이름입니다. |
| **ID** | 스냅샷 고유 ID입니다. |
| **생성 유형** | 스냅샷을 만든 주체입니다. `인스턴스`(VM 스냅샷에서 파생) 또는 `블록`(블록에서 직접 생성). |
| **연결된 리소스** | 스냅샷과 연결된 원본 리소스(인스턴스/블록)입니다. |
| **크기** | 스냅샷 크기입니다. |
| **타입** | 원본 디스크 포맷 형식입니다. (`QCOW` / `RBD`) |
| **생성 일시** | 스냅샷 생성 시각입니다. |

### 생성·롤백 가능 조건 (중요)
- 블록이 인스턴스에 **연결되어 있으면**, 그 인스턴스가 **`종료됨` 상태일 때만** 스냅샷 생성·롤백이 가능합니다(정합성 보장을 위해 정지 상태에서 수행). 실행 중인 인스턴스에 연결된 블록은 인스턴스를 먼저 종료해야 합니다.
- 인스턴스에 **연결되지 않은 독립 블록**은 상태와 무관하게 생성·롤백할 수 있습니다.
- 공유 블록은 연결된 인스턴스가 **모두** `종료됨` 상태여야 합니다. 다만 `읽기 전용 공유` 블록은 쓰는 인스턴스가 없으므로 연결된 인스턴스가 실행 중이어도 스냅샷을 **생성**할 수 있습니다. 롤백은 내용을 바꾸므로 연결된 인스턴스가 모두 종료돼 있어야 합니다.
- 스냅샷 생성·롤백 요청 후 처리가 진행되는 동안에는 관련 버튼이 일시적으로 비활성화됩니다.

### VM 파생 스냅샷 제약
- **인스턴스(VM) 스냅샷에서 파생된** 블록 스냅샷은 이 화면에서 **삭제·롤백이 비활성**됩니다. 해당 스냅샷은 소유 인스턴스의 스냅샷 화면(`인스턴스 구성 요소 > 스냅샷`)에서 관리합니다. `생성 유형` 컬럼으로 구분할 수 있습니다.

## 블록 스토리지 마이그레이션
블록을 **다른 스토리지 도메인**으로 이동합니다. 스토리지 도메인 정리·재배치나 유형 전환(예: 파일 → Ceph) 시 사용합니다.

연결된 인스턴스 상태에 따라 두 가지 방식으로 수행됩니다.

| 인스턴스 상태 | 방식 | 설명 |
| --- | --- | --- |
| 미연결 / `종료됨` | 콜드 마이그레이션 | 인스턴스를 정지한(또는 미연결) 상태에서 블록을 이동합니다. |
| `실행 중` / `일시 중지` | 라이브 마이그레이션 | 인스턴스 중단을 최소화(무중단)하며 블록을 이동합니다. |

공유 블록은 연결된 인스턴스가 **모두** 정지돼 있으면 콜드, 실행 중인 인스턴스가 **정확히 하나**이고 나머지가 정지돼 있으면 라이브로 이동합니다. 실행 중인 인스턴스가 둘 이상이면 이동할 수 없습니다. `읽기·쓰기 공유` 블록은 Ceph 스토리지 도메인으로만 옮길 수 있습니다.

### 수행 절차
1. 블록 목록 화면에서 블록을 선택합니다.
2. `스토리지 마이그레이션`을 클릭합니다.
3. 대상 `스토리지 도메인`을 선택합니다. (현재 사용 중인 도메인, 사용 불가(비UP) 도메인, 라이브 마이그레이션일 때 연결된 실행 중 인스턴스의 호스트가 접근할 수 없는 도메인(다른 노드 전용 `LOCAL` 등)은 선택할 수 없습니다. 마지막 경우에는 안내 영역에 "인스턴스가 실행 중인 호스트에서 접근할 수 없는 스토리지 도메인은 라이브 마이그레이션 대상으로 고를 수 없습니다."가 표시됩니다.)
4. `실행`을 클릭해 마이그레이션을 시작합니다. 요청은 비동기로 처리됩니다.

> 중요
>
> 스냅샷이 있는 블록은 **라이브 스토리지 마이그레이션을 수행할 수 없습니다.** 스냅샷을 삭제하거나 연결 인스턴스를 종료한 뒤 콜드 마이그레이션으로 수행합니다. 콜드 마이그레이션에서도 스냅샷이 있는 블록은 **유형이 다른 스토리지 도메인으로는 이동할 수 없습니다.**

> 참고
>
> 콜드 마이그레이션 도중 CloudiA 가 재시작되면 시스템이 중단된 작업을 자동으로 정리합니다. 디스크 전환 전에 중단됐으면 블록은 원래 스토리지 도메인에 그대로 남고 요청은 실패로 끝나며, 전환 뒤에 중단됐으면 대상 스토리지 도메인으로 이전이 완료됩니다. 정리가 끝나기 전에는 같은 블록을 다시 마이그레이션할 수 없습니다. 요청하면 `409`(이미 처리 중) 오류로 실패합니다.

### 노드 유지관리로 옮겨진 블록

관리자가 노드를 유지관리 모드로 넣으면서 스토리지 이전을 허용하면, 그 노드에서만 쓰는 스토리지 도메인에 있던 블록이 다른 스토리지 도메인으로 옮겨질 수 있습니다. 옮겨진 블록은 노드가 복귀해도 원래 스토리지 도메인으로 돌아오지 않습니다.

옮겨진 블록마다 이벤트 `노드 유지관리 블록 이전`(INFO)이 남습니다. 메시지에 인스턴스·블록 이름과 원래·대상 스토리지 도메인이 표시되며, 관리자와 프로젝트 사용자가 함께 볼 수 있습니다. 원래 스토리지 도메인으로 되돌리려면 위 절차로 직접 마이그레이션합니다.

## 블록 공유
한 블록을 같은 프로젝트의 여러 인스턴스에 함께 연결합니다. 블록마다 `공유 방식`을 정하며, 인스턴스에 연결할 때 따로 고르지 않습니다.

| 공유 방식 | 동작 | 스토리지 도메인 |
| --- | --- | --- |
| `공유 안 함` | 인스턴스 하나에만 연결합니다. | 모든 도메인 |
| `읽기 전용 공유` | 여러 인스턴스에 읽기 전용으로 연결합니다. 공유하는 동안 내용은 바뀌지 않습니다. 데이터셋·모델 파일처럼 같은 내용을 여러 인스턴스에 나눠 줄 때 씁니다. | 모든 도메인 |
| `읽기·쓰기 공유` | 여러 인스턴스가 동시에 읽고 씁니다. | Ceph 만 |

### 공유 방식 지정
| 화면 | 고를 수 있는 값 |
| --- | --- |
| 블록 생성 | `공유 안 함` / `읽기·쓰기 공유` |
| 블록 업로드 | `공유 안 함` / `읽기 전용 공유` / `읽기·쓰기 공유` |
| 블록 복제 | 원본 값이 기본이며 바꿀 수 있습니다. 대상 스토리지 도메인이 Ceph 가 아니면 `읽기·쓰기 공유`를 고를 수 없습니다. |
| 블록 편집 | 세 가지 모두. 아래 조건을 따릅니다. |

고를 수 없는 값은 화면에서 비활성으로 표시되고 이유가 함께 나타납니다.

### 공유 방식 바꾸기
- 블록에 연결된 인스턴스가 **모두 정지**돼 있어야 바꿀 수 있습니다. 정지된 인스턴스는 다음 기동 때 바뀐 방식으로 연결됩니다.
- 시작 템플릿이 이 블록을 참조하고 있으면 바꿀 수 없습니다.
- `공유 안 함`으로 되돌릴 때는 연결된 인스턴스가 하나 이하여야 합니다.
- 공유로 바꿀 때는 이 블록을 담은 인스턴스 스냅샷이 없어야 합니다.

### 공유 블록의 제약
- **인스턴스 스냅샷**에는 공유 블록이 포함되지 않습니다. 공유 블록의 스냅샷은 블록 상세의 `스냅샷` 섹션에서 만듭니다.
- **복제**: `읽기 전용 공유` 블록은 연결된 인스턴스가 실행 중이어도 복제할 수 있습니다. `읽기·쓰기 공유` 블록은 연결된 인스턴스가 모두 정지돼 있어야 합니다.
- **크기 변경**: `읽기 전용 공유` 블록은 크기를 늘릴 수 없습니다. `읽기·쓰기 공유` 블록은 연결된 인스턴스가 모두 정지돼 있을 때만 늘릴 수 있습니다.
- **시작 템플릿**: `읽기 전용 공유` 블록을 담은 시작 템플릿으로는 인스턴스를 여러 번 만들 수 있습니다.

> ⚠️ **주의:** Ceph 스토리지 도메인의 공유 블록을 함께 쓰는 인스턴스는 **서로 다른 노드**에 둡니다. 이 인스턴스들이 한 노드에서 실행되다가 그 노드에 장애가 나면, 다른 노드에서 다시 시작하지 못하고 노드가 돌아올 때까지 기다립니다. [선호도 그룹](../../vm/affinity-group/affinity-group.md)에서 `가상머신 선호도`를 `반선호도`, `가상머신 강제성`을 `강제`로 두면 늘 서로 다른 노드에 배치합니다.

### 게스트 장치 경로
인스턴스 안에서 장치 이름(`sdb`, `sdc` 등)은 인스턴스마다 다를 수 있습니다. 같은 블록을 가리키려면 `게스트 장치 경로`를 사용합니다. 블록 상세의 연결된 인스턴스 목록과 인스턴스 디스크 목록에서 확인할 수 있습니다.

```
/dev/disk/by-id/scsi-0QEMU_QEMU_HARDDISK_<블록 ID>
```

리눅스 인스턴스에서만 표시합니다(윈도우에는 이 경로가 없습니다).

### 읽기·쓰기 공유 블록 사용하기 (중요)
> 경고
>
> `읽기·쓰기 공유`는 여러 인스턴스가 같은 블록에 동시에 쓸 수 있게 연결만 해 줍니다. 쓰기 조율은 인스턴스 안에서 해야 합니다. **ext4·xfs 같은 일반 파일시스템을 여러 인스턴스에서 마운트하면 데이터가 손상됩니다.** 플랫폼은 블록 안의 파일시스템 종류를 검사하지 않습니다.

다음 중 하나로 사용합니다.
- **클러스터 파일시스템**(GFS2, OCFS2): 여러 인스턴스가 같은 파일시스템을 동시에 마운트할 수 있습니다.
- **`O_DIRECT`로 직접 쓰는 애플리케이션**: 데이터베이스 클러스터처럼 블록을 직접 다루며 쓰기를 스스로 조율하는 경우입니다. 페이지 캐시를 거치면 다른 인스턴스가 쓴 내용을 늦게 보거나 덮어쓸 수 있습니다.

GFS2 구성 순서(Rocky Linux·RHEL 계열 예시):
1. 같은 블록을 `읽기·쓰기 공유`로 만들고, 사용할 인스턴스에 모두 연결합니다.
2. 각 인스턴스에 클러스터 구성 요소(`pacemaker`, `corosync`, `dlm`, `gfs2-utils`)를 설치하고 같은 클러스터로 묶습니다. 노드 장애 시 쓰기를 끊는 펜싱(fencing) 설정이 필요합니다. 자세한 절차는 운영체제의 클러스터 문서를 따릅니다.
3. 인스턴스 한 대에서 파일시스템을 만듭니다. `-j` 에는 마운트할 인스턴스 수 이상을 넣습니다.
   ```
   mkfs.gfs2 -p lock_dlm -t <클러스터 이름>:<파일시스템 이름> -j <인스턴스 수> /dev/disk/by-id/scsi-0QEMU_QEMU_HARDDISK_<블록 ID>
   ```
4. 각 인스턴스에서 같은 경로로 마운트합니다. 클러스터 리소스로 등록해 마운트를 관리하는 것을 권장합니다.

# 파일 시스템

`파일 시스템`은 프로젝트에서 공유 가능한 파일 기반 저장 공간을 생성하고 관리하는 화면입니다. `NFS`와 `VIRTIOFS` 타입을 지원합니다.
`NFS`는 NFS 서버를 생성한 뒤, 해당 서버의 공유 경로를 인스턴스에 마운트하는 방식입니다. 이때 NFS 서버는 Rocky Linux 9 기반 어플라이언스로 자동 생성되므로 사용자가 별도로 서버 OS를 준비할 필요는 없습니다.
`VIRTIOFS`는 스토리지 도메인의 디렉토리를 인스턴스에 직접 마운트하는 방식입니다.


## 화면 개요
- `목록 화면`: 파일 시스템 현황을 조회하고 생성, 편집, 삭제 작업을 시작합니다.
- `상세 화면`: 기본 정보와 타입별 하단 정보를 확인합니다.
- `생성/편집 화면`: 이름, 타입, 크기, 스토리지 도메인과 네트워크 정보를 입력하거나 수정합니다.

## 파일 시스템 목록
### 주요 작업
- `생성`: 새로운 파일 시스템을 생성합니다.
- `편집`: 선택한 1개 파일 시스템을 편집합니다. (`NFS`: 이름/크기, `VIRTIOFS`: 이름)
- `삭제`: 선택한 1개 파일 시스템을 삭제합니다.

### 테이블 컬럼
| 컬럼 | 설명 |
| --- | --- |
| **이름** | 파일 시스템 이름입니다. |
| **ID** | 파일 시스템 고유 ID입니다. |
| **타입** | 파일 시스템 타입입니다. `NFS`, `VIRTIOFS` 중 하나입니다. |
| **크기** | 파일 시스템 크기입니다. 실제 크기를 표시합니다. |
| **상태** | `NFS`는 서버 인스턴스(VM) 상태를 표시합니다. `VIRTIOFS`는 서버 인스턴스가 없어 `-`입니다. |
| **연결된 리소스 수** | 현재 파일 시스템에 연결된 리소스(인스턴스·클러스터) 개수입니다. |
| **생성 일시** | 파일 시스템 생성 시각입니다. |

## 파일 시스템 상세
파일 시스템 상세 화면에서는 선택한 파일 시스템의 상세 정보를 확인할 수 있습니다.  
하단 패널에서는 파일 시스템을 이루는 스토리지 도메인·네트워크 인터페이스와, 이 파일 시스템에 연결된 인스턴스·클러스터를 조회할 수 있습니다.

### 상단 요약
- **이름**: 파일 시스템 이름입니다.
- **ID**: 파일 시스템 고유 ID입니다.
- **타입**: 파일 시스템 타입입니다. `NFS`, `VIRTIOFS` 중 하나입니다.
- **크기**: 파일 시스템 크기입니다.
- **상태**: `NFS`는 서버 인스턴스(VM) 상태를 표시합니다. `VIRTIOFS`는 서버 인스턴스가 없어 `-`입니다.
- **연결된 리소스 수**: 현재 연결된 리소스(인스턴스·클러스터) 개수입니다.
- **생성 일시**: 파일 시스템 생성 시각입니다.
- **NFS 쓰기 방식**: `NFS` 타입에서만 표시합니다. `동기` 또는 `비동기`입니다. 차이는 [`NFS` 타입 쓰기 방식](#nfs-타입-쓰기-방식)을 참고합니다.

### 하단 패널
상세 화면 하단에는 `파일 시스템 구성 요소`와 `연결된 리소스` 두 패널이 있습니다. 각 패널의 왼쪽 탭을 눌러 목록을 바꿉니다. 타입에 따라 보이는 탭이 다릅니다.

| 패널 | 탭 | `NFS` | `VIRTIOFS` |
| --- | --- | --- | --- |
| `파일 시스템 구성 요소` | `스토리지 도메인` | 표시 | 표시 |
| `파일 시스템 구성 요소` | `네트워크 인터페이스` | 표시 | 표시하지 않음 |
| `연결된 리소스` | `인스턴스` | 표시 | 표시 |
| `연결된 리소스` | `클러스터` | 표시 | 표시하지 않음 |

#### 파일 시스템 구성 요소
- **스토리지 도메인** 탭

  | 항목 | 설명 |
  |------|------|
  | 스토리지 도메인 유형 | 해당 파일 시스템이 사용하는 스토리지 도메인의 유형을 나타냅니다. |
  | 스토리지 도메인 이름 | 해당 파일 시스템이 사용하는 스토리지 도메인의 이름을 나타냅니다. |
  | ID | 해당 파일 시스템이 사용하는 스토리지 도메인의 ID를 나타냅니다. |

- **네트워크 인터페이스** 탭 (`NFS`만)

  | 항목 | 설명 |
  |------|------|
  | VPC | 해당 파일 시스템이 사용하는 VPC를 나타냅니다. |
  | 서브넷 | 해당 파일 시스템이 사용하는 서브넷을 나타냅니다. |
  | 보안그룹 | 해당 파일 시스템이 사용하는 보안그룹을 나타냅니다. |

#### 연결된 리소스
- **인스턴스** 탭

  | 항목 | 설명 |
  |------|------|
  | 이름 | 연결된 인스턴스의 이름을 나타냅니다. |
  | ID | 연결된 인스턴스의 ID를 나타냅니다. |
  | 상태 | 연결된 인스턴스의 상태를 나타냅니다. |
  | vCPU | 연결된 인스턴스에 할당된 vCPU를 나타냅니다. |
  | 메모리 | 연결된 인스턴스에 할당된 메모리를 나타냅니다. |
  | 마운트 포인트 | 연결된 인스턴스에서의 파일시스템 마운트 포인트를 나타냅니다. |
  | 생성 일시 | 연결된 인스턴스가 생성된 일시를 나타냅니다. |

- **클러스터** 탭 (`NFS`만)

  이 파일 시스템을 사용하는 쿠버네티스 클러스터 목록입니다. 조회만 할 수 있습니다. 클러스터 상세의 `스토리지` 탭에서 이 파일 시스템으로 스토리지 클래스를 만들면 연결되고, 그 스토리지 클래스를 지웠을 때 파일 시스템을 쓰는 곳이 남아 있지 않으면 연결이 자동으로 풀립니다.

  | 항목 | 설명 |
  |------|------|
  | 이름 | 클러스터 이름을 나타냅니다. 클릭하면 클러스터 상세 화면으로 이동합니다. |
  | ID | 클러스터의 ID를 나타냅니다. |
  | 상태 | 클러스터의 상태를 나타냅니다. |
  | 생성 일시 | 클러스터가 생성된 일시를 나타냅니다. |

> 💡 **참고:** 클러스터에 연결된 파일 시스템은 연결이 풀리기 전까지 삭제할 수 없습니다. 이 탭에서 어느 클러스터에 연결돼 있는지 확인한 뒤, 해당 클러스터 상세의 `스토리지` 탭에서 이 파일 시스템을 쓰는 스토리지 클래스를 삭제합니다.

## 파일 시스템 생성 및 편집
파일 시스템 생성 화면에서는 새로운 파일 시스템을 생성할 수 있으며, 편집 화면에서는 기존 파일 시스템의 일부 정보를 수정할 수 있습니다.  
사용자는 파일 시스템의 기본 정보를 입력해야 하고 파일 시스템의 타입을 `NFS`로 선택하는 경우 추가적으로 `네트워크 인터페이스 구성` 정보를 입력합니다.    
이 경우에는 연결 가능한 `VPC`, `서브넷`, `보안그룹`이 사전에 구성되어 있어야 합니다.  
반면, 파일 시스템의 타입을 `VIRTIOFS`로 선택하는 경우 추가적으로 `스토리지` 정보를 입력합니다.

### 기본 정보
- **이름**: 파일 시스템의 이름을 입력합니다.
- **타입**: 파일 시스템의 타입을 선택합니다. 선택 가능한 타입은 `NFS`, `VIRTIOFS`입니다.
- **크기**: 파일 시스템 크기를 입력합니다. `NFS`와 `VIRTIOFS` 모두 생성 시 입력하며, 크기 단위는 MB, GB, TB입니다.
  - `VIRTIOFS`는 입력한 크기만큼 선택한 스토리지 도메인의 디스크 할당량을 사용합니다. 생성할 때만 크기를 입력하고, 편집 화면에는 크기 입력란이 없습니다.
  - `VIRTIOFS`를 CephFS 스토리지 도메인에 만들면 입력한 크기가 실제 사용 한도로 걸립니다. 그 밖의 도메인에서는 할당량 계산에만 쓰이고 사용량을 물리적으로 막지는 않습니다.
- **스토리지 도메인**: 파일 시스템이 구성될 스토리지 도메인을 선택합니다.

> ⚠️ **주의:** `VIRTIOFS`는 `CEPH` 스토리지 도메인을 지원하지 않습니다.

### `NFS` 타입 네트워크 정보
- **VPC**: 파일 시스템이 사용할 VPC를 선택합니다.
- **서브넷**: 파일 시스템이 사용할 서브넷을 선택합니다.
- **보안그룹**: 파일 시스템에 추가로 적용할 보안그룹을 선택합니다. **선택 사항**입니다.

> ℹ️ **NFS 마운트용 보안그룹 자동 생성**: NFS 파일 시스템을 생성하면 마운트에 필요한 전용 보안그룹이 **자동으로 생성**되어 적용됩니다. 이 보안그룹의 이름은 파일 시스템마다 고유하게 `nfs-sg-{파일 시스템 ID}` 형식(접두사 `nfs-sg-`)으로 부여됩니다. 따라서 위 **보안그룹** 선택은 필수가 아니며, 추가 규칙이 필요할 때만 선택합니다. 자동 생성된 보안그룹은 선택 드롭다운에 나타나지 않고 읽기 전용으로 표시되며, NIC당 보안그룹 총 한도 중 1개를 차지합니다(사용자가 고를 수 있는 개수는 그만큼 줄어듭니다).

### `NFS` 타입 사용자 계정 (선택)
`NFS`는 Rocky Linux 9 기반 NFS 서버 어플라이언스로 생성됩니다. 이 서버 VM에 로그인할 **사용자 계정**을 생성 시 선택적으로 지정할 수 있습니다. **계정명·비밀번호·SSH 키는 모두 선택 입력**이며, 세 항목을 모두 비워 두어도 파일 시스템을 생성할 수 있습니다. (계정 정보는 **생성 시에만** 입력합니다.)

- **사용자 이름**: NFS 서버에 생성할 로그인 계정명입니다. 소문자·숫자·`-`·`_`만 사용할 수 있으며, `root`·`admin`·`test` 등 예약어는 사용할 수 없습니다.
- **비밀번호**: `등록` 버튼을 눌러 새 비밀번호와 확인 값을 입력합니다. 입력한 항목만 서버에 반영됩니다.
- **SSH 키**: NFS 서버 접근에 사용할 SSH 키를 선택합니다. **현재 프로젝트가 소유한 키만** 목록에 표시되며, 최대 5개까지 선택할 수 있습니다.

> ℹ️ **기본 계정명**: 계정명을 비워 두면(공백만 입력한 경우 포함) 로그인 계정은 항상 **`cloudia`** 로 생성됩니다. 즉 NFS 서버에 접속할 때 계정명을 따로 지정하지 않았다면 사용자명은 `cloudia`입니다. 계정명만 지정하면 그 이름으로 sudo 권한 계정이 생성되고 비밀번호는 잠깁니다.
>
> ℹ️ **로그인 가능 여부**: 비밀번호와 SSH 키 지정에 따라 다음과 같습니다.
> - 비밀번호·SSH 키 모두 없음: 로그인할 수 없습니다.
> - SSH 키만 지정: SSH 키로만 로그인할 수 있습니다.
> - 비밀번호 지정: 비밀번호로 로그인할 수 있으며, SSH 비밀번호 인증도 사용할 수 있습니다.
>
> ℹ️ 과거 버전에서 사용하던 고정(하드코딩) 기본 비밀번호는 제거되었습니다. NFS 서버에 로그인이 필요하면 위 사용자 계정을 직접 지정하거나 SSH 키를 등록하십시오.

### `NFS` 타입 쓰기 방식
NFS 서버가 클라이언트의 쓰기에 응답하는 시점을 고릅니다. 생성 화면과 편집 화면 모두에서 고를 수 있으며, 기본값은 **동기**입니다.

| 쓰기 방식 | 동작 | 맞는 용도 |
|---|---|---|
| **동기** (기본) | 파일을 만들거나 쓸 때마다 데이터 디스크에 기록을 끝낸 뒤 응답합니다. | 데이터베이스, 잃으면 안 되는 데이터 |
| **비동기** | 기록을 기다리지 않고 바로 응답합니다. 소스 압축 풀기·패키지 설치·빌드처럼 작은 파일이 많은 작업이 10배 이상 빨라집니다. | 다시 만들 수 있는 작업 공간, 빌드·캐시 데이터 |

> ⚠️ **비동기**로 두면 NFS 서버가 갑자기 멈췄을 때 최근 몇 초~수십 초 사이에 쓴 내용이 사라질 수 있습니다. 클라이언트는 이 유실을 알지 못하고, `fsync` 도 저장을 보장하지 않습니다. 데이터베이스나 데이터 무결성이 중요한 용도에는 쓰지 마십시오.

### 입력 필드 유효성
| 필드 | 허용 값                                   | 검증 규칙 | 비고 |
| --- |----------------------------------------| --- | --- |
| **이름** | 영문, 숫자, `-`, `_` 조합의 문자열               | 필수입니다. 80자 이내로 입력합니다. | 파일 시스템 식별용 이름입니다. |
| **타입** | `NFS`, `VIRTIOFS`                      | 필수입니다. 두 값 중 하나를 선택합니다. | 생성 후 변경할 수 없습니다. |
| **크기** | 0 이상의 숫자 + 단위 (MB, GB, TB)                 | 생성 시 `NFS`·`VIRTIOFS` 모두 필수입니다. | `NFS`는 편집 시 늘리기만 할 수 있고, `VIRTIOFS`는 생성 후 바꿀 수 없습니다. |
| **스토리지 도메인** | 관리자가 이 프로젝트에 배정한 스토리지 도메인(배정된 도메인이 없으면 고를 수 없음)              | 필수입니다. `VIRTIOFS`에서는 `CEPH`를 선택할 수 없습니다. | 생성 후 변경할 수 없습니다. |
| **VPC** | 현재 프로젝트의 VPC                           | `NFS` 타입에서 필수입니다. | 네트워크 연결 정보입니다. |
| **서브넷** | 선택한 VPC의 서브넷                           | `NFS` 타입에서 필수입니다. | 네트워크 연결 정보입니다. |
| **보안그룹** | 현재 프로젝트의 보안그룹                          | `NFS` 타입에서 선택 사항입니다. 마운트용 보안그룹(`nfs-sg-{파일 시스템 ID}`)은 자동 생성됩니다. | 추가 규칙이 필요할 때만 선택합니다. |
| **NFS 쓰기 방식** | `동기`, `비동기` | `NFS` 타입에서 선택합니다. 기본값은 `동기`입니다. | 편집에서 바꾸면 NFS 서버가 재시작됩니다. |

### 편집 시 주의사항
- 편집 화면에서는 `NFS`는 이름, 크기, SSH 키, 비밀번호, 보안그룹, NFS 쓰기 방식을, `VIRTIOFS`는 이름만 수정할 수 있습니다. (VPC·서브넷은 생성 후 고정이며, 자동 생성된 마운트용 보안그룹(`nfs-sg-{파일 시스템 ID}`)은 편집 대상이 아닙니다.)
- 타입, 스토리지 도메인, 네트워크 정보는 생성 후 변경할 수 없습니다.
- `NFS` 크기는 기존 값 이상으로만 수정할 수 있습니다.
- NFS 쓰기 방식을 바꾸면 저장할 때 NFS 서버를 껐다 켜서 반영합니다. 그동안 연결된 인스턴스·쿠버네티스 PVC 의 파일 접근이 잠시 멈췄다가 서버가 다시 뜨면 이어집니다.
